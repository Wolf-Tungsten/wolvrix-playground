# 02 技术路线讨论

围绕你提的四条思路逐条讨论。先说结论：

1. **语义固定性**——成立，但它买的是"封闭词表 + 离线重搜索可摊销"，买不来激活分布；后者仍需 profile 或静态估计。
2. **GNN 聚合邻居信息**——方向对，特征清单可以直接列出来；真正的难点不在编码器而在输出头怎么建模（想法四）。
3. **局部采样搜索 + RL**——同意，但建议明确分工：搜索负责产标签，GNN 模仿负责冷启动，RL 负责精修；reward 必须是可校准的 cost model，不能直接上 runtime。
4. **边二分类 + 修复**——这是四条里最弱的一条。更干净的建模方式：**学习节点排序（learn-to-order）**，无环性由构造保证，与产线骨架兼容；**已拍板为主路径**（含 coarsen 处置，见 §4 方案 A 拍板配置）。

## 1. 语义固定性能买什么

AM 图的确语义固定：46 个 Opcode（`wolvrix/include/grhsim/am/program.hpp:185-235`），设计确定则图确定。这带来三个具体好处：

- **封闭词表，跨设计泛化**。op 类型 embedding 是设计无关的，在 openc910 / xs-components 上学的模型可以直接往全香山迁移。特征工程一次到位，不存在词表漂移。
- **离线重搜索成本可摊销**。图是确定性输入，"同一个图反复跑重搜索"是合法的——训练标签、cost model 校准都可以离线做，生产编译期只需要一次前向推理。甚至 per-design 微调都在预算内（编译期允许分钟级搜索）。
- **结果可缓存、可复现**。图 → 划分是纯函数，便于做回归测试和增量更新。

但要划清边界：**固定的是结构和类型，不是运行时激活分布**。目标函数里的 $P(S\text{ 激活})$ 依赖输入激励，这正是当年 prob 路线踩坑的地方（NO0209：激活概率驱动的划分结构恶化、runtime 倒退）。所以：

- 语义固定性 → 用于**特征与监督信号**（结构侧）；
- 激活概率 → 只进 **cost model 的估计项**，且任何候选必须先过结构硬门槛（dag_edges / compute_compute_value_pairs / footprint 不劣于 plain 基线），再谈 runtime。

## 2. GNN 编码器：特征与聚合

这部分技术风险最低，先把清单定下来。

**节点特征**（两种粒度都封闭）：

- op 粒度（compute-op-dag 导出）：GRH op kind one-hot/embedding、位宽（log2 缩放）、入/出度、fanout 直方统计、topo 层（source 最长路径深度，与 Herrmann 的 top-level 一致）、是否 commit/state 相关。
- ~~atom 粒度（AM 生产路径）~~【已修正，见 03 文档：实践中 atom 恒为单指令，不存在"直方图"形态】AM 指令粒度：opcode embedding（46 类）+ 位宽 + 结构度特征，与 op 粒度特征形态一致。

**边特征**：value 位宽（64-bit 字数，导出已有）、边类型（def-use vs ordered effect）、重数。

**聚合器**：GraphSAGE / GIN 风格 2-4 层即可；注意 grhsim 图有重尾 hub（max outdegree 15,837，NO0010），聚合必须度归一化或邻居采样，否则 hub 会淹没信号。可加一个 virtual node 携带全局统计（图规模、密度）。**推理硬件约束（拍板 2026-07-29）：编译机无 GPU，全图推理走 CPU**——隐维 ≤64、层数 2-3 封顶；生产路径在 wolvrix C++ 内原生实现推理（读导出权重，SpMM/gather，约数百行），编译流不引入 Python/PyTorch 依赖；训练仍在离线 GPU 机器上。

选型结论：GNN 没问题，但**编码器不是本项目的难点**——输出建模与无环约束才是，见 §4。

## 3. 搜索 + RL：明确分工

"难构造最优解 ⇒ 采样搜索 + RL"这个判断对，但建议把三个组件的角色钉死，避免变成一锅粥：

```
重搜索（离线）  ──产标签──▶  GNN 模仿（监督）  ──冷启动──▶  RL 精修（cost model reward）
   ▲                                                              │
   └──────────────── 迭代：模型提议序/候选，搜索在提议邻域内再优化 ◀──┘
```

- **搜索产标签**：训练 case 来自**全香山采样**（拍板，见 §6.3）：采样区域数百~数千节点，区域内做重搜索——模拟退火 / late-acceptance，移动算子用 gsim 已验证有效的"序相邻移动"（`graphRefine` 的 checkIncoming/checkOutcoming 天然保无环）+ 切点扰动 + 段内重排；边界 halo 冻结（外部边记为固定 cut），搜索只排内部。小图可用 CP-SAT / 暴力 oracle 量 gap。重建的 harness（§6.3）承载这套流程。
- **GNN 模仿冷启动**：直接在稀疏 reward 上 RL 冷启动很贵；先用搜索标签做监督（排序偏好或边标签），把模型拉到"不差于 plain 基线"的水平。
- **RL 精修**：以 cost model 为 reward 做策略梯度，动作空间 = 局部移动或序扰动。参考范式：device placement 的 Placeto / REGAL（GNN+RL 学布局，可迁移）、ECO-DQN 类"学习局部搜索"。
- **迭代闭环**：模型提议的序/候选分区可以反过来限定搜索邻域，搜索改进后再蒸馏回模型（DAgger 式）。这是"学习 + 搜索"系统通常真正拿到收益的地方。

**reward 的纪律**：runtime 单次测量太贵（50k gate 分钟级），RL 只能用 cost model 作 reward；cost model 用历史 runtime 数据校准（NO 系列笔记里已有多次结构指标 ↔ 50k host time 的对照点）。最终 gate 仍然是结构硬门槛 + 50k difftest，这条是从 NO0209 买来的教训，不能省。

## 4. 建模与无环：核心讨论

你的初步设想是"边二分类（割/不割）+ 再学启发式做无环精修"，并且担心 GNN 输出无法保证无环。这个担心是对的：**无环是全局约束，GNN 的逐边独立预测本质上是局部的，指望网络自己输出无环解不可靠，加惩罚项也只能软约束**。

但有一个关键观察能把这个问题化解掉：

> **任何无环划分，都等价于"某条拓扑序上的连续分段"。**
> 证明一句话：商图是 DAG，取其拓扑序 $P_1<\dots<P_k$，段内节点再按原图拓扑序排列，拼接后跨段边全部前向，即得全图的一条拓扑序，且每段是连续段。

也就是说，"拓扑序 + 连续分段"这个解空间对无环划分是**完备的，没有任何表达力损失**（唯一的限制是容量由分段算法控制，而现有 DP 本来就管这个）。gsim 和 grhsim 现在的骨架恰好就是这个形式——它们差的只是"序"的质量。

### 方案 A（拍板主路径）：learn-to-order —— 学习节点势函数

- GNN 输出每个节点一个标量 $\phi(v)$；
- 用 $\phi$ 作为 Kahn 算法的优先级（每次从 ready 集合里取 $\phi$ 最小的），得到一个**真拓扑序**——即使 $\phi$ 本身不完全满足边方向，Kahn 投影也保证输出合法；
- 在这条序上跑**现有的连续段 DP**（或带位宽权重的改进 DP）得到最终划分。

无环性：**由构造保证，零额外机制**。序合法 ⇒ 连续段 ⇒ 商图无环。

优点：

- 与产线骨架兼容——只替换"序从哪来"，Kahn/段 DP/emitter 不动，回灌风险最低（coarsen 处置见下方拍板配置）；
- 监督信号好构造：搜索标签划分 $\Rightarrow$ 导出排序偏好（同段节点对应靠近，跨段节点对按商图拓扑定向），用 pairwise ranking loss 训练；也可以 RL 直接对最终 DP cost 做策略梯度；
- 自由度对上了病根：01 文档 §6 说过，现有算法的最大未优化自由度就是序。gsim 用一个普通拓扑序都能跑赢，说明这个自由度值得学。

**拍板配置（2026-07-29）：learn-to-order 定为主路径；产线 coarsen 从学习方案中移除，不是搭配而是替代。**

- **输入归一化 = comb-loop-atom 环收缩 + out1/in1 链收缩**。后者近乎免费（出度1链几乎总该合，gsim 的 mergeOut1 同理），留作消融实验验证；sibling 合并不预做，交给 φ+DP 裁决。
- **移除产线 coarsen**（32×128=4096 指令上限的三路合并，`wolvrix/include/grhsim/am/pipeline.hpp:134`）：它与 128 段上限的结构性矛盾制造 oversized block，正是 NO0067/NO0086 实证的"大块更慢"病根；移除后所有块保证 ≤128 指令，粒度向 gsim（35 节点）靠拢，正面应对"coarse but dense"。
- **规模不是 coarsen 的理由**：Kahn + 段 DP 近线性，4.66M 节点直接跑；3 层 GraphSAGE 全图推理约 4e9 MACs，GPU trivial。
- **多层 coarsen 降级为 v2 选项**：仅当全图搜索成本、或全局结构建模（GNN 感受野 vs 图直径）实验表明需要时再引入。
- 全香山规模标签搜索的对策：标签只在 xs-components 级 case（数百~数千节点）上生成，全香山只做推理 + 有限步精修。

### 方案 B（备选/互补）：边分类 + Kruskal 式约束解码

保留你的边二分类直觉，但**把无环保证从 GNN 挪到解码器**：

- GNN 输出每条边的 $p_{\text{cut}}(e)$；
- 解码：按 $1-p_{\text{cut}}$ 从大到小遍历，贪心收缩边——若收缩会在当前商图中成环（存在 dst⇝src 的绕行路径，增量维护）或超容量，则跳过。即"带可行性检查的 Kruskal"。

无环性同样由构造保证。这是 ML-for-CO 的标准模式：**网络只负责排序/打分，可行性由解码器强制**，而不是预测完再修复。

与 A 的关系：共用同一套 GNN 编码器；B 的边分数还可以反过来给 A 的 DP 当边权、或指导 coarsen。可以都试，但 A 先行。

### 方案 C（后备）：顺序生长 / 构造式 RL

策略网络从种子开始逐点扩张分区，每步只在"不破坏可行性"的候选集里选（增量无环检查）。表达力最强但训练最难，作为 A/B 不及预期时的后备。

### 方案 D（不推荐为主路径）：软惩罚聚类

DMoN 式可微聚类 + 无环惩罚项。惩罚永远给不了硬保证，最后还是要修复步骤兜底——既然解码时保证可行性既便宜又精确（A/B），没必要走"预测-修复"的弯路。

### 对"学成环精修"的直接回应

不需要"学修复"：**A/B 的解码器让不可行解根本不产生**。学习真正该放的精修位置是想法三里的局部移动策略（FM 式增益由 GNN 打分、移动合法性由检查器保证），那是改进已合法解的质量，而非修复非法解。

## 5. 分阶段提案

- **Phase 0（基建）**：在本项目重建 harness（拍板，见 §6.3）：LinearProgram 直导指令图的导出器（含输入归一化：comb-loop 环收缩 + out1/in1 链收缩）、checker/scorer（纯结构 cost = v2 文档目标函数的结构部分 + 结构硬门槛）、全香山采样器（topo 窗口 + BFS 区域两模式，带 halo 上下文）、搜索器。
- **Phase 1（搜索基线与标签）**：实现"序扰动 + DP 重切 + 序相邻 FM"搜索器，在 regular case 上产出远好于 plain 的划分；小图用 CP-SAT 量 gap。
- **Phase 2（模仿学习）**：GNN 编码器 + 势函数头，pairwise ranking 监督；评估 = 结构指标 + 与搜索标签的 gap。
- **Phase 3（RL 精修）**：cost model reward 策略梯度；模型↔搜索迭代闭环。
- **Phase 4（生产回灌与 gate）**：模型序接入 activity_schedule pass，过结构硬门槛 + 50k CoreMark difftest + host time。

## 6. 待讨论问题

1. **粒度**【已拍板】：学习问题定义在调度前的 AM 指令图上（46 opcode、全香山 4.66M 节点、单层）；产线 coarsen 移除，多层 coarsen 留作 v2 选项（§4 方案 A 拍板配置）。
2. **cost model 的激活项**【已拍板】：第一版纯结构 cost，完全不引入激活概率（prob 路线教训）；cost model 接口为未来的激活项留位。
3. **harness**【已拍板】：旧 tgp harness 是有意删除的——它建在 GRH IR 上而非 AM linear program 上。在本项目重建：输入 = LinearProgram 直导指令图（03 文档），case 来源 =**全香山采样**（替代模块级 component 提取）。
4. **泛化与 per-design 微调**【讨论中，提案如下】：采样方案改变了问题框架——训练分布 = 推理分布（同一张 XS 图），"零样本迁移"不再是主问题。泛化拆三层：
   - **区域泛化**（采样区域 → 全图）：同分布，风险低；评估纪律 = 整区域留出（随机抽子图会因相邻重叠而泄漏）。
   - **时序泛化**（XS RTL 演进）：采样重训天然覆盖，随设计演进定期重采样。
   - **跨设计泛化**（XS → 910 → 未来核）：训练集保留多设计数据（910 等）防冷启动。
   
   per-design 微调分预算内外两层【提案】：
   - **编译期内（≤15 min）**：不做梯度训练——CPU-only 约束（§6.5）已把这条物理坐实。C++ 原生推理 → Kahn+DP → 剩余预算做全图局部搜索精修（模型序邻域内的 FM/序扰动）。
   - **编译期外（离线循环，GPU 机器）**：采样 → 区域搜索产标签 → 模仿/RL 继续训练（向目标设计加权）→ 全图推理评估。产出的权重随编译器发布，或直接缓存最终划分随设计版本发布。
   
   已知残余风险：区域最优标签在冻结边界下学到的是局部排序偏好，全局最优由全图 DP 重新裁决；两者的 gap 可在小型设计上实测（全图搜索可行处）。
5. **编译期时延预算**【已拍板】：≤15 min。**编译机无 GPU，推理走 CPU**（拍板 2026-07-29）：粗算 3 层、d=64、约 20M 边的全图推理理论开销 <1s（memory-bound gather 主导），计入框架/算子开销后按 10-60s 预算；超时杠杆 = 降隐维 / 减层 / 算子级 C++ 实现。分配：推理 + Kahn/DP 约 1 min 内，其余给编译期局部搜索。Phase 0 末做一次 4.66M 节点 CPU 推理实测，校准模型规模上限。

## 7. 相关工作速查

- **Placeto / GDP / REGAL**：GNN+RL 做 device placement，与"序/指派 + 成本模型"同构，REGAL 的迁移性设计可直接借鉴。
- **ECO-DQN / 学习局部搜索**：RL 改进局部搜索选点策略。
- **DMoN**（Tsitsulin 2020）：无监督 GNN 聚类，本文方案 D 的出处，仅供对照。
- **Herrmann et al. 2019**（`reference/DAG-Acyclic-Partitioning-算法实施文档.md`）：多层无环划分，经典强基线；CoHyb 粗化 + 约束细化的思想可融入搜索器。
- **gsim graphRefine**：序相邻移动的合法性检查方式，是我们搜索算子的现成模板。
