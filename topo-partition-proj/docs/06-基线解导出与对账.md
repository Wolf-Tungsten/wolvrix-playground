# 06 基线解导出与对账（Phase 0 任务 2 前半）

2026-07-30。继 05（指令图导出）之后，生产 block assignment（plain 基线解）的导出已落地，
并且三项体检/成本指标完成了"生产统计 vs 独立复算"的对账——M0 验收门的核心证据。

## 1. 实现

- 代码：`wolvrix/lib/grhsim/am/production_activity_schedule.cpp`，在 block 形成、
  `instructionBlock` 填充完成后导出，与指令图导出相互独立、同次运行可同时开启。
- 开关：环境变量 `WOLVRIX_GRHSIM_AM_BLOCK_ASSIGNMENT_JSONL=<输出路径>`。
- 格式：`wolvrix.am-block-assignment.v1`（JSONL）——header（含生产侧三项指标）+
  block 记录（`id/kind/size`，input sink 记为 size 0 的 compute 块，entry block 0
  不含线性指令不列出）+ assign 记录（`instr→block`，指令 id 与指令图导出一致）。
- 格式细节同步在 `wolvrix/docs/grhsim/grhsim-am-pipeline.md` §3.2.4。

## 2. 对账口径（为什么三个指标能对上）

AM 生产代码此前没有 `dag_edges` / `compute_compute_value_pairs` 统计（它们只存在于
legacy transform 路线），因此导出器在生产内部按如下口径补算，harness 侧独立复算：

- `dag_edges`：def_use 边跨 block，按 (producer block, consumer block) 去重；
  order 边不计入。
- `compute_compute_value_pairs`：按 (value, 消费 compute block) 去重；value 不在该
  block 定义才计入；state target / 接口输入（导出图中的 `external_read`）是永久
  边界，对每个消费 compute 块都计一次；commit 块内的读不计。与段 DP 的 incoming
  activation 成本同口径（即 04 文档"不计位宽版本"的 cost）。
- `incoming_copy_cost`：每个对按 `max(1, ceil(width/64))` 折算求和——即 04 文档
  第一阶段的优化目标 cost。

## 3. 全香山结果与对账证据

同一次 `grhsim-am-lower-json` 运行产出两个文件（数据集
`topo-partition-proj/exp/dataset/xs_full_20260730/`）：

- `instruction_graph.jsonl`：与 05 文档首次导出逐项一致（调度确定性）；
- `block_assignment.jsonl`（233 MB）：34,236 blocks = 33,738 compute + 497 commit +
  1 input sink（stdout 统计的 34,237 含 entry block 0）。

对账（`exp/tools/reconcile_baseline.py`，从图侧独立复算）：

```
dag_edges:                    production=325838   recomputed=325838
compute_compute_value_pairs:  production=3305393  recomputed=3305393
incoming_copy_cost:           production=6468546  recomputed=6468546
```

三项完全一致。基线锚点：plain 基线在全香山上的 cost = **6,468,546**（位宽折算拷贝数），
后续搜索/学习的结果都和它比。
