# 04 实现计划（Phase 0–4）

本文档是可执行的实施计划，阅读不需要背景知识：所有术语在首次出现时都有大白话解释。方案论证见 02 文档，概念澄清（atom / comb-loop-atom）见 03 文档。

结构：背景一页纸 → 已拍板决策（K1–K9）→ 四个阶段的任务与验收门（M0–M4）→ 待定细节（D1–D12，附建议默认值）→ 风险（R1–R6）。

## 0. 背景一页纸

我们要做的事一句话：**用机器学习决定"哪段逻辑放进哪个 block"，让生成的模拟器跑得更快**。

- **block（块）**：模拟器代码的基本执行单位，一坨指令的集合。运行时一个 block 的输入值变了，它才会被唤醒执行。块分得好，每拍要检查的块就少、块间搬运的数据就少，模拟器就快。
- **指令图**：设计（如香山核）编译出来的中间形态——几百万条指令，指令之间有线连着（一条指令的输出是另一条的输入，或者两条指令之间有先后顺序要求）。它是一张有向无环图（DAG）：线有方向，且不会绕成圈（组合逻辑环这个例外见 03 文档）。
- **拓扑序**：把图上所有节点排成一队，保证每条线都从前指向后。我们只在"某条拓扑序的连续段"上切 block——这样切出来的块间关系天然不会成环，这是整个方案的根基。
- **切点 DP（段 DP）**：一种动态规划算法，给定一条排好的序列，能快速算出"在哪几个位置下刀切，总代价最小"。DP = 动态规划。
- 于是问题变成：**给几百万个节点排一个好的先后次序**，次序好，切点 DP 自然切出好 block。让图神经网络（GNN，一种在图上工作的神经网络：每个节点聚合邻居的信息来更新自己的表示）来学这个次序，就是本项目的核心思路——**learn-to-order（学习排序）**。

## Phase 0：harness 重建（搭实验台）

**目标**：导出 → 采样 → 评分 → 搜索的闭环能在全香山数据上跑通，并且打分器和生产代码的口径对得上账。

任务分解：

1. **导出器**（写在 wolvrix 里）：在指令图生成之后、调度之前把图导出来（用环境变量或配置开关触发）。导出内容：每条指令的类型、位宽，指令之间的连线（数据依赖 / 先后顺序），以及组合逻辑环的打包结果（打包逻辑直接复用生产代码里的环检测）。导出的图是之后一切实验的唯一输入。
2. **Scorer（打分器）**：输入一个划分结果，算出它的分数。分数越低 = 划分越好。
   - **分数怎么算（第一阶段只优化这一个数）**：`cost = Σ（每个 block：从别的 block 读入的不同值，按位宽折算的拷贝次数）`，每个值的拷贝次数 = ceil(位宽 / 64)——≤64 bit 是一次拷贝，超出就是多次。同一个 block 里多条指令用同一个值只算一次（按值去重）。注意这**有意不同于**生产 DP 的旧公式（旧的不折算位宽、每块另加 1）——新公式更简单，且直接对应运行时的数据搬运量。
   - **举个例子**：block A 产出值 x（32 bit）和 y（128 bit）；block B 用到 x 和 y；block C 只用到 x。那么 B 的跨块读入 = 1 + 2 = 3 次拷贝，C 的 = 1，A 没有 = 0。cost = 3 + 1 = 4。
   - **体检指标（只记录、不进优化目标）**：以下三个数每次评估照常算、照常记录，用来防止"目标降了但结构烂了"（NO0209 的教训）：
     - `dag_edges`：把每个 block 缩成一个点后，块与块之间依赖图的边数。边越多，块间牵连越重；
     - `compute_compute_value_pairs`：compute 块（纯计算、不写状态的块）之间跨块传递值的对数，约等于 cost 的不计位宽版本；
     - `footprint`：生成的模拟器代码体积，先用 block 数近似（每个 block 有一段固定代码开销）。
   - **对账（验证 scorer 没写错）**：把**生产 pass**（= 现在 wolvrix 里正在用的那段调度代码 `ProductionActivityScheduleStage`，"pass" 就是编译器流水线里的一个处理阶段）跑出的 **block assignment**（= 划分结果本身：每条指令属于哪个 block 的对应表）导出来，用我们的 scorer 重新算一遍，再和生产代码自己统计输出的 `activity_schedule_stats.json` 对比。两边数字一致，才说明我们的打分器和生产口径相同——相当于"用已知答案考新判卷老师"。注意生产统计里没有现成的位宽折算数，所以对账对的是不计位宽的版本（体检指标）；位宽折算的正确性靠单元测试保证。这份参考解叫 **plain 基线解**（plain = 现有线上算法，历史笔记里的叫法，区别于 prob/CBAW 等已废弃变体）。
3. **采样器**：把 466 万个节点的全香山大图切成一个个小的"训练区域"，每个区域就是一个训练样本。为什么要采样：标签靠搜索来产，搜索只在小图上跑得起；而且几千个小样本比一整张图更适合训练。
   - **一个区域怎么取**（两种方式各取一半，防止模型只习惯一种切法）：
     - **topo 窗口**：在拓扑序上取连续一段（比如第 10000 到第 15000 个节点）。理由：切点 DP 看到的世界就是拓扑序上的连续段，这种切法和最终用法一致；
     - **BFS 区域**：随机挑一个种子节点，顺着边一圈圈向外扩，扩到规模上限为止。理由：这抓到的是"一坨逻辑"的自然形状（比如某个功能部件的一段数据通路）。
   - **halo（光晕）= 区域外面的一圈节点**（默认往外 2 跳）。它不是训练对象，只是上下文，有两个用途：一是区域边缘节点算特征时能看到区域外的邻居，否则边缘节点的邻居信息被人为砍断，和全图推理时对不上；二是搜索区域内划分时，跨出区域的边是"天生被割的"，halo 让搜索知道哪些内部节点有重边通向外面。**halo 只读不写**：打标签、算损失都只看区域内部。
   - **留出区域管理**：留一部分区域永远不进训练集、只用于考试。做法：把拓扑序的连续 10% 划为禁区，训练采样不许碰。必须用连续区间而不是随机撒点——两个位置接近的窗口会大量重叠，随机留出等于把考题答案泄漏给训练。
4. **搜索器骨架**：给定一个区域，尝试不同的节点排列，用切点 DP 算出每种排列的分数，留下最好的。核心是一种叫**模拟退火（SA）**的随机搜索：随机改动排列，改好就接受，改差按一定概率也接受（避免卡在局部最优），随着"温度"下降越来越保守。Phase 1 再把它做完整。
5. **CPU 推理速度摸底**：编译机没有 GPU，所以提前在 CPU 上测"466 万节点、3 层 GNN、向量长 64"的推理要多久。GNN 推理的核心计算就两个：沿边把邻居的向量收过来（gather，按下标取向量），再求和/平均（等价于一次稀疏矩阵乘，SpMM）。用 numpy 或 torch 的 CPU 模式测这两个操作的耗时，就能推算模型规模上限，防止到最后才发现推理超时。

**产出物**：`exp/` 下四个模块 + 第一版训练数据集（512 个区域）+ 对账报告。

**验收门 M0**：全香山导出成功；对账通过（打分器给现有算法结果打的分，和生产代码自己统计的一致）；采样覆盖检查通过（各种指令类型、各种规模的区域都取到了）；CPU 摸底给出模型规模的实测上限。

## Phase 1：搜索出标准答案（标签）

**目标**：在采样区域上，用搜索找出比现有算法明显更好的划分，作为训练的"标准答案"（标签），并量化搜索答案离理论最优还有多远。

任务：

1. **搜索器完整版**（参数见 D7）：在一个区域里反复做两类改动——把一个节点挪到合法范围内的另一个位置（合法范围 = 必须排在它所有前驱之后、所有后继之前），或交换两个节点的位置；每改一次用切点 DP 重算分数，按模拟退火规则决定接不接受。区域外圈的 halo 节点位置固定不动（冻结），只排内部节点。
2. **标签流水线**：批量跑 512 个区域，把每个区域搜到的最好排列和它的分数落盘保存。
3. **离最优有多远**：在小区域（≤200 个节点）上用 CP-SAT（Google OR-Tools 的约束求解器，能算出数学意义上的精确最优解）算出满分答案，对比搜索答案，报告差距。
4. **对照锚点**：同一批区域上，也跑一遍"简化版现有算法"（固定拓扑序 + 切点 DP，不做预先捆包），再加上生产代码导出的真实结果，作为比较基准。

**验收门 M1**：搜索答案的分数中位数比现有算法好 ≥10%（做不到说明"排次序"这个自由度的油水没想象中大，要回头检查评分公式）；小区域上搜索离精确最优 ≤5% 为佳。

## Phase 2：模仿学习（照着答案学）

**目标**：GNN 在没见过的区域上，给出的排序切出来的 block 不差于现有算法，并尽量接近搜索找到的标准答案。

任务：

1. **特征管线**：把每个节点的信息变成一串数字（指令类型、位宽、有几个输入输出、在图里的深浅等），清单见 02 文档 §2。
2. **模型**：2-3 层 GraphSAGE（一种 GNN 层：每个节点把邻居的向量取平均来更新自己的向量；取平均是为了防止"枢纽节点"——连着上万个邻居的节点——淹没信号），最后接一个小网络把每个节点的向量压成一个分数 φ。
3. **训练方法：成对比较**（pairwise ranking）。从标准答案里抽成对的节点："这个区域里 u 应该排在 v 前面"，训练让 φ(v) − φ(u) 尽量大（至少拉开 1.0 的差距）。不需要模型猜中绝对位置，只要相对顺序学对。
4. **评估**两个指标：排序相似度（Kendall τ，越接近 1 说明模型排的序越像标准答案）和实际分数（模型排序 → Kahn 修正 → 切点 DP 之后的 cost，和现有算法比、和标准答案比）。

**验收门 M2**：在留出的考试区域上，模型结果的 cost ≤ 现有算法（硬指标）；比标准答案差不超过 +5%（争取目标）。

## Phase 3：强化学习精修 + 模型与搜索互相促进

**目标**：让模型在模仿的基础上再进一步；跑通"模型提议 → 搜索改进 → 改进结果再教给模型"的循环。

任务：

1. **强化学习**（配置见 D9）：让模型带点随机性——Kahn 算法每次挑节点时不再总挑分数最高的，而是按概率挑（分高被挑中的概率大），同一个模型就能产出多种排法；用最终 cost 当奖惩来更新模型（这个经典算法叫 REINFORCE）。奖惩的基准是模仿阶段模型的分数：比它好就奖，比它差就罚。随机程度（温度 τ）随训练逐渐调小，从"多探索"过渡到"多利用"。
2. **互相促进一轮**：模型先给出排序，搜索只在这个排序的邻域里做小幅改动找更优；找到的更优答案再当教材教给模型（这个套路叫 DAgger，中文常叫"蒸馏"——把搜索找到的好答案当教材）。
3. **全图演练**：在完整香山图上完整跑一遍"推理 + 有限步搜索改进"，测时间，为编译期预算做彩排。
4. 定发布形态（D12）。

**验收门 M3**：强化学习在模仿基础上再降 ≥3% cost；全图演练总时间 ≤ 15 分钟的 1.5 倍（给编译期留余量）。

## Phase 4：接回生产线

**目标**：把模型排序接入 wolvrix 的调度代码，过全部及格线。

任务：

1. **C++ 原生推理**：在 wolvrix 里手写 GNN 推理，读训练好的权重文件（= 模型参数落盘的文件）；核心就是 gather + SpMM 两个操作，几百行 C++。集成点（D10）：现有调度器里 Kahn 排序"挑节点"的环节，原来用固定规则，换成按模型分数挑；没有权重文件时自动回退到原来的固定规则——不引入新依赖，不影响现有流程。
2. **编译期搜索**：给局部搜索一个硬性时间上限（时间盒，默认 10 分钟），随机种子固定（同样的输入永远得到同样的结果，便于复现和回归），到点就用当前最好的结果。
3. **及格线流程**：先查三个结构体检指标不劣于现有算法，再跑香山 CoreMark 50k 差分测试，确认正确且更快。
4. **版本管理**：权重、数据集、设计版本对应关系落档；加回归测试。

**验收门 M4**：编译时分区环节 ≤15 分钟；体检指标不劣于现有算法；50k 差分测试通过且耗时改善。

| D8 | 模仿训练参数 | 成对比较：每个节点抽 32 对（16 对同块、16 对不同块），要求模型把对的顺序拉开至少 1.0 的分差 |
| D9 | 强化学习参数 | Kahn 挑节点时按 softmax(分数/温度) 的概率随机挑（softmax = 把分数变成概率分布，分高概率大）；温度随训练逐渐调小；奖惩基准 = 模仿阶段模型的分数 |
| D10 | 模型插在哪 | 现有调度函数 `scheduleGrhSimAmActivityBlocks` 里 Kahn 排序挑节点的位置；权重文件路径走配置传入；没配权重就用回原来的固定规则 |
| D11 | 编译期搜索 | 时间上限 10 分钟硬切；随机种子固定；超时就用模型直接给的排序 |
| D12 | 成果怎么发布 | 两个候选：训练好的权重随编译器发布（编译时现场推理），或离线搜到的最终划分缓存起来随设计版本发布（编译时直接用）——**留到 Phase 3 定** |

## 风险登记

| # | 风险（白话） | 应对 |
|---|---|---|
| R1 | 小区域里搜到的"最优"，拼到全图上可能不是最优（因为区域边界被冻结了） | 在 openc910 这种较小设计上做全图搜索实测差距；差距大就改为全图搜索产教材 |
| R2 | 模型最终超不过现有算法 | 退路：不用模型，只用搜索（模型只负责给个好的起步排序） |
| R3 | CPU 推理太慢超预算 | 缩小模型（更短的向量、更少的层数）或把推理算子写得更高效；Phase 0 的摸底会提前暴露 |
| R4 | 离线分数好看了，实际模拟反而变慢（历史上发生过：NO0209） | 体检指标及格线和 50k 差分测试不松手；真发生就回头查评分公式 |
| R5 | out1/in1 预先串联其实有害 | 留了对照开关，关掉做对比实验验证 |
| R6 | 香山 RTL 一改版，旧标签和旧权重就过期了 | 离线流程随设计版本重跑；数据集和权重都带版本号 |
