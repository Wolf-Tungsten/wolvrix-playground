# 05 图结构导出实现记录（Phase 0 任务 1）

2026-07-30。Phase 0 任务 1（导出器）已落地：写在 wolvrix 生产代码里，调度前直导 AM 指令图，
JSONL 格式。本文档记录 as-built 事实（与 04 文档 D1 建议默认值的差异）和验证证据。

## 1. 实现位置与触发方式

- 代码：`wolvrix/lib/grhsim/am/production_activity_schedule.cpp`，导出点位于
  `ProductionActivityScheduleStage::schedule` 内 def-use 索引、ordered effect 边、SCC
  都建好之后、block 形成之前——导出的就是调度器自己看到的那张图，环收缩（comb-loop-atom
  识别）零成本复用生产 SCC 结果，符合 03 文档"导出器内顺带做环收缩"的要求。
- 开关：环境变量 `WOLVRIX_GRHSIM_AM_INSTRUCTION_GRAPH_JSONL=<输出路径>`。未设置时零开销；
  设置后导出失败（路径不可写等）会让调度报错退出，不静默跳过。
- 格式版本标识：`wolvrix.am-instruction-graph.v1`（首行 header 记录）。
- 格式说明同步写在 `wolvrix/docs/grhsim/grhsim-am-pipeline.md` §3.2.4。

## 2. as-built 记录格式（对 D1 的小扩展）

每行一条 JSON 记录，共四类：

- `header`（首行）：`instructions / variables / atoms / comb_loop_atoms / def_use_edges /
  external_reads / order_edges` 七个计数。
- `node`：`id / op（Opcode 数值，46 类，可直接做 embedding 下标）/ opcode（名称）/
  width（全部 result 位宽之和，Array 按元素位宽×深度）/ state_write / atom（SCC 分量号）/
  comb_loop_atom`。
- `edge` kind=`def_use`：`src / dst / var / width`，按 (src,dst,var) 去重。
- `edge` kind=`order`：`src / dst`（ordered effect 组链 + 隐式 host 序链）。

与 D1 建议默认值的三处偏差，均为信息补全而非语义变更：

1. 节点多了 `op`（数值）与 `atom` 字段。`atom` 让 comb-loop 打包结果完全可重建
   （D1 只有一个布尔标志，无法区分多个环）。
2. 多了一类 `external_read` 边：无定义指令的变量（state target、接口输入）被谁读。
   理由：生产段 DP 把这类变量当永久边界计入 incoming 成本（
   `wolvrix/lib/grhsim/am/activity_schedule.cpp:460-463`），缺了它 scorer 无法对齐
   生产口径（对账是 M0 验收门）。state target 操作数按依赖规则不算 use，不会出现。
3. use 侧不做 commit 过滤：commit 指令内的普通读照常导出，生产 DP"跳过 commit 内 use"
   的口径由消费方按 `state_write` 标志自行过滤（导出保持全量，口径选择留给 harness）。

D2 决策照原样执行：导出器只做组合环打包（恒等映射 + 环检查），out1/in1 串联留给
harness 读图侧带开关实现。

## 3. 验证证据

- 单元测试（`wolvrix/tests/grhsim/am/test_production_activity_schedule.cpp`，
  `grhsim-am-production-schedule` 目标）：手工构造含外部读、def-use 链、双指令组合环、
  显式 order 组、寄存器写的 7 指令程序，逐行断言 header 计数与全部节点/边记录；
  另有导出路径不可写时的报错用例。全部通过，全量 `ctest` 无回归。
- 全香山端到端：`grhsim-am-lower-json` + 环境变量，输入
  `build/xs/grhsim-am-detgroup/wolvrix_xs_post_stats.json`（SimTop），调度正常完成
  （34,237 blocks），导出耗时包含在 schedule 的 6.9s 内。产物：
  `topo-partition-proj/exp/dataset/xs_full_20260730/instruction_graph.jsonl`（1.44 GB，
  14,954,654 行）。
  - 计数：4,669,495 节点 / 8,031,598 def_use 边 / 2,234,514 external_read /
    19,046 order 边；行数与 header 计数完全一致；抽样 JSON 解析字段与 id 范围合法。
  - `atoms == instructions`、`comb_loop_atoms = 0`：再次实证 03 文档"真实电路上 SCC
    收缩是恒等映射"的结论。
  - 对导出图（def_use + order 边）做 Kahn 拓扑排序：4,669,495 节点全部可排，
    违序边 0——导出图为 DAG，learn-to-order / 段 DP 的前提成立。
