# 01 问题定义与现状

## 1. 问题形式化

输入：DAG $G=(V,E)$（compute 侧调度图），节点容量上限 $W_{\max}$。
输出：划分 $\mathcal{P} = \{S_1, \dots, S_k\}$，满足：

- **无环**（硬约束）：商图（把每个 $S_i$ 缩成一点）仍是 DAG；
- **容量**（硬约束）：每个 $S_i$ 的 op/instruction 数 $\le W_{\max}$（oversized 单 cluster 例外）；
- **目标**：最小化模拟的期望执行成本。

期望成本的形式化已写在 `ptmp/new-partition-algo/partitioning-problem-v2.md`：

$$\text{cost} = \sum_{S} C_{\text{check}}(S) + \sum_{S} W(S)\cdot P(S \text{ 被激活})$$

其中 $C_{\text{check}}$ 与跨边界 activation 输入边数相关，$W(S)$ 是块内工作量（指令字数），$P(\cdot)$ 是激活概率。该文档与配套的 `ptmp/new-partition-algo/partitioning-algorithm.md`（50M 节点增量算法框架）是目标函数设计的现成起点。

**注意**：当前生产代码并没有实现这个目标函数，实际用的是简化代理（见下节）。学习方法的第一步就是把 reward 落到一个可解释、可校准的 cost model 上，而不是直接对齐 runtime。

## 2. 现有算法（legacy 与 am 完全同构）

两条路线是同一算法的两份实现（AM 版"从 legacy 逐行移植"，`wolvrix/docs/grhsim/grhsim-am-pipeline.md:340-348`；2026-07-28 重构后全仓只剩一份语义）：

1. **Plain coarsen**：在 atom DAG 上做 out1 / in1 / siblings 三路合并（并查集），cluster 上限 4096 ops
   - legacy：`wolvrix/lib/transform/activity_schedule.cpp:5572-5700`
   - am：`wolvrix/lib/grhsim/am/activity_schedule.cpp:249`（`coarsenRound`）
2. **确定性 Kahn 拓扑排序**：am 版 `activity_schedule.cpp:424-451`
3. **连续分段 DP**：在固定 topo 序列上切连续段，cost = 跨段去重 incoming activation variable 数 + 1.0×段数，段上限 128 ops/instructions
   - legacy：`buildComputeSupernodeSegments`，`activity_schedule.cpp:4719`
   - am：`activity_schedule.cpp:535-615`
4. commit 侧单独按 (event, guard) 分桶/合并，上限 4096。

关键局限（都有文档或代码佐证）：

- **不是真 DAG partition**：划分被限制为"某条固定拓扑序的连续段"（`wolvrix/docs/transform/activity-schedule.md:84-92` 明说"不做任意 DAG partition"）。
- **cost 不含位宽/指令成本**：每跨段 variable 记 1.0（am 版 `activity_schedule.cpp:574`）；位宽只出现在 `-export-compute-dag` 导出 JSON 的边权里（`ceil(Σwidth/64)`），DP 完全不用。
- **拓扑序是固定的**：确定性 Kahn 序一旦定下，DP 只能在这个序里选切点。序的质量是分区质量的最大自由度，而它现在完全没有被优化。

## 3. gsim 对照

实现：`reference/gsim/src/graphPartition.cpp`。

1. **Coarsen**（`graphCoarsen()` :50）：mergeResetAll（reset 逻辑抽特殊超节点）、mergeWhenNodes（共享 when 条件的节点组，>5 才合）、mergeOut1/mergeIn1（度1合并，带防环序检查）、mergeSublings（prev 集合完全相同的兄弟合并，≤30）。
2. **Kernighan DP**（`graphInitPartition()` :63）：拓扑序上切连续段，段内节点数 ≤ `SuperNodeMaxSize`（默认 **35**，`main.cpp:49`），代价为**无权**割边条数。
3. **Refine**：FM 风格精修存在（`graphRefine()` :278，只允许移到序相邻超节点以保无环），但在 :400 被注释，默认不启用。

比 Herrmann 2019 多层算法（`reference/DAG-Acyclic-Partitioning-算法实施文档.md`）简单得多——gsim 本质上就是"**启发式 coarsen + 拓扑序连续段 DP**"，和 grhsim 同一骨架。差距不在算法框架，而在：

- **粒度**：gsim 段上限 35 节点 vs grhsim 128 ops（且 coarsen cluster 可到 4096）。结果：全香山 gsim 294,107 → 84,863/132k 超节点（细而稀疏）；grhsim 77,272 超节点 / 1,252,417 dag_edges，出度 max 15,837 的重尾 hub——"少点多边，coarse but dense"（`pdocs/grhsim_opt/NO0010`，`NO0212`）。
- **合并规则的语义利用**：gsim 的 when/sibling 合并针对性很强；grhsim 的 out1/in1/siblings 是结构规则，不带语义。

## 4. 历史教训（必须内化为约束）

来自 `pdocs/grhsim_opt/` 笔记（prob 与 CBAW 两条路径已被移除，见 git log `9f82aad`、`be3beab`）：

- **NO0209（prob 路线失败复盘）**：prob_dp1_fm4 让 dag_edges 变 1.98x、50k 从 326s 退到 629s。结论：离线结构指标改善 ≠ runtime 收益；任何新算法必须先过 **plain-first 结构硬门槛**（dag_edges / compute_compute_value_pairs / code footprint），再上 50k gate。
- **NO0067/NO0086**：单纯放大 supernode（batch 粗化、size20/24/32）均使 50k 变慢——粒度不是越大越好。
- **NO0210-0215（CBAW）**：FM8 能显著降 boundary/compute-compute 指标且 50k PASS（347,528ms），说明"结构代理 + 精修"方向本身可行，后被移除是工程原因。

对学习方法的含义：**评估闭环 = 结构硬门槛 → 50k CoreMark difftest + host time**，不能只盯离线指标。

## 6. 一句话总结

问题不是"分区算法框架选错了"——gsim 和 grhsim 是同一个"coarsen + topo 序连续段 DP"骨架；差距在**拓扑序与切点的质量、粒度控制、以及 cost 对语义/位宽的利用**。这恰好都是"学习"可以着力的自由度，且骨架本身对无环性的保证方式（连续段）可以直接被学习方案继承（见 02 文档想法四）。
