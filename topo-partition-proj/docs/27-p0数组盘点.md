# 27 P0 数组盘点：ingest 直建 memory 语义的决策门输入（2026-08-01）

承接 doc 25（reg-to-mem matcher 路线证伪）之后的新路线评估：**ingest 直接把
SV 数组建成 memory 语义 op（kMemoryReadPort/kMemoryWritePort），不再炸成逐
entry 寄存器**。P0 决策门：香山爆炸逻辑中来自"能装进现有 memory op 语义"
的数组的 op 是否 ≥40 万。

**决策门结论（主会话 lane 同构 v4 数据）：GO——1,811 组、901,408 ops 可省，
过 ≥40 万门。** 本文是 P0 盘点的过程资产与独立佐证：总账、E1 存量、
Rob.robEntries 的 guard 形态实测分类、reset 形态、未进组数组规模。因时间
止损，guard 分类只实测了 Rob.robEntries 一族（最大单点，doc 21 Δlogic
+229,405），其余代表数组的分类 probe 已就绪未跑（§8）。

## 3. guard 形态分类（Rob.robEntries 实测）

工具 `exp/tools/p0_array_guard_probe.py`，pre-reg2mem 图（7月31 build
`resume_from_pre_reg_to_mem_json=True`，即 reg-to-mem 的真实输入图）。
方法：把每个 element 写端口的 nextValue 分解为 (条件路径, 数据) 分支
（kMux 链；1-bit 寄存器的布尔编码 and(a,b)=mux(a,b,0)、or(a,b)=mux(a,1,b)
现场改写），updateCond≠1（显式使能型）以 updateCond 的 DNF 地址结构分类，
updateCond==1（always-write RMW 编码，如 valid）以分支选择分类；mux 链
下行负字面量只编码分支优先级、不参与分类。分类定义：

- **A**：受地址约束的 DNF 项每项恰 1 个地址等式 eq(addr,i)；不同项可用
  不同地址信号 = **多写口**（ingest 直建时每信号一个写端口，现有
  priorityGroup 语义支持）。整元素写。
- **B**：每项恰 2 个地址等式（bankSel==b && ptr==i），地址表达式可编码。
- **C**：mask 非全 1，或分支数据真 read-modify-write（字段级部分写）。
- **V**：lane 级写——无地址等式的元素索引条件（如 commit 清
  entries[i].valid），不是单地址写。
- **D**：其他（DNF 爆表且钉扎分析也不过、交叉地址等式、反地址项等）。

40 个字段 × 每字段 7 个采样元素（idx 0/58/117/176/234/293/351）：

| 类 | 字段数 | 字段 |
|---|---:|---|
| A | 25 | commitType, crossFtqCommit, debug_pc/instr/ldest/pdest/fuType/fuOpType/fusionNum/commitType/v0Wen/vecWen, dirtyVs, fpWen, ftqIdx_flag/value, ftqOffset, isHls, isRVC, needVTB, perfDebugInfo_dispatchTime/renameTime, rfWen, traceBlockInPipe_iretire, wflags |
| D | 13 | uopNum, valid, mmio, vxsat, realDestSize, traceBlockInPipe_itype, interrupt_safe, perfDebugInfo_enqRsTime/selectTime/issueTime/writebackTime, debug_lqIdx_value, debug_sqIdx_value |
| V | 2 | needFlush（lane_clear）, fflags（RMW + always_rewrite） |

A 类字段的形态清一色是 **8 dispatch 口 × 每口恰一个 `enqPtr_j==i` 等式**
（detail.addr_sigs=8）——多写口 A，直接装进 8 个 kMemoryWritePort。

**DNF 爆表 ≠ 非 A**（对 D 类字段补做的线性钉扎分析：guard 的每个 or 备
选项是否都带地址等式，idx=58 采样）：interrupt_safe（pins=8，全部钉
扎）、fpWen（8，钉扎；DNF 分类时落在 A）、realDestSize（8，钉扎）、
traceBlockInPipe_itype（11，钉扎）实为多口 A；**perfDebugInfo_issueTime /
enqRsTime（pins=32，存在未钉扎备选）、debug_lqIdx_value（12，未钉扎）、
uopNum（pins=18，未钉扎 + 7 处交叉地址等式）是真 D**。钉扎修正后约
A 29 / D 9 / V 2。

**与 doc 25 的核对（任务指定项）**：doc 25 §2 实测 robEntries_0_uopNum
为 D 形态（嵌套 or + 同一 AND 链多个不同地址 kEq + ReduceOr(Concat)）。
本文确认 uopNum 的 D **属实但它是 Rob 的个别字段，不是普遍形态**——
Rob 主流是 8 口单等式 A。matcher 的"每项恰好一个行等式"模型装不下 A
类是因为 8 个不同地址信号（union>1 即拒），而 ingest 直建对此无损：
8 个写口各写各的地址表达式。

读侧（E1 实测）：robEntries 29,408 个读端口中选通树 13,376、并行消费
16,032；并行侧主体是 **concat 打包**（fpWen 等 1-bit 字段 512 个 concat
用户：全部 entry 打成向量做 CAM 式消费）与 and 项——这些读变不成
memory 读端口，P1 收益测算须扣除。选通树 op union 18,786。

## 4. reset 形态

- robEntries 全部 14,080 个写端口 mask = 常量全 1（采样 280/280 一致）。
- **仅 valid 字段（352/352 端口）带非 clock 事件**——异步复位写端口，
  正是 R2 栽过的 reset_attr 形态；其余字段的复位编码在 always 块内
  （cond=1 型字段的复位分支 / 显式使能型字段的条件项），采样内
  clear-term 签名逐字段一致（clear_sig_variants 小）。
- 含义：A 类字段的 reset 一致性好，可统一处理；valid 类（异步复位 +
  lane set/clear）需要 kMemory 之外的复位策略——P1 设计必须包含，
  否则会在同一处再栽一次。

## 5. 未被 reg-to-mem 发现的数组

pre 图 ≥4 簇 261,140 寄存器 vs 报告组内 132,739 元素 → **约 12.8 万
寄存器从未进组**（在"组 ⊆ 名字同构簇"假设下为精确值；610 个命名组
全部名字同构，假设有支撑）。另有 24,874 寄存器在 <4 小簇（标量为主）。
构成：LogPerfEndpoint 验证数组（~3.1 万，4032x64 mshr_latency 等）、
MSHR_64 路径索引字段、BusyTable table_r（223x1 等）、Ftq perfQueue
（2,048）、TLBFA entries（384×多族）、Sbuffer data/mask（1,024+1,024）、
simMMIO/DelayN 等仿真 harness。这些数组的 op 足迹包含在 doc 21 的模块
表里，但 reg-to-mem 的组账完全看不到它们——P1 做 ingest 直建时这部分
是"白捡"的覆盖（discovery 不再依赖图模式匹配）。

## 6. op 足迹估算与决策门

两种方法（均为估算，标注口径）：

- **方法 A（实测 cone，Rob.robEntries，E1 图）**：写侧 union cone
  434,488 ops（限 Rob.sv；不限 loc 434,719，字段和 961,343 说明共享
  译码占 ~55%）+ 读选通树 union 18,786 + 寄存器 14,080 + 读写端口
  28,160 ≈ **49.5 万 ops**（其中 A 类 25 字段占主体；4 个 D 类
  perfDebugInfo 字段 cone 各 81,756）。**单个数组族已接近 40 万量级**。
- **方法 B（元素数 × 每 entry 平均 logic，doc 21/22 实测比 Rob≈12.7、
  MSHR≈6.7 ops/reg）**：被拒 58,367 元素 × 7–13 ≈ **41–76 万**；加未
  进组数组（~12.8 万寄存器中的设计部分）更多。

决策门：**GO**（主会话 lane 同构 v4：1,811 组、901,408 ops 可省，
≥40 万）。本文两个独立估算方向一致，Rob.robEntries 实测 A 类占主体
支持"能装进现有 memory op 语义的占比足够高"。

## 7. 与背景文档的矛盾/修正

1. **doc 25 §2 的 D 形态不是 Rob 普遍形态**：uopNum 属实 D（本文复核：
   18 钉扎信号未全钉 + 7 交叉等式），但 25–29/40 字段是干净的多口 A；
   doc 25 由单字段外推"香山 guard 语言"的结论对 matcher 路线成立，
   对 ingest 直建路线不成立（两者对 guard 的表达能力要求不同）。
2. **读侧 concat 打包占比被低估**：doc 25 §1 说"读出实际走 concat+slice
   打包（reg-to-mem 已认识的形态）"——实测 robEntries 读侧 55% 是并行
   消费（concat 打包/CAM 式），这些读无法变成 memory 读端口；P1 收益
   测算必须扣除读侧并行部分。
3. **RenameBuffer 不是存储爆炸**（§2）：主存储仅 399 寄存器，其 Δlogic
   主体是读译码树，ingest 直建对它的收益形式与其他阵列不同。
4. kMemoryWritePort 现有语义比任务预设的更宽：**带 mask 操作数**（任务
   书把 masked write 划为需 IR 扩展的 C 类——位级 mask 其实现有 op
   就支持；本文 C 类仍保留"数据真 RMW/字段级部分写"义项）且写端口
   **无复位语义**（复位由上层 updateCond/data 显式控制，§4 的 valid
   类须走这里）。
