# 10 确定性基线方案（去 coarsen + 规范 Kahn + 新段 DP + λ 段惩罚）

2026-07-30。Phase 1 证据（docs/08 区域 + CP-SAT，docs/09 c910 全图）表明"排序"
相对确定性规范序没有可利用的油水，触发 04 文档 R2 预案。本文把 R2 指向的退路
固化为正式方案：**不引入任何学习组件的确定性分区流水线**，并给出它与生产
grhsim 算法的逐项差异、收益证据与落地路径。

**决策状态：建议采纳为主交付路线（GNN 路线搁置），待拍板。**

## 1. 方案定义（四要素）

1. **去 coarsen**：不做任何"预先捆包"。只保留 comb-loop-atom 收缩（正确性要求，
   实践中恒等），out1/in1 串联留 harness 侧开关做消融（K2），当前结果均为纯不捆包。
2. **规范 Kahn**：确定性 Kahn 拓扑序，平局取最小指令 id——与生产同一平局规则，
   但作用在未被捆包破坏的原始指令图上。
3. **新段 DP**：连续段 DP，目标 = 跨段读入的去重值按 `ceil(位宽/64)` 折算的拷贝
   总数（直接对应运行时数据搬运量）；容量 128 为硬上限。
4. **λ 段惩罚**：DP 目标内加每段惩罚 λ（建议 2–4），在 cost 几乎不变的前提下
   回收 footprint 与 dag_edges；报告的 cost 指标本身永远不含 λ，口径一致可比。

## 2. 与生产 grhsim 算法的逐项差异

| 环节 | 生产 grhsim（plain 基线） | 本方案 |
|---|---|---|
| 预处理 | comb 环收缩 **+ coarsen 捆包**（out1/in1/sibling 多轮合并，预算 1.5×128=192；legacy 旧默认 32×128=4096） | comb 环收缩，**不捆包** |
| 排序 | Kahn 平局取簇内最小指令 id，**在捆包后的簇图上** | 同一平局规则，**在原始指令图上** |
| 段 DP 目标 | 跨段读入值**按个数计**（每个值 1.0，不看位宽）+ 每段惩罚 1.0 | 跨段读入值**按位宽折算** ceil(w/64) + 每段惩罚 λ（2–4） |
| 容量 | 128 软上限：超大单簇独占一段，**块可超 128** | 128 硬上限，无例外 |

代码锚点：coarsen 合并轮 `wolvrix/lib/grhsim/am/activity_schedule.cpp:249`；
预算默认 `production_activity_schedule.cpp:1363`；平局规则
`activity_schedule.cpp:424`；旧代价公式 `activity_schedule.cpp:588`
（`incomingActivationCost += 1.0` + `segmentPenalty`）。

四条差异的因果：

- **去 coarsen 是最核心的一条**。捆包是局部度数启发式，一旦并错 DP 就再也拆
  不开——错配的值被拖着跨段计拷贝，还造出超容量巨块（NO0067/0086：巨块运行时
  更慢）。删掉后 DP 看到全部合法切点。DP 规模不再是瓶颈（C 内核 4.45M 节点
  4.2s）。
- **排序规则本身没变**。收益不来自"更聪明的排序"，而来自把同一规则放回未被
  捆包锁死的图上——这正是 docs/09 全图实验的读法：规范序之上 +0.0016%。
- **位宽折算让 DP 优化运行时真正付的钱**：1 bit 与 512 bit 的值旧公式都计
  1.0，运行时实际差 8 倍拷贝。
- **λ 是重标定而非新机制**：生产本有每段惩罚 1.0；λ=2–4 是 cost–footprint
  权衡的甜点（见 §3）。

## 3. 收益证据

香山全图（docs/08 §4，4,450,505 非 commit 指令）：

| 指标 | 生产 plain | 本方案（λ=0） | Δ |
|---|---|---|---|
| cost | 6,468,546 | 5,921,453 | **−8.5%** |
| dag_edges | 325,838 | 312,938 | −4.0% |
| ccvp | 3,305,393 | 2,903,510 | −12.2% |
| footprint（块数） | 34,236 | 41,637 | +21.6% |

香山 λ 扫描（docs/08 §5）：λ=2 时 cost −8.4%、dag_edges −7.2%、footprint
+16.6%；λ=4 时 cost −8.4%、dag_edges −7.8%、footprint +13.5%。

c910 全图（docs/09 §2，1,081,280 非 commit 指令，λ=0）：

| 指标 | 生产 plain | 本方案 | Δ |
|---|---|---|---|
| cost | 5,343,459 | 5,101,136 | **−4.5%** |
| dag_edges | 128,669 | 89,453 | **−30.5%** |
| ccvp | 782,245 | 601,694 | **−23.1%** |
| footprint（块数） | 15,765 | 17,757 | +12.6% |

两个设计、两套代码路径（生产 pass 导出 vs harness 独立复算）方向一致：
**cost 降、结构指标显著更优、footprint 越红线是主要代价。**

## 4. 已知代价与未决问题

1. **footprint 红线（K9 体检矛盾）**：+12~22% 的块数抬升源于 128 硬容量本身
   （生产经 coarsen 实际块更大），λ 只能部分回收。待选项：放宽容量 / 接受
   footprint 抬升 / 更聪明的块合并；决策前需先弄清 footprint 近似（块数）与
   真实代码体积的关系，并面对 NO0067/0086"大块更慢"的反方向证据。
2. **尺度外推残留**：全图 SA 实测在 c910（1.08M 节点）完成；香山全图
   （4.45M）未做（同工具同命令可跑，约 2h），作为稳健性确认项保留。
3. **运行时验证未做**：所有数字都是离线结构指标；K9 的香山 CoreMark 50k
   差分测试（正确性 + 墙上时间）是最终及格线，未跑。
4. **out1/in1 串联消融未做**（R5）：当前结果不含它，是否引入留对照实验。

## 5. 落地路径（生产侧现状盘点）

生产侧旋钮已存在大半（`production_activity_schedule.cpp` 的 options）：

- `enableCoarsening=false` + 容量 128：等价于"去 coarsen + 硬上限"（超大簇
  独占段的例外在无捆包时只剩 comb 环，实践中不存在）；
- `dpSegmentPenalty`：即 λ，直接可配；
- **缺口 1**：段 DP 代价公式不按位宽折算（`+= 1.0` 处需改为按 var 位宽
  `ceil(w/64)` 加权）——唯一必须改代码的点，改动面约十几行；
- **缺口 2**：及格线流程（体检指标核对 + 50k 差分）与回归测试。

harness 侧工具已齐：`tools/run_fullgraph_plaindp.py`（--penalty）可预先评估
任何（容量, λ）组合的四个指标；`tools/run_fullgraph_search.py` 可在接回前做
编译期搜索收益的预演（docs/09 已示范：≈0）。

**K9 运行时基线实测（2026-07-30，本机）**：当前生产 grhsim-am（plain，
未改任何参数）跑香山 CoreMark 50k 差分（NEMU 参考逐拍比对，通过）：

| 指标 | 数值 |
|---|---|
| 墙上时间 | **575.5 s**（user 575.4s，单核 99%） |
| 模型周期 / 提交指令 | 50,000 cycles / 73,580 instr（IPC 1.47） |
| 速率 | ≈86.9 cycles/s |
| 峰值内存 | 288 MB |

链路 as-built：`build/xs/grhsim-am/`（pre_reg_to_mem 断点续跑 → emit，
34,235 blocks、schedule 7.7s）→ difftest `GRHSIM=1` 编译 emu（本机缺
zstd 开发头文件，用 difftest 自带 `NO_ZSTD_COMPRESSION=1` 开关绕过；
CoreMark bin 为裸二进制不受影响）→ `./emu -i coremark-2-iteration.bin
--diff riscv64-nemu-interpreter-so -b 0 -e 0 -C 50000`。后续任何分区改动
的耗时对比都以 575.5s 为基准。
