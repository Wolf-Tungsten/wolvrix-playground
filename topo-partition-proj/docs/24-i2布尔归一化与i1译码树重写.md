# 24 I2 布尔归一化与 I1 译码树重写：便宜路线的终点（2026-07-31）

承接 doc 23 §6 的后续：不改语义（无数组 value / 向量语义）的前提下，
用局部模式重写还能从 87.1 万 logic 差里拿回多少。结论先行：
**两个 pass 合计 −31,256（图 −0.71%，logic 差 −3.6%），便宜重写路线
到此耗尽；剩余差是阵列形态，非局部模式可消。**

## 1. 两个 pass（已实现、单测、注册、默认关）

- **`logic-normalize`**（I2，`lib/transform/logic_normalize.cpp`）：
  `kLogicAnd/Or→kAnd/Or(t(a),t(b))`（多 bit 操作数插 `kReduceOr`）、
  `kLogicNot→kNot`（1-bit）/ `kReduceNor`（多 bit），语义保持。
  动机：统一 SV 布尔族与位运算形态（doc 22 I2：35.2 万 logic_*），
  为 CSE 与模式识别铺路。
- **`onehot-to-mux`**（I1，`lib/transform/onehot_to_mux.cpp`）：识别
  `or(and(eq(idx,Cᵢ),vᵢ),…)` 一热选择树（idx 共享、Cᵢ 互异、项数
  3..1024、不拆共享子树），改写为 mux 链 + 默认常量 0（2-state 等价，
  X 传播差异已注记）。**关键语义护栏**：GRH 的 `kAnd(1-bit eq, W-bit v)`
  是 SV resize 语义（= `v & 1`），仅当 W==1 才等价于 `eq?v:0`，故
  Form A 只收 1-bit 树；W 位的 `kReplicate(eq)` 广播形态留作扩展点。
- 单测各 6 例（含 const-fold 真值比对、负例、端口重绑），
  `ctest -R "onehot|logic|transform"` 全过（仅 3 个既有失败）。
- 注册进 `makePass`；XS 流水接线（`comb-loop-elim` 后、simplify 前），
  开关 `WOLVRIX_XS_GRHSIM_LOGIC_NORMALIZE`（默认 **0**）。

## 2. 探针实测（E1 post-stats 图，pybind 直跑）

| E1 基线 | 4,384,949 | — |
| + logic-normalize + simplify | 4,367,882 | −17,067（−0.39%） |

归一不是数量杠杆**（doc 19 §6 早有同样判断）。

## 3. 为什么 I1 也只有 1.4 万：模式与实物不符

对 DataModule__64entry_16 切片做 op 形态直查（113,216 行）：

- kAnd 操作数形态：`(kRegisterReadPort, kSliceStatic)` 4,096 +
  `(kRegisterReadPort, kSliceDynamic)` 4,096——是数据通路的掩码/使能
  AND，**不是** `and(eq, v)` 选择项；`kReplicate` 0 个。
- kOr 操作数形态：`or(kMux, kOr…)` 7,936 + `or(kAnd, kOr…)` 7,936——
  是 **mux/and 项的或归约链**，不是一热选择树。
- 且 `or(mux(s0,v0,0), or(mux(s1,v1,0),…))` 即使识别为一热，改写成
  嵌套 mux 也是平价（2N−1 → 2N−1），无收益。
- MSHR 切片复核：entry 选择本来就是 `kMux`——AM 并非不用 mux，
  而是阵列读写的**逐 entry 数据通路**本身就是这么贵。

结论：doc 22 I1 表格里 AM/gsim 的 and/or 差，大头是阵列数据通路的
逐 entry 展开（register×slice 掩码 + or 归约），gsim 把它压进
REG_UPDATE/mem 语义里。**不做数组语义（doc 23 §6 的搁置项）就拿不回**
——局部模式重写只能碰到 1-bit 控制选择（Form A 实测 1.4 万）。

## 4. 对路线图的最终影响

- 两个 pass 保留在树上（已注册、单测、默认关）；0.7% 的收益不跑全量
  验证链（流水重跑 + emu + difftest 的成本远超收益）。后续若做数组
  语义，`onehot-to-mux` 的 W 位扩展（kReplicate 广播）可与
  `array_read` 语义一并评估——届时局部重写多半被数组 op 直接取代。
- doc 23 的归因结论因此更硬：87.1 万 logic 差在"局部语义保持重写"
  维度已证不可消（上限 3.6%），T5 清算表把它归入惯用法/建模差异是
  对的；剩下的路只有 doc 23 §6 列的数组/向量语义评估。
- L2 生产路径接入（`GrhSimAmPipeline::setAmOptimizeOptions`，默认
  全开）已随本次完成（doc 20 §3.1 的跟进项）。
