# 13 GSim Node 打平前后 XiangShan CoreMark 50k 对比（2026-07-31）


本文记录"gsim node 层次打平"逆向实验的参数对齐过程、XiangShan coremark
50k 打平前后性能对比与图结构对比。实验设计、打平 pass 实现与基线口径见
[`12-gsim-node打平实验设计与实现`](12-gsim-node打平实验设计与实现.md)。

## 对比对象

两边使用同一份 FIR（`build/xs/rtl/rtl/SimTop.fir`，sha256 见 [`12`](12-gsim-node打平实验设计与实现.md)）、
同一条 gsim 流水线、同一台机器，唯一差别是打平版在 graphPartition 前打开
`--flatten-nodes` 并把 `--supernode-max-size` 从 15 调到 16 以对齐超节点数：

| 版本 | emu | gsim 参数 |
| --- | --- | --- |
| 基线 | `build/xs/gsim/gsim-compile/emu` | `--supernode-max-size=15` |
| 打平 | `build/xs/gsim-flat/gsim-compile/emu` | `--flatten-nodes --supernode-max-size=16` |

## 打平规模

`--flatten-nodes` 在 PreCoarsen 图上（候选节点 `2,540,405`）：

- 实际拆开表达式树的节点 `151,905`，新造节点 `335,823`
  （PreCoarsen 超节点 `2,708,065` → `3,043,888`，+12.4%）；
- 被移动算子以 `OP_CAT`（196,660）、`OP_SHR`（72,403）、`OP_PAD`（30,167）、
  `OP_BITS`（12,574）、`OP_SHL`（11,795）为主；
- 保留在原位的 `OP_WHEN` 骨架 enode 共 `87,356` 个。

注意：exprOpt/commonExpr 之后多数表达式树本来就很浅（根算子 + ref/常量
叶子），因此打平只带来 12.4% 的节点增长，远小于"每个算子一个 node"的
理论上限。

## 超节点数对齐过程

`--supernode-max-size` 只作用于 graphInitPartition 的 DP 分段。以
`[InitPartition]` 超节点数对齐基线 `84,786`：

| max-size | InitPartition 超节点 |
| ---: | ---: |
| 15（与基线同参） | `88,375`（+4.2%） |
| 18 | `78,997`（-6.8%） |
| **16（线性插值选定）** | **`84,901`（+0.14%）** |

最终发射超节点数：打平 `84,754` vs 基线 `84,642`，**+0.13%**，对齐达标。

有趣现象：打平后 coarsen 把图合得比基线更狠（`286,748` vs `293,985`），
但 DP 段因 coarsen 超节点平均成员变大而装得更少，最终数量仍上升。

## CoreMark 50k 性能对比

相邻三连跑（flat → base → flat，同一机器空载），日志在
`build/logs/xs/flatten_{flat_s16_50k_1,base_50k_2,flat_s16_50k_3}_20260731.log`；
基线另有一次更早的单跑（`xs_gsim_flatten_baseline_20260730.log`）：

| 次序 | 版本 | Host time | instrCnt / cycleCnt |
| --- | --- | ---: | --- |
| 0（更早） | 基线 | 22,914 ms | 73,584 / 49,998 |
| 1 | 打平 | 23,573 ms | 73,584 / 49,998 |
| 2 | 基线 | 22,747 ms | 73,584 / 49,998 |
| 3 | 打平 | 23,549 ms | 73,584 / 49,998 |

- 功能门：四次运行 `instrCnt = 73,584`、`cycleCnt = 49,998` 完全一致，
  difftest 全部通过——打平后功能与基线逐拍等价。
- 性能：打平均值 `23,561 ms` vs 基线相邻 `22,747 ms`（两次基线
  22,914/22,747，run-to-run 波动 ~0.7%；打平两次波动 ~0.1%）：
  **打平比基线慢 `+3.6%`（1.036x）**。

## 结论

1. 在"每个 node 至多一个计算 enode"的打平图上，gsim 原封不动的
   coarsen + DP partition + 激活机制，在相同超节点预算（84.6k）下重建了
   与基线几乎同构的超节点图：超节点间边数 +0.68%、激活边 +0.96%。
2. 运行时性能只退化 3.6%，且这部分差距更可能来自"多 1.5% 状态变量、
   多 1% 激活边、更大代码体积"等机械开销，而非 activity 划分质量下降。
3. **因此本实验不支持"node 层次（node 作为 enode 容器）是 gsim
   activity 划分更优的根本原因"这一猜想**：把该层次打平后，activity
   划分结构与运行时行为几乎不变。gsim 的划分优势应归因于其他环节
   （coarsen 启发式、DP 切分、激活协议本身），而不是 node 的表达式树
   容器形态。
4. 附带观察：香山 FIR 经 exprOpt/commonExpr 后表达式树已相当浅
   （打平只 +12.4% 节点），"node 层次"在划分阶段输入图上的实际厚度
   有限，这也从侧面降低了它成为决定性因素的可能。

## 局限

- 只测了 XiangShan SimTop + coremark 50k 一个负载；rocket 冒烟（未对齐
  超节点数）同样只有小幅 slowdown（690k → 657k cycles/s），趋势一致。
- 对齐粒度是"最终超节点数 ±0.13%"；超节点成员分布未逐一对齐。
- 性能差 3.6% 未做 perf 级归因；如需精确定位，可对比两侧
  instructions/branches 计数（本机 perf 计数器未在本次采集）。

## 增量更新 2026-07-31：打平有效性核查

应"结果出人意料，图结构是否真的打平了"的质疑，做了三项核查，
结论是**打平确实生效，但打平前的图本来就几乎是平的**。

### 1. 算子总数守恒

两份 `SimTop_supernode_stats.json` 的 `enode_op_types` 逐项对比：45 类
算子总计 `5,018,986`（基线） vs `5,018,987`（打平），单项最大偏差
`±4`（when2mux 噪声量级）——打平没有增删任何算子，只是搬运了它们的
属主节点。

### 2. 逐节点计算 enode 分布（pass 内置核查计数器）

打平 pass 对全部 2,540,405 个候选节点在打平前逐树统计计算语义 enode
（ref/常量/OP_WHEN 骨架/OP_GROUP/OP_INDEX 不计入）：

| 每节点计算 enode 数 | 节点数 | 占比 |
| ---: | ---: | ---: |
| 0（纯连接） | 186,784 | 7.4% |
| **1（本来就没得打）** | **2,203,676** | **86.7%** |
| 2 | 118,661 | 4.7% |
| 3–5 | 16,126 | 0.6% |
| 6–10 | 10,202 | 0.4% |
| >10 | 4,956 | 0.2% |

合计 2,687,309 个计算 enode，平均每节点 1.06 个。打平移动的 335,823
个算子与分布自洽（≈ 118,661×1 + 16,126×~2.6 + 10,202×~6 + 4,956×~22）。

**打平后验证：候选节点中"单棵树 >1 个计算 enode"的数量为 0；新建
temp 节点中"算子数 != 1"的数量为 0。**（9,049 个多树候选节点的每棵树
也均 ≤1。）

stage dump（`--dump-stats-json`）前后对照：节点数 `2,708,079` →
`3,043,902`（恰好 +335,823）；nodes_enodes 均值 `5.11 → 4.76`，
p99 `12 → 9`；max 保持 `270,469` 不变——最大的那个节点属于打平跳过
的类别（数组/存储端口类），属设计内的例外。

### 3. 生成代码抽查

打平版 `SimTop100.cpp` 中，原节点 `_T_127` 的 54 级 `OP_CAT` 链变成
54 条连续 `$flat` 临时变量语句，每条恰好一个 gsim 算子
（`t = (prev << 1) | bit`，shift+or 是 `OP_CAT` 的 emitter 降阶写法，
属一个 enode）；原节点保留根算子。形态与三地址码一致。

### 4. 对主结论的加强解释

- 打平**确实生效**（0 违规），"图结构几乎不变"不是打平失效，而是
  香山 FIR 经 exprOpt/commonExpr 后表达式树本来就浅（86.7% 节点
  只有 1 个计算 enode）。
- 更关键的机制：`graphInitPartition` 的 DP 按拓扑序连续装段，打平
  产生的单算子链与原节点在拓扑上相邻，几乎总是被重新装进同一个
  超节点——335,823 个新 temp 中仅 **269 个**成为跨超节点的状态变量
  （出现在 `SimTop.h`），其余全部是超节点内局部变量。超节点粒度
  （max-size 成员数预算）掩盖了 node 粒度差异，这正是"node 层次
  不是 activity 划分优势根因"的机理层面证据。
