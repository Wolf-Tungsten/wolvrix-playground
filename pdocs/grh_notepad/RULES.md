# grh_notepad 文档管理规则

本文是 `pdocs/grh_notepad` 的强制性管理规则。目标是在约 5 万篇 GRH 记录下保持稳定路径、可读的树状导航和低 Git 冲突率。

## 1. 范围与单一事实来源

- 记录类文档包括方案、实验、诊断、决策、实现记录、回归、gate 和勘误；每个独立议题对应一篇记录。
- `README.md`、`RULES.md`、`templates/` 与 `tree/` 中的文件都是管理文件，不占用 `NO` 编号。
- 每篇记录的唯一规范正文只能位于 `notes/`。`tree/` 只能保存该正文的相对链接、标题、日期和简短状态，不得复制正文、使用硬链接或使用符号链接。
- 原始大日志、生成代码、二进制和波形不进入本目录；记录中写入可复现命令、产物路径、摘要和必要的小片段即可。

## 2. 编号、文件名与编号树

- 记录编号统一为五位十进制 `NOxxxxx`，从 `NO00001` 开始，按进入目标分支的顺序单调递增，已分配编号永不复用。
- 五位宽度是对 `grhsim_opt` 四位 `NOxxxx` 规则的扩展，可覆盖 `NO00001` 至 `NO99999`；50,000 篇记录不会耗尽编号空间。
- 文件名固定为 `NOxxxxx_slug_YYYYMMDD.md`。`slug` 使用小写 ASCII 字母、数字和下划线；日期必须与 YAML 中的 `date` 一致。
- 正文路径由编号计算，不按主题、状态或日期移动：
  - 一级分片 `NN = floor(number / 1000)`，两位补零。
  - 二级分片为该千位内的百位范围：`000-099`、`100-199`，直到 `900-999`。
  - 例：`NO00001` -> `notes/00/000-099/`；`NO01234` -> `notes/01/200-299/`；`NO50000` -> `notes/50/000-099/`。
- 叶目录最多 100 篇正文。新的分片目录按需创建，不预先创建空目录。

## 3. 编号分配与并发提交

- 不维护或提交可变的 `NEXT_ID` 文件。创建前在最新目标分支上检查已存在的最大 `NO` 编号，再分配下一个编号。
- 一个分支同时新增多篇记录时可申请连续编号；合并前 rebase 后必须再次检查冲突。
- 两个分支发生编号冲突时，后进入目标分支的记录改用新的未占用编号，同时改正正文文件名、正文元数据、主题索引链接和文内相对链接。
- 不得为了填补缺号而重编号历史文档。缺号保留为历史事实。

## 4. 正文元数据与增量规则

- 每篇正文必须以 [模板](./templates/NOTE_TEMPLATE.md) 中的 YAML front matter 开始，至少包含 `id`、`date`、`title`、`kind`、`status`、`area`、`topic`、`tags`、`parents`、`related` 和 `supersedes`。
- `kind` 取值为 `note`、`plan`、`experiment`、`diagnosis`、`decision`、`implementation`、`gate`、`correction` 之一；`status` 取值为 `active`、`blocked`、`superseded`、`archived` 之一。
- `area` 和 `topic` 使用小写 ASCII 加连字符。`area` 是一级主题，`topic` 是其下的二级主题；同一记录只选择一个主路径，跨主题关系通过 `tags`、`parents`、`related` 和 `supersedes` 表达。
- 正文采用只追加原则。可新增“增量更新 YYYY-MM-DD”或“勘误”章节，但不得删除历史结论、整体改写旧记录或把独立议题塞入旧记录。
- 新结论、一次新的实验、一次新的 gate 或新的 root cause 都应新建记录，并通过 `parents`、`related` 或 `supersedes` 连接历史记录。
- 标题、状态和主题可以修正，但编号、正文路径和文件名中的 `slug` 保持不变；主题变更时，从旧主题叶索引移除过期链接、向新主题叶索引追加链接，并同步更新元数据。

## 5. 主题导航树

主题树的根为 `tree/`，路径由正文的 `area/topic` 和编号分片组成：

```text
tree/
├── README.md
└── <area>/
    ├── README.md
    └── <topic>/
        ├── README.md
        └── <NN>/
            ├── README.md
            └── <range>.md
```

- `tree/README.md` 只列出直接的 `area` 节点；`tree/<area>/README.md` 只列出直接的 `topic` 节点；更深层 `README.md` 也只列直接子节点。
- 一个节点的直接子项不得超过 32 个；超出时新增语义明确的中间节点，而不是把所有链接堆在同一个文件。
- 叶索引是 `tree/<area>/<topic>/<NN>/<range>.md`，与 `notes/` 的编号分片一致，每个文件最多 100 条记录链接。
- 叶索引的每条记录使用一行 Markdown 表格或列表，至少包含 `NO`、日期、标题、状态和指向 `notes/` 正文的相对链接。新增记录追加在本叶索引末尾，不为排序重写历史行。
- 首次创建 `area`、`topic`、`NN` 或叶索引时，补充其父节点的直接子链接；已有父节点不因普通新增记录而改写。
- 主题树是导航副本，不是按关键词复制的二级归档。正文只能在一个主主题叶出现一次；需要多维检索时使用 tags 和全文搜索。

建议的一级 `area` 是 `architecture`、`grh-model`、`ingest`、`transform`、`emit`、`store-load`、`simulation`、`performance`、`verification`、`tooling`、`decision-log`。新一级分类应在确有稳定边界时才增加。

## 6. 链接与可检索性

- 目录内和跨目录 Markdown 链接一律使用相对路径；禁止使用仓库绝对路径或机器本地绝对路径作为链接目标。
- 正文标题应明确说明主题和结论，避免“测试记录”“问题分析”等无信息标题。
- tags 使用小写 ASCII、连字符分隔的稳定术语；同义词统一到一个 tag，临时词不进入 tags。
- 关联记录优先引用 `NO` 编号和相对链接；在本目录根部书写时，形式为 `./notes/01/200-299/NO01234_node_origin_map_20260713.md`。
- 检索优先级为：已知编号查 `notes/` 编号树；已知领域沿 `tree/` 主题树；已知术语使用 `rg` 搜索 `notes/` 的元数据与正文。

## 7. Git 提交边界与维护

- 一次普通新增的最小提交是“一篇正文 + 一个主题叶索引”；首次出现的树节点才额外修改对应父节点索引。
- 不维护全局全量表，不批量重排索引，不因状态或主题修正移动正文文件。这些规则用于缩小 diff、降低并发冲突并保留稳定链接。
- 合并前检查：编号唯一、路径符合分片规则、YAML 与文件名一致、主题叶索引存在且链接为相对路径、引用的 `NO` 可解析。
- 删除记录仅在明确的仓库治理决议下进行；通常应改为 `superseded` 或 `archived`，并新建说明记录，而不是删除历史证据。
