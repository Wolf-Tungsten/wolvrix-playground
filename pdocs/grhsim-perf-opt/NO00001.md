## 量化分析

历史冻结版事件修复模型的 100k 采样共128385个样本：writer占51968
（40.478%），nonsink占45054（35.093%），activity dispatcher仅3529
（2.749%）。因此单独优化 activity 扫描不具备10%整体提升的空间。
这些采样只用作选题依据，不代替本轮旧模型构建和性能复测。

当前 emitter 在每个 run 中先生成全部 payload cone，再生成全部 writer。
核对已提交基线对应生成代码，最重 `writer_run_batch1420` 有1159个函数、
约298802字节跨 chunk frame；其中一个大 run 包含362个纯计算 helper、
1个混合 helper、469个纯写入 helper。59512个 frame 槽先被定义，再由
21605次 small-state 写入消费；定义到最后使用的中位跨度191709源码行，
p90为359093行。这是长存活区间导致的数据搬运，而非文本重复表达式。
该 batch 历史占4.067%，单点优化不足；本假设适用于全部 writer runs。

本轮旧模型的紧凑输出核验得到相同结构：1421个writer batch、15618个
writer函数、7102534行writer源码；388个writer frame共344746个字段，
完整C++类型的payload合计1051103字节（不含ABI padding）。batch1420为
73842个字段、298802字节payload、1159个函数/749835行。该完整统计包含
`size_t`及全部`_BitInt`，不使用曾漏计这些类型的历史总frame字节数。

上述结构可由受跟踪的 [cpu-st-cpp.cpp](../../wolvrix/lib/emit/grhsim/cpu-st-cpp.cpp)
`CpuStEmitContext::buildPhases()` 的 cone→enabled→writers 顺序复现。
历史性能背景见 [grhsim.md](../grhsim.md) 7.5、7.11。

## 假设提出

将仅有一个 writer 消费的纯 payload 子图移动到该 writer 的原始位置，
在其 enable guard 内先算后写，能缩短局部值生命周期并让编译器保持寄存器
局部值，减少跨 helper spill。全部 enable 祖先、共享/观测 producer 保留
原先拓扑位置；writer 相对顺序和六阶段调度完全不变。small writer 写 Next，
延迟的私有读取仍读本轮 current snapshot；large writer 仍只捕获，之后提交。

若整体 writer 成本减少约22.5%，在历史占比下有达到10%整体加速的可能。
可证伪条件：语义回归失败、完整构建超时，或正式六次总提升不足10%。

## 代码实现

已在 emitter 中基于最终图重新计算唯一 writer 消费归属（不能依赖
早期 partition pass 的私有性，因为 simplify 可共享表达式）。反向 demand
传播同时记录无条件需求、enable 集合及唯一 writer；多个 writer 的需求合流
后标记为共享。仅可克隆、非无条件且唯一 writer 的 producer 延迟到原 writer
guard 内，按原拓扑顺序生成；其余 producer 保留原有路径。每个 writer 重置
packing cache，避免跨非支配作用域使用局部值；共享 payload 仍按 enable
集合求值一次。
不修改 GRH/GrhSIM op 定义、named store、state publish 或固定点语义。

同配置整机生成验证：writer frame payload从1051103降至780316字节
（−25.76%），字段344746→284055，frame数388→372；batch1420从298802
降至41290字节（−86.18%），其uint64跨helper字段31439→214。
该batch的计算/混合/纯写helper从362/1/469变为194/558/0；仍有21605次
状态写入，总计算赋值143941不变，21604次frame赋值转为local赋值。
这支持实现确实缩短了临时值生命周期，而非少算逻辑。

限制：95.10%的frame字节缩减来自batch1420，其余batch净缩减仅1.76%
（87个batch降低、29个增长）。该batch历史只占4.067%总样本，所以不能
由总frame降幅推断整体10%速度提升，必须由正式六次结果判定。
静态native census补充了frame以外的效应：排除batch1420后，非padding
指令10013382→10012686（−0.00695%），显式内存指令4573793→4431287
（−3.116%），直接`%rsp`访问750399→675023（−10.045%），其中栈写入
237838→188262（−20.844%）。batch1420指令927402→606893，但直接栈访问
9940→34396；全部writer指令/内存/直接栈访问分别减少2.936%/6.079%/6.697%。
这些是按符号聚合的静态指令计数，未按真实执行频率加权；不把`%rbp`访问
直接当作栈spill，也不把静态降幅当作性能结论。

## 总结复盘

判定为**方向错误：实现符合假设，但整体收益不足**。两轮早期输出上限错误
已在原节点修正，最终双方构建与正确性均通过，不用这些配置错误解释正式
性能结果。最终图私有性、enable祖先、共享/观测值、Current/Next及写入顺序
的代码与回归复核未发现实现遗漏；不能将3.6371%的收益称为达到10%。

frame缩减确实发生，但95.10%的字节收益集中于历史仅占4.067%样本的
batch1420，其余writer batch净缩减仅1.76%；这解释了为何不能由25.76%的
frame总降幅预言10%的整机提升。静态计数未按执行频率加权，尚不能进一步
归因每毫秒收益。下一方向需减少更广泛的实际发布/比较工作。

撤除范围限定于私有payload streaming：恢复emitter及新增专项测试到本节点
源码基线，并删除两份有效机制文档中的streaming段；保留本节点失败记录、
公用测量工具、readability透传和输出文件上限修正。撤除后emitter和测试文件
与wolvrix `63bfde598ba2806d0ae6c41e31dbefdb52aa9111`逐字节一致，两份文档
仅保留公共配置说明，diff检查通过。冻结旧模型可继续作为后续比较基线；
已安装的候选库尚不代表撤除后的源码，下一节点必须经Make重建并核验实际
加载库。本节点以失败结案，转NO00002；本次goal仍未完成。
