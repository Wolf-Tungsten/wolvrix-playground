# NO0016 AM 与 gsim 剩余差距拆解（1.0x 完全对齐场景）

日期：2026-08-01
前置：[NO0015](NO0015_lane-aggregate实施与验收_20260801.md)（lane-aggregate 落地后 compute 3,278,538，1.1653x）

## 0. 问题与口径

[NO0015](NO0015_lane-aggregate实施与验收_20260801.md) 的不可达论证针对的是 ≤1.10x（差 ~17.9 万）。本文换一个场景：**如果要与 gsim 完全对齐（1.0x），剩余 465,007 compute-op 的差距大头在哪里、哪些是可消的**。

数据勾稽（本次全部复核通过）：

- AM 侧复用 r4 探针产出 `build/xs/lane-agg-probe/r4/lane_agg_summary.json`：total 4,160,925 / compute 3,278,538，与 [NO0015](NO0015_lane-aggregate实施与验收_20260801.md) §2 一致。
- gsim 侧从 `topo-partition-proj/exp/dataset/xs_gsim_flatten_20260731/instruction_graph.jsonl`（3,043,902 节点）重新逐 opcode 统计，按 [NO0008](NO0008_t5口径清算表_20260731.md) 桶映射归并后与该文 §1 表逐项一致（logic 910,486 / mux 737,356 / compute 2,813,531，含 OP_SUB 6,977）。
- 净 compute 差 = 3,278,538 − 2,813,531 = **465,007（1.1653x）**。

## 2. logic +751,427 的解剖

来源：本次新跑 `module_attr_compare.py` → `/tmp/module_attr_r4.json` + r4 JSON 的 `loc.pass` 标签流式分解。

### (a) no_loc transform 产物 +128,931（总池 346,177 compute，全图最大单"模块"）

r4 no_loc 403,112 ops = E1 no_loc 191,311 + lane-aggregate 新增 211,787（勾稽差 14）。按 pass 标签：

| pass 标签 | ops | compute 构成 | 含义 |
|---|---:|---|---|
| lane-aggregate | 211,787 | logic 99,235 + concat 58,948 + slice 52,566 | 宽寄存器合并产物：reduce-concat-normalize 94,664、mux-select-broadcast 75,093、lane-read-slice 24,167、lane-mask 11,320 |
| comb-lane-pack | 124,773 | concat 56,163 + slice 46,684 + logic 21,926 | E1 就有的打包产物（pack-mux-mask 48,180 等） |
| reg-to-mem | 58,419 | 主体 state 50,835（mem 口形态） | E1 已有 |

**这 ~34.3 万 no_loc compute 是"已合并/已打包数组"在 AM 打平 IR 里的表达成本**——宽 masked-write 的 `(reg&~mask)|(data&mask)`、condition broadcast、打包 concat/slice；gsim 侧同一段逻辑由数组级节点（REG_UPDATE/READ_MEM）+ when 区域承载，落在 compute 口径之外。

## 4. 总 op 口径（顺便）

Δtotal = 4,160,925 − 3,043,902 = **+1,117,023（1.367x）**：compute +465,007；**state(+mem) +467,204**（register 三元组 187,553×3=562,659 vs gsim REG_UPDATE 148,956 的建模口径 + mem 口 57,939 vs 5,426 + LogPerf state 差 +61,041）；wire +149,868（kAssign vs gsim AliasAnalysis 消别名）；const +27,264；special +7,463。**total 口径差距里 compute 只占 42%，state 三元组建模占 42%**——total 对齐同样绕不开 IR 建模口径。

## 5. 可消除性分类（1.0x 场景）

| 桶 | 规模 | 判定 | 依据 |
|---|---:|---|---|
| no_loc 宽形态/打包产物 | ~343k compute（lane-agg 新增 211k） | **结构性** | 宽 masked-write/broadcast/打包是打平 IR 表达数组的必然成本；消它 = 引入数组级 value/when 语义，是换 IR 不是写 pass |
| gsim 负桶（mux/cmp/shift/cast −431k） | 净差里的"赠送" | **结构性（口径）** | OP_WHEN/pad-shift/eq(x,0) 是 gsim 特有 op，AM 无从产生也无从消 |
| guard 组合树 vs when 区域（I4） | Rob Δlogic +71k 主体 + LogPerf +43k 等 | **结构性** | 同一 guard，gsim 由 126k 个 OP_WHEN 区域 op 承载，AM 物化成 and/or 数据流树 |
| state 三元组（仅 total 口径） | +467k | **结构性（建模口径）** | register+read/write port vs REG_UPDATE×1 |
| C2 LogPerfEndpoint 跳过 | −148,468（全模块 compute） | **易，但行为变更** | 唯一大额"易"项；丢性能计数打印、对比口径变不对称（[NO0012](NO0012_logperf核查与memory-op语义备忘_20260801.md)，默认不做） |
| C1 分段算术/比较 IR | ~50-150k | **理论可做，新目标级工程** | 分段 add/sub/lt 宽 op 需 IR 定义+lower/emit/调度全线穿透（[NO0010](NO0010_数组语义路线终局_20260731.md) "另一个量级的工程"） |
| I1/I3 译码/选通树重写 | 账面 ~150-250k | **理论可做，工程量大且账面虚高** | [NO0009](NO0009_i2布尔归一化与i1译码树重写_20260731.md) 已证 1-bit 局部重写上限 3.6%；需 W 位 onehot/译码 ROM 新 matcher |
| 剩余 lane 扩展（MSHR 跨实例、WB_4 降阈值、issueQueue） | 元素 ~30k，op 量级未证 | **未证伪的残余机会，中难** | MSHR_64 556 组 no_majority 是分组规则局限还是真非同构，需一轮探针；WB_4 仅 4 lane |

## 6. 结论

- 剩余差距的大头已经不是"未合并的逐 entry 展开"（Rob 已被 lane-aggregate 消 92%），而是三样结构性东西：**打平 IR 表达宽数组的必然成本（no_loc ~34 万）、guard 物化树 vs when 区域、gsim 特有 op 形态的口径差（负项 −43 万）**。
- 易项只有 C2（−148k）；理论可做项（C1 + I1/I3 + 残余 lane）乐观合计 ~200-400k 且每项都是独立工程；结构性地板兜底。
- **C2+C1 全做 ≈ 1.09-1.11x（刚好贴原 ≤1.10x 目标线）；1.0x 完全对齐在 ingest/transform/pass 层面不可达**，唯一通路是给 GRH IR 引入带维度的数组 value 与 when 区域语义（换 IR 量级）。
- 待决（三选一，用户拍板）：① 按本路线收尾；② C2 LogPerf 跳过（→~1.12x）；③ C1 分段算术 IR 语义。
