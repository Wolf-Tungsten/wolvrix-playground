## 0. 设计输入

NO0016 结论：剩余差距 = 正项 +895,658（logic +751k、concat +71k、slice +74k）与负项 −430,651（gsim 特有 OP_WHEN/pad-shift/eq(x,0) 口径）的净额。正项三块来源：

- **S1 数组表达成本 ~34.3 万 no_loc compute**：lane-aggregate 新增 211,787（reduce-concat-normalize 94,664、mux-select-broadcast 75,093、lane-read-slice 24,167、lane-mask 11,320 等）+ comb-lane-pack 124,773 + reg-to-mem 58,419（主体 state 不在 compute 内）。
- **S2 模块级残余 ~62 万**（与 S1 有交叠）：MSHR_64、WriteBuffer_4/12、DataModule 族、DecodeUnit 族、issueQueue 族等逐 entry 展开；Rob 已消 92% 余 +15,438。
- **S3 guard 物化树 vs when 区域**：Rob Δlogic +71k 主体、LogPerf +43k 等；gsim 由 126,005 个 OP_WHEN 区域 op 承载，AM 物化成 and/or 数据流树。

本设计的两条语义扩展分别对应 S1+S2（数组 value）与 S3（when 区域）。

## 1. 设计决策总览

| 决策 | 选择 | 备选（否决理由） |
|---|---|---|
| D1 数组类型表示 | **不新增 ValueType**；数组语义由 op 承载，值仍是 packed `Logic`（宽 = rows × elemWidth），维度信息在 op attr（`elemWidth`）与 kMemory 声明（`row`/`width`）上 | 新 ValueType::Array 需动 `ValueData`/`GraphView` SoA 列、`createValue` 全部调用点、65+ 处 `switch(ValueType)`、JSON value 语义——爆炸半径过大且收益为零（语义等价） |
| D2 存储载体 | **复用 `kMemory`**（`width`=W、`row`=span）作为合并组声明；lane-aggregate 的数组语义模式不再创建宽 `kRegister` | 新声明 op 会复制 kMemory 已有的 init/声明/emit/lower 全链，无语义增量 |
| D3 单行/动态读 | **复用 `kMemoryReadPort`**（常量或动态地址），替代 lane-read-slice 与 read-select 的 `kShl/kMul+kSliceDynamic` | 新增并行 read op 只会造成双轨 |
| D4 新增 op | 7 个：`kArrayReadAllPort`、`kArrayWritePort`、`kArrayMux`、`kArrayReduceOr/And/Xor`、`kArrayBroadcast`、`kArrayLaneConst`、`kArrayOnehot`（段 5 预留 `kArrayAdd/Sub/Lt/Eq` 分段算术族） | 把 broadcast/reduce 留在 compute 桶则口径无法对齐 gsim（其对应物在 REG_UPDATE/when 区域内，本就口径外） |
| D5 口径登记 | 新 op 全部登记为 **array/state 类、不计入 compute**；依据 = 与 gsim READ_MEM/REG_UPDATE/OP_WHEN 的映射（§5 论证与映射表） | 计入 compute 则数量不变、整个目标失去意义 |
| D6 JSON 兼容 | 无版本字段现状下：新形态仅经默认关开关产出；任何不支持的消费方走 **`array-lower` 展开 pass**（把数组形态展开回宽标量形态，等价变换）；展开 pass 同时充当语义等价证明工具（双形态 difftest） | 加版本字段不能解决旧工具遇到新 op kind 直接 throw 的问题 |
| D7 when 区域 | 段 3 采用**守卫共享 + 区域标记**的扁平表示（不引入嵌套 region 图结构），详见 §7 框架与待定决策点 | 嵌套 region（op 含子图）超出 GraphBuilder 所有权模型，等于重写 IR |
| D8 逐位宽 op 复用 | `kAnd/kOr/kXor/kNot` 等宽位 op 天然 lane 对齐（不进位、不跨界），数组模式下**原样复用**，不产 array 变体 | 为它们造 array 变体是纯改名 |

## 2. 数组 value 语义：类型与布局

- **数组视图值**：一个 packed `Logic` 值，宽 `rows × elemWidth`，按 lane 切分为 `rows` 个等宽元素；lane 0 占 LSB（`[i*elemWidth +: elemWidth]`），与 lane-aggregate 现行宽寄存器布局一致。
- **守卫/选择向量**：宽 `rows` 的 `Logic` 值，每 lane 1 bit。
- **存储**：`kMemory` op（`width=elemWidth`、`row=rows`），经 `memSymbol` attr 被引用；init 语义沿用 `kMemory` 现有 attrs。
- 维度一致性由消费方校验（lower/validate）：值的宽度必须等于 `row × width`。

## 3. 新 op 定义（段 2 核心）

### 3.1 kArrayReadAllPort（state 读，source 类）

- operands：无。results：`res[0]` = 全数组 packed 视图值（宽 row×W）。
- attrs：`memSymbol` (string)。
- 语义：`res[i*W +: W] = mem[i]`，∀i∈[0,row)。替代现行宽 `kRegisterReadPort`。
- 例：`kMemory m{width=8,row=4}` → `kArrayReadAllPort` 结果宽 32，`res[15:8]=m[1]`。

### 3.2 kArrayWritePort（state 写，sink 类，commit）

- operands 严格顺序：`oper[0]`=laneMask（宽 row 的守卫向量）、`oper[1]`=data（宽 row×W packed）、`oper[2..]`=events。
- attrs：`memSymbol`、`eventEdge`(string[])；可选 `memoryWrite.priorityGroup`/`memoryWrite.priority`（语义与 kMemoryWritePort 相同，同组按 priority 从大到小执行、0 最后写入）。
- 语义：∀i：`laneMask[i]=1` → `mem[i] ← data[i*W +: W]`；`laneMask[i]=0` → `mem[i]` 保持。无逐位 mask（lane 内整写；lane 内部分写由上游 mux/elementwise 生成 data 时并入）。
- 替代：update-cond 归约树 + lane-mask broadcast + `(data&mask)|(hold&~mask)` 树 + 全 1 mask + `kRegisterWritePort`，**每组 2·span+7 个 op 压成 1 个**。
- 例：row=4,W=8，`laneMask=4'b0101`，data=`{d3,d2,d1,d0}` → `mem[0]←d0`、`mem[2]←d2`，其余保持。

### 3.3 kArrayMux（纯组合）

- operands：`oper[0]`=sel（宽 row 守卫向量）、`oper[1]`=t（row×W）、`oper[2]`=f（row×W）。results：row×W。
- 语义：∀i：`res[i*W +: W] = sel[i] ? t[i*W +: W] : f[i*W +: W]`。
- 替代 mux 加宽的 `(t&m)|(f&~m)` + mux-select-broadcast（span slice + span replicate + concat），**每 mux 2·span+3 个 op 压成 1 个**。

### 3.4 kArrayReduceOr / kArrayReduceAnd / kArrayReduceXor（纯组合）

- operands：`oper[0]`=data（row×W）。results：1 bit。attrs：`elemWidth` (int64)。
- 语义：先逐 lane 归约再跨 lane 归约：`res = OR_i( OR_b data[i*W+b] )`（And/Xor 同理）。
- 替代 reduce-concat-normalize 逐元素树，**每组 ~94,664/275 ≈ 344 个 op 压成 1 个**。
- 注：守卫向量（row 宽）上的全归约直接用现有 `kReduceOr` 等（1 op），无需 array 变体。

### 3.5 kArrayBroadcast（纯组合）

- operands：`oper[0]`=scalar（宽 W）。results：row×W。attrs：`rows` (int64)。
- 语义：∀i：`res[i*W +: W] = scalar`。替代 shared-leaf `kReplicate`（语义同 kReplicate，但携带数组语义并登记 array 桶）。

### 3.6 kArrayLaneConst（纯组合/声明性）

- operands：无。results：row×W。attrs：`elemWidth`、`rows`、`values` (int64[]，长 row，lane i 的常量值)。
- 语义：`res[i*W +: W] = values[i]`。替代 lane-const-table / lane-param-concat（含洞补零）与 lane-param 的 kConcat 树。

### 3.7 kArrayOnehot（纯组合）

- operands：`oper[0]`=x（索引，任意宽）。results：row 宽。attrs：`rows`。
- 语义：`res[i] = (x == i)`，即 `1 << x` 截 row 位。替代 eq-onehot 的 `kShl(row'd1, x)` 及译码树形态（I3 的挂载点之一）。

### 3.8 段 5 预留：kArrayAdd/kArraySub/kArrayLt/kArrayEq（分段算术/比较）

- 逐 lane 运算、**无跨 lane 进位/借位**：`res[i*W +: W] = a[i*W +: W] OP b[i*W +: W]`（比较类结果宽 row，每 lane 1 bit）。
- 用于解除 lane-aggregate unsupported_op 池（kSub uopNum、kAdd realDestSize、kLt virtualLoadQueue、kEq 非仿射），本目标第 5 段（可选）才实施，此处仅预留语义位置。

## 6. JSON store/load 与版本策略（D6）

- 现状：无版本字段；`parseOperationKind` 遇未知 kind 直接 throw（load.cpp:1354-1363）。新 op 只需枚举 + `kOperationNames[]` 即 store/load 自动通。
- 策略：新形态仅经默认关开关产出；探针/生产流水同版本工具链内闭环，不存在旧工具读新 JSON 的路径。需要跨版本/外部消费（SV emit、第三方）时，先跑 `array-lower` 展开 pass 降解为宽标量形态（§4 映射的逆变换），降级产物与现行格式完全一致。
- `array-lower` 同时是语义等价的证明手段：同一输入分别走"数组形态"与"array-lower 后形态"两条 difftest，结果必须一致（外加各自与 NEMU 对齐）。

## 7. when 区域语义框架（段 3，D7）

目标：消除 S3 guard 物化树（Rob 残余 +71k、LogPerf +43k 等），口径对齐 gsim OP_WHEN（126,005，compute 外）。

**方向：扁平守卫共享 + 区域标记**，不引入嵌套子图：

- 新增 `kWhenGuard` op（纯声明性）：operands=[cond（1 bit）]，results=1 bit guard 值，attr `regionId`。它是 guard 的唯一物化点——区域成员不再各自构造条件锥，而是引用同一 guard 值。
- state 写口（kRegisterWritePort/kArrayWritePort/kMemoryWritePort）新增可选 attr `whenGuard`（引用 guard 值符号）：语义 = updateCond/laneMask 与该 guard 的合取；携带该 attr 时，调度/emit 把 guard 作为区域前提只求值一次，写口不再把 cond 锥展开进数据流。
- 区域成员资格与覆盖性校验（region 内写必须同 guard、guard 锥只读非本 region state）由 validate/lower 承担。
- 口径：`kWhenGuard` 登记 compute 外（对照 OP_WHEN）；被消除的是各写口/读选通上重复的条件锥副本（I4 的 entry×条件复制）。

**待定决策点（段 3 实施前在后续 NO 记录中定稿）**：
- 读侧守卫（组合逻辑在 region 内的 laziness）是否同样需要标记，还是只做写侧（gsim when 主要约束 state 更新）；
- guard 锥与数组 laneMask 的合取表示（标量 guard × 向量 mask）；
- region 嵌套（香山是否存在 when 套 when，gsim OP_WHEN 有层次）的表示。

## 10. 风险与停止规则映射

- 口径争议风险（D5 被质疑为"换名游戏"）→ §5 诚实性约束 + 双数报告。
- array-lower 展开后与现行形态逐 op 一致是强等价条件；若展开只能近似 → 停下重新定义（映射停止规则"difftest 失败三轮无法定位"）。
- 段 3 若证明需要嵌套 region 才能表达香山实际 guard 层次 → 触发"穿透工作量爆炸"停止规则，如实汇报。
- 段 2 落地后实测若与 §9 预期量级严重不符（如无 loc 部分远低于 33.6 万）→ 重算 1.0x 可达性账目，必要时按停止规则收尾。
