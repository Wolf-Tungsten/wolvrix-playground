## 6. runtime 回退假设与调查计划

初步假设（按嫌疑排序）：
1. **ArrayReadAll 物化成本**：wide 模式的宽 kRegisterReadPort 是 state 变量别名（零成本）；array 模式的 `array_readall_pack` 每次求值做 rows×stride 行拷贝（robEntries 344 行 × 多组）。memory 按 word-stride 行存储，W 非 64 幂时与 packed 布局不同，必须逐行 pack。
2. **array_write_scatter 逐 lane 循环**：每次写判 rows 次 laneMask。
3. helper 均为通用实现未特化（W=64k 快路径、块掩码等未做）。
4. r4 wide 的 +21% 回退根因未查，可能与 array 回退部分同根。

调查：perf 采样 50k 已跑（本记录入库时分析中），结论与优化在后续 NO 记录。优化方向（按预期收益）：W%64==0 时 readall 退化为别名（零拷贝）、scatter 写按 laneMask 字级预筛、helper 特化。

## 7. 段 3 设计决策已定稿（取证完成）

段 3（when 区域）三个待定决策点已用 gsim 打平图 + FIR 源 + AM a2 图三方取证回答：

- **D-a：只做 state 写侧**（gsim OP_WHEN 72.2% 是出度 0 的 REG_DST/SPECIAL 终端；状态读一律无守卫）。
- **D-b：guard 与 laneMask 分层，执行时合取**（gsim 存储写口 when(enable) 与 per-lane mask 始终两层；a2 实测合取点正是 `kAnd(kArrayBroadcast(scalarGuard), laneVec)`）。

## 增量更新 2026-08-02：runtime 回退已修复（473.6s）+ 段 3 前提修正

**runtime 对账闭环**：
- 定位：perf 被内核禁用（paranoid=4），改用生成产物 rdtsc 插桩（一次性补丁，已被重 emit 覆盖回滚）。50k 对拍实测：`array_mux_words` 占 array helper 总 tsc 的 89.5%（15.8M 次调用，约合总 runtime ~30%）、`array_broadcast_words` 9.1%、其余 <1.3%。mux 根因 = 逐 bit 构造 lane 掩码（每输出字 64 次迭代 + 每 bit 一次除法）。
- 修复（cpp_emitter.cpp 两 helper 生成实现，语义逐位等价、interpreter 为 oracle）：elemWidth==1 直通；2 幂 Morton pair-spread；通用按 lane 迭代（每字 2-3 次 vs 64 次）。微基准 mux w=36 快 22.5×、bcast 2 幂快 152×。
- 复测（重 emit + 重 emu + 50k）：**difftest 通过（instrCnt=73,580 / cycleCnt=49,996）、Host time 473.6s**——640.7s → 473.6s（−26%）；**array 模式反超 wide**（r4 524~533s）。对 E3 基线 +9.8%，仍略高于判据 +5%（≤453s），残余 +42s 是 lane-aggregate 自身的结构性成本（wide 模式 +95s 同根，未单独立项）。
- 结论：判据 4 的阻塞基本解除（从 +48% 压到 +9.8%）；残余 +42s 列为观察项，不阻塞段 2 收口。

**段 3 前提修正（双边取证，判定 (c) 前提有水分）**：
- gsim 的 guard 逻辑**同样在 compute 口径内**（OP_WHEN 计 mux 桶、guard 锥计 logic/cmp，分母 2,813,531 包含它们）；gsim Rob guard 锥并集 64k~168k ≥ AM 112k，共享度 6.18× ≤ AM 7.46×。
- Rob Δlogic +71k 的主因是**桶间形态平移**（gsim 锥内 31% OP_MUX 计 mux vs AM 布尔归一化后计 logic），不是 guard 复制；lane-aggregate 后 AM 已是"guard 单点物化+引用"结构，Rob cond 锥真实复制仅 9,572 op（8.5%）。
- 推论：when 区域（kWhenGuard）若把 guard 移出 compute 是单方面口径变更，违反 NO0017 §5 诚实性约束，**不做**；其诚实收益仅 ~9.6k 去重 + IR 表达力，段 3 降级为非必选项。
- 1.0x 主战场转到段 4（模块残余，真实 op 池）：MSHR_64 +72,651 / WriteBuffer_4 +72,428 / WriteBuffer_12 +54,048 / DataModule 族 +77,608 / DecodeUnit 族 +74,543。

**段 4 侦察结论（agent-20，复刻校验可信度已验）**：
- MSHR/WB 被拒的主因**不是真非同构**，是签名 marker 在共享值上的 lane 相关不对称（形态 A：共享 reset 锥 lane 0 特化；形态 B：全范围 sibling 归约签名全裂）。性价比最高解锁 = **no_majority 时对全候选直接跑 ConeAnalyzer（exact-all 兜底）**。
- 第二层解锁 = **C 级 lane-param 物化叶**（同 kind/arity/attrs 的非 pointwise op 作叶）：WB12 232/232 全过、WB4 78%、MSHR 100/372 组。
- min_lanes 8→4 + 上两项：WB4 296/379（C 级）且新增 L2 slices_* 区（~105k 池）；WB4 全收需 R 级叶（attrs 可异）。
- 预估 compute 收益（cone 侧去重口径，偏乐观）：WB12 ~+40k、WB4 ~+40-50k、MSHR 干净路径 ~+11.5k（拆类另计）、L2 新区另计。
- 落地顺序建议：exact-all 兜底（中）→ C 级叶（中）→ min_lanes=4（小）→ R 级叶/sibling 降级（中）→ MSHR 类拆分（大，最后）。
