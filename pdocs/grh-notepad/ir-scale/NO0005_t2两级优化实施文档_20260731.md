# 20 T2 实施文档：GRH 层与 AM 层两级优化（2026-07-31）

承接 [`19`](19-gsim逐pass算子贡献与am死代码验证.md) §7 的调整，T2 分两个
层面实施（用户提出）：

- **L1（AM 生成前）**：在 GRH IR 上补做 DCE / 常量折叠 / CSE——改动落在
  生产流水线配置（`scripts/wolvrix_xs_grhsim.py`），不写新 C++。
- **L2（AM 生成后、分块前）**：在 AM 指令流（LinearProgram）上做同一组
  算法——新组件 `grhsim/am/optimize.*`，挂在 `lower()` 与 `schedule()`
  之间。

先做诊断定界，再给两级实施方案。

## 1. 诊断定界（本次新事实）

> 修正 [`18`](18-am多出op的归因与验证计划.md)/[`19`](19-gsim逐pass算子贡献与am死代码验证.md)
> 的一处表述：`simplify` pass 内部本就迭代
> `ConstantFold + RedundantElim + DeadCodeElim` 至不动点
> （`wolvrix/lib/transform/simplify.cpp:52-54`，maxIterations=8），且 XS
> 流水跑了两次。"CSE 未接入流水"的说法作废；`redundant-elim` 只是没有
> 独立的 pass 名（未注册进 `makePass`），不影响其生效。

两个探针（pybind Session 直跑 `build/xs/grhsim-am/wolvrix_xs_post_stats.json`，
即 AM lowering 的输入）：

| 探针 | 方法 | operation_count | Δ |
|---|---|---:|---:|
| P1 | `dead-code-elim`（keep_declared=false） | 5,158,238 → 4,429,173 | **−729,065** |
| P2 | `simplify`(2state) 全量 | 5,158,238 → 4,373,328 | −784,910 |

结论：

1. **AM 的 72.9 万死指令在 lowering 之前就以同量存在于 GRH JSON 中**
   （P1 删 729,065 vs AM 死锥 729,077，差 12）。它们生于 simplify 之后：
   流水顺序为 `simplify ×2 → memory-init-check → reg-to-mem → stats`
   （`scripts/wolvrix_xs_grhsim.py:679-700`），死 op 形态（logic_and /
   mux / logic_or / eq 的 guard 树）与 reg-to-mem 的 guard 重写行为吻合
   ——**L1 的落点因此确定：在 reg-to-mem 之后补一次 DCE**。
   （memory-init-check 为只读检查，精确到 pass 的 pinning 留作 T2-0
   逐段探针，不影响 L1 落点。）
2. **GRH 层的 fold+CSE 已近饱和**：P2 比 P1 只多删 5.7 万。gsim 的
   常量分析（−39 万 logic）/CSE（−14 万 logic）那种量级的收益在 GRH
   层拿不到——前面的 simplify×2 已把能拿的都拿了。**剩余 ~88 万
   logic 差不是 GRH 层优化能消化的**，要靠 L2（AM 层视角的重写机会）
   或属惯用法差异（T4）。
3. 附带：P1 报告显示 202,342 个 register 仅靠 system_task 根存活、
   168,802 个靠 dpic_call 根存活——验证/断言逻辑体量巨大，是 T4/T5
   的素材。

**两级预期分工**：L1 收编全部 72.9 万死指令（logic −48.7 万，占 logic
差 36%）；L2 在最终指令流上兜底 lowering 产物并做 op 级 CSE，目标
消化剩余 logic 差中可在指令流层面看到的重复部分（量级未知，实测决定）。

## 2. L1 实施（GRH 层）

改动极小，只做流水线配置：

- **改动点**：`scripts/wolvrix_xs_grhsim.py` 的 `reg_to_mem_pipeline`
  （696-700 行）在 `reg-to-mem` 之后、`stats` 之前插入
  `("simplify", {"semantics": "2state"})`。用 simplify 而非裸
  dead-code-elim：DCE 是主菜，fold+CSE 的 5.7 万尾量白拿，全香山仅
  ~57 s（P2 实测）。
- **开关**：环境变量 `WOLVRIX_XS_GRHSIM_POST_REG2MEM_SIMPLIFY`
  （默认 true；置 0 恢复旧行为，供对照实验）。
- 不新增/修改任何 wolvrix C++。

验证链（每格实验共用，下称"标准验证链"）：

1. 重跑 `make` XS GrhSIM 流，产出新 post-stats JSON（核对
   operation_count ≈ 437 万）；
2. `grhsim-am-lower-json` 重导 topo-proj JSONL 到新数据集目录
   `exp/dataset/xs_full_<date>_l1/`（沿用现有环境变量导出方式）；
3. `exp/tools/op_shape_compare.py` 对比 gsim 打平图：logic 差应
   ≤90 万；
4. 死锥复测（doc 19 §4 的 BFS 方法）：死指令占比 <1%；
5. 规范化 DP cost 复算（doc 16 方法，`run_fullgraph_plaindp.py`），
   记录 incoming_copy_cost 变化；
6. 功能门：AM emu 构建 + CoreMark 50k difftest（instrCnt/cycleCnt 与
   基线逐拍一致），并记录 host time（doc 11 口径）。

**验收**：指令数 ≤ 3.95M（−15%）；死锥 <1%；logic 差 ≤ 90 万；difftest
通过。

## 3. L2 实施（AM 层）

### 3.1 组件与挂点

- 新文件：`wolvrix/include/grhsim/am/optimize.hpp`、
  `wolvrix/lib/grhsim/am/optimize.cpp`（登记进
  `wolvrix/CMakeLists.txt` 的 lib 源列表，113-121 行处）。
- API：`AmOptimizeOptions{bool dce=true, constFold=true, cse=true}` +
  `bool optimizeLinearProgram(LinearProgramArtifact&, const
  AmOptimizeOptions&, diag::Diagnostics&)`。
- 挂点（实验路径）：`tests/grhsim/am/lower_json_smoke.cpp` 在
  `lowering.lower()` 与 `scheduler.schedule()` 之间，新 CLI
  `--am-optimize=dce,fold,cse`（默认全开；`--no-am-optimize` 关闭）。
  实验与生产共用此二进制，一处改动同时覆盖 topo-proj 导出与 AM emu。
- 生产路径（`pipeline.cpp` 的 `GrhSimAmPipeline::run`）留到 T2 验证
  通过后跟进，不在本期范围。

### 3.2 算法

- **DCE**：根集合 = `instructionEffects ∈ {StateWrite, StateReadWrite,
  HostRead, HostEffect}` ∪ `orderedEffects` 涉及指令 ∪ 产出
  `ExternalOutput / Observable` 角色的指令；def-use 反图标记活指令，
  其余删除。StateRead（MemoryRead）结果无引用时可删，但若出现在
  `orderedEffects` 中则保留（读写序语义）。
- **const-fold**：操作数全为 literal 的纯 op 求值进 literal 池并替换；
  与 DCE 迭代至不动点（预期收益小——GRH 层已饱和，作为兜底）。
- **CSE**：纯 op hash-cons，key = (opcode, result type, 规范化操作数
  [可交换 op 排序：And/Or/Xor/Xnor/Eq/Ne/LogicAnd/LogicOr], 立即数与
  slice/system 属性）；重复指令的结果变量别名为首次出现的变量，再
  DCE。Memory/DPI/System/Changed 类一律不参与（读序与副作用语义）。
- **facts 维护（关键约束）**：`schedulingFacts` 按稠密 id 索引
  （`pipeline.hpp:77-86`），因此**采用 compaction 重写而非 NOP 标记**
  ——NOP 会把死指令留在分块容量预算里。compaction 时：
  `instructionEffects` 由 `opcodeTraits(opcode).effect` 机械重算
  （`lowering.cpp:650-671` 同款逻辑）；`variableRoles`、
  `orderedEffects`、`interface.ports/declaredVariables`、
  slice/system/dpi 属性记录全部随 id 重映射。
- 完成后跑 `validate(artifact)`（`pipeline.hpp:113`）自检。

### 3.3 测试

新 `wolvrix/tests/grhsim/am/test_optimize.cpp`（CMake 注册，风格参照
`test_lowering.cpp`）：手工构造小程序覆盖——死锥删除、可交换 CSE、
fold 级联、interface/facts/orderedEffects 重映射正确、根集合不误删
（ordered MemoryRead 保留）、`validate()` 通过。先过单测再上全香山。

### 3.4 全量验证

走标准验证链（§2），但用 `--no-am-optimize` / L1 开关分离两级贡献；
L2 单独一格时数据集目录 `exp/dataset/xs_full_<date>_l2/`，L1+L2 为
`xs_full_<date>_l1l2/`。**L2 的判据不设死目标**：它要消化的是 L1 之后
剩余的重复/产物型 logic，量级事先未知；以"logic 差再收窄幅度 +
DP cost 变化"说话。

## 4. 实验矩阵与验收

| 格 | 配置 | 指令数 | logic 差 | 死锥 | 规范 DP cost | 功能门 |
|---|---|---|---|---|---|---|
| E0 | 基线（现有数据） | 4,669,495 | +1,366,236 | 729,077 | 5,921,453 | 已过 |
| E1 | L1 | 3,946,245（−15.5%） | +876,840（−35.8%） | 11,627（0.29%） | 5,479,716（−7.5%） | **过** |
| E2 | L2（无 L1） | 3,930,359（−15.8%） | +871,433（−36.2%） | 11,627（0.30%） | 5,480,584（−7.4%） | **过** |
| E3 | L1+L2 | 3,929,884（−15.9%） | +871,433（−36.2%） | 11,627（0.30%） | 5,480,531（−7.4%） | **过** |

最终验收（第一步收口子集）：E3 的 logic 差、规范化 DP cost 较 E0 的
下降幅度，连同 doc 19 的分解表，构成图结构优势归因的定量闭环。

### 4.1 实测记录（2026-07-31）

- **L1 验收全部达成**：指令数 −15.5%（验收 ≤3.95M）；logic 差 +876,840
  （验收 ≤+0.90M）；死锥 0.29%（验收 <1%）；50k difftest 通过，
  instrCnt=73,580 与 E0 基线（doc 10 §K9）一致。GRH operation_count
  5,158,238 → 4,384,949，与 P2 探针预测 4,373,328 差 0.3%（探针在
  stats 输出上跑 simplify，流水里 simplify 在 stats 之前，口径略异）。
- **L2 在脏图上的 DCE 有效**：E2 收编 717,423 / 729,077（98.4%）死指令
  （fold=6、cse=21,712）；在 L1 干净图上只剩 cse=16,359（0.4%）、
  fold=2、dce=0（E3）。
- **两级终态收敛**：E2 3,930,359 vs E3 3,929,884 指令，logic 差同为
  +871,433——L1 与 L2 对指令数/logic 差的贡献高度重叠。L1 的价值在
  GRH 层先行清理（下游所有消费方受益、成本 0.5 天）；L2 的独有价值是
  兜底 lowering 产物，并验证 AM 层 DCE 的可行性（为生产
  `pipeline.cpp` 接入铺路）。
- **剩余 logic 差 871,433 非优化可消化**：两层 DCE/CSE 均已饱和，印证
  §1 结论——余量归 T4 惯用法差异（doc 19 §5 分解表中的"余量"项）。
  E1 残留死锥 11,627 的构成：eq 6,931、assign 3,067、and 1,625 等
  （assign 3,067 在 E0 同数存在，是本根集合口径下的固有"假死"，
  非 T2 产物）。
- **规范 DP cost**：E0 5,921,453 → E1 5,479,716（−7.5%）→ E3
  5,480,531（L2 增量 ≈0）；生产 incoming_copy_cost 同趋势
  6,468,546 → 5,949,859 → 5,938,405。图清理的收益主要体现为指令数
  与 logic 差收窄，DP cost 大头（跨块传值）由真实活跃逻辑决定。
- **E2 输入图再生噪声**：复跑（开关=0 断点续跑）得 graph_operations
  5,158,247，较 E0 存档 5,158,238 多 9（2ppm）；AM 指令差 5
  （4,669,500 vs 4,669,495）。不影响归因，如实记录。
- **数据集与工具**：`exp/dataset/xs_full_20260731_l1/`、`_l2/`、
  `_l1l2/`（instruction_graph + block_assignment + plaindp 复算）；
  死锥复测脚本固化 `exp/tools/dead_cone_check.py`（E0 复现
  729,077 / 486,528，与 doc 19 §4 分毫不差）。
- **host time（CoreMark 50k 差分，独占串行复测）**：E0 575.5 s（doc 10
  §K9）→ E1 520.1 s（−9.6%）、E2 515.8 s（−10.4%）、E3 515.4 s
  （−10.4%）。三格 instrCnt/cycleCnt 均为 73,580 / 49,996，与 E0 基线
  逐拍一致；NEMU 逐拍比对全部通过。指令数 −16% 换来运行时约 −10%。
- **代码落地**：`scripts/wolvrix_xs_grhsim.py`（L1，开关
  `WOLVRIX_XS_GRHSIM_POST_REG2MEM_SIMPLIFY` 默认开）；wolvrix
  `grhsim/am/optimize.{hpp,cpp}` + `grhsim-am-lower-json` 挂点
  （`--am-optimize=dce,fold,cse` 默认全开 / `--no-am-optimize`）+
  `tests/grhsim/am/test_optimize.cpp`（6 用例）；wolvrix 侧设计记录
  `docs/grhsim/grhsim-am-pipeline.md` §3.2.5。生产路径
  （`pipeline.cpp`）接入按 §3.1 留待后续。

## 5. 工作量与风险

- L1：~0.5 天（改脚本 + 全量验证链）；**先行**，立即收编 36% logic 差。
- L2：~2-3 天（新组件 + 单测 + 全量验证）。
- 风险：
  - DCE 根集合过宽误删 → `validate()` + difftest 双兜底；Observable
    变量先全保留（偏保守），后续再评估放开。
  - CSE 改变指令共享结构可能影响 activation/调度形态 → 只动 Pure
    op，且以 DP cost 与 difftest 终判。
  - reg-to-mem 后再 fold 理论上可能触碰 memory-init 结构 → L1 的
    simplify 若触发功能门失败，退化为只挂 `dead-code-elim`。

## 6. 对后续任务的接口

- T3（模块级归因）在 E1 数据集上重做，剔除死代码干扰；
- T5（口径清算：state/mem/wire）不受影响——探针确认 reg/mem 端口数
  不被 simplify 改变（kRegister 211,642 / kMemoryReadPort 49,321 不变）；
- 第二步（划分算法能力）的输入基线 = E3 的 AM 图：在其上重跑 doc 16
  同一规范化 DP，剩余 cost 差即"划分算法 + 不可消图性质"的净差距。
