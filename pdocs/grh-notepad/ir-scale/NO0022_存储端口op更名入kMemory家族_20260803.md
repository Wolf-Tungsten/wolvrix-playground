# NO0022 存储端口 op 更名入 kMemory 家族

日期：2026-08-03
前置：[NO0017](NO0017_数组value与when区域语义总体设计_20260801.md)（op 定义）、[NO0021](NO0021_默认开启与全面测试_20260802.md)

## 1. 动机

NO0017 D4 引入的 12 个新 op 实为两类，命名应区分：

- **存储读写端口（2 个）**：经 `memSymbol` attr 读写 `kMemory`——`kArrayReadAllPort`（全行 packed 读）、`kArrayWritePort`（lane 向量选择写）。存储对象是 `kMemory`，"数组"只是传输数据的形状，不是存储的种类。
- **纯组合（10 个）**：只在 packed 数组视图值上变换，不碰存储——`kArrayMux`、`kArrayReduceOr/And/Xor`、`kArrayReduceLanesOr/And/Xor`、`kArrayBroadcast`、`kArrayLaneConst`、`kArrayOnehot`，`kArray*` 命名保持。

既有命名惯例（`wolvrix/include/core/grh.hpp`）严格按"存储对象 + Port"命名：`kLatch→kLatchReadPort/kLatchWritePort`、`kRegister→kRegisterReadPort/kRegisterWritePort`、`kMemory→kMemoryReadPort/kMemoryWritePort/kMemoryFillPort`。枚举中不存在 `kArray` 存储 op，旧名 `kArrayReadAllPort` 暗示一个不存在的 "Array" 存储对象，故更正。

## 2. 改名映射

| 旧名 | 新名 | 说明 |
|---|---|---|
| `kArrayReadAllPort` | `kMemoryReadAllPort` | 与 `kMemoryReadPort`（单行动态地址）的区分点是"全行" |
| `kArrayWritePort` | `kMemoryWriteLanesPort` | 特征 = 一次寻址全部行 + lane 向量（每行 1 bit）选择；不用 "Masked" 以免与 `kMemoryWritePort` 既有逐位 mask 概念混淆 |

- toString/parse 字符串同步更名（store/load 以此为持久化名）。
- 语义零变化：纯改名，操作数序、attr、lower 行为均不变。

## 4. 两个"不改"决策

- **AM opcode 保持 `Opcode::ArrayReadAll`/`Opcode::ArrayWrite`**：AM 是 grhsim 抽象机层的独立指令集，非 GRH IR；更名收益不抵改动面（interpreter/cpp_emitter/validate/pipeline/schedule + 4 个测试）。对应关系由 `docs/grhsim/grhsim-am-instructions.md` 映射表记录。**（已于当日撤销，见文末增量更新）**
- **`compare_ir_shapes.py` 的 `array_state` 桶保持不动**：两个更名 op 仍归 `array_state`（而非移入 `stateful_port`）。桶是"数组模式引入、不计 compute"的统计分组，调整只增加报告 churn，对 compute 口径无任何影响。

## 5. 兼容性

旧 build 产物（JSON）中的 `"kArrayReadAllPort"`/`"kArrayWritePort"` 字符串将无法被新 parse 识别，重跑流水重新生成即可，不做向后兼容。

## 增量更新 2026-08-03（二）：AM opcode 同步更名，§4 第一条撤销

复核后确认 §4 "AM opcode 不改"的理由不成立：AM 自身惯例就是按状态访问对象命名（`MemoryRead`/`MemoryWrite`/`MemoryFill`，字符串 `mem.read`/`mem.write`/`mem.fill`、`reg.write`、`latch.write`），而这两个 opcode 的 stateTarget 正是 memory Variable——与 GRH 层相同的"暗示不存在的 Array 存储"问题在 AM 层同样存在。已同步更名：

| 旧 | 新（枚举 / 字符串） |
|---|---|
| `Opcode::ArrayReadAll` | `Opcode::MemoryReadAll` / `"mem.read_all"` |
| `Opcode::ArrayWrite` | `Opcode::MemoryWriteLanes` / `"mem.write_lanes"` |

- 触点（15 个文件）：`program.hpp`（枚举原位）/`program.cpp`（字符串表）/`opcode_traits.hpp`、`lowering.cpp`（函数同步改名 `lowerMemoryReadAll`/`lowerMemoryWriteLanes`）、`validate.cpp`/`pipeline.cpp`/`production_activity_schedule.cpp`/`interpreter.cpp`/`cpp_emitter.cpp`、4 个 AM 测试（测试函数名同步）、`tests/transform/test_array_lower.cpp` 助手名、`docs/grhsim/grhsim-am-instructions.md`（12.4 节及映射表述）。
- 保留不改：cpp_emitter 生成代码内部 helper 名 `array_readall_pack`/`array_write_scatter*`（codegen 实现细节，非 op 名）；其余 9 个纯组合 `array.*` opcode。
- 验证：`build/wolvrix-l2` 构建全过；ctest 63/66 = 既有 3 失败基线，无新增；wolvrix 全树 grep `ArrayReadAll`/`ArrayWrite`/`array.read_all`/`array.write` 零残留（仅余预期保留的小写 helper 名）。AM opcode 名仅出现于即时 dump，无持久化兼容问题。
