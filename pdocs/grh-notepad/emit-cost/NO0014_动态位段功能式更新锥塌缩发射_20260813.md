# NO0014 动态位段功能式更新锥的塌缩发射

- 日期：2026-08-13
- 状态：已收口（dynblend 锥塌缩落地，四门齐过）
- 前序：NO0013（F1 链式窗口化收口，遗留形态 3 掩码锥 ≈66G）
- 用户裁决（2026-08-13）：先做 gsim 侧同 node 形态调研再定方案；
  调研推翻了"helper 内联化"为 F3 主刀的前提（内联只省跨 TU 调用
  开销，锥结构仍在），正解为锥塌缩——本项实施之。

## 1. 调研实证（gsim 形态 vs AM 形态，同 node）

gsim（`build/logs/no0009/gsim_run/SimTop251.cpp:25543-25552`，
node 2506554 = intRat `difftest_table` 多写口更新；vecRat 2514452 /
vlRat 2510256 同构）：

```cpp
next[0]=table_0; ... next[31]=table_31;   // 逐元素基座拷贝
if (wen_0) next[addr_0] = pdest_0;        // 逐端口条件动态标量存
if (wen_1) next[addr_1] = pdest_1;
```

AM（f1e emit b66190，同族 node，520–1040 锥/块，376 位全宽）：

```
elem  = slice_dynamic(base, idx)
onehot= shl(ones, idx);  elemm = zext(elem) & ones;  placed = shl(elemm, idx)
merged= (base & ~onehot) | placed
result= mux(cond, merged, base)          // 结果再作下一锥的 base（链式）
```

每锥 4–8 次跨 TU helper 调用（376b≈6 字，per-call ~70–150 cycles）。
语义 = `if (cond) result[idx+w-1:idx] = elem`（ones = 2^w−1 的位段
功能式更新），与 gsim 的 `if (wen) next[addr] = data` 一一对应。

## 2. 目标形态（与 gsim 同成本类）

```
copy_words(D, base, W);                        // 链头一次
if (cond_k) blend_window_dyn_words(D, W, idx_k, ones, elem_k, w);  // 逐锥
```

`blend_window_dyn_words(t, W, idx, ones, elem, w)` 语义
`t = (t & ~(ones<<idx)) | ((elem & ones)<<idx)`；内置快路径：
`ones == bit_mask(w) && (idx % w) == 0 && w == 8` → 单字节存
（≈gsim 平价），否则动态移位 RMW（6 字 ≈25-35 cycles，仍 ~5-10x
优于现状）。emitter 侧模式识别 + 塌缩发射，program/图不动，
atom 边集不变（QC-E 门延续 NO0013 脚本与基线）。

## 3. 锥识别与安全保障

- 锥签名（opcode 拓扑）：`shl(ones, idx)` 与 `shl(and(zext(elem), ones), idx)`
  共享同一动态 idx；`not(onehot)`；`and(base, not)`；`or(and, placed)`；
  可选 `mux(cond, merged, base)`。链：锥结果作下一锥 base。
- 中间值消费者闭包：锥内中间值（onehot/not/and/or/elemm/placed）仅锥内
  消费方可跳过；锥结果的非链消费者（如 slice_dynamic 读 elem、跨块
  引用）须满足"发射位置在下一锥更新之前"（F1 同套位置判定），
  否则该锥结果物化（assign 拷贝回退）。
- mux-run 覆盖即 bail；接口可见变量物化。
- escape hatch：`WOLVRIX_GRHSIM_AM_DISABLE_DYNBLEND`；
  stats 入 JSON（dynblend_cones/chains/materialized/bailed）。

## 6. 实施实录（2026-08-13）

**已落地**（emitter 侧，program/图不动）：

- `planDynBlendCones`（接在 planWindowedChains 之后）：锥签名匹配
  （`or(and(base,not(shl(ones,idx))), shl(and(zext(elem),ones),idx))`，
  双操作数序兼容；ones/idx 变量一致性；elemWidth ≤64；BitVector kind
  守卫）；mux 尾识别（sole merged 消费者且两臂匹配 → 条件锥）；
  锥内闭包校验；链式链接（base==前锥 result，分支即整链 bail）；
  消费者校验（下一锥 cleared+tail 由累加器实现语义放行；同块 slice
  位置安全重指 D；非 slice/跨块/接口可见/早读 → 物化；mux-run/窗口
  动作冲突 → 整链 bail；末锥同块早读 → bail）。
- 发射 hook（**挂在 emitInstruction 顶部**，非 emitNonScalarInstruction——
  见 bug 2）；条件锥发 `if (cond) blend_window_dyn_words(D, W, idx,
  idxW, ones, elem, elemW)`，链头先 `assign_words(D, base)`，物化回退
  追加 assign 拷贝。
- 新 helper `blend_window_dyn_words` + `shl_word`：通用动态移位 RMW；
  字节对齐快路径（ones==0xFF 全零高位、elemWidth==8、idx 8 对齐、
  范围内 → 单字节存，≈gsim 平价）。
- escape hatch `WOLVRIX_GRHSIM_AM_DISABLE_DYNBLEND`；stats 入 JSON
  （dynblend_chains/cones/skipped/remapped/materialized/bailed）。
- 实测计数（v2 emit）：chains=1,008、cones=2,819、skipped=19,733、
  remapped=1,811、materialized=（tail 放行修复后重计）、bailed=0。
- 形态实证（block 66190）：旧=1,560 bitwise+520 not+1,040 shift+
  1,561 assign；新=520 条件 blend + 521 assign + 1,040 slice_dynamic。
- QC-E：vs NO0013 基线 atom 边集 diff=0。

**实施期 bug（已修）**：

1. Array 类型误匹配：锥 anchor 只查 bitWidth>64，Array 类型的 Or 被
   误收 → 非 BitVector 路径报"requires bit-vector operands"（ctest
   grhsim-am-cpp-emitter 的 array 模型失败抓到）。修=anchor/base/ones
   三处加 TypeKind::BitVector 守卫。
2. zext 漏跳：锥内 zext 是 Opcode::Assign，走 emitInstruction 顶部的
   宽 Assign 专用路径，不经过 emitNonScalarInstruction 的 hook →
   未跳过（520 次/块白算）。修=dynblend/windowed 两个 hook 上移到
   emitInstruction 顶部（muxRun 检查之后、专用路径之前）。
3. 物化虚高（64%）：下一锥 mux 的 false 臂 base 是对前锥结果的消费者，
   初版只放行 cleared 导致前锥几乎全物化（每锥每 fire 多一次全宽
   拷贝）。修=消费者白名单加 tail（累加器"不 blend 即保持"语义天然
   覆盖 false 臂）。
