# NO0003 flatten 图单一对象对齐（gsim when 展开增强 + 导出/导入/指标同图）

日期：2026-08-10
状态：进行中

## 1. 目标

用户诊断与修正方案（原话要点）：

1. 增强 gsim 对于 compute node 的 flatten 能力，把**包括 when 的节点也展开**；
2. gsim 导出的、grhsim am 导入的，都得是**这张 flatten 的图**；
3. **指标对齐**的都得是这张 flatten 的图。

即：让"同一张图"从当前的"语义同一张、结构两个对象"变为真正的单一对象——
gsim 内部分区的图 == topoProj 指标图 == exec.json 导出图 == AM 导入图 ==
两侧全部指标的测量对象。

## 2. 现状实证（2026-08-10 源码核查）

gsim 管线（`reference/gsim/src/main.cpp:404-421`）：

```
commonExpr → removeDeadNodes
  → [opt-in --flatten-nodes] flattenNodes()     # 默认关，生产未开
  → graphPartition()                             # graphPartition.cpp:367
      ├─ exportTopoProjGraph(instruction_graph.jsonl)   # gsim 侧指标图（入口，coarsen 前）
      ├─ exportExecutableGrh(SimTop.exec.json)          # AM 消费的导出图（PreCoarsen 边界）
      └─ graphCoarsen(mergeWhen/mergeOut1/...) → DP → replication
```

三个结构性事实：

1. **flattenNodes 保留 when 骨架**（`reference/gsim/src/flattenNodes.cpp:172-177`）：
   OP_WHEN 被视为"条件赋值骨架（控制，非计算）"，永远留在 owner node 内，
   只抽出其下的 value/cond 子表达式。且该 pass 为 opt-in
   （`FlattenNodes=false` 默认，main.cpp:44），生产导出命令（Makefile:646）
   不带 `--flatten-nodes`——gsim 分区/指标用的是 **when 折叠的树形图**
   （2,708,079 nodes，平均 5.1 enodes/node）。
2. **导出器在导出边界递归炸开 when**（`ExecutableGrhExporter.cpp:2031
   lowerWhen` → `emitTypedOperation("kMux")`）：exec.json 是 when 完全展开
   的扁平图（5,108,493 vals = 2,698,858 锚点 + 2,409,635 `gsim.tmp.N`）。
   缺失 else 分支的 fallback 语义（exporter 实测口径，
   `lowerAssignedNode` 2311-2353 行）：
   - REG_DST：hold = 引用配对 reg.src（2318-2323 行）；
   - 其他节点：首棵 assignTree 的 fallback = 同宽零常量（2324-2335 行，
     FIRRTL invalid 在二态运行时取确定性零基），后续 tree 按源序链式覆盖
     （`current` 逐 tree 传递）。
3. **AM 导入的正是这张扁平图**——所以 NO0002 归因的 cross 残差
   1.83x ≈ 导出展平 ~1.5x（树形 vs 扁平，结构差）× mergeWhen ~1.24x，
   其中 1.5x 因子是"两侧测量对象不同一"的直接产物。

结论：当前 when 展开只发生在导出器内部（一次性、导出专用），gsim 自己的
分区与指标从未见过展开后的图。本立项把展开能力下沉为 gsim 图上的正式
pass，使分区、指标、导出、导入四方消费同一对象。

## 3. 实施方案

### 3.1 flattenNodes 增强：when 展开（控制→数据）

修改 `reference/gsim/src/flattenNodes.cpp`，在现有抽取机制前增加
when→mux 转换（沿用 `--flatten-nodes` 旗标，pass 目标本就声明为"每 node
至多 1 个 compute enode"，when 展开是该目标的补全）：

- `when(cond, then, else)`（else 存在）→ `mux(cond, then, else)`；
- `when(cond, then, ∅/invalid)` → `mux(cond, then, fallback)`，fallback
  严格按 exporter 语义：
  - owner 为 REG_DST → 引用配对 NODE_REG_SRC（hold 语义）；
  - 其他 flatten 目标（NODE_OTHERS/NODE_OUT，非数组）→ 首棵 tree 用同宽
    零常量，第 i 棵 tree 用第 i-1 棵的结果值（源序链式，与 exporter 的
    `current` 传递一致）；
- 转换后复用现有抽取循环：mux 与普通算子一样被抽成独立 node
  （1 node = 1 compute enode），post-check 增加"无 when 骨架残留"断言。

注意点：

- REG_DST 展开后新增 reg.src→mux 的边——这正是 exporter 早已在导出图中
  物化的 hold 引用，展开后 gsim 内部图与导出图结构一致（本立项的目的）。
- 数组节点维持跳过（`isFlattenTarget` 的 `isArray()` 排除），when 只对
  标量 flatten 目标展开。
- 展开后节点数预期 ~5.1M（对齐 exec.json 的 val 计数）；graphPartition
  （coarsen+DP）在该规模上的时空开销需实测记录。

### 3.2 两条流程同开 flatten

- **导出流程**（Makefile `run-xs-gsim-executable-grh` 目标，Makefile:646
  附近）：gsim 命令追加 `--flatten-nodes`；产物 exec.json 即 flatten 图
  （预期锚点值 ≈ 节点数、`gsim.tmp` 趋零——exporter 面对的已是单算子
  节点）。
- **指标流程**（topoProj 导出，`build/logs/no0002/gsim_topo/` 同款）：
  同一旗标下 instruction_graph.jsonl 与 block_assignment 均为 flatten 图
  上的分区结果。

### 3.3 AM 导入与指标同图复测

- AM 侧 `grhsim-am-lower-json` 消费新 exec.json（格式不变，锚点增多、
  tmp 消失），导入图与 gsim 内部图应为同一对象；
- 三层计数（L1 instr/enode、L2 atom/node、L3 block/supernode）+
  cross_values_compute_network 全部在 flatten 图上同口径复测
  （`scripts/supernode_align_metrics.py`、`scripts/no0002_align_report.py`）；
- mergeWhen 属于策略层（gsim 的 coarsen 在扁平图上无 when 可合并；AM 侧
  mergeWhen 是独立旋钮）——干净读数先两侧都不做 when 合并，策略评估另记。

### 3.4 正确性硬约束

flatten 图路线产物重跑 50k coremark difftest，73,580/49,996 逐位一致
（when→mux 展开必须保持 exporter 同款 fallback 语义，difftest 是裁决者）。

5. 对齐配置（fold 帽/max-atoms 等 NO0002 锁定值）在新图上的适配结论记录

### 2026-08-10 flattenNodes when 展开实现 + 首轮 XS 导出

实现（`reference/gsim/src/flattenNodes.cpp` 重写）：

- `expandWhenEnodes`：把每棵 assignTree 内的 OP_WHEN 全部原地翻成 OP_MUX；
  缺失/invalid/empty 分支填充 hold 值——REG_DST 首 tree 用配对
  NODE_REG_SRC 引用（holdRef），其他节点首 tree 用位宽对齐的零常量
  （holdZero），多 tree 节点先拆成单 tree 链（`$whold<i>` 节点），第 i 棵
  tree 的 hold = 前一链节点引用（与 exporter 的 `current` 源序链一致）；
  整树 invalid/empty 时退化为纯 hold 引用（holdOnlyTree）。
- 展开后复用原抽取循环（mux 作为普通 compute enode 抽成独立节点）；
  post-check 增加 when 骨架残留计数（目标 0）。
- 小规模冒烟（test/repro-usefulreset.fir 等）：8 when 全展开、holdRef 9、
  holdChain 2，post-check 全零，通过。

首轮 XS 导出（--flatten-nodes，stub profile）：flattenNodes 本身全量通过
——候选 2,540,405 节点、expandedWhen 225,457、holdRef 219,681 /
holdZero 64,672 / holdChain 15,230 / holdOnlyTree 66,048、新抽取节点
423,179、post-check 三项全零、pass 耗时 29.3s。但**导出器报
`zero-width integer literal has no positive-width scalar context`**
（tpDataTable wdata 节点下一个 width=0 的 OP_INT）。

根因：exprOpt 会造 width=0 的零字面量（`allocIntEnode(0,"0")`），旧图里它
们只出现在 when 的直接分支位置，靠 exporter lowerWhen 向分支透传 fallback
获得位宽；OP_MUX 不向下透传 fallback（lowerWhen(mux, nullopt)），when→mux
后这些字面量失去尺寸上下文。

修复：展开时对每个被转换 when 的直接 OP_INT(width=0) 子节点原位定宽
（cond→1，分支→when 位宽；sizedInt 统计）。零字面值与位宽无关，语义不变。

### 2026-08-10 gsim 自身下游验证：cpp emit 通过 + 编译暴露 replication 销声明 bug（已修）

用户要求验证 flatten 图在 gsim 流程中能否完整 emit cpp 并编译输出。

- **全管线 emit**：`--flatten-nodes` 下 graphPartition（115,000 超节点）→
  replication → generateStmtTree → instsGenerator → cppEmitter 全程 exit=0，
  产出 407 个 cpp（旧树形图同流程在 cppEmitter 段错误 exit=139 的问题也
  随之消失）。
- **模型编译**：407 个模型文件 -O3 编译 406 通过，唯一失败 SimTop1.cpp：
  `subReset2()`（异步复位函数）引用
  `cpu$l_soc$reset_sync_resetSync$_raw_reset_T`（pipe_reset[2] 切片节点）
  未声明。
- **根因**：`replicationOpt`（replication.cpp）的 `repOpCount` 遇 OP_WHEN
  直接返回 -1（不可复制）——树形图上含 when 的节点天然免于复制；flatten
  后所有节点都是无 when 的单算子节点，复位条件节点 `_raw_reset_T` 被复制
  到各消费超节点（$DUP_1...）且原节点状态置 REPLICATION_NODE 被删除。
  但复位条件的消费走 dep 边而非 next 边，`genResetDef` 直接打印
  `super->resetNode->name`——名字失去声明存储。这是 gsim 潜在 bug
  （任何无 when 的单算子复位条件节点落在单成员超节点都会触发），flatten
  只是让它必然暴露。
- **修复**：`replicationOpt` 的保留条件增加 `member->isReset()`
  （mergeResetAll 已在 graphCoarsen 中给复位条件节点打 asReset 标记，
  时序上先于 replicationOpt）。修复方向只减不增复制范围，对树形图安全。
- **AM 侧新发现（待查）**：同一份 flatten exec.json 的 AM 模型 emu
  编译通过但 50k coremark **零提交挂死**（周期前进、无一条指令退休）。
  下一步用 gsim 自身 emu 运行结果做二分定位：gsim 引擎跑通则展开语义
  无罪、问题在 AM 导入/优化（头号嫌疑 optimize 的 1.68M DCE 在扁平导入
  上误删活逻辑）；gsim 引擎也挂则展开语义本身有错，回查 flattenNodes。

### 2026-08-10 AM 挂死根因：flattenNodes 把 ref enode 误判为空分支（EmptyRef bug，已修）

排查链：no-opt AM 模型仍挂死（optimize 无罪）→ 死值对照扫描：flatten 导出
死锚点 162,852 vs 树形导出 1,604（+161k 断边嫌疑）→ 逐节点追踪
`fpRegFile$wData_136`：树形导出中它经 kMux 写入 `mem$NEXT_136`（regfile
条件写），flatten 导出中 `mem$NEXT_136` 变成 `kAssign(mem_136)`——**mux
消失、写数路径丢失，寄存器只能自保持** → 全设计 comatose。

最小复现（`/tmp/no0003_hold.fir`，10 行 when-hold 寄存器）导出
`assign(src)` 而非 `mux(we,d,src)`。

根因：**ref enode（`ENode(Node*)` 构造）的 opType 默认就是 OP_EMPTY**。
`expandWhenEnodes` 用 `opType == OP_EMPTY` 判"分支缺失"，把 when 的
ref(d) 数据分支也当成缺失分支，替换成 holdRef(src)——`when(we, d, ∅)`
变成 `mux(we, src, src)`，exporter 分支相同折叠成 `assign(src)`。
同理，bare-ref 根的别名树（`q <= r`，极常见）被 holdOnlyTree 路径整体
换成零常量/src 引用。两处都漏了先判 `getNode()`。

影响面（首版 flatten 导出）：225,457 个 when 全部丢失数据分支
（holdRef 219,681 ≈ 每 when 一处误填）、66,048 棵别名树被改值——
等价于全设计寄存器只读不写，AM 的 1.68M DCE 级联（真实数据网络变成
无消费者）也由此而来。

修复（flattenNodes.cpp）：分支缺失判定与根退化判定都先排除
`getNode() != nullptr`（ref 是真实值）。修复后最小用例导出正确的
`mux(we, d, src)`，holdRef 统计从 2 降到 1（只填真正缺失的 else）。

启示：gsim 的 ENode 不变量——"ref enode 的 opType 恒为 OP_EMPTY"——
任何按 opType 分派的遍历都必须先判 nodePtr。countComputeEnodes 与
isFlattenLeaf 原本就是对的（先判 getNode），新写的 expandWhenEnodes
漏了这一条。

### 2026-08-10 勘误：L1 口径纠正（instr vs enode）+ 数量差三段分解

前节 L1 行把 AM 的 **instr** 比成 gsim 的 **node**，口径错误（用户指正）。
flatten 图上正确口径：gsim 每节点恰 1 个根 enode，L1 应比 **enode**。
node 计数恰等于 enode 计数只是数值巧合，概念上必须分清。cross 的
mergeWhen 归因也下得太快——先把单位账算清，再谈切割质量。

**三段流水账（v2 图，全部实测）**：

| 阶段 | 总量 | 关键族计数 |
|---|---:|---|
| gsim 内部扁平图 | 3,146,488 节点 = 同数 enode；非叶 3,076,833（REF 69,173 / CONST_INT 311 / INPUT 8 / NONE 163 为叶）；状态/效应类 160,716 | MUX 836,808（+残留 WHEN 3,134）、AND 379,268、OR+ORR 473,071、EQ 242,955、ADD 114,504、**MUL 211**、BITS 族 295,559、CAT 286,284 |
| exec.json 导出 | **4,900,121 expr ops**（+5.03M 值：锚点 3,137,267 + tmp 1,974,182） | kMux 1,337,941（**命名者 846,016 ≈ 内部 MUX+WHEN 精确对上**；另有 ~492k 无名 tmp mux 来自数组成员节点的树 lowering）、kSliceStatic 912,996（内部 3.2x）、kConcat 406,246（1.42x）、kAssign 393,785（内部 REF 69k 的 5.7x）、**kMul 67,791 vs 内部 OP_MUL 仅 211——不是乘法变多，是动态数组索引被物化成行主序 mul/add/lt 算术链**（`lowerIndexPath`，Exporter 1620-1676 行；内部 OP_INDEX/OP_INDEX_INT 选择子是不透明 enode 子节点、不计 compute；最宽内部 mul 仅 67b，与宽值展开无关）、kEq 242,955（**1.00x 精确**——无索引无适配的操作严丝合缝） |
| AM linear（optimize 后） | **4,037,003 instr**（簿记 act/changed 955,741 不在其中） | mux 1,302,671、slice_static 572,498、concat 345,701、assign 189,068（胶类合计 **1,132,397 = 28%**）、and 437,007、eq 200,143、mul 11,010、状态类 162,656（≈gsim 160,716 ✓） |

**数量差归因（AM linear 4.04M vs gsim enode 3.08M = 1.31x）**：

1. **导出显式化膨胀（主因，+55~68%）**：gsim 内部图把三类语义保持在
   enode 隐式结构中，显式 IR 必须逐一物化：
   (a) **动态数组索引算术**——内部 `OP_INDEX` 选择子是不透明 enode，
       导出降成行主序 `acc*dim+idx` 的 mul/add 链 + `kLt` 越界检查
       （kMul 211→67,791、kLt 2.4x、kAdd/kAnd 各 1.4x 的主源）；
   (b) **位宽/符号适配胶**——ref 免费 → kAssign 物化（69k→394k），
       定形切片/拼接（kSliceStatic 289k→913k、kConcat 286k→406k）；
   (c) **数组成员节点的树 lowering**——数组/聚合成员（非 flatten 目标，
       名字含 `$$`）内部保留整棵表达式树，导出炸成无名 tmp op
       （~492k 无名 kMux 等）。
2. **AM optimize 回收（-24%）**：5.30M→4.04M（cse 761k / fold 366k /
   slicefuse 118k / alias 60k）；回收的是重复胶，宽字展开是真实独立算子
   收不回。
3. **净残余**：AM 持有胶类 instr 1.13M（28%）；剔除胶类后的纯计算族
   AM 2.74M vs gsim 2.29M ≈ **1.20x**（mux 族 1.30M vs 0.84M 是最大
   单项，主要来自导出侧的 tmp mux lowering）。

**结论与方向**：instr/enode 差距主因不是 AM 图形态不良，而是 **exec.json
交换格式的显式化代价**。要对齐 L1，正确方向是让导出保留宽值与隐式适配
语义（GRH 格式本身支持宽 op），而非在 AM 侧硬消。这也给 cross 指标的
解读立了前提：AM 图的值基数天然多 ~1.3x（胶值也参与跨块计数），
cross 比较需在剔除胶值或同值基数口径下重估——前节 1.74x/1.33x 的
绝对水平应在此前提下重新解读，mergeWhen 的相对影响（开 328k vs 关
251k，+31%）仍成立但需重测确认。
