# NO0006 node↔atom 构造性对齐（gsim node 结构导出 → AM atom 直建）

日期：2026-08-11
状态：**规划待审**（用户审阅后实施）
前置：[NO0002](NO0002_三层结构量化对齐_20260810.md)（调参式三层对齐）、[NO0003](NO0003_flatten图单一对象对齐_20260810.md)（flatten 图单一对象）、[NO0005](NO0005_enode逐类全量映射矩阵_20260811.md)（enode→instr 全量矩阵）

> 编号说明：NO0005 §6 的 mask 写发现曾建议占用 NO0006 编号；经用户决定，
> 本专题 NO0006 用于本战略转向，mask 写立项顺延至后续编号。

## 1. 背景：为什么需要战略转向

既有对齐路线（NO0002）是**调参式**的：AM 侧从 exec-GRH op 重新 atom 化
（启发式建树），再用 fold 帽/max-atoms 等参数把 L2（atom↔node）逼近到 0.95x。
NO0005 的全量矩阵证明：gsim enode → AM instr 的 lowering 含大量表示法脚手架
（计算段 1.270x），这些差异**在指令层不可能消除到 1:1**——但它们都发生在
"一个 gsim 节点的译码内部"。

用户提出的战略转向：**gsim compute node 与 grhsim am atom 语义对齐，拓扑可
1:1 迁移，把差异化映射留在 atom 内部**。对齐不再靠参数逼近，而靠**构造**：
让 gsim 导出 node 结构，AM 按 node 直接建 atom。

## 2. 两个前提假设的核实（2026-08-11，代码级）

### 假设 A：node ↔ atom 语义对齐、拓扑 1:1 可迁移 —— **成立**

- gsim compute node = 单输出值生产者（exporter `nodeValues_` 每节点恰一个值）；
  AM atom = 单输出指令树（`AmAtomKind::Singleton/Tree`，
  `grhsim_am_program.hpp:67`；NO0008 已定"atom 是单输出 when 树"）；
- 边对应：gsim 节点边 = REF enode 引用关系；AM atom 边 = atom 结果变量的
  def-use 引用——flatten 图上是同一张值依赖图；
- 破例点（§5 清单处理）：ext/dpi 多输出、数组巨 atom、commit 侧无 node 对应物。

### 假设 B：分区中 atom/node 是原子，不拆、不合，只成组 —— **成立**

- gsim `mergeWhenNodes`（`mergeNodes.cpp:78`）：仅移动 super 成员归属
  （`whenSuper->member.push_back(member)`），node 对象与 assignTree 永不变；
- AM mergeWhen（`grhsim_am_compute_graph_partition.cpp:520`）：注释明示
  "Membership moves only (DSU)"——只改簇归属与块内排序键；
  `grhsim_am_program.hpp`：atom 是"Block 内指令的**不可再分**结构"；
  分区大小单位 = atom（NO0007 P3 注释 "the atom IS the size"）。

推论：只要 atom 边界 = node 边界，两图的**顶点集、边集、分区可行解空间
三者完全相同**，L3（block↔supernode）与 cross 边对比才第一次成为纯净实验。

## 3. 目标

1. **L2 由构造对齐**：AM atom 数 == gsim node 数（白名单外零残差）；
   atom ↔ node 双射可逐个点名（atom 携带 gsim.node_id）。
2. **边对账**：atom 图边集 == node 图边集（compute 内；commit/事件边为
   AM 附加层，单独列账不参与对齐）。
3. **差异内化**：enode→instr 的脚手架差异（NO0005 矩阵）全部关在 atom 内部，
   只影响 atom 的 instr 计数/emit 成本，不影响图结构。
4. **在彻底 flatten 的图上做**（NO0003 v2 口径：标量 when 已展开为 mux）；
   数组节点骨架不可 flatten，整体成为一个大 atom（见 §5.2）。
5. 后续 all 对齐实验（分区形态、cross 边、运行时）在这张构造对齐图上重做。

## 4. 方案

### 4.1 导出侧：给每条 exec-GRH op 戳 node 归属

现状：anchor 机制只给每节点**最后一条** op 挂 `gsim.node_id`
（3,299,777 / 5,423,223 = 61%），glue op 无归属。
改动：exporter 在 op 发射时统一戳 `gsim.node_id`（owner Node* 在每个发射点
都在作用域内；NO0005 仪器的 enode 上下文栈已证明可行性，node 级戳更简单）。
无 node 的 op（状态声明、读写端口、effect、ext 声明）不戳，导入侧按现状分流。

### 4.2 导入侧：按 node_id 直建 atom

- AM 导入（lower-json）按 `gsim.node_id` 分组：同组 op → 一个 atom
  （组内指令树以 anchor op 为根/结果值；既有 atom 化启发式在该路径下线或
  退化为校验）；
- 每 atom 记录 node_id、节点类型（REG_DST/OTHERS/…）、指令数；
- commit 侧不变：reg.write/mem.write/changed/system.task 走既有事件聚类。

### 4.3 分区侧：大小核算改用 atom 计数

- gsim supernode 大小按 **node 数**核算（max-size=15 是 node 计数）；
  AM block 大小必须同样按 **atom 数**核算（而非 instr 数），否则巨 atom
  会把容量口径打歪；
- mergeWhen/coarsen/DP 等策略不变（输入图已对齐，策略行为自然可比）。

### 4.4 验证口径

- L2：atom 数 vs node 数（目标 1.000x ±白名单）；
- 边：atom 图边数 vs node 图边数、逐边抽样对点；
- L3/cross：同分区参数（max-size 对齐 gsim supernode-max-size）复测
  cross_values_compute_network，与 gsim 同图对比；
- 正确性：difftest 逐位一致（硬约束）；coremark 50k 性能记录。

## 5. 边界情况清单

### 5.1 ext/dpi 多输出（111 EXT + 14 EXT_OUT 节点）

kDpicCall 多结果 + 输出分发 assign。atom 单输出假设不覆盖。
方案候选：① atom 允许多结果特例（kind 标记）；② call 本体入 atom、
每个输出成员各立单输出 atom（分发 assign 为根）。实施时择一，白名单核销。

### 5.2 数组节点 → 巨 atom

2,280 个 when 骨架 REG_DST + 108 个 OTHERS + mem 端口：一个节点 →
一个 ~380 instr 的 atom。1:1 保持，但 atom 粒度极不均。
**分区大小按 atom 计数（§4.3）后与 gsim 同约束**；巨 atom 的运行时成本
是 emit 问题（NO0001 线），不在本专项范围。
注意：**不做数组 flatten**——逐元素节点化会把 node 数吹到 ~576 万
（flattenNodes 日志 leaves 口径），破坏 node↔atom 对齐基础。

### 5.3 commit 侧不参战

reg.write/mem.write/changed/system.task 是 AM 的时钟域附加层（gsim 折叠在
节点语义里），不进入 compute 图对齐口径；其成本单列（用户已接受此差异）。

### 5.4 寄存器读/常量

kRegisterReadPort → 变量引用（非 instr）；常量 → 全局常量变量。均不产生
atom，node 侧 REG_SRC 是寄存器语义的另一半（不产生 compute 节点内容）。
REG_DST 节点 → atom（次态计算）+ commit reg.write（附加）。CONST_INT/NONE
根节点 → 单 instr atom（1:1）。

### 5.5 复制（replication）策略

gsim 分区期复制节点（+145）降 cross 边；复制不改原子性（拷贝仍是原子）。
本专项先对齐**复制前**的图；复制策略对齐属后续分区策略专项。

## 7. 步骤分解

- **P1 导出侧**：op 级 node_id 戳 + 导出校验（每 op 必有归属或属白名单）；
  产出带归属的 exec.json（格式微扩展，向后兼容）。
- **P2 导入侧**：node 分组直建 atom + 既有 atom 化路径下线/转校验；
  atom↔node 双射 dump（对齐审计 artifact）。
- **P3 分区与指标**：大小核算改 atom 计数；三层指标 + cross 边复测；
  difftest 50k + coremark 50k。
- **P4 收口**：更新 grhsim-am-pipeline 等文档的口径表述；本专项结论回填
  NO0002（调参对齐路线标记为被构造对齐取代）。

## 8. 风险

- **巨 atom 分区可行性**：atom 不可拆，2,280 个 ~380 instr 的巨 atom 可能
  顶破 block 容量策略——但 gsim 侧节点同样不可拆且同大小核算，两边同约束，
  属"真实对齐"而非新问题；
- **op 归属边界**：跨节点 coerce/anchor 迁移（NO0005：add/sub 宽适配 assign
  760/1,638 条）的归属规则需定义清楚（归属触发节点），否则 atom 内部 instr
  数出现歧义——用 NO0005 的 enode 上下文归属规则（触发者归属）即可闭合；
- **既有 AM 优化 pass 的兼容**：atom 直建后 cse/fold 等 pass 跨 atom 工作
  的口径需重新确认（优化不得抹掉 atom 边界，否则破坏对齐审计）。

## 9. 勘误（2026-08-11）：§5.1 不成立——atom 不要求单输出

经用户质疑后代码级核实：**"atom 单输出"是 compute 侧折叠的构造约定，
不是 atom 结构的约束**。

- 结构层：`grhsim_am_program.hpp` 定义 atom 为"Block 内指令的不可再分结构/
  元数据分组，纯结构层，不承载语义"；validate 无单输出检查；
- 现状已有多输出 atom：`CombLoopScc` atom（组合环 SCC）；`dpi.call` 多结果
  指令即多输出 singleton effect atom；
- 约定来源：`grhsim_am_compute_graph_optimize.cpp:786`——"result feeds exactly
  one consumer folds into that consumer's atom, so every atom becomes a
  single-output expression tree (the gsim node = signal + assignTree analogue)"，
  fold 屏障豁免 commit/comb-loop/effects/pinned 结果。

**§5.1 更正**：EXT/dpi 多输出（111 EXT + 14 EXT_OUT 节点）不是问题——
EXT 节点 → **一个多输出 atom**（kDpicCall + 输出分发 assign），与 gsim EXT
节点的多成员输出天然对应；无需拆分候选方案，无需白名单。§6 验收表中
"白名单"相应缩减（仅保留 commit 侧附加层条目）。

## 10. 增量更新（2026-08-11）：§5.2–§5.5 审阅订正

依据用户审阅意见订正如下（原 §5 各节保留上下文，以本节为准）：

### §5.2 数组巨 atom —— 接受现状，根治靠 when 映射修复

巨 atom（2,280 个 when 骨架 REG_DST → ~380 instr/atom）**可以接受**；
根治方案 = 改进 when 的映射方式，即 NO0005 §6 记录的"向量寄存器 when 骨架 →
mask 写"翻译修复（后续专项）。该修复落地后，巨 atom 自然消解为少量 compute
instr + commit 侧 mask 写序列，无需在本专项内处理。
§4.3 容量核算改 atom 计数**保留**——既对齐 gsim supernode 的 node 计数口径，
也与 mask 写修复后的形态兼容。

### §5.3 commit 侧 —— 确认不参战

reg.write/mem.write/changed/system.task 为 AM 时钟域附加层，不进入
compute 图对齐口径，成本单列。已确认，无需改动。

### §5.4 寄存器读/常量 —— 规则：不改变 node↔atom 拓扑为最高前提

订正为一条**全局约束**：一切处理以不改变 node↔atom 拓扑关系为前提；
寄存器读、常量这类对象**内联到 atom 里**（作为操作数），不物化为独立
instr/atom：

- kRegisterReadPort → atom 内操作数引用（现状已是，非 instr）；
- kConstant → 全局常量变量（现状已是，非 instr）；
- 导入与优化 pass（cse/fold/alias 等）不得把这两类对象物化为独立 atom，
  也不得跨 atom 抹掉 node 边界（§8 风险条同步受本约束）；
- CONST_INT 根（311）/ NONE 根（163）是 gsim 图真实节点，保留单 instr
  atom 1:1，不适用内联规则。

### §5.5 复制策略 —— 本专项不管，对比测试时关闭 gsim replication

复制属分区期策略，本专项不对齐；后期对比测试**关闭 gsim 的 replication**
后同口径对比。现状：`main.cpp:410` 无条件调用 `replicationOpt()`，
**无现成开关**——实施对比实验前需加一个（如 `--no-replication`），
改动微小，随 P3 指标复测一并落地。

### 11.7 边残差解剖（2026-08-11，scripts/no0006_edge_residual_anatomy.py + no0006_edge_case_dump.py）

§11.4 把 AM-only 尾差 ~27.5k 归为"宽值展开/coerce 边界表示差"——**该标签是
未验证的拍脑袋归类，实测不成立**。解剖（opcode 对直方图 + 2-hop 路径分析 +
逐案 dump，build/logs/no0006/edge_residual_anatomy.log）：

- AM-only 142,701 构成：`OP_MUX→REG_UPDATE` 49,189 + `OP_BITS→REG_UPDATE`
  37,614 + `REF→REG_UPDATE` 23,974 + `OP_WHEN→REG_UPDATE` 1,459 ≈ 112k（79%）
  为复位/状态胶（已核销）；**OTHERS↔OTHERS 尾差 ~22k 的 opcode 对高度集中于
  `OP_BITS→{AND 9,571 / MUX 2,164 / SHR 906 / SHL 710 / CAT 654}` 等位切片族**；
  `?→*` ~3.1k 为 topoProj 普查外节点。
- 2-hop 分析：AM-only 边在 gsim 内 2-hop 路径命中 **0/142,701**——不是"绕过
  中间节点"，而是同一逻辑值接到了**不同 node id** 上。gsim-only 35,798 镜像
  （`OP_BITS→OP_AND` 15,546 与 AM-only witness `slice_static→and` 15,546
  精确同数）。
- 逐案实证（no0006_edge_case_dump.py）：gsim 节点 9909328
  （`OP_BITS fpRegion…issueQueueFEX0…$entries$fuTypeVec_9$12_12`，w1，源 =
  concat 节点 4115890，扇出 24 个 OP_AND + 1 个 OP_SHL）；AM 侧**完全相同的
  接线**（同一 concat 4115890 的 slice_static，扇出到逐一相同的 24 个 AND +
  同一 SHL）却打在 atom 760428 上，其 node_id = 9909398
  （`…$age_2$io$$enq_1$2_2`，gsim 里毫不相干的另一个位切片节点）。而
  9909328 自己的 node_id 落在 CommitEvent reg.write atom（state 更新路径）。
  **值与消费集 100% 相同，只有戳不同**——exporter 在寄存器数组逐位读视图
  （`member$i_j` 批量 lowering）时 node 上下文戳在兄弟位切片节点间错位/置换，
  属**溯源簿记伪差，不是图结构分叉**（difftest 逐位一致旁证）。
- 结论：边残差三大家族 = ①复位胶（~112k，白名单）②**寄存器数组逐位读/写
  的 node_id 戳置换**（AM-only ~22k + gsim-only ~24k 镜像，与 NO0005 §6
  向量寄存器翻译问题同源）③WHEN 残留 1,459 + 普查外 ~3.1k。与"宽值按字
  展开"无关。修法：修 exporter 戳（簿记级小修）或前移到 NO0005 §6 根治时
  一并解决；届时 recall 99.20% / precision 96.88% 还应显著上移。
