# NO0005 enode 逐类全量映射矩阵（gsim flatten 图 → grhsim am，导入过程口径）

日期：2026-08-11
状态：已收口（2026-08-11 矩阵实测完成，行列闭合）
前置：[NO0003](NO0003_flatten图单一对象对齐_20260810.md)（flatten 图单一对象）、[NO0004](NO0004_enode到instr映射矩阵对齐_20260810.md)（映射矩阵 v1/v2，根 enode 口径 + 机制归因）

## 1. 背景与问题

NO0004 建立了 enode→exec-GRH op→AM instr 的机制级映射矩阵，但存在两个口径缺陷：

1. **gsim 侧只覆盖 op 型 enode 普查**（5,021,459），REF enode（9,764,504）与常量
   enode（OP_INT 1,140,364 + OP_INDEX_INT 437,094）被归入"另计"，没有逐类成行；
2. glue（脚手架 op）只按 exec kind 成桶（kSliceStatic 61 万、kMux 49 万、
   kAssign 35 万……），每桶**由哪些 enode 类型触发、各多少**靠机制文字推断，
   不是实测——用户判定此为"图结构根本对不齐，不具备分析的条件"。

用户要求的最终形态：**gsim flatten 图一个 enode →（导入过程中）grhsim am 一条
instr 的映射可逐格对账**。

## 2. 目标与品质要求

1. **唯一对象**：gsim flatten 图（NO0003 v2 口径，when 已平化）；
   **导入过程口径**：AM 侧取导入质控点（pre-opt，`build/logs/no0004_am_import_qc.log`），
   不含任何 am.optimize 效果。
2. **全量逐类**：每一种 gsim enode 类型一行——REF、非 REF、常量（OP_INT /
   OP_INDEX_INT）全部保留，不做任何过滤。
3. **二维量化矩阵**：行 = gsim enode 类型，列 = grhsim am instr 类型，
   交叉格 = flatten 图上由该 enode 类型映射（经 exec-GRH 1:1 导入）产生的
   该 instr 类型的**实测数量**。
4. **行列闭合**：每行各列之和 + 未映射余量（→ 操作数引用 / 常量变量 / 状态声明等
   非 instr 对象）= 该 enode 类型普查总数；每列行之和 + AM 侧附加（coerce /
   result_bridge / changed 等非 enode 来源）= AM pre-opt 普查数。残差必须
   精确可解释。

## 3. 方法：导出器仪器化实测（不做推断）

现有普查数据（exec-GRH anchor/glue 按 kind 分桶）无法把 glue 拆到触发它的
enode 类型上。因此给 `reference/gsim/src/ExecutableGrhExporter.cpp` 加归因仪器：

- `lowerExpression` 入栈当前 enode 的类型键（REF/OP_*），全递归生效；
- 非 lowerExpression 路径补上下文：`lowerAssignedNode`（逐 assignTree 根 +
  anchor kAssign 用最后树根）、`lowerRegisterReset`（OP_RESET 根）、
  `lowerMemoryWriteExpression`（when 骨架逐层）、mem 写端口发射（按
  `write.expression`）、effect（按 plan.kind → OP_PRINTF/OP_ASSERT/OP_EXIT）、
  外部实例（OP_EXT_FUNC）；寄存器/存储声明、读写端口等保持 `<non-enode>` 桶；
- `emitOperation` 统一计数：`enodeOpAttribution_[上下文键][exec kind]++`；
  同时按 enode 类型计 `visits`（lowerExpression 访问次数，用于与普查总数对账）；
- 导出结束 dump `SimTop.exec.json.enode_matrix.json`（visits + ops 两节）。

数据链：

```
gsim flatten 图 enode 普查（topoProj SimTop_supernode_stats.json，行总额）
  → 仪器化导出实测 enode×exec-op 矩阵（本次新跑，build/logs/no0005/）
  → exec-op → AM instr 1:1（NO0004 §8.3 导入段闭合差 0）
  → AM pre-opt 普查（no0004_am_import_qc.log，列总额校验）
```

口径声明：行总额取自 topoProj 运行普查（partition+replication 后，与导出图同一
flatten 输入，差异仅 replication +145 节点）；导出进程自身无 enode 普查输出，
visits 计数用于交叉验证覆盖率。

### 4.3 行覆盖（visits vs 普查）说明

- **24 类 op 精确覆盖**（visits == 普查 ±≤15）：OP_OR/OP_AND/OP_CAT/OP_EQ/OP_ADD/OP_XOR/
  全部比较/归约/OP_BITS/OP_NOT/OP_PAD/OP_RESET/OP_SHL/OP_SHR/OP_DSHL/OP_DSHR/OP_SUB/
  OP_BITS_NOSHIFT/OP_HEAD/OP_GROUP/OP_DIV/OP_MUL/OP_ASSINT/OP_ASUINT/OP_CVT/OP_SEXT 等；
- **REF 未访问 3,799,405**：= 3,148,843 个节点 lvalue 根引用 + ~65 万索引路径子引用，
  由 lowerIndexPath/insertIndexedValue 结构性直读，不经 lowerExpression（不产生 op）；
- **OP_INT 未访问 45,090**：字面量被 emitConstant 去重缓存/掩码生成器结构性直读；
- **OP_INDEX_INT 437,094 / OP_INDEX 37,350 visits=0**：静态索引折入位偏移（0 op）、
  动态索引由 lowerIndexPath 结构性消费——其成本体现在 REF/OP_WHEN/OP_WRITE_MEM 行的
  slice_dynamic/mul/add/lt 格中，**OP_INDEX 行 0 op 不代表免费**；
- **OP_WHEN 未访问 1,644 / OP_WRITE_MEM 未访问 198**：常量分析整树消去；
- **OP_ASSERT/OP_PRINTF/OP_EXIT/OP_EXT_FUNC/OP_READ_MEM/OP_INFER_MEM visits=0**：
  effect/ext/存储端口不经 lowerExpression，由各自专用 lowering 路径计数（ops 格实测非零）。

## 5. 结论（收口）

### 5.1 "1 enode → 1 instr" 的三段定量分解

| 段 | enode | → op/instr | 比率 | 性质 |
|---|---|---|---|---|
| REF | 9,764,504（66.0%） | 575,720 | 0.059 | 绝大多数成为**操作数引用**（非 instr）；产出集中在数组/动态索引脚手架（slice_static 264,458 / mul 49,291 / add 34,687 / lt 26,412 / and 26,420 / concat 26,406 / mux 25,070 / slice_dynamic 25,066）与 anchor/强转 assign 97,500 |
| 常量（OP_INT+OP_INDEX_INT） | 1,577,458（10.7%） | 26,398 | 0.017 | 去重为全局常量变量（kConstant 总 11,566 个，**非 instr**）；静态索引全折入位偏移 0 op |
| 真计算 enode | 3,444,001（23.3%） | 4,373,195 | **1.270** | 24 类精确 1:1；膨胀集中机制见 5.2 |
| 非 enode 来源 | — | 447,942 | — | kRegister 148,956 / kRegisterReadPort 148,956 / kRegisterWritePort 149,436（寄存器链，节点级）+ 空树零基 assign 56 + 零基/门控常量 538 |
| AM lowering 附加 | — | 185,300 | — | coerce 115,949 + result_bridge 68,797 + pre_commit 439（全部 add/sub 进位位宽处理）+ changed.pos/neg 115 |

对账：575,720 + 26,398 + 4,373,195 + 447,942 = 5,423,255（exec op 总量）；
AM instr 5,295,811 = 5,423,255 − 非 instr 类 312,744（kConstant 11,566 + kRegister 149,436
+ kMemory 2,274 + kRegisterReadPort 149,436 + kDpicImport 32）+ AM 附加 185,300。两侧精确闭合。

**总量口径回答**：flatten 图 14,785,963 enode → AM pre-opt 5,295,811 instr（0.358/enode）；

## 6. 增量发现（2026-08-11，待立项）：向量寄存器 when 骨架翻译不良——应译为 mask 写

矩阵分析暴露的最大单桶膨胀（OP_WHEN 行 +494,788 / OP_MUX 行 +255,865）经定位为
**翻译缺陷而非语义必需**：向量寄存器的条件部分更新被译成功能式全量合并 mux 链，
而非 AM 原生支持的 mask 写。

### 6.1 宿主确认（topoProj 节点普查，`gsim_topo_flat_v2/instruction_graph.jsonl`）

- when 骨架宿主 = **REG_DST 2,280 个（向量寄存器，状态数组）** + SPECIAL 836（effect
  守卫）+ OTHERS 18（组合数组，可忽略）；flattenNodes 标量 keptWhen=0，
  故 ~37 万 when enode 主体在 2,280 个 REG_DST 树内，**平均 ~170 层嵌套/树**
  （Chisel Vec 逐表项条件写 last-win 链；ROB/队列/重命名表量级吻合）；
- 组合数组（NODE_OTHERS）几乎不使用动态/条件写：根 OP_WHEN 仅 18、OP_GROUP 仅 90。

### 6.2 两侧形态差异（同一逻辑：when c0: v[1]<=x；when c1: v[2]<=y）

- **gsim**：骨架折叠在 REG_DST 节点内（无图边）；emit 为**控制依赖**的 if 门控
  RMW 语句序列（`instsGenerator.cpp:285 instsWhen`，:364 `if(c){...}else{...}`），
  条件不成立则跳过；写回是节点边沿语义，无写指令。
  `if (c0) nv = (nv & ~0xFF00) | (x<<8);` —— **这本身就是一条 mask 写**。
- **grhsim am**：骨架标量化为**数据依赖** mux 链（slice_static 取旧元素 → and/not
  守卫 → mux → concat 重打包，动态下标再加 lt/mul/add/shl/slice_dynamic），
  实测 2.26 ops/when、170 层 ≈ 380 条 instr 全在 compute 块且**永远全算**；
  写回为单条 reg.write 全量整体写，**mask 恒全 1**（.c 149,323 vs .m 仅 113），
  部分写语义全部物化进 nextValue，写指令的 mask 能力闲置。

### 6.3 翻译不良的判定证据

1. gsim 自身 emit 就是 mask 写形态（见 6.2），与 reg.write.m(cond+mask+nextValue)
   一一对应；
2. **同一 exporter 的 mem 路径已是正确做法**：`lowerMemoryWriteExpression` 逐写叶发
   kMemoryWritePort（守卫累积、无重打包链），实测 OP_WRITE_MEM 3,674 → mem.write
   3,476；寄存器路径却走 `insertIndexedValue` 功能式合并；
3. AM 指令定义自 NO0005-前序改革起即支持 mask 写变体，供给端闲置。

### 6.4 目标形态与收益上界（矩阵实测算账）

```
; 现状（功能式合并，~10 条 compute + 1 条全量写）
t0=slice(v,8,8); n0=mux(c0,x,t0); p1=concat(...); ...; reg.write.c(v,1,p2,全1)
; 目标（效果式部分写，0 条新 compute + 逐层 mask 写）
reg.write.m(v, c0, x<<8, 0x00FF00);  reg.write.m(v, c1, y<<16, 0xFF0000)
```

- 消除 OP_WHEN 行 mux/slice/concat/守卫主体 ~76 万 ops（超额 49.5 万全消）；
- 代价：commit 侧每级 when 一条 mask 写（~37 万条），但 **cond 门控可跳过**——
  用"永远全算的 mux 链"换"条件稳定即跳过"的写，正面对上 gsim if 的运行时优势；
- 动态下标写收益更陡：现状每层 lt+shl+slice_dynamic+插入链 → mask 写仅 1 条 shl 造 mask。

### 6.5 所需语义扩展（实施时的工作点）

1. **多写口/寄存器**：放开 AM "1 寄存器 1 reg.write" 假设（现 149,436 精确 1:1），
   定义同寄存器多 mask 写的**源序 last-win**（exec 侧 mem 写已有
   `memoryWrite.priority` 先例可搬）；同寄存器所有写同事件签名→同 commit 块，
   沿用既定时钟域聚类规则；
2. **复位优先级**：同步复位 = 全 1 mask 写排最后（赢过普通写）；异步复位走 event；
3. **落地位置**：exporter 寄存器路径复用 mem 骨架遍历（逐叶发 mask 写）+ AM 导入
   放开单写假设；优于在 AM 侧事后 pattern-match 170 层 mux 链反推；
4. **正确性硬约束**：重叠 mask 同周期双写、partial invalid、读写同周期——
   difftest 逐位一致为验收线。
