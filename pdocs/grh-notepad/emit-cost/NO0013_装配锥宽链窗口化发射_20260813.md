# NO0013 装配锥宽链的窗口化发射（atom 边不变硬约束）

- 日期：2026-08-13
- 状态：已收口（F1 窗口化落地；F2 实测负优化已回撤；F3 留专项）
- 前序：NO0012（Tier1+2+3 收口，eval 401.9s / compute 854.5G，遗留装配激活回归 ~+158G）
- 用户约束（2026-08-13）：**剥离调度差异，只治 emit 形态**——优化前后 atom
  之间的连接关系不变：原来有边的必须有边、不新增边（QC 硬门）；边携带的
  数据量减少是喜闻乐见的（区分"数据"与"边结构"）；重点全部放在最终生成的
  C++ 代码形态上。

## 1. 目标与范围

修复 NO0012 §5 遗留第 1 项：fan/dynlane **装配锥**（assembly cone）的
emit 形态不良。NO0012 把 352-member 逐 lane 写合并成 fan/dynlane 写后，
链本体真消亡（净收 -367G），但装配锥本身以**全宽物化**形式发射，
且装配块激活与 fan 任意输入活动绑定（激活率抬升），形成 ~+158G 残余回归。

修复后硬指标（coremark 50k，taskset 绑核，三次中位）：

- difftest 4/4 逐位一致（73,580/49,996）为硬门，任何一步不过即回退；
- **QC-E（边不变）**：优化前后 atom 级边集 diff = 0（instruction-graph
  jsonl 对账，脚本落 scripts/）；边携带位宽允许下降并记录；
- 目标装配块 per-fire 向 gsim 逐元素量级收敛（数量级对齐，允许残差）；
- 净回收 ≥ 100G；am eval Host 中位 < 401.9s（NO0012 基线）。

明确排除（不在本项目）：

- atom 图任何结构变更（划分/调度/合并/复制）——NO0008 冻结继续有效，
  本项目再加"边集不变"硬门；
- commit 账（~365G，用户裁决继续搁置）；
- 窄 atom 机制（decode-isMove gnode 926448 / VFMA gnode 297258，
  非宽链机制）——下一专项候选，本项目只在 Phase A 顺手留数；
- #1 巨簇长尾（56,204 块固定激活/簿记开销）。

## 2. 病灶证据（tier3 实测，build/logs/no0012/tier3/）

|---|---|---|---|---|
| 77932 | 21,614 | 26.83G | 1.24M | 42,402 |
| 38653 | 15,873 | 24.19G | 1.52M | — |
| 77703 | 36,637 | 19.54G | 0.53M | — |

| 66190 | 30,857 | 12.82G | 0.42M | — |

5 块合计 ~98.9G；NO0012 口径全装配族 ~+158G。

机制实证（block 77932，`grhsim_SimTop_blocks_38_part_1.cpp`）：

1. **块级单字节门控**：`active_byte_ref(9741) & 0x10` 一击即整链
   15 chunk / 42,402 指令全跑，块内无 atom 级门控（detGrpblk 仅 1 项，
   用于块出口的下游变动检测）。
2. **全宽物化 rebuild 链**：指令构成 = 73,766 条 resize_value（窄 mux
   链节）+ 3,655 slice_words + 3,623 insert_words + 1,218 zero_words，
   链值 1,040 字（66,560 位）逐步全量重建；每 fire 宽字搬运算术量级
   ~百万字，而每 lane 实际数据仅 4–64 字。
3. **激活率抬升**：门控字节由 fan 全部输入活动共享，任一 lane 输入
   变动即整链重算（ROB 场景接近每拍）。

gsim 侧同 node 集为逐元素标量下标形态，per-fire 为逐元素量级
（NO0010 join 口径 per-fire 差 2–3 个数量级）。

## 3. 修复方案（按优先级，全部不动 atom 图）

- **F1 lane-build 窗口化发射（主刀，emitter 侧）**：在 blocks 发射段识别
  "zero_words + 逐 lane insert/slice 步进 rebuild"模式（lane 两两不交
  已由 NO0012 fan 成形时证明），改写发射为：
  **基座单次拷贝**（old 值或清零）+ **逐 lane 条件窗口拷贝**
  `if (cond_k) copy_words(dst + off_k, data_k, lane_words)`。
  中间全宽链值不再物化。适用前提：中间宽值的消费者闭包在本模式内
  （块内数据流分析，emitter 可见整块指令流）；任一中间值逃逸则该链
  回退现状发射。program/interpreter/validate 不动（语义锚点保留）。
- **F2 旧值 lane slice 发射期共享**：装配锥内同 old+同窗口的重复
  `slice_words` 提取只算一次（发射期 CSE，局部表即可）。
- **F3 dynlane 装配 elem mux/slice 窗口化**：writebackTime 族残余
  225 instr/atom 的 elem 装配同法处理。
- **F4 事件 or-tree 形态**（条件触发）：Phase A 量化若显示事件聚合锥
  占比可观再定方案；占比小则仅记录。
- 备选路径（仅当 F1 模式识别证明不可行时启用）：program 级指令改写
  （图到 program 物化段把宽链步替换为窄窗 op、中间值收窄），需 ISA
  全链路配套（traits/layout/interpreter/validate），侵入性明显更高——
  Phase A 末做一次可行性裁决。

escape hatch：`WOLVRIX_GRHSIM_AM_DISABLE_WINDOWED_EMIT`（逐模式回退，
默认开启新形态）。

## 5. 风险与回退

- 窗口化改变中间值物化范围：消费者闭包证明必须保守，存疑即回退现状
  发射（逐链粒度）；
- dynlane "每 eval lane 唯一"语义假设延续（NO0012 已记录在档）；
- 窗口化后代码变为大量小条件拷贝，需关注编译器友好性（helper 用
  `__restrict__` + 固定字数内联展开，沿用 dynlane_write_words 风格）；
- emitter 模式识别复杂度须局部化在 blocks 发射段，不外溢。

**两个翻案**（修正 NO0012 遗留分类）：

1. VFMA b38653（g297258）与 decode-isMove b77703（g926448）**不是**
   "窄 atom 机制"——实测为 2,048 / 1,056 条中等宽度（2,048/2,464 位）
   zero+insert+slice rebuild 链，属形态 2，F1 直接覆盖。"窄 atom"分类
   仅对 b83400 成立。
2. b83400（70.1G、每拍激活、7,001 atom / 27,448 纯窄指令、per-instr
   ≈25 cycles）**无任何宽链**——locality/窄 atom 机制（窄 atom 机制
   专项的头号靶子，含 56,204 块长尾外的单块大头），确认不在本项目。

**per-fire 成本机制补证**：b77932 每 fire 宽 helper 调用 8,496 次、
宽字搬运 ~45k 字，实测 1.24M cycles ≈ **每次宽 helper 调用 ~150
cycles**（8KB 级访存 + 非内联循环）；gsim 侧为逐元素标量内联代码。
F1 窗口化同时消除指令数与访存流量（352 步全宽物化 → 基座单拷 +
条件窗拷）。

**F1 可行性裁决（emitter 侧，不动 program）**：链步在 emit 产物中为
`zero_words+insert_words×3+slice_words×2` 规则序列；窗口两两不交已由
NO0012 fan 成形证明；逐 lane 条件/数据为块内窄值（resize_value 三元
式）可直接引用；中间链值的逃逸检查=块内消费者闭包（非 slice/链内消费
者或跨块引用 → 该中间值物化回退）。形态 2（concat pack）更简单：
窗格满覆盖时 zero_words 为死代码，切片源直拷免中间临时。
**结论：走 emitter 侧主路径，program 级备选路径放弃。**

F3（形态 3 掩码锥）per-instr ≈34 cycles 异常（窄 op 不应这么贵），
Phase B 先量化其机制（访存/调用形态）再定方案。

## 8. Phase B 实施实录（2026-08-13）

**F1/F2 已落地**（emitter 侧，program/图不动）：

- `planWindowedChains`（接在 planMuxFusionRuns 之后）：
  - 链识别：wide Concat（≥256b）的 backbone 操作数 = 同块前序 Concat 的
    恒等放置 SliceStatic（lsb == concat 内偏移）；非 backbone 即 elem 窗口；
    前序唯一、分支即整链 bail。
  - 消费者校验（CSR 全程序 def-use）：同块 SliceStatic 消费者满足
    "发射位置 < 首个改写其窗口的后续步"则重指 D（kRemapSlice），否则
    物化回退（step 位置补 `assign_words(C_j, D)`）；骨干 slice 唯一
    消费者=下一链步 → 跳过；非 slice/跨块/接口可见消费者 → 物化；
    mux-run 覆盖的任何成员/消费者 → 整链 bail；末成员的同块早读 → bail。
  - F2：非链宽 Concat 改写为纯 replace_window 序列（操作数满铺 →
    zero_words 为死代码；末尾补顶字掩码保持槽位不变式）。
- 发射 hook `emitWindowedInstruction`（emitNonScalarInstruction 顶部）；
  新 helper `replace_window_words`（= insert_replace_words 的 RMW 半段，
  去掉全量 assign）；escape hatch
  `WOLVRIX_GRHSIM_AM_DISABLE_WINDOWED_EMIT`；stats 入 JSON
  （windowed_chains/steps/concats_f2/skipped/remapped/materialized/bailed）。
- 实测计数（f1b emit）：chains=203、steps=12,817、F2 concats=13,199、
  skipped slices=25,251、remapped=12,818、materialized=1、bailed=30。
- 形态实证（block 77932）：宽 helper 调用 8,496 → 2,787/fire，
  中间宽值全部不物化，逐 lane 步进 = 1 次 4-bit `replace_window_words`。

**两个实施期 bug（已修，教训入档）**：

1. F2 段曾被 `if (stepByVar.empty()) continue;` 整体跳过——无链块
   （b38653 等形态 2）完全没吃到 F2；修复为无链也跑 F2，且 F2 对
   mux-run 内 concat 同样适用（单指令改写、位置无关）。
2. F2 顶字掩码语句缺括号（`wideValues_.data() + off[4]` 优先级错误）→
   生成 C++ 编译失败。**ctest -R grhsim 17/17 也抓不到**：grhsim 小模型
   无 ≥256b concat，F2 路径无覆盖；该门只有 xiangshan emu 构建能验。

**基础设施备忘**：宽值 helper（zero/insert/slice/replace/bitwise/assign…）
定义在 `grhsim_SimTop_runtime.cpp` 单独编译，块 TU 全部跨 TU 调用
（-O3 无 LTO 不可内联）——每次调用即使 4-bit 窗口也付整调用开销；
F3/掩码锥（376b ≈6 字）per-call ~150 cycles 的根源即此。候选修复
（F3a）：热点小字宽 helper 改头文件 inline 定义，或 emitter 对
≤8 字宽 op 发射内联直排代码。

## 10. 终版结果（f1e，F2 回撤后，2026-08-13）

**f1d 裁决**：顶字掩码移除对 b77703 回归**无效**（24.70G→25.00G 未
回落）——真凶是 F2 的 replace-RMW 本身：对非对齐宽窗，replace 的
逐字窗格计算 + RMW 比 stock zero fill + OR-insert 更贵（F2 前提
"zero 是死代码所以省了"在成本上不成立：memset 纯写无读、insert OR
逐字极简单）。**F2 回撤**（独立宽 concat 保持 stock 发射；
kWindowConcat 发射 case 留作参考，计数恒 0）；F1 链不在此列
（其收益来自消除逐步全宽重建，非 insert/replace 互换）。

**三门终核（f1e）**：

| 门 | 结果 |
|---|---|
| QC-E | atom 边集 diff=0（f1c 对账；f1e 与 f1c 仅 emitter 差异，图同一） |
| difftest | 3/3 reps 逐位一致（73,580/49,996，IPC 完全相同） |
| ctest -R grhsim | 17/17（最终代码） |
| eval Host 中位 | 378.4/376.8/377.9 → **377.9s**（vs 基线 401.9s，**-6.0%**） |

**块级终态**（同会话对照 tier3-fresh，噪声带 ±5-12%）：

- F1 链块真修复：b77932 -25%（per-fire 1244K→934K）、b17656 -47%、
  b77811 -19%、b66083 -82%、b45266 -45%、b66135 -80%、
  b49802/49812/49813 ≈-67%、b83412 -19%；
- F2 回撤后 b77703/b38653/b57029/b75532/b37481 全部回落到噪声带内；
- 残余回归均在未触碰块（b83400 +3.9G、commit 每拍块 +0.5-0.9G），
  代码逐字节相同 → 布局/热态噪声。

**净账**：compute 单元成本（execs 块内）1,167.7G→1,175.8G（+8.1G，
噪声主导的块间搬迁）；Host 377.9s（-24.0s ≈ -101G cycles），差额
在块外（分派/icache/TLB 全局效应，§9 存疑点保留）。

**结论与遗留**：

1. 装配锥宽链窗口化（F1）成立：203 链 / 12,817 步 / 25,251 slice 跳过
   / 12,818 重指 / 仅 1 物化 / 30 bail；atom 边集不变。
2. F2（独立 concat 去零）实测负优化，已回撤并留档——教训：emit 形态
   改动必须过实测门，"看似死代码"不等于"去掉更快"。
3. F3（掩码锥，b66190/66205/66186 等 ≈66G）未实施：机制=小字宽
   helper 跨 TU 调用开销（376b ≈6 字，per-call ~150 cycles），方案
