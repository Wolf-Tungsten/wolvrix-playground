# NO0009 跨侧 id 溯源贯通：supernode/node 与 block/atom 关联导出及 cpp 注释对齐（2026-08-12）

> 状态：**已收口**（2026-08-12）。三侧能力全部落地，difftest 逐位一致，
> join 量化对比产出首版调度差异画像（§5.4）。
> 来源：用户 2026-08-12 指令——进一步增强 gsim、grhsim am 的导出对齐能力，
> 目的是**跟踪调度差异**（gsim 的 supernode 划分 vs AM 的 block 划分）。

## 1. 目标（用户要求拆解）

1. **gsim 侧**：为每个 node、supernode 分配 id；输出 supernode 与 node 的
   关联关系；输出的 cpp 中要能看出每个代码段来自哪个 node、supernode。
2. **AM 侧**：导入 gsim node id 作为 atom 的溯源标识；能看出哪个 atom
   属于哪个 block。
3. **AM emit cpp**：要能看出代码与 atom、block 的对应关系。
4. 最终用途：在共享的 gsim node id 空间上 join 两侧成员关系，量化跟踪
   gsim supernode 划分与 AM block 划分的差异。

## 2. 现状盘点（2026-08-12 勘查）

### 2.1 gsim 侧（reference/gsim）

- id 已存在：`Node::id`（include/Node.h:107）、`SuperNode::id`
  （include/Node.h:374），均为进程内分配计数器（自 1 起）。
  **注意**：受 splitArray 指针序影响，id 跨进程不稳定（NO0007 已记录），
  但同一 gsim run 内 exec.json / cpp / 任何新导出全部自洽——本专项所有
  导出必须落在同一个 gsim 调用内。
- exec.json 已逐 op/value 戳 `gsim.node_id`（NO0006），AM 导入的 node
  空间与 gsim node id 空间同一。
- 缺失①：supernode↔node 成员关系从未以 `super->id` 口径导出
  （topoProj 的 block_assignment 用的是 Dense 重编号，且不走 cppEmitter）。
- 缺失②：emit cpp 无 node/supernode 溯源注释。现成注入点：
  `cppEmitter.cpp` 的 `genSuperEval`（:958，持有 SuperNode*）与
  `translateInst`（:929，持有 `InstInfo::node` 回指针，字符串构造的
  inst 无回指针，需判空）。

### 2.2 AM 侧（wolvrix/lib/grhsim/am）

- gsim node id 目前仅以逐指令侧表挂在 `AmGraph`（`gsimNodeId`，
  grhsim_am_graph.hpp:140-150），`toLinearProgram()` 即丢弃；
  `ScheduledProgram`/`ExecutableModel` 无任何溯源。
- split 阶段有瞬时 `atomGsimNodeId`（grhsim_am_graph_split.cpp:673,747-755），
  仅服务于 node-atom 审计 jsonl（`WOLVRIX_GRHSIM_AM_NODE_ATOM_AUDIT_JSONL`，
  写于分区**前**，无 block 归属，且其 atom 编号 ≠ ScheduledProgram 的
  AtomId 编号）。
- 缺失①：atom→gsim node 溯源不进 ScheduledProgram。
- 缺失②：atom→block 成员关系无任何导出。
- 缺失③：emit cpp 无 atom/block 注释。注入点：块循环（内联路径 :7184、
  分块路径 :7267）与每指令收口 `emitBlockPositionCode`（:2776）；atom 区间
  可由 `ScheduledProgram::{blockAtomCount,blockAtom,atomInstructionCount}`
  连续平铺关系导出。

## 3. 设计

### 3.1 gsim 侧

**G1. supernode 成员导出**（新文件 `<name>_supernode_members.jsonl`）：
在 `graph::cppEmitter()` 内 cppId 分配之后（与现有
`writeSupernodeStatsJson` 同处，cppEmitter.cpp:1405 附近）写出，每个
supernode 一行：

```json
{"super": 12345, "cpp_id": 678, "type": "SUPER_COMPUTE", "member_count": 12, "nodes": [101, 102, ...]}
```

- `super` = `SuperNode::id`（权威 id），`cpp_id` = 发射期 Dense id
  （ emitted cpp 注释里可见的那个），两者并列便于双向查。
- 成员节点取 `SuperNode::member`，写 `node->id`。

**G2. cpp 溯源注释**：
- 每个 supernode 段首 banner（`genSuperEval` 内）：
  `// ===== super=<id> cpp_id=<cppId> type=<SuperType> members=<n> =====`
- 每条语句尾注释（`translateInst` 内，`inst.node != nullptr` 时）：
  ` // node=<node->id>`
- 新增开关 `--cpp-trace-comments` / `--no-cpp-trace-comments`
  （`Config::CppTraceComments`，**默认开**——本 fork 服务于分析；
  注释对编译产物语义零影响）。

### 3.2 AM 侧

**A1. atom→gsim node 溯源贯通进 ScheduledProgram**：
- `AmComputeActivityGraph` / `AmCommitEventGraph`
  （grhsim_am_graph_partition.hpp）各增 `atomGsimNodeId` 向量，由 split
  阶段填入（现成瞬时数据上移）。
- `detail::ProgramStorage` 增 `atomGsimNodeIds`（与 `atomKinds` 平行的
  原子层数组）；`ScheduledProgramBuilder::beginAtom` 增 gsimNodeId 参数；
  `ScheduledProgram` 增视图 `atomGsimNodeId(AtomId)`。
- `materializeAmProgram` 合并 compute/commit 两侧编号时同步搬运。
- 取值口径：atom 内全部指令同一 node id → 该 id；全无主 → -1；
  混合（仅非 node-aligned 模式可能出现）→ -2。node-aligned 模式下
  严格 1:1。

**A2. atom→block 成员导出**（新 jsonl，环境变量
`WOLVRIX_GRHSIM_AM_BLOCK_ATOM_JSONL` 给路径，沿用现有 env 导出惯例）：
materialize 完成后写出：
- 每 block 一行：`{"block": b, "role": "entry|compute|commit", "atom_count": n, "instr_count": m}`
- 每 atom 一行：`{"atom": a, "block": b, "kind": "...", "gsim_node": n, "instr_count": m}`
（atom/block 编号均为 ScheduledProgram 的 Dense id，与 emitted cpp
注释同口径。）

**A3. emit cpp 溯源注释**（`GrhSimAmCppOptions` 增 `traceComments`，
默认开，`lower_json_smoke` 加 `--no-trace-comments` 关闭）：
- 每个 block 段首 banner：
  `// ===== block <id> role=<entry|compute|commit> atoms=<n> instrs=<m> =====`
  （entry/内联/分块三条路径都加。）
- 每个 atom 段首注释：`// --- atom <a> kind=<k> gsim_node=<n> ---`
  （按 atom 平铺区间在块循环里跨界时输出；mux-fusion run 路径若绕过
  收口函数，单独补或记为已知缺口。）
- 不做逐指令注释（3M 行量级，注释本身即够定位）。

### 3.3 对比分析脚本

`scripts/compare_supernode_block_membership.py`：
join 键 = gsim node id。
- 输入：gsim `*_supernode_members.jsonl` + AM block_atom jsonl。
- 指标：
  - 覆盖率：gsim 成员 node 中存在于 AM node 空间的比例（残差来源：
    coarsen 期 mergeResetAll 的 REG_RESET dup、replicationOpt 复制节点，
    均为导出后新生 id，预期存在，需显式列账）；
  - 每个 gsim supernode 的节点散落在多少个 AM compute block（分布直方图、
    完全包含比例）；
  - 每个 AM compute block 触及多少个 gsim supernode（对称指标）；
  - 与 supernode-align 路线的块数/跨边口径衔接说明。

### 3.4 口径与注意事项

- gsim 全部导出（exec.json、members jsonl、cpp）必须同一 run 产生，
  id 才可比（进程内计数器，跨 run 不稳定）。
- AM 侧 join 只用 `gsim_node >= 0` 的 atom；-1（AM 附加层：时钟域 helper、
  commit）与 -2（混合）单列。
- 本专项为**纯增量**（侧表 + 导出 + 注释），不改任何求值语义；difftest
  基线不应变化。

## 5. 实测结果（2026-08-12，xiangshan SimTop 全流程）

### 5.1 复现命令（最终可用口径）

gsim 单次全跑（同 id 空间产出全部产物，**不要** `--stop-after-stage=PreCoarsen`，
**不要** `--sep-mod/--sep-aggr`——见 §5.5 坑 2）：

```bash
reference/gsim/build/gsim/gsim --flatten-nodes --no-replication \
  --export-executable-grh=build/logs/no0009/gsim_flat_export/SimTop.exec.json \
  --export-topo-proj=build/logs/no0009/gsim_topo_flat \
  --executable-grh-profile=xiangshan-gsim-coremark-stub \
  --supernode-max-size=15 --cpp-max-size-KB=8192 \
  --dir=build/logs/no0009/gsim_run \
  build/xs/rtl/rtl/SimTop.fir
# wall 14m16s，峰值 RSS ~111GB，exit 0
```

AM 导入 + 调度 + emit（新增 `WOLVRIX_GRHSIM_AM_BLOCK_ATOM_JSONL`）：

```bash
env WOLVRIX_GRHSIM_AM_INSTRUCTION_GRAPH_JSONL=build/logs/no0009/am/am_instruction_graph.jsonl \
    WOLVRIX_GRHSIM_AM_NODE_ATOM_AUDIT_JSONL=build/logs/no0009/am/atom_node_audit.jsonl \
    WOLVRIX_GRHSIM_AM_BLOCK_ATOM_JSONL=build/logs/no0009/am/am_block_atom.jsonl \
  wolvrix/build/bin/grhsim-am-lower-json \
    build/logs/no0009/gsim_flat_export/SimTop.exec.json SimTop \
    --schedule --emit build/logs/no0009/am_emit --block-chunk-instructions 3000
```

join 分析：

```bash
python3 scripts/compare_supernode_block_membership.py \
  --gsim-members build/logs/no0009/gsim_run/SimTop_supernode_members.jsonl \
  --am-members build/logs/no0009/am/am_block_atom.jsonl \
  --out-json build/logs/no0009/membership_join_v3.json
```

### 5.2 gsim 侧产出

- `SimTop_supernode_members.jsonl`：**113,963** 行（= supernode 数），字段
  `{"super", "cpp_id", "type", "member_count", "nodes":[...]}`。
- emitted cpp（296 个 TU）：`// ===== super=<id> cpp_id=<n> type=<T> members=<n> =====`
  banner **113,963** 条（与 members 行数 1:1）；逐语句 `// node=<id>` 尾注释
  **3,758,411** 条。最大 TU（SimTop0.cpp）带注释 clang -c 仅 0.95s。
- 单元级验证（实现时）：fir-tests 9/9；注释剥离后与 `--no-cpp-trace-comments`
  产物逐字节一致（纯注释，零语义影响）。

### 5.3 AM 侧产出

- blocks：compute **84,873** / commit 2,981 / entry 1；atoms 总计 **4,507,879**
  （Singleton 3,604,986 + Tree 680,254 + CommitEvent 222,639）。
- `am_block_atom.jsonl`：block 行 `{"block", "role", "atom_count", "instr_count"}` +
  atom 行 `{"atom", "block", "kind", "gsim_node", "instr_count"}`。
- emitted cpp（431 文件）：`// ===== block <id> role=<> atoms=<> instrs=<> =====`
  banner 88,838 条（87,855 个唯一 block + 分块函数的重复 banner）+
  `// --- atom <id> kind=<> gsim_node=<> ---` 边界注释 **4,507,879** 条
  （与 atom 总数精确 1:1）。
- 单测：grhsim/am 17/17 通过（含新增 atomGsimNodeId 视图、block_atom 导出
  round-trip、trace 注释开/关断言）；transform 模块 2 个失败为本分支既有问题
  （stash 验证与本次无关）。

### 5.4 join 量化对比（v3 终版，v2 复测数字结构一致）

**id 空间对接质量**（gsim 3,146,488 个成员 node → AM node 空间）：

| 桶 | 数量 | 占比 |
|---|---|---|
| 映射到 AM compute atom | 3,068,340 | 97.52% |
| 仅映射到 AM commit atom | 77,957 | 2.48% |
| 无映射（coarsen 期 reset-dup 等导出后新生 id） | 191 | 0.01% |

node→compute-atom 重复映射 = **0**（node-aligned 1:1 严格成立）。

**调度差异画像**（本专项的核心产出能力）：

| 指标 | 值 |
|---|---|
| gsim supernode 完整落在 1 个 AM block | 41,817 / 113,963（**36.69%**） |
| 每 supernode 散落 AM block 数（均值） | 3.309 |
| AM compute block 只触及 1 个 gsim supernode | 35,868 / 84,873（**42.26%**） |
| 每 block 触及 supernode 数（均值） | 4.443 |
| 块数对比 | 113,963 supers vs 84,873 compute blocks（0.745x） |

极值 outlier：6 个 5,281 成员的 SUPER_VALID 巨 supernode 各散落 **1,409** 个
AM block；最大 AM block（76,683 atoms）触及 **13,010** 个 supernode。
明细：`build/logs/no0009/membership_join_v3.json`（含逐 supernode/逐 block 记录）。

### 5.5 流程坑记录

1. **`--executable-grh-profile=full-fidelity` 会在 XiangShan 上中止导出**：
   `PrintCommitIDModule`（initial $fwrite 的 NODE_EXT）触发 RequiresWrapper 硬错误
   （ExecutableGrhExporter.cpp:1060），exit 1 且无 exec.json。正确 profile 为
   `xiangshan-gsim-coremark-stub`（NO0007 §14.2 已据此追加勘误）。
2. **`--sep-mod/--sep-aggr=__DOT__` 会改写 exec.json 端口名**
   （`difftest$$uart$$...` → `difftest__DOT__uart__DOT__...`），AM emit 出的模型
   头文件端口名随之变形，difftest ABI 静态断言直接失败（missing uart port）。
   导出 run 不得携带 sep 改写参数（gsim 参考 emu 的那四个 flag 里，
   `--supernode-max-size/--cpp-max-size-KB` 不影响名字，可带）。
3. node id 为进程内分配计数器（ASLR 致跨 run 置换）：exec.json / members jsonl /
   注释 cpp 必须同一 run 产出。v2/v3 两次全跑结构指标完全一致（supernode 数
   113,958 vs 113,963 的 5 个差为 partition 平局破序噪声），证明该口径稳定。
4. gsim 在 `--dir` 不存在时 segfault（genHeaderStart fopen 空指针，既有 bug，
   未修）；跑前先 mkdir。

### 5.6 端到端验证（emu 构建 + coremark）

- AM emu 构建（带注释全 TU，-j16）：**7m38s，exit 0，全日志零 -O0/-O1 降级**
  （no0007 无注释基线 7m44s——注释对编译时长无可见影响）。
- coremark 50k difftest：**exit 0，instrCnt=73,580 / cycleCnt=49,996 /
  IPC=1.471718，与基线逐位一致**；Host time 680.6s（基线 682.1s，持平）。
  证明本专项全部改动（gsim 侧 + AM 侧）为纯增量/注释，语义零漂移。
