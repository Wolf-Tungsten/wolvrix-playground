# NO0012 动态基座逐元素宽链的元素级发射改写

- 日期：2026-08-13
- 状态：立项（开工）
- 前序：NO0010（逐单元计时差分排名）、NO0011（常量基座宽链已根治，遗留动态基座族）
- 用户裁决（2026-08-13）：**本项目不管 commit 成本**（commit 账 365.4G、23% 留给后续专项）；只修计算侧动态基座逐元素宽链。

## 1. 目标与范围

修复 NO0011 §4 遗留的"动态基座功能式单元素更新/读取被物化为全宽字向量运算"族。
两形态同一本质：**逐元素操作被展开成 O(元素数 × 全宽字数) 的全宽重建链**，
gsim 侧为标量数组下标读写，AM 侧为每步重建全值的 zero/insert_words 链。

修复后硬指标（coremark 50k，taskset 绑核，三次中位）：

- difftest 4/4 逐位一致（73,580/49,996）为硬门，任何一步不过即回退；
- 目标簇 per-fire 向 gsim 水平收敛（数量级对齐，允许残差）；
- 回填总账：am eval Host、am 单元成本、正 Δ 总量、top 簇排名重测。

明确排除（不在本项目）：

- commit 账（365.4G，激活过滤/检测轮询成本）；
- #1 巨簇长尾（626G、60.7%，56,204 块的每块固定激活/簿记开销，机制不同，
  待本项目收口后立项分解）；
- 图结构（atom 数量/连接关系）任何变更——NO0008 冻结继续有效。

### 2.1 形态 A：动态索引读链（基座动态，消费者是静态窄 slice）

实证 `grhsim_SimTop_blocks_8_part_3.cpp:23292` 起，block 17632
（atoms=100 instrs=14,758），atom 851430（Tree，gsim_node=3767190）：

```
zero_words(dst_k, 14336);                          // 每级重建 14,336 位 = 224 字
insert_words(dst_k, 14336, 64(k+1), hi_{k-1}, 14336-64(k+1));
insert_words(dst_k, 14336, 64k,     elem_k,   64);  // 只改一个 64 位窗口
insert_words(dst_k, 14336, 0,       lo_{k-1}, 64k);
slice_words(&local[k], 64, dst_k, 14336, 64(k+1)); // 全链唯一消费者：静态 64 位窗
```

223 级 × 每级 ~700 字操作 ≈ 15.6 万字操作/激活；实际只需要一条 223 节
**标量 mux 链**（每节 64 位）。块内该形态 223 处 `zero_words(·,14336)` 实测。
per-fire 1,713.6k vs gsim 11.6k ≈ 148x。

### 2.2 形态 B：动态写口功能式更新链（消费者是寄存器 next-value 全值）

实证 `grhsim_SimTop_blocks_36_part_3.cpp:34557` 起，block 75182
（atoms=5,281 instrs=5,632），atom 3159727（Tree，gsim_node=926459，
`robEntries$$perfDebugInfo$$renameTime$NEXT`，w=22,528 位 = 352 字）：

```
// 352 级，每级全宽重建 352 字，只把第 k 个 64 位窗口换成新元素
zero_words(dst_k, 22528);
insert_words(dst_k, 22528, 64(k+1), base_k, 22528-64(k+1));
insert_words(dst_k, 22528, 64k,     elem_k, 64);
insert_words(dst_k, 22528, 0,       dst_{k-1}低段, 64k);
```

352 级 × 352 字 ≈ 12.4 万字操作/激活（chunk_1 内 zero/insert 实测 1,406 行）。
块 70436（writebackTime，NO0011 已录 `mux(cond,(old&~mask)|(new<<shift),old)`
同构）。消费者是全值（寄存器写），不能塌缩成标量链，但可改写为
**基座一次拷贝 + 逐窗口 64 位标量 patch**：O(n²) → O(n) 字。
per-fire 896.1k vs gsim 22.1k ≈ 40x（#2 块 70436 处为 1.80M vs 4.3k ≈ 418x）。

### 2.3 单位勘误（防止误读）

`zero_words/insert_words` 第二参数是**位宽**，内部 `word_count()` 换算
（emitter 1526-1558 行、support 6317 行），无 64x 位宽膨胀；开销全部来自
O（级数 × 全宽字数） 的链式重建本身。

## 3. 修复方案

统一改写：**窗口化懒重放（windowed lazy replay）**——在 lowering（op 级，
gsim node 分组）对宽链做位级段（bit-segment）溯源：每个宽值 = 若干
(root_var, lsb, width) 段；concat/slice_static 只追加/截取段；链内部值
不物化，仅对外逃值（escapes）按段重放（slice/assign + 至多一次 concat）。
O(级数×全宽) → O(全宽) 一次。

### 3.1 原型验证（2026-08-13，build/logs/no0012/）

仪器：instruction-graph jsonl 导出扩展（additive 字段 res/ops/lsb/gnode，
`grhsim_am_graph_split.cpp`），`scripts/no0012_window_provenance.py` 位级段
溯源原型。结果（min_width=4096b）：

- 5,035 个含宽数据指令的 atom，**4,950 个全匹配**（85 拒绝）；字操作
  3,214,444 → 478,231（6.7x）；
- bloomFilter 巨 atom（gnode 5500963，69,624 指令、49,144 链指令）：
  1,596,991 → 12,351 字（**129x**）；
- intRegFile（gnode 3767190）：99,680 → 224 字（**445x**，escaped=1）；
- TAGE 族（gnode 7372714 等）：179,700 → 300 字。

### 3.2 机制补查（修正 §2 的部分认知）

- **形态 B 真实消费者是 lane-write fan**（ROB renameTime 族，gnode
  926459/926451/926452/926455）：352 级 concat 链的**每一级**都外逃——
  每级全值喂一个 `reg.write.cm`（操作数布局 [cond, mask, data, target,
  event]，mask=单 lane one-hot、event 相同），即每 lane 的写从不同链级取值。
  等价语义：lane k 的最终值在链级 k 插入后不再变化 → 352 个 masked lane 写
  ≡ **一次 plain reg.write**，data = 逐 lane `mux(cond_k, elem_k, old_lane_k)`
  的 concat。变量级懒物化对此族无效（全逃），需消费者感知的写合并（Tier 2）。
- **writebackTime 族**（gnode 926462/3/4，block 70436，per-fire 1.80M）：
  宽 op 为 shl/and/not/or/mux/assign（mux-form 混合链，32 步），需把
  位运算/mux 纳入逐窗口"op"段重放（Tier 3）；mask/shl 若可证 onehot，
  351/352 窗口退化为透传，每步只剩 ~6 个标量 op。
- **decode-isMove（gnode 926448，3,520 指令）与 VFMA（gnode 297258，
  8,192 指令）无 ≥4096b 宽 op**——非宽链机制（大量窄 atom），本项目
  不覆盖，留待后续立项。

### 3.3 分层实施

- **Tier 1（本项目主刀）**：concat/slice_static 链 + root/zero 段懒物化，
  lowering op 级按 gsim node 分组重写；外逃守卫沿用 F1 的
  firstUseOrdinal 纪律（所有外逃消费序 > 组末 op 序，否则整组回退）；
  exposed/declared 值按外逃物化到其声明变量。覆盖 形态 A、bloomFilter、
  TAGE 族、4,950 atom 类。
- **Tier 3**：+"op"段（and/or/xor/not/mux 逐窗口）+ 段级化简
  （and(x,0)=0、or(x,0)=x、mux(c,x,x)=x、onehot 透传），覆盖 writebackTime
  mux-form。
- **Tier 2**：消费者感知的 lane-write fan 合并（352 masked 写 → 1 plain
  写 + 逐 lane 标量 mux），ROB renameTime 族整链消亡（escaped=0）。
  注意：改动 commit 侧写口结构（352→1），目的仍是杀 compute 链；
  commit 成本本身不在本项目优化目标内。
- 顺序：Tier 1 → 验证 → Tier 3 → Tier 2，每步 difftest 守门。
- escape hatch：`WOLVRIX_GRHSIM_AM_DISABLE_CHAIN_REPLAY`（沿用
  `WOLVRIX_GRHSIM_AM_DISABLE_*` 惯例）。

### 3.4 候选挂点（已定）

**已定为 lowering op 级**（`grh_ir_to_grhsim_am_graph.cpp`，
computeFirstUseOrdinals 之后、lowerInstructions 之中）：op↔instr 对链
kind 1:1；valueMap_ 重指机制与 F1 同型；不动 atom 边界/数量/连接
（NO0008 冻结安全）；emitter/解释器零改动（重放产生的是标准 opcode）。

## 5. 实施与实测（Tier 1 + Tier 2 已落地）

实现（`wolvrix/lib/grhsim/am/grh_ir_to_grhsim_am_graph.cpp`，op 级规划 +
lowerInstructions 挂钩，difftest 逐位一致为硬门）：

- **Tier 1（chain replay）**：`planChainReplay()` 按 gsim node 分组做位级段
  溯源 + 组内常量求值；常量值**规划期直接 valueMap_ 重指**（guard-immune，
  覆盖 F1 因乱序无法折叠的常量链）；动态外逃值在组 flush 点按段重放；
  收益门（replay 字数 ≥ 链字数一半则整组回退，ROB 全逃族据此留给
  Tier 2）。escape hatch：`WOLVRIX_GRHSIM_AM_DISABLE_CHAIN_REPLAY`。
- **Tier 2（lane-write fan 合并）**：`detectLaneWriteFans()` 先于链规划
  检测（常量 one-hot lane mask、同 target+event key、lane 两两不交、
  同 key 前序常量写吸收进 old 值）；fan 成员不再计为链值的全值消费者
  → 链整组消亡；`emitLaneWriteFan()` 在 fan flush 点发射"逐 lane
  `mux(cond_k, 窗口, old lane)` concat + union mask + 合并 cond"的单写。
  escape hatch：`WOLVRIX_GRHSIM_AM_DISABLE_LANE_WRITE_MERGE`。
- 仪器：instruction-graph jsonl 导出扩展（additive res/ops/lsb/gnode，
  保持 v1 字段前后缀兼容）；`scripts/no0012_window_provenance.py`。

实测（coremark 50k，taskset 绑核，difftest 4/4 逐位一致 73,580/49,996，
wolvrix `ctest -R grhsim` 17/17）：

| 口径 | NO0011 基线 | Tier1+2 | 变化 |
|---|---|---|---|
| am eval Host（3 次中位） | 486.1 s | **444.4 s**（447.2/444.4/440.6） | -8.6% |
| 其中 compute | ~392 s | ~352 s | -10% |
| 其中 commit | ~94.8 s | ~90 s | -5% |
| 引擎比（vs gsim ~65s） | 7.4x | **6.8x** | — |

簇级（per-block cycles，vs no0010/fix rep1）：

- 修复命中：intRegFile 17632（41.1G→7.3M）、ROB renameTime 族
  75182/75183/75184（合计 -55.8G，链整组消亡）、decode-isMove 77513
  （-20.5G）、77742/38564/49686/1041/83183 等（单块至 -71.7G）；
- 搬迁非回归：writebackTime 链（gnode 926462/3/4，mux-form + **动态
  mask**）从 70436 搬到 70464，per-fire 持平 ~1.8k cycles——Tier 2 对
  动态 mask 不可合并，Tier 1 对 mux-form 不可溯源，**遗留 ~90G**；
- 新成本：fan 数据装配块（or-tree + 逐 lane mux/slice/concat，≈1.4k
  instr/352 成员 fan），752xx/77676/38582 等合计约 +173G——装配成本
  接近 gsim 逐元素量级，但激活率抬升（输入扇入变宽）；or-tree（每 fan
  成员数-1 个 or op）是可削减项（可改"总是写 + changed 过滤"）。

**遗留与下一步**：

1. writebackTime 动态写口族（~90G）：根因是组合数组动态索引写在 IR 层
   无表达（mask/nextValue 全宽物化 + mux-blend 链）。正解=动态 lane 写
   指令族（reg.write.dynlane: cond, index, elemData, target），指令模型
   + commit 语义 + emitter + interpreter 联动，另立项处理（NO0013 候选）。
2. fan 装配激活调优（or-tree 削减、装配块调度局部性）。
3. decode-isMove（926448）/VFMA（297258）大量窄 atom 机制（非宽链），
   已在 §3.2 记录，待独立立项。
