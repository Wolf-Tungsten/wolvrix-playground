# NO0002 三层结构量化对齐（enode↔instr / node↔atom / supernode↔compute block）

日期：2026-08-10
状态：进行中

## 1. 目标与立场

本专题（emit-cost）的最终目的是优化性能，但子项目的当前目标是**定位
emit 形态不良的原因**，不是一步到位优化性能。要干净地分析 emit 差距，
gsim 与 grhsim am 两侧建立的**超图结构必须先严格对齐**——否则单位成本
对比把"分区形状差"和"发射形态差"混在一起，无法归因（NO0001 实测遗留
15.3x 单位成本差即卡在此）。

概念层次映射（相同概念的不同命名，需对齐）：

| gsim | grhsim am | 说明 |
|---|---|---|
| enode | instr | 原子操作（表达式树内的一个算子/引用） |
| node | atom | 折叠表达式树单元（when 树 / tree-atom） |
| supernode | compute block | 活动度分区单元 |
| —（无时钟域概念） | commit block 等 | AM 多出的一侧；**非性能差距的决定性因素，其成本可接受、计量后豁免** |

**对齐要求：三个层次全面量化对齐，理论上应能同时成立，而不是只对齐
其中一个维度。** 只有三层同时对齐，后续才有干净的基板深入 emit 差距
分析。非目标：本立项不做性能优化本身；性能数字仅作为对齐的副产品记录。

## 2. 现状差距（同一 exec-GRH 图，实测）

数据源：gsim 原生构建（`build/xs/gsim/gsim-compile/`，SuperNodeMaxSize=15、
MergeWhenSize=5，管线计数见 gsim-gen-cpp.log）与 AM b2cap（指令预算
32768，`build/logs/no0001-b2/emit_b2cap.log`）。两侧 DP 规则名义一致
（15 members/段、mergeWhen 阈值 5、链合并帽）。

| 层次 | AM | gsim | 比值 | 备注 |
|---|---:|---:|---:|---|
| L1 instr vs enode（静态） | 4,036,478 linear instr | 2,708,065 nodes（每 node 1 assignTree，enode 数待补测） | ~1.49x（按 node 粗估） | AM 指令流含 ~17-20% 调度簿记物化（NO0017 注记） |
| L2 atom vs node | 869,542 atoms | 2,708,065 nodes | **0.32x** | atom 肥 3.1x（4.64 instr/atom vs ~1.49 当量/node） |
| L3 block vs supernode | 28,674 blocks | 84,642 supernodes | **0.34x** | coarsen 存活 20.2% vs 10.9%；DP 6.14 vs 3.46 clusters/段 |

L3 差距的算术分解（0.338 ≈ 三因子连乘）见 NO0001 文末附记；**主因是
L2 单元肥瘦**，但 L1 的簿记物化、slice/concat 显式网络、宽值字循环展开
也可能使 AM 的 instr 流系统性长于 gsim 的 enode 流——需逐层定量。

动态侧（NO0017 D 层 + b2cap）：操作量 1.10x（instr vs non-ref enode/
周期）、组分发 0.32x、rounds/eval 1.5 vs 1——动态形状大体合理，但静态
三层未对齐意味着动态对比仍带形状混淆。

## 3. 嫌疑清单（每层候选驱动因素）

- **L1（instr ↔ enode）**：
  a. 调度簿记指令物化（act/changed/检测器的指令化，~17-20%）；
  b. slice/concat 显式切片网络（NO0016 已知：SV 路线的形态残留）；
  c. 宽值（>64b）按字循环展开产生的 helper 指令；
  d. 常量/复制指令的保留策略差异（gsim 的 ref enode 近免费、常被优化掉）。
- **L2（atom ↔ node）**：
  a. tree-atom fold 比 gsim 节点形成更激进（折整棵组合锥 vs when 树
     为主）；
  b. gsim 的 when 树折叠时机（mergeWhen 时折）vs AM 的 fold 在 atom 化
     阶段；
  c. gsim replication（rep）改变节点数/边形态，AM 侧对应 pass
     （fanout absorb）默认关闭。
- **L3（block ↔ supernode）**：
  a. coarsen 合并率差（80% vs 89%）——mergeWhen 虚拟锚点组（AM 独有，
     state-select 巨组曾达 36,578 atoms）与链合并帽的单位差；
  b. DP 打包密度差（6.14 vs 3.46 clusters/段）；
  c. 以上大体是 L2 肥瘦的衍生，但也可能有独立的分区规则差。

## 4. 实验计划

1. **口径固化**：定义三层各自的静态指标（计数、尺寸分布直方图、跨单元
   边/值数）与动态指标（fires、evals/周期、rounds）；写一个对比脚本
   从 gsim stats json + AM block_assignment.jsonl 双侧产出同口径表。
   enode 静态计数需从 gsim 导出（或按其 stats 推算），ref/non-ref 分开。
2. **L1 归因**：AM 指令流按 opcode/来源分类，标出簿记物化、slice/concat、
   宽字循环等"gsim enode 中不存在"的成分占比；目标给出 instr:enode 的
   干净比值与成分构成。
3. **L2 归因**：atom 尺寸分布 vs node 尺寸分布（instr/atom vs enode/node
   直方图）；标出 tree-atom fold 的肥度来源（何种 opcode 主导折叠体积）；
   评估 fold 帽/规则修正（参照 gsim 节点形成）使 atom:node 收敛。
4. **L3 归因**：在 L2 对齐后复测 coarsen/DP 存活率与块尺寸分布；
   mergeWhen 虚拟锚点组在 exec-GRH 导入路径上的必要性重审（导入图的
   select 是图内节点，state-select 情形的语义可能与原生 SV 路线不同）。
5. **同时对齐验收**：三层静态计数 + 尺寸分布同时落入容差（目标 ≤1.1x
   或明确记录残差原因），产出对齐后的 AM 图与块划分作为 emit 分析的
   干净基板；commit 侧单独计量成本上限后豁免。
6. 对齐完成后重跑 50k coremark difftest（正确性硬约束 73,580/49,996）
   并记录单位成本读数变化（不作为本立项验收指标）。

## 5. 验收标准

- 三层量化对照表（静态计数 + 尺寸分布 + 动态指标）同口径产出，
  三层比值同时 ≤1.1x（或残差有逐条记录的结构原因）。
- 对齐过程只改分区/表示层规则的配置与必要 pass，不牺牲 difftest
  逐位一致。
- 结论明确回答：三层对齐后，剩余单位成本差中有多少可归因于
  纯 emit 形态（生成代码形状），多少归于结构残差。

### 2026-08-10 跨块值 1.83x 残差的严格归因：不是没对齐，是图形态 + mergeWhen

质疑：同图、块数匹配（0.979x），cross_values_compute_network 为何还差
1.83x（313,410 vs 171,021）？分层实验闭合归因：

1. **跨块值 = 每 atom 一个**（去重生产者 atom 后仍是 313,410，
   values-per-atom = 1.0）——粒度膨胀假设证伪，残差为真。
2. **簿记零跨块**（act/changed 值 0 个跨块）；成分：compute 55%（and
   83,403 / eq 36,768 / or / add…）+ mux 28% + slice/concat/assign 17%。
3. **mergeWhen 巨组贡献 60,410**（对齐配置下 mergeWhen 关闭重测：
   253,000 vs 开启 313,410，+23.9%）；其中 ≥1000 atoms 的 232 个巨块
   触及 93,566 个（含小巨组的重叠）。
4. **图形态是主因（~1.48x）**：把 gsim 生产分区器逐行复刻
   （`topo-partition-proj/exp/partition_lab`，NO0014 验证过保真）跑在
   **同一张 AM 图**上（cap9/budget7000/penalty0）：cross = **266,889**
   ——与 AM 自家分区器（mergeWhen 关闭）的 253,000 相差 ±5%。
   **gsim 自己的算法在 AM 的扁平指令图上也切不出更少的边**：
   266,889 vs gsim 原生图 171,021 = 1.56x（两算法取中 ≈1.48-1.56x）。

**结论**：1.83x ≈ **图形态 1.48x（扁平指令形态 + slice/concat 显式网络
本质更难划分）× mergeWhen 1.24x（同 select 巨组拉值过界）**。
对齐的是**分区结构**（块数/member 分布/单元粒度，已达标）；而
cross_values 度量的是**图的可划分性**——AM 导入图（assignTree 展平
为指令 DAG + SV 路线显式切片网络残留）本质上是比 gsim 节点图更难切
的形态。这与 supernode-align NO0016 的图病灶结论在同图上互证。

含义：
- 分区器与分区结构无需再改（两算法同图同结果，±5%）。

### 2026-08-10 "图是 gsim 导出的，为何还有差异"——差异在 gsim 自己的导出格式里

机制实证（`wolvrix_xs_post_stats.json` 与 `SimTop.exec.json` 同源核对）：

- gsim 内部参与分区的是**树形节点图**：2,708,079 nodes，每 node =
  一个值 + 一棵 assignTree（平均 5.1 enodes：1.85 真实算子 + 3.3 引用）。
- gsim 自己的 executable-GRH 导出把这棵树**展平**：5,108,493 vals =
  **2,698,858 个锚点值**（`gsim.v.N`/`gsim.reg.N`，与 gsim 节点一一
  对应）+ **2,409,635 个 `gsim.tmp.N` 临时值**（assignTree 内部件被
  炸成独立值），5,420,299 ops。AM 消费的是这张展平图。

所以"同图"的真实含义是：**语义同一张图，结构两个对象**——gsim 分区
树形图（cross=171,021），AM 分区展平图（cross=253,000，mergeWhen 关）。

同对象对照（决定性）：gsim 分区器的逐行复刻跑在**同一张展平图**上
cross=266,889（cap9/budget7000）——展平的可划分性代价是 gsim 自己的
导出格式制造的（171,021 → 266,889 = 1.56x），与 AM 无关。**在展平图
这个同一对象上，AM 分区器（253,000）比 gsim 复刻（266,889）还低 5%
——同图同算法口径下 AM 分区已对齐并微优。**

最终账目（cross_values_compute_network，gsim 树形分母 171,021）：
- AM 313,410 = 1.83x = **导出展平 ~1.5x**（gsim 自己导出器造成）
  **× mergeWhen ~1.24x**（AM 侧同 select 巨组）。
- 结构对齐（L1/L2/L3）与分区器质量均无罪；剩余杠杆：mergeWhen 巨组
  成本闸门、以及（若要对 gsim 树形口径）导入时按 2,698,858 个锚点值
  设 atom 屏障、把 gsim.tmp 折回——属"复刻 gsim 节点边界"的可选验证项。
