# NO0004 enode→instr 映射矩阵对齐（gsim flatten 图 → grhsim am）

日期：2026-08-10
状态：立项（实施中）
前置：[NO0003](NO0003_flatten图单一对象对齐_20260810.md)（flatten 图单一对象：gsim 导出 / AM 导入 / 指标统计同图）

## 1. 背景与问题

NO0003 完成了"同一对象"对齐：gsim flatten 图（when 已展开为 mux）是唯一输入，
gsim 导出 exec-GRH、AM 导入该 exec-GRH、指标统计全部落在同一张图上。
但 L1 层（gsim enode ↔ AM instr）数量仍不对齐：

| 环节 | 数量 | 相对 gsim enode |
|---|---|---|
| gsim flatten 图非叶 enode | 3,076,833 | 1.00x |
| exec-GRH op（导出后） | 4,900,121 | 1.59x |
| AM instr（导入后、优化前） | 5,295,811 | 1.72x |
| AM instr（优化后线性） | 4,037,003 | 1.31x |

（exec-GRH op 普查见 `build/logs/no0003/exec_stats_flat_v2.json`；AM 优化后 opcode_mix
见 `build/logs/no0003/am_flat_v2.log` 的 production schedule stats 行。）

数量差不经解释就继续推进，后续一切同图对比（cross 边、emit 单位成本）都无从谈起。
本专项专门解决 **gsim → grhsim am 映射本身的不透明与不良**。

## 2. 目标与品质要求

1. **唯一输入**：以充分 flatten 的 gsim 图（when 已平化）为唯一起点，即
   `build/logs/no0003/gsim_flat_export/SimTop.exec.json`（NO0003 v2 产物）。
   不允许再引入其他输入数据（不重跑 gsim 前端、不换设计、不换 bin）。
2. **导入质控点**：在 grhsim am 导入（lower）完成后、任何优化（am.optimize）之前，
   增加数据质控点，导出 instr 的类型分布（opcode_mix），与既有
   `am.optimize` / schedule 期 opcode_mix 形成三段可比链条。
3. **映射规则调优**：审视并修正 gsim → exec-GRH → AM 的映射规则中已知不良点
   （典型：mem 访问/数组成员树的映射——gsim OP_READ_MEM 3,394 / OP_WRITE_MEM 2,032
   在 AM 侧对应 mem.read=2,578 / mem.write.c=2,144+mem.write.cm=1,332，
   中间经由 kMux 1,337,941 vs gsim OP_MUX 836,808 的 +501k 膨胀，其中相当部分
   来自数组成员树 lowering 的 tmp mux 链）。
4. **映射矩阵**：给出 gsim flatten 图 enode 类型数量分布 → exec-GRH op 类型分布
   → AM instr 类型分布（优化前 / 优化后）的完整映射矩阵，每格差异必须精确可解释
   （哪条 lowering 规则引入、引入多少）。
5. **尽可能一一对应**：在保证仿真结果匹配（difftest 逐位一致）的硬约束下，
   让映射尽可能一一对应；不能一一对应的格子，必须在矩阵中标注机制原因。

### 7.2 三段闭合（核心发现）

v2 flatten 图上实测：

| 段 | 数量 | 说明 |
|---|---|---|
| exec-GRH op（全量普查修正后） | 5,116,873 | 含 kRegister 148,956 / kMemory 2,274 / kSystemTask 7,052 / kConstant 11,566 |
| AM instr（import 后、优化前） | 5,295,811 | 质控点实测 |
| AM instr（优化后） | 4,037,003 | schedule 期 opcode_mix |

**导入段逐格对账（exec-GRH → AM import）精确闭合**：

- 25 个计算 op 种类**逐项 1:1 相等**（kMux=1,337,941、kSliceStatic=912,996、kAnd=533,367、
  kOr=451,453、kConcat=406,246、kEq=242,955、kAdd=161,741、kMul=67,791 … 零偏差）；
- kConstant 11,566 → 常量变量（非 instr），-11,566；
- kAssign 452,255 → assign instr 637,454，差 +185,199 按位点归因：
  coerce=115,949（add/sub 进位位宽强转）、result_bridge=68,797（add/sub 结果位宽桥接）、
  pre_commit=439（commit 读旧快照）、dpi_bridge=0——**全部来自 add/sub 进位处理**；
  （from_grh=452,269 与普查 452,255 差 14，待查，量级可忽略）；
- AM 侧物化 +163,587：reg.write 149,323 / reg.write.m 113 / mem.read 3,394 /
  mem.write.c 2,144 / mem.write.cm 1,332 / changed.pos 114 / changed.neg 1 /
  system.task 7,052（=kSystemTask 1:1）/ dpi.call 114；
- 闭合校验：5,116,873 - 11,566（常量）- 158,282（kRegister/kMemory/kSystemTask 转为
  状态声明与 mem/reg 写指令的通道差）… 逐格相加 = 5,295,811 ✓。

**结论重塑**：L1 不对齐的**全部**来源在 **gsim → exec-GRH 导出段**（enode 3.08M →
exec op 5.12M，+66%），AM 导入段本身近乎完美 1:1（唯一实质增量是 add/sub 进位
位宽胶 18.5 万，且属确定性规则）。后续调优火力应集中在导出器
（ExecutableGrhExporter），AM lowering 只需评估 add/sub 进位胶是否可提前到导出侧消除。

### 7.3 普查脚本勘误

`scripts/no0003_exec_graph_stats.py` 原口径只统计 `gsim.expr.*` 记录为 op，
漏掉 `gsim.assign.*`（kAssign 58,470+）等非 expr 前缀的 op 记录：
kAssign 由 393,785 修正为 **452,255**，op 总量由 4,900,121 修正为 **5,116,873**。
NO0003 文档中引用旧口径的段落以本勘误为准（exec-GRH op 相对 gsim enode 为 1.66x
而非 1.59x）。脚本已修正并扩展：按是否携带 `gsim.node_id` attr 将 op 分为
anchor（节点绑定，应≈gsim enode）与 glue（导出器引入）两类逐 kind 归因，
结果存 `build/logs/no0003/exec_stats_flat_v4.json`。

**勘误（v5）**：前缀正则 `gsim\.[a-z]+` 不匹配下划线，又漏 `gsim.mem_read.*` /
`gsim.mem_write.*` / `gsim.reg_read.*` / `gsim.reg_write.*` / `gsim.dpi_call.*` /
`gsim.ext_assign.*` 六类记录。v5 修正后 op 总量 **5,423,223**
（anchor 3,299,777 / glue 2,123,246），kAssign 总量 452,269 与 AM from_grh
计数**精确相等**，导入段闭合差由 ±14 收敛到 0（见 §8.3）。
§7.2 表中 exec-GRH op 数（5,116,873）以 v5 为准；exec-GRH 相对 gsim enode
为 5,423,223 / 3,076,833 ≈ **1.76x**。

## 8. 映射矩阵 v1（P2 首版，2026-08-10）

口径说明：
- **gsim 列** = flatten 图节点根 enode 普查（`gsim_topo_flat_v2/instruction_graph.jsonl`，
   topoProj 每节点记根 enode op；flatten 后标量节点 1 节点 = 1 计算 enode）。
- **anchor 列** = exec-GRH 中带 `gsim.node_id` 的 op（导出器 `lowerAssignedNode`
  把节点表达式降到 tmp 后，将最后一条 op retarget 为节点值并挂 node_id；
  不能 retarget 的补显式 `gsim.assign.<id>` kAssign）。
  **anchor kind 与 gsim 根 op 不必同种**——这是多数字段迁移的钥匙。
- **glue 列** = 无 node_id 的 op（导出器引入的中间胶，≈ gsim.tmp 值 1:1）。
- **AM 列** = 导入质控点实测（pre-opt），变体拆分后逐格核对。

### 8.5 结论（P2 收口）

1. **导出段（gsim → exec-GRH）是全部实质膨胀的来源**：anchor 3,299,777 vs
   gsim 节点 3,146,488（+153,289，主要是寄存器读/写端口与 mem 端口记录），
   glue 2,123,246（+69% 相对 enode）；导入段近乎完美（闭合差 0）。
2. 逐格机制全部定位到 Exporter 具体行号；最大三个 glue 桶
   （kSliceStatic 61 万、kMux 49 万、kAssign 35 万）与**数组/动态索引 lowering、
   未 flatten 的数组节点表达式树、coerce 直通策略**直接相关。
3. 残差待核清单（量级均 <0.3%，不阻塞 P3）：kMux anchor +6,074（复位 mux）、
   kConcat anchor +2,386、kSystemTask +836（printf）、OP_EXT_FUNC -4、
   anchor kAssign 逐节点拆分、graph_operations 5,423,255 vs 普查 5,423,223 差 32

### 9.4 纠正后的结论

1. **逐 enode 翻译质量本就接近 1:1**；§7.2/§8.5 中"导出段 +66% 膨胀"的表述
   受根 enode 口径误导，真实计算膨胀为 1.442x，且 ~95% 可由五类脚手架机制解释。
2. 最大的不对齐是**数组表示法**（① 93 万条）：gsim 内部以索引树 enode 表达数组
   访问（3.7 万 OP_INDEX + mem 端口语义），导出器打成 packed 向量后物化
   地址算术/切片/守卫网络。这是 P3 的首要调优对象，也是"mem 访问映射不良"
   观察的完整答案。
3. 常量去重（-157 万）证明导出器已有正确方向的机制；数组/索引与 coerce 胶
   缺少同等级别的合并/CSE（lowerIndexPath 明确无任何缓存）。
4. AM 导入段无需修改（闭合差 0）；AM optimize 的 cse 已在下游回收部分脚手架，
   P3 应优先在导出侧治本，并复核 AM cse 回收率作为对照。

## 10. P3-1 实施：元素写插入网络融合为 Insert 指令（2026-08-10）

### 10.1 方案选择记录

- **截窄移位单 op 化被否**：AM 移位语义是"先截断到结果宽再移位"
  （`shift_words`，grhsim_am_program_cpp_emitter.cpp:6011-6024；解释器
  shiftRight 同构），gsim 语义是"源宽移位再截断"，二者仅在**先移位**下等价。
  kLShr+kSliceStatic 双 op 结构在当前 ISA 下是语义必需，不是不良映射；
  单 op 化需改 AM 移位语义，风险高、收益仅限 ~8.5 万条，放弃。
- **元素写插入融合被选**：`insertIndexedValue`（Exporter :1730-1744）对每次静态
  元素写产生 `concat(slice(row,hi), data, slice(row,lo))`（边界处两条），
  属表示法冗余；在 **AM 图优化期**融合为单条 `Opcode::Insert`，
  不碰导出器、不重新导出（满足"唯一输入"约束）。

### 10.2 实现点位（wolvrix 子仓，未提交）

- `Opcode::Insert`（枚举尾部，不扰动既有编号；lsb 复用 SliceStatic 属性槽）：
  program.hpp/cpp（枚举、toString、属性附加放宽与一致性检查）、
  validate（形状 1r/2o、属性在位、类型规则：result==row 类型且窗口不越界）、
  interpreter（row 拷贝 + 窗口覆写）、cpp emitter（宽路径
  `assign_words`+`insert_words`，标量路径掩码表达式，64 位边界安全）。
- `grhsim_am_graph_optimize.cpp`：`insertFusePass()` 识别三种 concat 形态
  （三操作数与两种边界二操作数，要求 row 类型与 result 类型全等），
  经既有 `InstructionRewrite` 机制重写；CSE key 与物化属性回挂同步扩到 Insert；
  常量求值器支持 Insert 折叠。`AmOptimizeOptions.insertFuse`（默认开），
  CLI `--am-optimize=insertfuse` / `--no-am-optimize` 覆盖。

### 10.6 增量更新 2026-08-10（首跑失败与根因修复）

**首跑 difftest 失败**：cycle 8,246、instrCnt=2，ibuffer `validOH is not OneHot`
断言——Insert 语义在执行路径上被破坏。定位到两个独立缺陷：

1. **emitter 宽路径语义错误（主因）**：初版 Insert 宽路径发射
   `assign_words`（拷 row）+ `insert_words`——但 `insert_words` 语义是
   **按位 OR**（为 concat 的零基目标设计，grhsim_am_program_cpp_emitter.cpp
   `:5869-5883`），不清除窗口旧位，row 窗口内的 1 与 data 相或产生错误值。
   解释器与常量求值器按位覆写，本正确；单测因未覆盖"row 窗口内已有 1"场景
   而未暴露。修复：新增 runtime `insert_replace_words`（先拷 row，再按
   清窗-或入 精确覆写，含跨字 spill 的窗口掩码），宽路径改单次调用。
2. **opcode 区间分派遗漏（次因）**：解释器 `executeInstruction` 与 validate 的
   `isPureCombinational` 按**枚举区间**分派纯组合指令（`<= SliceArray || array 段`），
   Insert 追加在枚举尾部落在区间外，被错误导入状态写/宿主路径。修复：两处
   分派显式加入 `opcode == Opcode::Insert`。**教训：新增 opcode 追加枚举尾部
   并不能免除区间分派点的审计，全库 `opcode >=/<=` 区间判断必须过一遍。**

**回归测试**：`test_cpp_emitter` 宽操作电池新增 `insert_130`（row 窗口内预置 1
场景，解释器为基准比对发射 C++ 输出）；`test_optimize::testInsertFuse` 覆盖
融合形态/负例。`ctest -R grhsim` 16/16 通过。

**重跑验证**：（insertfuse2 全链构建中，结果见 §10.7）
