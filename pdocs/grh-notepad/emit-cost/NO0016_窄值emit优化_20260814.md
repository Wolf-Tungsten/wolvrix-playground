# NO0016 窄值 emit 优化（存储分档 + chunk 内标量化）

日期：2026-08-13
> 状态：**已收口**（2026-08-14）。Stage A（窄存储分档）实测持平被 microbench
> 证伪假设；Stage B（chunk 内值标量化）落地：difftest 3/3、ctest 17/17、
> QC block_atom 逐字节一致；eval Host 366.6s→**348.3s**（-5.0%），compute
> 单元 801.0G→738.0G（-7.9%）。
前置：NO0015（精准匹配对差分：尾部 289 对持 148G，机制=窄值网络 uint64 统一槽）
来源：用户 2026-08-13 指令——完成窄值 emit 优化。

## 1. 问题（NO0015 的实证）

同一份 7,001 节点窄值网络（intBusyTable/BPU abtb 族），gsim 发密集 uint8
标量局部量（~150 cycles/遍），AM 发 `uint64_t localblk_<id>[N]` 统一槽 +
逐 op `resize_value`/掩码包装（~25 cycles/instr，per-fire 303K cycles）：
每个 1-bit 值占 8 字节内存槽，11,368 槽 = 91KB 栈数组击穿 L1，访存受限。

## 2. 设计

**block-local 值按宽度分档存储**：

| 档 | C 类型 | 宽度 |
|---|---|---|
| 0 | `std::uint8_t` | ≤8 bit |
| 1 | `std::uint16_t` | ≤16 bit |
| 2 | `std::uint32_t` | ≤32 bit |
| 3 | `std::uint64_t` | 其余（含 >64 的遗留行为） |

- inline 块：分组标量声明（`std::uint8_t local8_0, ...;`；3 档保持旧名
  `local_<k>`，escape hatch 下输出与 NO0015 前逐字节一致）；
- chunked 块：单一 uint64 数组拆成 per-class 类型化数组
  （`uint8_t localblk8_<id>[n8]` 等），chunk 函数按非空类各传一个
  `__restrict__` 指针；
- `localValueIndices` 改为**类内密集序号**。

### 安全性论证（为什么窄化不丢语义）

1. 写侧：`resultAssign` 一律把结果掩码到值宽（逐处核实，含 branchy mux
   显式掩码）；无掩码写入的位段也只会污染"值宽以上"的位。
2. 读侧：一切表达式操作数经 `resize_value`（按显式位宽掩码）；`boolExpr`
   为 `!= 0`（截断中性）。窄化仅丢弃"存储宽以上"的位，而这些位在读写
   双侧纪律下本就不可观测。
3. 取地址的值**必须留 uint64**：审计出的 word 指针流（`slice_words` 窄
   target、`slice_dynamic_words` 索引、`insert/replace/blend/shift/
   bitwise_words` 窄源）全部来自——
   - 含非标量（>64b 或非 BitVector）操作数/结果的指令（走
     emitNonScalarInstruction/wide-assign 路径）；
   - NO0013 windowed / NO0014 dynblend 计划指令（其 cone 具名字段
     base/idx/ones/elem/cond/result 由 tail 发射处取地址，不一定是该
     指令自身操作数，故从 plan 直接钉住）；
   - memory/array/system/host 操作码（其值本就 escape，钉住是双保险）。
   `classifyLocalValueStorage` 按此钉住（pinWide），其余按宽度分档。
   **漏钉会被 C++ 类型系统以编译错误硬拦**（`uint8_t*`→`uint64_t*`），
   不会静默错编译；difftest 逐位门兜底。

### escape hatch

`WOLVRIX_GRHSIM_AM_DISABLE_NARROW_LOCALS`：全部钉 3 档，输出与旧版
逐字节一致（3 档名 `local_<k>`/`localblk_<id>[k]` 与旧拼写相同，且全 3
档时类内序号 == 旧扁平序号）。

## 3. 实施落点（wolvrix/lib/grhsim/am/grhsim_am_program_cpp_emitter.cpp）

- `EmitState`：`localValueClasses`（每变量档位）、
  `activeLocalityDeclClasses`/`activeLocalityClassCounts`（活动块类内序号
  与计数）、`narrowLocalPinned` 统计；Stage B 增 `chunkScalarIndex`
  （≠kInvalidChunkScalar 即 chunk 内标量及其类内序号）、
  `blockChunkScalarCounts`（每块每 chunk 每档声明计数）、
  `chunkLocalScalarCount`；
- `classifyLocalValueStorage`（新，Stage A）：在所有 emit 计划
  （windowed/dynblend/mux 融合）之后运行（读取其计划数组做钉住）；
- `planChunkLocalScalars`（新，Stage B）：复用 `blockChunkRanges`（与发射
  同参数：chunkInstructions + blockCommitGate headCount）做 chunk 归属，
  一遍指令扫描得首读 chunk/冲突标记，按规则指派 chunk 内标量序号；
- `valueExpr`/`localValueDeclarations`/`chunkedLocalValueDeclarations`/
  `blockChunkParamsFor`/`blockChunkParameterList`/`blockChunkArgumentList`/
  `writeChunkedBlockBody`（chunk 内标量声明）全部按档分发；3 档保留旧
  拼写；
- 统计：`narrow_local8/16/32/64` + `narrow_local_pinned` +
  `chunk_local_scalars` 进 locality stats。

## 4. 验证与实测

### 4.1 Stage A（仅存储分档）：持平，假设证伪

- wolvrix ctest 17/17；xiangshan emu 构建零错误（编译期类型系统佐证
  钉住规则无漏）；difftest 3/3（73,580/49,996）；QC block_atom /
  instruction_graph 对 NO0014 逐字节一致。
- Host 中位 **366.9s vs 基线 366.6s（持平）**；目标块 ±1-5% 噪声带内。
- **microbench 证伪"存储宽度主导"**（`build/logs/no0016/microbench/mb.cpp`，
  8K 值依赖链）：AM 数组+胶形态 3.86 cycles/op；数组去胶 3.26（胶仅 ~15%）；
  **寄存器标量 0.29 cycles/op（13x）**。真因=值在内存数组里的 store→load
  往返（依赖链逐拍 stall），不是槽宽。

### 4.2 Stage B（chunk 内值标量化）：落地收益

在 Stage A 的分档之上， oversized（chunked）Block 的"定义与所有读取都在
同一 chunk 内"的 localizable 值改为 **chunk 函数内类型化标量**（寄存器
候选），仅跨 chunk 值保留共享数组。规则：class<3（未钉住）+ 首读 chunk ==
def chunk + 未被 mux 融合覆盖（融合成员的读写锚定在 run head 位置，一律
留共享数组）+ 至少被读一次（避 -Wunused-variable）。误分类会被编译器以
undeclared identifier 硬拦，不静默。escape hatch：
`WOLVRIX_GRHSIM_AM_DISABLE_CHUNK_LOCALS`。

实测（coremark 50k，taskset -c 12，3 reps 中位）：

| 口径 | NO0014 基线 | NO0016 Stage B | Δ |
|---|---|---|---|
| Host | 366.6s | **348.3s** | **-5.0%** |
| compute 单元 | 801.04G | 738.00G | **-7.9%** |
| commit 单元 | 328.92G | 319.43G | -2.9% |
| difftest | 73,580/49,996 | 同，3/3 | ✓ |
| QC block_atom | — | 逐字节一致 | ✓ |

块级（rep1 对照，超 ±5-12% 噪声带为真修复）：

- **窗口链块（F1/dynblend 族）最大赢家**：b77932 19.1G→5.9G（-69%）、
  b77811 -73%、b77949/77947/77937 -62~-63%——链值不再穿数组；
- 窄值网络族：b57029 per-fire 303K→266K（-12%）、b77348 -9.5%、
  b75472 -46%、b77350 -35%、b22035 -38%；b83400 68.0G→61.9G（-9%）；
- 个别小块 +5~9% 微回归（绝对值 <0.3G，噪声/调度抖动量级）。
- 匹配对口径（NO0015 脚本重测）：>100x 尾部 148.0G→136.0G（-8%），
  加权比 8.06x→7.62x，匹配 Δ 217.1G→203.6G。

## 5. 残留与下一步候选

1. **融合 mux 分支**（Stage B 后尾部主账嫌疑）：窄值网络块仍有 ~18% 行是
   数据依赖 if/else（branchyMux 形态，当年为 clang 编译时长引入），
   每次 mispredict ~15-20 cycles。b57029 寄存器化后仍 22 cyc/instr
   （microbench 纯链 0.29），分支误预测是最可能的残留大头。候选：窄值
   mux 的 branchless/select 形态（注意当年 ternary 巨体的编译时长坑，
   需限定范围或按块决策）。
2. b38653（top-1 匹配对，24.2G）对 Stage B 无感（+0.1%）——其成本
   另有来源（跨 chunk 共享值/状态读为主？），单独分解。
3. resize/mask 去胶（microbench 示 ~15%）、helper 内联化（遗留微优化）。
4. commit 账 ~319G：维持既有裁决不动。
