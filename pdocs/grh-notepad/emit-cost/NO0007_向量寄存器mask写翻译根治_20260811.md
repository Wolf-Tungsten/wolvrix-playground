# NO0007 向量寄存器 mask 写翻译根治（2026-08-11）

## 1. 背景与问题陈述

两项已记录发现同源，合并根治：

1. **NO0005 §6**：向量寄存器（register array）的条件部分更新被 exporter 译成
   功能式全量合并 mux 链（slice→and/not→mux→concat 重打包，~170 层/树，
   ~380 instr/树，全部永算），而非 AM 原生支持的 mask 写；写回是单条全量
   reg.write（mask 恒全 1：.c 149,323 vs .m 仅 113）。gsim 自身 emit 就是
   if 门控 RMW 的 mask 写形态（`instsWhen`）；同一 exporter 的 mem 路径
   （`lowerMemoryWriteExpression` 逐写叶发 kMemoryWritePort）已是正确做法。
2. **NO0006 §11.7**：边对账残差（AM-only ~22k + gsim-only ~24k 镜像）实证为
   寄存器数组逐位读/写 lowering 的 **node_id 戳置换**（同值同消费集、戳错
   兄弟位切片节点），簿记伪差，与本条同源同路径。
3. **NO0006 §11.6 编译事故**：该翻译还制造 145,450 指令巨 atom（10.6 万行
   单函数），-O3 四个 TU 卡死，3 个 -O1 + 1 个 -O0 才链上。

## 2. 目标

- exporter 寄存器写路径：复用 mem 骨架遍历，逐写叶发 mask 写
  （reg.write.m：cond+mask+nextValue），替代 `insertIndexedValue` 功能式合并；
  同一路径内修正 node_id 戳归属。
- AM 导入：放开"1 寄存器 1 reg.write"假设（现 149,436 精确 1:1），定义同
  寄存器多 mask 写的**源序 last-win**（参照 exec 侧 `memoryWrite.priority`
  先例）；同寄存器所有写同事件签名→同 commit 块，沿用时钟域聚类规则。
- 复位优先级：同步复位 = 全 1 mask 写排最后（赢过普通写）；异步复位走 event。
- 正确性硬约束：重叠 mask 同周期双写、partial invalid、读写同周期——difftest
  逐位一致为验收线。

## 3. 验收线（goal completion criterion）

1. difftest：instrCnt=73,580 / cycleCnt=49,996 / IPC=1.471718 逐位一致；
2. 最大 atom 指令数 145,450 → 千级以下；emu 全 TU 正常优化级别编译链接；
3. 边对账：位切片戳置换家族清零，recall/precision 优于 99.20%/96.88%；
4. AM compute instr 总量下降实测（收益上界 ~76 万 ops，NO0005 §6.4）；
5. coremark 50k 实测记录，与 683.7s 基线对比。

## 4. 步骤分解

- P0 代码精读：exporter 寄存器写路径 vs mem 写路径；AM 导入单写假设位置。
- P1 exporter：寄存器 when 骨架逐叶 mask 写导出 + 戳修正；小规模用例先行。
- P2 AM 导入：多 mask 写接收（源序 last-win）、复位优先级、commit 聚类。
- P3 全量重导 exec.json + AM 复测（巨 atom、instr 总量、L1/L2/L3）。
- P4 边对账 + difftest + emu 编译 + coremark 50k。
- P5 文档回填。

## 5. 风险

- 多写口语义变更波及 AM optimize/partition/emit 全链（act.f、changed 聚合、
  commit 块事件签名一致性检查）；
- mask 写运行时形态变化（cond 门控跳过 vs 永算 mux 链）对 coremark 的影响
  需实测，不排除个别路径回退；
- 戳修正依赖对 exporter 位切片批量 lowering 循环的正确定位，若错位源头在
  更上游（flattenNodes 的节点生成顺序），修法需相应调整。

## 6. P0 重大发现（2026-08-11）：边残差≠翻译缺陷，是跨运行 node id 空间不稳

开工精读时的链式实证（全部基于既有 dump，无需重跑）：

1. exec.json 内 `gsim.v.9909398` 的名字是 `fuTypeVec_9$12_12`，而 topoProj
   普查内 9909398 是 `age_2$io$$enq_1$2_2`；反向亦然（exec.json 9909328 =
   `othersEntriesComp_14$…$srcType_2$1_1` REG_SRC，topoProj 9909328 =
   `fuTypeVec_9$12_12`）。**同一 node id 在两份产物里指向不同逻辑节点**。
2. 机制：splitArray/splitNodes/flattenNodes 晚创建的成员/位切片节点拿
   `Node::counter++` 高段 id；splitArray.cpp 用 `std::set<Node*>` /
   `std::map<Node*,…>`（**按指针值排序**，splitArray.cpp:14-17/68/70/351/386/513）
   驱动拆分与成员创建（`arrayMemberNode`, splitArray.cpp:477），堆布局逐进程
   变化（ASLR）→ 创建顺序不稳 → **id 仅单次运行内自洽**。exec.json（11:52
   运行）与 topoProj（13:11 运行）是两个进程 → 晚创建节点 id 置换。
3. 范围：错配集中在 $/_ 后缀的成员与位切片节点（9.9M 高段 id），基础节点
   （如 4115890）两侧一致——与 recall 99.2% 的"多数稳定"观测吻合；两次运行
   的 pass 统计逐项相同（splitArray 856 / flatten newNodes 423,179），图结构
   等价，只是 id 标签不同。
4. 结论：NO0006 §11.7 的"exporter 戳置换"判断**再次修正**——exporter 无错，
   AM 导入无错，是**测量基础设施错**（两个进程的 id 空间不可比）。difftest
   逐位一致本就旁证：若真换源，功能必错。
5. 修法（零代码）：**单次运行同时导出两份产物**——graphPartition() 内
   instruction_graph.jsonl（graphPartition.cpp:371）与 exec.json（:377）
   本就相邻且都在 PreCoarsen 前；命令去掉 `--stop-after-stage=PreCoarsen`、
   同时给 `--export-topo-proj` 与 `--export-executable-grh` 即可同进程同 id
   空间产出全套（含 coarsen/dp 块指派）。coremark-stub profile 只影响 exporter
   外部实例选择（ExecutableGrhExporter.cpp:226），不改图构造，组合安全。
   本专项 P3 起改用该单跑流程；gsim id 确定性（指针序容器改稳定序）记录为
   已知瑕疵，不在本专项修。

## 7. P1/P2 实施记录（2026-08-11）

**exporter（reference/gsim/src/ExecutableGrhExporter.cpp）**：

- 新增 `LoweredRegisterWrite` 结构与三个函数：`lowerRegisterWriteLeaves`
  （when 骨架控制遍历，镜像 `lowerMemoryWriteExpression`）、`appendRegisterWrite`
  （镜像 `appendMemoryWrite`：静态下标→常量 range mask；动态下标→shl 造 mask
  且 inRange 并入 cond；数据按零基打包 `insertIndexedValue`）、
  `appendRegisterSyncReset`（同步复位=全 1 mask 的末位写叶，源序最后→赢；
  广播规则沿用 `lowerRegisterReset` 的 OP_INT 限定）。
- `emitRegisterWrites` 分流：`usePerLeafRegisterWrites`（dst 数组类型 且
  非 ASYRESET）→ 逐叶写；其余（标量/异步复位数组）维持原单写全量合并路径。
  叶计算 op 打 dst 的 node_id 戳，写端口 op 打 src 的戳（名
  `gsim.reg_write.<srcId>.<leafIdx>`）。不加 `memoryWrite.priority*`（AM 对
  寄存器写会报错；同 target 多写本来就按 op 源序 last-win）。
- `lowerAssignedNode`：走逐叶路径的数组 REG_DST 直接标记 assigned、不再
  物化功能式合并值（巨 mux 链的源头被掐掉）。安全性实证：全量 exec.json
  扫描 REG_DST 值符号的全部引用方 = kRegisterWritePort（74,812）+
  register_reset kMux（74,144）+ kMemoryReadPort prewrite_read_data（480，
  均为标量 mem 读地址寄存器，$NEXT）——数组 REG_DST 值无第三方读者。
- `lowerMemoryGuard` 微优化：guard 一侧为常量 1'h1 时直接返回另一侧
  （`isConstOneBit`，emitConstant 记忆化判定），消除每层 when 的冗余
  and(1,·)；mem 路径同源受益。

**AM 侧（wolvrix）**：零功能改动。`materializeStateWrites` 的 per-target
ordered-effect group 原生支持同寄存器多写源序 last-win（同签名→同 commit
块），解释器与 cpp emitter 的 mask 写语义 `(t & ~m) | (d & m)` 早已就绪。
仅修正 `grh_ir_to_grhsim_am_graph.cpp:2228` 一处过时注释（"collapse to one
write per signature" 与实现不符）。ctest grhsim-am 15/15 通过。

**小用例验证（reference/gsim/test/executable-grh-vector-register-writes.fir）**：
嵌套 when 静态叶 + 动态下标叶 + 同步复位聚合初始化 + 标量对照。结构断言
（checker py + Makefile 目标注册）：v=4 写（mask 0xff00/0xff00/0xff0000/
动态 shl）、r=2 写（末叶 sync 全 1 mask）、s=1 写（旧路径不变）。语义对拍
（AM emit C++ + 5 周期手写激励）：含同元素同周期双叶 last-win（v[2]=0x77
胜 0x11）、复位优先、保持语义的边界，全部通过。

## 8. v1 全量结果与两个修正（2026-08-11）

**v1（仅非异步复位数组走逐叶）实测**：

- 逐叶路径只覆盖 **850/2,356** 个数组 REG_DST（9,067 条叶写）：**1,496 个
  向量寄存器带异步复位被保守排除**——XiangShan 的大向量状态（ROB/队列/
  重命名表）全是 async reset。mux 仅 -12k，远不及 ~76 万预期。
- **验收线(3) 已达成**：单跑双产物（同进程同 id 空间）后边对账
  gsim-only 35,798→**12,617**、AM-only 142,701→**112,185**（余项
  74,059+37,566+282+198+80 恰好全部是复位胶/状态端口附加层，白名单），
  recall 99.20%→**99.72%**、precision 96.88%→**97.55%**。位切片"戳置换"
  家族清零——坐实其为跨运行 id 伪差，非翻译缺陷。
- **巨 atom 未动（145,450），且真凶不是寄存器写**：audit 显示该 atom 宿主
  node 2365441 = `decoderComp$csBundle$$lsrc`（w1560 = dims[65,4]×6b，
  数组类型 OTHERS 中间值）——**译码器逻辑锥整体装在一个聚合数组成员节点内**，
  flattenNodes 的 `isFlattenTarget` 排除数组类型节点（isArray），exporter 把
  整棵树 lowering 成 ~14.5 万 op 全打一个 node 戳。属 NO0003 归因的
  "(c) 数组成员树 lowering" 桶，与 when 骨架是两个病灶。≥1000 instr 的
  atom 共 70 个，前 5 个（145k/69k/50k/48k/42k）全是 decoderComp 字段 +
  dcache bloomFilter data_next（数组 OTHERS）。

**修正 1（异步复位扩展，已实施）**：逐叶路径放开 ASYRESET——复位叶携带
第二事件（reset 信号 posedge），cond=复位条件，全 1 mask，源序最后：
无时钟沿时 reset posedge 触发；时钟沿且复位有效时末位叶压过普通叶；
复位释放后普通叶恢复。与旧单写路径 `mux(rst, rv, normal)` 语义逐态等价。
小用例已加异步寄存器 + 三场景（无沿复位/沿上复位优先/释放后写落）对拍通过。

**修正 2（待立项）**：聚合数组成员巨树（decoder 锥）需要 flattenNodes
支持数组类型 OTHERS 节点的抽取（下钻 OP_GROUP 子表达式），或 emitter 侧
原子内分块。这是验收线(2) 的前提，超出本专项的写路径范围，拟立 NO0008
处理（见 §9 待定）。

## 9. flattenNodes 扩展：数组中间值的元素锥抽取（2026-08-11）

为消 decoder 锥巨 atom（验收线 2 的前提），flattenNodes 增加数组类型
OTHERS/OUT 节点的打平：

- `isFlattenTarget` 放开数组 OTHERS/OUT；**数组 REG_DST 仍排除**（其 when
  骨架是逐叶 mask 写的控制结构，§7）。
- 数组节点不做 when 展开、不做多树链拆（那些是标量语义；数组级 when/mux
  是宽 op，一条指令而已，无需拆）；**只下钻 OP_GROUP 并抽取其下的逐元素
  计算锥**（标量，新节点无需 dimensions）。
- 失败教训：第一版对数组节点也做 phase-1 链拆，`$whold` 节点未带
  dimensions，exporter 报 "packed array cannot be coerced to a different
  scalar width"（loadQueueReplay exceptionVec$whold0）——修正为数组节点
  跳过 phase-1 后消失。
- 实测 flatten 统计：候选 2,540,405→2,542,912 节点，新节点 423,179→
  **693,010**（+27 万来自数组元素锥），post-check 0 违规。
- 小用例加数组中间线网 `w[4]`（add/and/or/xor 元素锥 + 动态读）对拍通过。

### §9 补记：抽取规则的二次修正（宽度规则）

第一版"只下钻 OP_GROUP 抽元素锥"实测抽取为 0（newNodes 维持 423,179）——
decoder 锥的元素不是挂在 GROUP 下，而是挂在数组级 CAT/mux/when 骨干下。
修正为**宽度规则**：数组节点树内，凡宽度 < 数组全宽的计算 enode 即抽出
（元素锥/条件锥均为窄值）；全宽操作数（数组级 mux/when/concat 骨干）保留
原位但继续下钻。数组节点仍跳过 when 展开与链拆。被抽子树整体被引用、
无索引访问，故新节点无需 dimensions（规避了 whold 崩溃的同类问题）。

### §9 三次修正（2026-08-11 晚）：真因定位与 flatten 扩展回退

调试运行（GSIM_DEBUG_ARRAY_FLATTEN）拿到决定性数据：巨 atom 宿主的树形态是
**单节点挂海量逐元素 assignTree**——bloomFilter data_next 12,288 棵、
csBundle$$ldest 1,364 棵、uopIdx 1,323 棵、srcType 1,241 棵（rootOp 多为
OP_WHEN/OP_EMPTY）。每棵树 lowering 出 ~110 ops（extract-hold + mux +
insert 重打包），1,364 棵 × 110 ≈ 15 万 instr 全打一个 node 戳。**爆炸来自
树的条数而非单树深度**，树内抽取（无论 GROUP 下钻还是宽度规则）无货可挖
（2,489 个数组候选 extracted=0）。flattenNodes 数组扩展已回退（对图无实际
影响，stats 与基线逐项相同）。

**结论**：巨 atom 是"组合数组中间值的逐元素多树功能式合并"问题，与向量
寄存器写是两个病灶 → 拟立 NO0008（方向：exporter 对数组 OTHERS 节点按
下标分组逐元素合并、整组装配一次，替代逐树全数组 merge 链；或 emitter
侧 atom 内分块）。

**v5 全量（逐叶写含异步复位，flatten 同基线）AM 实测**：
- kRegisterWritePort 结构：reg.write 146,975 / .c 1,621 / .m 322 /
  **.cm 70,245**（v1 仅 113 .m）——逐叶写已全量落地（叶写 72,083 条，
  覆盖 2,346 个数组寄存器）；
- mux 1,337,941→1,237,013（-10.1 万），slice_static -6.4 万，总 instr
  5,295,811→5,236,657（**-5.9 万**，远不及 NO0005 估的 76 万上界——
  该上界按 37 万 when × 2.26 ops 全消估算，实际叶均守卫/打包开销与
  CSE 共享使净收益小一个量级；注：~49 万无名 mux 属聚合成员树 lowering
  桶，不在本专项范围）；
- commit atoms 152,912→222,639（+7 万写指令），compute 3,072,265→
  3,069,067；max_atom=145,450 依旧（decoder 锥，归 NO0008）。

## 10. NO0008（已立项 2026-08-12）：组合数组中间值的逐元素多树合并（巨 atom 根治）

> 立项文档：`pdocs/grh-notepad/emit-cost/NO0008_组合数组多树合并巨atom收缩_20260812.md`。
> 本节保留问题史；动机以立项文档 §2 为准（编译时长已被 §12 关闭，剩余动机
> 仅为活动度分区保真）。

**问题**：数组类型组合中间值（OTHERS wire）携带海量逐元素 assignTree
（bloomFilter data_next 12,288 棵、decoder csBundle 字段各 ~1,300 棵），
exporter 的 lowerAssignedNode 对每棵树做"extract 旧元素→mux→insert 重打包"
全数组功能式合并，~110 ops/树 → 单节点 6.9~14.5 万 instr，形成一个 atom
（indivisible），-O3 编译卡死、活动度分区失真。

**已排除的路线**：flattenNodes 树内抽取（GROUP 下钻/宽度规则均试过，
2,489 个数组候选 extracted=0）——爆炸在树的条数，不在单树深度。

**候选方向**：
1. exporter 对数组 OTHERS 节点按**下标分组**逐元素合并：同一元素的若干
   树先合并成元素值（小 mux 链），最后整组装配一次 concat。静态下标直接
   分桶；动态下标树保留现状（insert 链）。预期 145,450 → 数千。
2. emitter 侧 atom 内分块（一个 atom 的 instr 拆成多个顺序调用的函数），
   只治编译卡死，不治分区失真。
3. gsim 侧 splitNodes/splitArray 把这类节点预先按元素拆开（影响面最大）。

**验收挂钩**：NO0007 验收线(2)（巨 atom ≤ 千级 + emu 无降级编译）移交
NO0008 关闭。NO0007 范围内已关闭：验收线(3) 边对账（99.72%/97.55%）。

簿记增长"两个候选因素在全 -O3 下不构成可测回退，证伪。教训：**凡有降级编译
参与的 coremark 对比都不可作为性能结论**。

**结论**：本专项主体（向量寄存器逐叶 mask 写翻译 + 同进程双产物测量流程 +
emit 层编译时长根治）落地并全量验证；验收线 (1)(3)(5) 关闭，(4) 以实测修正
预期，(2) 的"emu 无降级编译"半由 §12 关闭、"巨 atom ≤ 千级"半移交 NO0008。

### §10 修正（用户点拨）：巨块两边对称，正解在 AM emit 层分块

用户指出：巨块在 gsim 侧同样存在（node 不可分两边一致），gsim 是靠
cppEmitter 按文件大小切 subStepN 多函数活下来的（cppEmitter.cpp:1017）。
实证 AM 侧病灶形态：`grhsim_SimTop_blocks_18_part_1.cpp` = 单函数
`eval_scan_18_part_1()` 10.65 万行直线语句 + ~3.1 万局部变量，-O3/-O1
均不可编译。因此 NO0008 方向修正：**AM emitter 对超大 block 的语句体做
子函数切分（顺序调用）** 升为主选；exporter 树分组/flatten 抽取等图手术
降级为不必要（巨 node 是两边共同的合法形态，活动度语义对称）。

## 12. emit 编译时长根治：chunk 函数指针参数 `__restrict__`（2026-08-12）

**症状**：§10 修正后落地的 emitter 分块（`blockChunkInstructions=3000`）把"编不出"
变成"编得慢"：最病 TU `grhsim_SimTop_blocks_0_part_3.cpp`（62,272 行/6.9MB，
含巨 atom block_709 的 14 个 chunk 函数）单任务 -O3 **40 分钟未编完**（超时被杀），
-O1 需 1m56s。对照 gsim 15.6 万行单函数 -O3 仅 58s。

**定位（gdb 栈采样实锤）**：卡死在
`GVNPass::processBlock → MemoryDependenceResults::getNonLocalPointerDepFromBB →
TypeBasedAAResult::alias`——GVN 的非局部 clobber 查询里做 TBAA 别名判断。

**根因**：chunk 函数以裸指针参数共享父作用域数组
（`std::uint64_t *localblk_N` 等 5 个）。该文件 6.2 万行中含 59,019 次
localblk 指针访问 + 31,587 次成员变量访问；每条经裸指针的 store 对优化器而言
may-alias 全部 142 万个成员变量，GVN 每条 load 的 clobber 查询都要爬过成山的
may-alias store → 超线性爆炸。gsim 无此问题：其临时量是函数内真 C++ 局部变量
（纯 SSA，别名分析天然免疫）。

**修复**（`grhsim_am_program_cpp_emitter.cpp::blockChunkParameterList`，声明/定义
同源一处）：chunk 函数全部共享数组参数加 `__restrict__`（localblk/wrChgblk/
arrChgblk/detGrpblk/byteFlags）。合法性：这些指针指向调用方栈上数组，绝不指向
成员存储。clang 将 restrict 参数降为 noalias 属性，BasicAA 直接判 NoAlias，
别名网整片消除。

**效果**：同一 TU 同一参数（-O3 + PCH，单任务）**>40min → 10.31s**（>230x），
峰值内存 1.4GB。ctest grhsim-am 15/15 绿；emit 产物仅签名差一个
`__restrict__`，语句体逐字节相同。

**遗留候选（暂不需要）**：chunk 内值进一步局部化为纯 C++ 局部变量（当前
localblk 数组元素仍是内存形态）；若日后 -O3 时长再成瓶颈再做。

## 13. 对齐终态量化：node/atom 节点数、边数、L2、fanout 分布（2026-08-12）

数据：`build/logs/no0007/gsim_topo_flat/instruction_graph.jsonl`（gsim flatten
图，3.0G 单跑双产物的 topo 半份）vs `am_instruction_graph_v5.jsonl` +
`atom_node_audit_v5.jsonl`（NO0007 v5 导出，与 restrict emit 同图同参数）。
口径与 NO0006 边对账一致：gsim node-id 空间、有向去重、去自环；AM 侧仅
node-mapped compute atom（commit/无归属附加层剔除）。脚本：
`scripts/no0007_fanout_compare.py` / `no0007_fanout_top.py`。

### 13.1 节点数

| 口径 | gsim flatten | grhsim AM | 比值 |
|---|---|---|---|
| 全量单元 | 3,146,488 nodes | 3,291,706 atoms | 1.046x |
| compute（映射集合） | 3,068,421 nodes | 3,069,067 atoms | **1.0002x** |
| 时钟域附加层 | — | 222,639 commit atoms | — |

compute 侧构造性 1:1（零重复，仅 +646 无归属 atom：531 assign 胶 + 115
changed 检测器；2,555 multi_sink = EXT 多输出 node）。不产生 compute atom
的 78,067 个 gsim node = REG_DST（NO0007 后下沉 commit 层 mask 写）+
常量/输入 + mem 端口类。

### 13.2 边数（node/atom 级 def_use）

gsim 4,470,434；AM 4,570,002（+2.23%）；交集 4,457,817；
**recall 99.72% / precision 97.55%**；AM-only 112,185（复位胶家族），
gsim-only 12,617（mem/写口映射差异）。AM 另有 384,339 条 commit 附加层边
（不计入口径）。注意 AM 头部的 7,699,230 是指令级边，与 node 级不可直接比。

### 13.3 L2（atom 数 / node 数）

**1.0002x**（映射集合）/ 0.975x（全量 node 口径）。历史轨迹：NO0002 初期
0.32x → fold 帽=2 时 0.95x → NO0006 node-aligned 后 ~1.0x。
atom 尺寸：mean 1.59 instr、p50=1、p90=2、p99=3、max=145,450（两边对称
合法形态，保留，见 NO0008 冻结裁决）；oversized atom 19,769。

### 13.4 fanout 分布（out-degree，去重后继数）

| 桶 | gsim node | AM atom |
|---|---|---|
| 0 | 308,674（9.8%） | 165,567（5.4%） |
| 1 | 2,558,742（81.3%） | 2,624,979（85.5%） |
| 2 | 141,485 | 140,833 |
| 3 | 33,958 | 33,991 |
| 4-7 | 47,483 | 47,304 |
| 8-15 | 35,805 | 35,522 |
| 16-63 | 18,184 | 18,081 |
| ≥64 | 2,157 | 2,144 |
| ≥2 密度 | **8.9%** | **9.1%** |
| mean/p50/p90/p99 | 1.421/1/1/11 | 1.486/1/1/12 |
| **max** | **6,167** | **36,062** |

中高段（2 到 ≥64）逐桶贴平。唯二差异同源于一个层次差：

1. fanout=0 段 AM 少 14.3 万：gsim 的 REG_DST 等写目的 sink 在 AM 下沉
   commit 层，不在 compute 全集内。
2. max 离群 36,062 = `cpu$l_soc$reset_sync_resetSync$_raw_reset_T`（原始
   复位信号）：AM 把它作为 compute 值送入 ~3.6 万个复位胶 atom；gsim 的
   复位传播不走 compute def_use 图（寄存器复位口/REG_RESET 层）。
   **该节点同时就是 §11(3) AM-only 边残差的枢纽**（一族贡献 ~3.6 万条），
   即 max fanout 差与 precision 差是同一层次差，不是图形状缺陷。
   两侧第 2 名起 top fanout 逐项相同（6,167 xbar ready、6,152×6 ROB
   renameBuffer 字段等）。

### 13.5 结论

节点数、边数、L2、fanout 分布在 compute 口径全部贴平，残余全部可解释为
AM 时钟域分层（commit/复位/写口）相对 gsim 隐式层次的记账差。NO0003 时代
遗留的"AM fanout≥2 密度 51.6% vs gsim 8.9%"疑点（不同图路线的产物）
正式关闭。
