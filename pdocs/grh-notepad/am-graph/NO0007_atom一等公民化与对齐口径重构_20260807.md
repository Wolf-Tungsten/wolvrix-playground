# NO0007 atom 一等公民化与对齐口径重构（立项）

日期：2026-08-07
前置：supernode-align 线证实 gsim flatten 不打平 when（见 §1）；[NO0006](NO0006_同条件mux原子化与if-else发射_20260807.md) mux-merge atom 已落地。

## 1. 缘起：gsim when 折叠口径的证实（2026-08-07 核实）

supernode-align 专题一直以 `xs_gsim_flat_prod_20260804`（gsim `--flatten-nodes` 打平图）为对齐基线，本次核实该"打平"口径并不打平 when：

- `reference/gsim/src/flattenNodes.cpp`：所有 compute enode 拆成"一节点一算子"，但 `OP_WHEN` 被明确豁免（头注释定义为 "conditional-assignment skeleton (control, not compute)"，永远留在 owner 节点，仅其下挂的 cond/分支值表达式被抽出）。
- `reference/gsim/src/topoProjExport.cpp`：指令 op 取**树根** enode 的 opType——一整棵嵌套 when 骨架（任意层 when 套 when）导出为 **1 条 OP_WHEN 指令**；def_use 边全量保留（递归穿过骨架收集 ref）。
- 量化（`xs_gsim_flat_prod_20260804` 实测）：OP_WHEN 根 **126,005** 条，打平日志 `keptWhen 87,356`（折叠隐藏的嵌套 mux 决策，平均 1.69 个/根）；对照 AM 侧（`xs_am_flat_final_20260804`）**468,709 个 mux 全部展开为独立指令**。
- 结论：gsim node = "1 个 compute enode + 任意大小的控制骨架"，AM instruction = 单算子全展开。两侧"节点"粒度不同，导致统计口径（T5 节点数、mux 数）与划分效果（折叠链强制同块、容量按节点计、跨块边被口径美化）双重偏差。NO0010–NO0012 基于该口径的 cross_values 数字（193,181 基线、2.4x 差距）含口径成分，应视为差距上限。

## 2. 用户判断与规划（2026-08-07，原文记录）

1. **保持 gsim 的统计不动**：之后还是相同的分析，compute node 就算一个 node，flatten 也不打平 when。
2. **保持图结构 + atom 层次到发射端**：比起制造线性的 am program，保持图结构 am graph + block 内部的 atom 层次更有价值；cpp emitter 直接消费带 atom 的 am block 会更容易；可以在 atom 层次上附加信息，比如实现 SCC 收敛、compute am graph 中的 mux 合并、乃至 commit am 上的 cond 聚合。
3. **分图算法和统计口径与 gsim 看齐**：atom 就是原子——是分区大小的单位，是边结构的基础。

## 3. 架构现状核实（代码证据，2026-08-07）

atom 在管线中已存在，但只活在**中段**，两端都没有它的位置：

- **atom 已是分区单位（中段）**：`splitAmGraphStage` 把指令打包成调度 atom（SCC 缩点 + singleton，`grhsim_am_graph_split.hpp:74-82`）；`AmGraphPartitionInput` 就是 atom DAG 的视图（`grhsim_am_graph_partition.hpp:14-40`）；compute/commit 两路分区 pass 均在 atom DAG 上工作；NO0006 `mergeMuxSelectAtoms` 在 partitionInput 组装前重写 atom 表并重建诱导子图（`grh_ir_to_grhsim_am_program.cpp:1014-1020`）。
- **atom 在 materialize 死亡**：`grhsim_am_graph_to_program.cpp` 把 atomTopo 展平为 block→instruction 线性序列（`appendBlockInstruction`）；Program 存储只有 `BlockOffsets`/`BlockInstructions` arena（`grhsim_am_program.hpp`），**无 atom 层**。
- **emitter 重新推导**：`planMuxRuns`（`grhsim_am_program_cpp_emitter.cpp:3999`）在块内线性扫描"连续同 select 的 mux（≥2 成 run）"来融合 if-else——这是 NO0006 pass 已精确知道的信息的**弱启发式重建**；pass 级 atom 与 emit 级 run 双机制并存，可能不一致（cap 跳过的组若碰巧相邻仍会被兜底融合）。
- **AmGraph 无 atom 概念**：`grhsim_am_graph.hpp` 没有任何 atom API；atom 只是 split context 的中段工作集。
- **容量口径按指令**：`maxInstructionsPerBlock=128` 按指令数计（gsim `supernode-max-size=15` 按 node 计）。
- **边口径不一致**：gsim 导出按 (dst, ref) 去重（`topoProjCollectRefs` 用 `std::set`）；AM def_use 边带 operand 槽位，同一 var 对可有多条边。
- **commit 门控是指令而非元数据**：commit 块的事件门控目前以 changed/act 指令序列显式存在于 program（NO0001 时代设计），event 签名不以 atom 元数据形式存活到 emit。

## 4. 对三点判断的分析结论

**点 1（gsim 统计不动）：正确。** gsim node 口径自洽（"1 compute enode + 控制骨架"），折叠隐藏量已完全量化（§1），基线不需要再次翻动。对齐负担移到 AM 侧单位采用——即点 3。注意边界：gsim 折叠语义是**嵌套结构**（when 套 when，无尺寸上限），AM atom 是**同 select 归组 + 锥吸收**（cap 512），两者是同类不同构的单位——完全等价不可达，单位级对齐可达。

**点 2（图结构 + atom 层次到发射端）：正确，正中当前架构缺口。** 现状（§3）证明 atom 信息被"算了又扔、扔了又猜"：分区用完即弃，emitter 弱启发式重建。落地形态需细化一点：**materialize 不消失，改为保层次物化**（block→atom→instruction 三层）；atom 是**纯结构/元数据层，不承载语义**——指令级语义不变，interpreter 可无视 atom 层直接执行指令流，validator 增加 atom 不变量校验（互斥归属、内部拓扑、kind 签名一致），emitter 消费 atom 直出融合结构。atom 上可附：kind（singleton / mux-merge / scc / commit-event）、select 或 event 签名、活动度事实——SCC 收敛、mux 合并、commit cond 聚合并入同一抽象。

**点 3（分区与统计 atom 化）：方向正确，且比现状多三步实质内容。** 分区内部虽已在 atom DAG 上工作，但：(a) 块容量与成本模型（coarsen budget、DP segmentPenalty、refinement 成本）目前按**指令**加权，要换成 atom；(b) 边结构要换 atom 粒度 + 按 var 去重的研究口径（生产图保留 operand 槽位供 emitter 使用，分区输入用去重视图）；(c) 全部对齐指标（supernode_align_metrics 等）切换为 atom-as-node 计数，NO0010 基线在新口径下重测（AM atom 数 vs gsim node 数、atom 粒度 cross_values）。

## 5. 重构范围规划（阶段）

- **P0 立项与口径固化**：本文档；明确 atom 分类学（singleton / mux-merge / scc / commit-event）与不变量。
- **P1 Program 结构升级**：Program 增加 atom arena（block→atom→instruction 三层视图 + atom kind/签名元数据）；store/load、interpreter（无视 atom 层）、validate（新增 atom 不变量）、研究导出 JSONL 适配。验收：发射产物字节级不变。
- **P2 materialize 保层次 + emitter 直消费**：materialize 输出 atom 层次；emitter 按 atom kind 发射（mux-merge→融合 if-else、scc→收敛循环、commit-event→单 if 门控），删除 `planMuxRuns` 重推导与块内兜底；`muxAtomMax` 退化为纯激活粒度旋钮，"整组放弃+emit 兜底"双机制随之删除。验收：difftest 73,580/49,996，性能不回退。
- **P3 分区经济模型换 atom**：块容量/成本/精化按 atom 计；commit atom 事件签名固化为元数据；研究口径边按 (dst,var) 去重。验收：AM 套件通过，分区统计口径文档同步。
- **P4 指标口径切换与基线重测**：`scripts/supernode_align_metrics.py` 等切 atom-as-node；NO0010 对比在新口径下重测登记（旧口径数字标记存档，不回改）。

每阶段硬约束沿用专题约定：执行语义不变、香山 difftest 73,580/49,996 通过、性能不回退。

## 6. 决策点（实施前需裁定）

1. **cap 语义**：atom=分区单位后，过大的 atom 是不可分的大分区单位（gsim 接受无上限 when 骨架）。建议：分区视角不设上限（对齐优先），`muxAtomMax` 仅作 emit/激活粒度保护。
2. **atom 元数据的维护责任**：pass 改写指令后必须维护 atom 表（NO0006 的重建逻辑可复用为通用机制）。
3. **interpreter 不感知 atom**：atom 非语义层，解释器仍按指令流执行（本方案的关键简化器）。

## 7. 风险

- Program 格式变更波及六个消费面（store/load、interpreter、validate、emitter、研究导出、测试夹具）——最大的一批机械改动，需逐面核对。
- 口径切换后历史数字不可比：NO0010–NO0012 数字保留为旧口径存档，不回改，新口径在 P4 重测登记。

## 8. 实施结果（增量更新 2026-08-08）

### P1（Program atom 层）——完成

- ScheduledProgram 新增 block→atom→instruction 三层视图：`AtomId`、`AmAtomKind{Singleton, MuxMerge, CombLoopScc, CommitEvent}`、4 个 atom arena、7 个视图方法；builder `beginAtom/endAtom` + 隐式 Singleton 兜底（现存调用点零改动合法）。
- 管线标注：split 标 SCC/commit atom（CommitEvent 带 event rank 签名）；mux-merge 重建表携带 MuxMerge kind + select 变量签名；materialize 按 atom 层次写入 program；validate 新增 `validateScheduledAtoms`（tiling 铺满、kind 形状、CommitEvent/MuxMerge 块区间归属）。
- 验收：发射产物与 NO0006 版 `diff -rq` 逐字节一致（255 个产物）；AM 套件 14/14（新增 grhsim-am-program-atoms 5 用例）。

### P2（emitter 直消费 atom）——完成

- 删除 `planMuxRuns` 及块内连续段兜底；新增 `planMuxMergeAtoms`/`emitMuxAtom` 两相发射（preamble 锥先行、臂归 if-else）；统计 `mux_run_fused` → `mux_atom_fused`（atom 驱动口径）。
- 行为变化点（预期内）：cap 跳过/解合并组不再被 emit 兜底融合——生产 `mux_atom_fused=227,925` 精确等于 pass 归组数（旧双机制为 241,450，含 13,525 条兜底）。
- 验收：difftest 73,580/49,996 逐位一致；host 314.2s（canonical 312.8s，+0.4% 噪声内）；AM 14/14（新增 testCapSkippedMuxGroupStaysUnfused 钉死兜底删除）。

### P3（分区经济模型换 atom）——代码完成

- compute 分区 `member[rid]=1`（atom 即权重单位），mergeLimit/DP maxNodes/refinement 随之 atom 计数；commit 桶合并主限改 atom 计数，保留 `kMaxGuardEventMergeOps=4096` 指令数二级护栏。
- 命名链路诚实化：`maxAtomsPerBlock`(128) / `maxCommitAtomsPerBlock`(4096) / `coarsenAtomBudget`(256)，CLI/Makefile/xs-components 同步。
- 导出补齐：指令图 JSONL 的 `atom`/`comb_loop_atom` 调用点上移到 mergeMuxSelectAtoms 之后（post-merge 口径）；块归属 JSONL assign 记录 +`atom`、block 记录 +`atoms`。
- 生产效应（香山）：compute 块 25,281 → 22,084（−12.6%），commit 块 481 不变（commit atom 多为 1-2 指令，单位切换近中性，符合预期）；scheduled_instructions 4,405,187 → 4,349,027（−1.3%，块数减少的合成基础设施指令相应减少）。
- 验收：AM 14/14；XS difftest/计时见 §9。

### P4（指标口径切换）——完成

- `topo-partition-proj/exp/harness/scorer.py`：Assignment 增加 `instr_atom`（assign 记录有 `atom` 列时解析，全有或全无）。
- `scripts/supernode_align_metrics.py`：`nodes`/`block_node_max`/`block_node_mean` 按 node_unit（atom 或 instruction）统计，compare 增加 nodes 比与块尺寸对比；cross_values* 为去重值口径，对同一 assignment 与粒度无关（不变式）。旧数据集（无 atom 列）回退 instruction 单位，已回归验证。
- 实测数字（P3 数据集 vs gsim 打平图基线）见 §9。
