# NO0005 状态写指令 cond/mask 变体族

日期：2026-08-07
状态：已完成并验收（difftest 73,580/49,996 逐位一致，host 308.8s −4.5%，AM 12/12）

## 1. 目标

`reg.write` / `mem.write` / `latch.write` 等状态更新指令改为**变体族**：带/不带
`cond` × 带/不带 `mask`（显式 opcode）。lowering-to-am-graph 在从 GRH IR 建图时，
按 `cond`、`mask` 的常量性质把每个写**选型到最简变体**：

- `cond` 为常量 1 → 选无 cond 变体；`cond` 为常量 0 → 写整条的消除（现状已有）。
- `mask` 为全 1（或无部分写需求）→ 选无 mask 变体；`mask` 为常量 0 → 写整条消除。

硬约束沿用本专题：执行语义不变、香山 difftest 通过（73,580/49,996）、host 性能不回退。

## 2. 立项缘由（对 NO0001 决策的勘误性修正）

NO0001 把 `reg.write`/`latch.write` 的 `cond`、`mask` 操作数去除、语义并入
`nextValue`（mux/blend 数据化）。用户裁定该决策有误：

- **重复读取**：合并写要求链首对 old 值做 pre-commit 快照（`targetSnapshot`，
  `wolvrix/lib/grhsim/am/grh_ir_to_grhsim_am_graph.cpp:2387`），old 值作为数据流
  进入 compute 图；
- **重复计算**：每个写口插 `pureMux(cond, blended, acc)` 自 mux + `blendValue`
  三件套，守卫在 compute 图内扇出给 N 个 mux（NO0003/compute-partition 归因中的
  形态 A 更新 mux，17,442 个 od-2 节点含此消费者）；
- commit 端无条件写 + 无条件 changed 比较，丢失了"cond 不命中就什么都不做"
  的运行时剪枝。

正确方向不是回到"全通用操作数"（现 `mem.write` 永远拖
`[cond, addr, mask, data, target, events...]`，见同文件 2448 行），而是按常量性
特化的**变体族**——本质是把 gsim when 边"守卫是控制不是数据"的思想落到 AM
写指令上。

## 3. 已核实的关键事实（2026-08-07 代码核实）

1. **GRH IR 的条件写链已 canonicalize 到单写口**。ingest 写回规划把同一
   target、同一 control domain 的所有守卫写合并为一个 entry：
   `updateCond = makeLogicOr(各分支守卫)`（`wolvrix/lib/core/ingest.cpp:13796`），
   `nextValue = makeMux(guard, writeValue, nextValue)` 优先级链（同文件 13807）。
   多写口仅为时钟域分离/异步复位单独建模保留
   （`wolvrix/docs/grh/grh-ir.md:1109`）。
   **推论**：AM lowering 的 signatureGroup 正常 size 为 1；"按链段发射多条写"
   的方案被否决——每（寄存器，event 签名）恰好一条写指令。
2. **现状两个极端**：
   - `reg.write`/`latch.write`：全数据化，`emitMergedScalarWrites`
     （`grh_ir_to_grhsim_am_graph.cpp:2403`）折叠 snapshot+blend+self-mux；
   - `mem.write`：全通用操作数，只折叠 cond=0/mask=0 死写，cond=1、mask 全 1
     未简化。
3. **mask 大概率几乎都是常量**：GRH 寄存器写口 mask 由
   `ingest.cpp:21505-21516` 生成为静态连续切片掩码（全写=全 1 常量）。若量化
   证实，`.m`/`.cm` 变体可进一步精简（常量 mask 可特化，甚至不拖 mask 操作数）。

## 4. 设计裁定（已与用户确认）

1. 变体用**显式 opcode**（如 `reg.write` / `reg.write.c` / `reg.write.m` /
   `reg.write.cm`，mem/latch 同理），不用 schema 标志位——AM 本来就是扁平
   指令+定长操作数表，dispatch/validate/emit 的 switch 直观。
2. 每（寄存器，event 签名）**一条写指令**；同签名多写口组（罕见）在 lowering
   输入侧合并：cond 取 OR、next 按端口顺序套优先级 mux——不需要 old 值参与
   （写只在 OR-cond 为真时发生）。
3. `targetSnapshot` 机制（snapshot assign + pre-commit 快照）**整体删除**：
   "所有分支不触发 → 保持旧值"由**不写**保证，mux 链最内层 else 不再挂 old 值。
4. mask 变体的 old 值读取是 commit 局部行为（`v = (v & ~m) | (d & m)`），
   不作为图值跨 compute→commit 边界。
5. changed 检测：每寄存器每 commit block 一次，cond 门控内（cond 不命中则
   不写也比较）。

### 7.2 （target, event 签名）组尺寸

- **kRegisterWritePort：135,284 个组全部 size=1**——单写口 canonicalize
  成立（第 3.1 条），多写口同签名组在香山不存在；合并逻辑只作兜底。
- kMemoryWritePort：1,430 组 size=1，其余 2~520 不等（511/514/520 约 10 组，
  为多写口存储阵列，逐端口独立写、不合并，维持现状语义）。
- kLatchWritePort 的 eventEdge 属性为空（电平敏感），分组键需在实施时单独处理。

### 7.3 变体集合裁定（按数据精简）

- `reg.write` / `latch.write`：全 2x2 族（plain / `.c` / `.m` / `.cm`）**定义保留**
  （GRH 写口 mask 语义存在，hdlbits 等部分位写场景需要 `.m`/`.cm` 兜底），
  香山实测只选中 plain（37.33%）与 `.c`（62.67%）。
- `mem.write`：香山只选中 `.c`（mask 全 1，49.75%）与 `.cm`（50.25%）；
  mask 全为常量 → `.cm` 的 mask 在 emit 端折叠为立即数，不拖变量读。
- latch 402 口全部非常量 cond → 全选 `.c`。

### 7.4 消除量预估

- 每个非常量 cond 的标量写当前造 1 个自 mux（`pureMux`）+ 每 target 1 条
  快照 assign（`targetSnapshot`）：预估移除 **~85k mux + ~135k 快照 assign**
  （约 AM 指令的 6%，compute 图节点的 ~7%），形态 A「更新 mux」整体消失。
- 62.67% 的寄存器写获得 commit 端 cond 门控（不写、不比较）。
- mem.write 50.25% 的 mask 从变量读变 emit 立即数。
- 对 ge2 / cross_values 的影响实施后实测（形态 A 相关 od-2 节点 17,442 个
  预计整体消除）。

### 8.1 实施清单（wolvrix 仓，AM 套件 12/12、全量 ctest 无新增失败）

- opcode：`include/grhsim/am/grhsim_am_program.hpp` enum 末尾追加 9 个变体
  （`RegisterWriteCond/Mask/CondMask`、`LatchWriteCond/Mask/CondMask`、
  `MemoryWriteCond/Mask/CondMask`），toString 同步（`reg.write.c/.m/.cm` 等）。
- layout：`grhsim_am_opcode_traits.hpp` 新增 `StateWriteLayout`/`stateWriteLayout`/

  `[cond?, addr?(mem), mask?, data, target, events...]`；`MemoryWrite` 基座布局改为
  `[addr, data, target, events...]`（traits 的 stateTargetOperand 4→2）。
- lowering：`emitMergedScalarWrites` 重写为 `emitScalarWrites`——逐写口按常量性
  选变体（const-0 消除；const-1 cond / 全 1 mask 不占操作数位）；同签名多写口组

- interpreter / cpp emitter / validate / common.hpp / graph.cpp / graph_to_program /
  grh_ir_to_grhsim_am_program 的分类与校验全部改按 layout/写族驱动；emitter 新增
  `scalarConstantWord`/`constantWordsDecl` 把常量 mask 渲染为立即数（valueExpr 不
  内联常量，此折叠是新增而非自然成立）。optimize pass 零改动（全部 traits 驱动，
  commitOperand_ 保护闭包自动覆盖新变体操作数）。

## 9. 增量更新 2026-08-07：回归疑云排查（结论：误报，变体版与基线指令流逐条一致）

**疑云**：变体版首次 difftest 越过 50k 周期上限继续运行（90k+ 未停）、包装日志未
见 coremark banner，初判语义回归。

**排查链**：

1. 加 lowering 环境开关 `WOLVRIX_GRHSIM_AM_MERGED_SCALAR_WRITES`（恢复 NO0001 时代
   的 snapshot+blend+self-mux 合并写形态，作为语义参考）做 A/B：merged 版
   73,580/49,996 通过（host 316.3s）→ 嫌疑收缩到标量变体执行侧。
2. 双 commit trace 对差（merged vs 变体，各 50k/60k 周期）：**前 35,920 条提交
   （pc/inst/wen/dst/data）逐条完全一致**——35,920 条即 50k 周期验收窗口的全部
   提交，变体版 seq 35,920 落在 cycle 49,999，与基线终点（49,996）精确对齐。
3. 结论：**不存在语义回归**。首跑"异常"的两个成因均为观察/操作失误——
   ① 首跑未带 `XS_SIM_MAX_CYCLE=50000`（`max_cycles=unlimited`），coremark 本就
   需要远超 50k 周期才完成，验收口径一直是"50k 周期窗口内无 mismatch"而非自然
   终止；② banner 实际已打印在 emu 侧日志，包装日志 grep 误读。
   IPC 差异（2.04 vs 1.47）亦为误读：instrCnt ≈ 2.05 × trace 行数在两版中比例
   一致，trace 行/周期比率相同，流一致。
4. 副产品确认：merged 回退版 host 316.3s（基线 323.3s），mem 变体（.c/.cm +
   mask 立即数折叠）单独就带来 ~2% 收益。

bisect 脚手架（`WOLVRIX_GRHSIM_AM_MERGED_SCALAR_WRITES` 及 pureBinary/blendValue/
targetSnapshot 恢复段）为临时调试设施，终验通过后移除。
