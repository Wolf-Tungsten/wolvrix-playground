# NO0006 同条件 mux 原子化与 if-else 发射

日期：2026-08-07
状态：已完成并验收（difftest 73,580/49,996 逐位一致 ×4 cap 点，运行时中性，默认 T=512 开启）

## 1. 目标

在 GRHSIM AM Compute Graph 上识别 **select 条件相同的 mux 组**，包装为
mux-merge atom：组内成员的单用子表达式锥尽可能吸收进 atom，共享值成为 atom
接口输入；调度/分区把 atom 作为**不可分割的整体**处理；emit cpp 时把 atom 内
同 select 的 mux 序列融合成**一个 `if (S) {...} else {...}` 门控结构**——一次
条件判断控制多条赋值（对齐 gsim 的 when 合并效果）。

非目标：不改变图的数据流语义（每个 mux 的求值结果不变）；不追求条件等价证明
（只按 select 变量结构相等归组，与 gsim `checkCondENodeSame` 同级）。

## 2. 动机与背景

- gsim 的打平图里 when 是按 cond 聚合的控制骨架，发射期
  `StmtTree::mergeExpTree` 再把同 cond 的 when 合并进同一个 if——条件只判断
  一次。AM 现状是每个 mux 独立生成三元表达式 `r = S ? t : e`，select 既在图内
  扇出给 N 个 mux（compute-partition NO0003 归因的守卫扇出大头），又在发射
  代码里被重复求值 N 次。
- am-graph NO0005 已把"写回层"的守卫收进 commit 门控（reg.write.c 的
  `if (cond)`）；本立项处理**数据选择层**的同条件 mux 合并。
- 变体选择的历史结论（2026-08-06 会话，canonical compute 图，待复核）：
  ≥8 路同 select 组 2,093 个、覆盖 40,182 个 mux；**打包成宽 mux 的变体 B 已被
  数据否决**（全组汇聚同一 concat 的组仅 4 个，打包后节点/边双持平）。本立项
  是变体 A（atom 归组 + if-else 发射）。

## 3. 已核实事实

1. 调度器已有 atom 机制：指令 DAG 的 SCC 凝聚节点，atom 表
   （`instructionAtom` / `atomMembers` / `atomGraph`，见
   `wolvrix/include/grhsim/am/grhsim_am_graph_split.hpp:45-55`），分区与
   materialize 均按 atom 表工作——mux-merge atom 可作为**额外凝聚单元**挂在
   同一机制上（复用，不另造概念）。
2. `opt-am-compute-graph` 是 NO0004 框架预留的**空阶段**，本 pass 是其天然
   首位住户：compute 侧纯改写，位于 partition-am-compute-graph 之前，分区
   自然把 atom 当整体。
3. mux 是纯操作，同块内重排/相邻化语义安全；emitter 的 Mux case 目前逐条
   生成三元表达式（`grhsim_am_program_cpp_emitter.cpp`）。

## 4. 设计要点（立项裁定，实施时细化）

1. **归组**：select 为同一 value 的 mux 归一组；各 mux 位宽/符号性可不同
   （臂各自保型）。一个 mux 只能属于一个 atom（嵌套 select 组重叠时按
   尺寸/优先级裁决归属）。
2. **吸收**：producer 的全部消费者都在组内的子表达式锥吸进 atom；被组外
   共享的值成为 atom 输入接口。吸收设尺寸上限（cap），防止 atom 过大
   损失调度粒度（参照 mergeLimit 思路，量化定数值）。
3. **atom 化**：pass 产出 atom 记录（成员、select、接口输入/输出）并注册
   进 atom 凝聚层；SCC、compute 分区、materialize 将其视为单节点——
   select 的 N 条图内扇出边收敛为 atom 的一条输入边。
4. **物化与发射**：atom 在 compute block 内物化为连续指令段（select 先行
   求值一次）；emitter 对同 select 连续 mux 段（或 atom 元数据直通）生成
   `if (S) { r_i = t_i; ... } else { r_i = e_i; ... }`；两臂相同/常量时
   进一步简化（单边 if、常量折叠）。
5. **pass 顺序**：现有图形级 rewrite（stateReadAlias/logicUnify/
   muxNotAbsorb/sliceFuse）先行，mux-merge atom 化最后做，避免互相拆台。
6. **指标口径**：主攻发射代码质量（判断次数、代码尺寸、分支效率）；对
   ge2/cross_values 的影响如实测量记录，不预设承诺。

## 9. 增量更新 2026-08-07：cap 策略修正（对照 gsim 源码裁定）

查证：gsim 的 `StmtTree::mergeExpTree`（reference/gsim/src/StmtTree.cpp:107）
**不设尺寸 cap**，唯一约束是依赖序（anyLimit/path）。它不需要 cap 的原因：
when 合并是**发射期**操作，在已定型的 super node 内部进行，合并结果天然被
super node 尺寸兜住——cap 活在分区器里，不在 merge 里；巨型 when 链（一个
lvalue 的整棵 ExpTree）在 gsim 中本就是"原子化单赋值树"，分区器按普通或
oversized super node 安置，merge 从不因尺寸拒绝。

对本立项的修正（替换 §4.2 的 cap 条款与 §8.2 的"超 cap 整体跳过"处理）：

1. **mux 组不设 cap**：任何尺寸的组都 atom 化；≥64 的大组天然独占一块，
   对应 gsim 的 oversized super node，且正是 if-else 融合收益最大处。
2. **cap 只加在锥吸收上**（实施时按 128/256 量化定值）：中等组吸收全锥；
   超限时**截断吸收、保留 mux 组 atom 化**（§8.2 的 875 个大组按此处理，
   不放弃）。
3. 备选路线（gsim 更忠实的形态）：不做分区前 atom，仅 emit 端块内同 select
   融合——不动分区、无需 cap，但放弃图形状收敛（接口边 −56%）与跨块组
   融合。维持 atom 路线（两处收益都要），cap 仅为保护分区粒度而设于吸收。

## 10. 增量更新 2026-08-07：cap 终裁——不截吸收，截 atom 化（附阈值扫描）

承接 §9 的追问「锥吸收需要截断吗」：**不需要**。被吸收锥是独占使用节点
（所有消费者都在组内），本就无处可调，吸收不改变分区可行解空间，只把必然
同居显式化。真正的风险不在分区粒度而在**激活粒度**：仿真按块激活，
atom 的任何输入变化都会激活整个 atom——无 cap 时最大 atom 100,299 节点
（28 个 >2048），近全周期激活会把活动度分区省下的运行时全部还回去。
gsim 的 oversized super node 也未达此量级。

**终裁规则**：
1. 吸收锥不设限（独占即吸）。
2. **对 atom 总尺寸设阈值**：超阈值的组不做 atom（保持现状，发射端块内同
   select 融合仍兜底），阈值内全吸收。这是激活保护，不是分区可行性保护。
3. SCC/comb-loop 节点不参与吸收（正确性硬规则，与尺寸无关）。

阈值扫描（贪心认领、总尺寸 T 以上跳过，canonical wvar 图）：

| T | 保留 atom | 覆盖 mux | 吸收锥 | 触碰边→接口边（−%） |
|---|---|---|---|---|
| 64 | 43,619 | 243,045 | 118,763 | 1,086,974 → 584,875（−46.2%） |
| 128 | 45,107 | 262,463 | 184,915 | 1,343,819 → 656,567（−51.1%） |
| 256 | 45,956 | 284,810 | 244,185 | 1,592,390 → 723,785（−54.5%） |
| 512 | 46,646 | 294,761 | 322,635 | 1,875,012 → 767,145（−59.1%） |

| ∞ | 46,915 | 342,666 | 680,127 | 3,196,177 → 901,773（−71.8%） |

收益递减明显；**推荐默认 T=512**（保留 99.4% 的组、86% 的 mux、−59% 触碰
边，仅跳过 ~270 个巨组），备选 T=256；T 做成单参数，实施时按 host 计时

## 11. 增量更新 2026-08-07：实施记录

**落地内容**（wolvrix 仓，AM 套件 13/13，全量 ctest 无新增失败）：

- pass：`mergeMuxSelectAtoms` 入驻 `grhsim_am_compute_graph_optimize.cpp`
  （opt-am-compute-graph 阶段首位住户），在 splitAmGraphStage 之后、
  partitionInput 组装之前调用。atom 粒度归组（单指令 compute atom 的 mux 按
  select 变量归组，≥2 成组）→ 独占锥吸收（atom 整体候选：全产出变量的全部
  使用在组内）→ cap（atom 总尺寸 > T 整组放弃）→ SCC 成环检查与解合并 →
  atom 表/诱导图重建（确定性：尺寸降序+select id 升序贪心认领）。
- 实施补充的两条语义安全规则（文档未列、实施中证明必要）：
  ① **taint 排除**：吸收候选若（传递）依赖组内 mux 结果则不吸收——否则
  「锥前置 + mux 连续」的成员序无法保 def-before-use；被排除者成为 atom
  接口输入。② **SCC 成环兜底**：组内经外部节点的 M1→X→M2 路径会成 2-环，
  命中即整组解合并恢复原状（生产实测 2,038 组触发，一轮修复）。
  comb-loop atom 不参与吸收（§10.3 硬规则）。
- 成员排序：锥子集拓扑序在前（preamble，eager 求值，v1 不做 branch-lazy）、
  组内 mux 连续在后（供融合）；atomMinInstruction 取成员最小值。
- emitter：`planMuxRuns` 模式识别块内连续同 select mux 段（≥2），段首一次
  求值 select，`if/else` 两臂按原序逐条赋值（链式 mux 直接读前条分支结果）；
  宽窄值各自适配；不成段的自然退化为逐条三元。零 program 格式改动。
- 参数链：`ActivityScheduleOptions.muxAtomMax`（默认 512，0 关）→ CLI
  `--mux-atom-max` → Makefile `XS_WOLF_GRHSIM_AM_MUX_ATOM_MAX` →
  `wolvrix_xs_grhsim_am.py` 透传。
- 测试：新增 `grhsim-am-mux-atom`（6 用例：归组/吸收/cap 跳过/两种成环形态
  解合并/comb-loop 不可拆/确定性双跑）；emitter 新增 `testMuxRunFusion`
  （文本断言 + 编译运行行为等价，含 72 位宽值与链式）。

**生产规模冒烟**（canonical，T=512）：合并 33,783 组、227,925 个 mux、
吸收锥 217,945 节点；cap 跳过 122 组（47,818 mux）；SCC 解合并 2,038 组；
一轮修复。量化口径 46,915 组中其余为认领重叠/taint 排除。

### 12.4 结论与默认

中性、if-else 结构是立项目标本身；cross_values 回退知悉并接受（该指标归
supernode-align 线继续追）。备选后续方向：atom 只影响发射不影响分区
（emit-time-only 融合）、branch-lazy 锥求值。
