# NO0005 图形级 fanout 收敛 pass（香山）

日期：2026-08-06
状态：完成。四 pass 落地（stateReadAlias/logicUnify/muxNotAbsorb/sliceFuse），
AM 套件 10/10，coremark 50k difftest 通过（73,580/49,996，host 315.2s）；
cond-form 待裁决（见 §6）。

## 1. 目标

按 NO0003 的微观归因，在 grhsim am 线开发图形级 pass，消解 AM compute 图与
gsim 打平图的 fanout 差异（出度≥2 节点数 599,947 vs 252,832，excess 347,115）。
本专题只关注图形态指标，不关注仿真性能。

## 2. 先行仿真：候选 pass 的收益估算（scripts/fanout_pass_sim.py）

在 split 导出的 compute 图（named.compute.jsonl，3,062,283 节点）上直接模拟各
候选 pass，逐级累计 ge2 变化：

| 阶段 | ge2 | 说明 |
|---|---:|---|
| S0 基线 | 599,947 | 与 NO0001 口径一致 |
| S1 assign 旁路（读外部变量、纯消费者） | 574,792 | **−25,155**，杀 96,245 个 assign 节点 |
| S2 1-bit logic_*→按位统一 | 574,792 | 转换 203,789 个 op（纯改名，0 收益） |
| S3 统一后 GVN/CSE | 575,412 | **只合并 4,548 节点，ge2 反 +620** |

**关键否定结论：and/logic_and 的 excess（占 45%）不是重复计算**——统一双形式后
CSE 几乎无合并。NO0003 设想的"守卫链合并=CSE 去重"不成立；excess 是结构性的
（见 §6）。GVN 合并 od1 副本后代表节点变 od2，ge2 反而微升。

## 3. 落地的 pass（optimizeAmGraph，grhsim_am_graph_optimize.cpp）

框架扩展：在"别名表"之外新增**指令重写表**（opcode/operands[/slice lsb] 重写项），
fold/CSE/alias/DCE/compact 全部改走 effective 访问器，定点迭代后一次稠密重建。

| pass | 规则 | 香山实测计数 |
|---|---|---:|
| stateReadAlias | assign 别名细化：读 State 的 Assign 若结果（沿单操作数 Assign 链闭包）不可达 commit 侧指令操作数，则旁路；只有真正喂 commit 的 preCommit 快照保留 | alias 总数 185,426→354,984 |
| logicUnify | 结果与操作数全 1-bit 的 LogicAnd/LogicOr/LogicNot → And/Or/Not | 205,278 |
| muxNotAbsorb | 只喂 mux select 的 Not/LogicNot（单用或共享）吸收进 mux 并交换两臂；限 1-bit（校验器要求 select 1-bit） | 93 |
| sliceFuse | slice(slice(x,l1),l2)→slice(x,l1+l2)（两级均在界内）；恒等 slice 旁路（**带 commit 保护**，见 §4） | 4,706 |
| notUnify（默认关） | 1-bit Not→Eq(x,0) | 100,398 转换但 CSE 仅 +6，ge2 +8，纯桶间搬移 |

## 4. difftest 抓到的真实 bug（identity-slice 的 commit 保护）

首版 fanout1 发射后 coremark 50k difftest **ABORT pc=0 @ instrCnt=2**（canonical
emu 同命令对照通过：73,580/49,996）。根因：sliceFuse 的恒等 slice 旁路把
`slice(S,0)`（S 为状态变量）结果别名到 S，但该结果经 commit 闭包被写指令引用
——旁路后 commit 读到的是本轮已提交的新值而非 pre-commit 值。修复：恒等
slice 旁路与 assign 别名一样查 commitOperand_ 闭包。香山实例中该情形出现
**131 次**（slicefuse 4,837→4,706），不是理论风险。

## 5. 实测效果（生产管线全香山，cap=128/L=256 分区口径）

| 指标 | 前 | 后 | Δ |
|---|---:|---:|---:|
| AM 指令数（optimize 出口） | 3,630,947 | 3,111,542 | −14.3% |
| compute 图节点 | 3,062,283 | 2,964,177 | −3.2% |
| **ge2 节点** | 599,947 | **574,730** | **−25,217（excess −7.3%）** |
| ge2/gsim 比值 | 2.37x | 2.27x | |
| sum_outdeg | 5,147,372 | 4,921,132 | −4.4% |
| **cross_values（生产划分）** | 459,864 | **434,458** | **−25,406（−5.5%）** |
| cross_values/gsim 比值 | 2.58x | 2.44x | |

ge2 减少几乎全部来自 stateReadAlias（仿真预测 −25,155 vs 实测 −25,217）；assign
族 ge2 从 26,458 降到 1,383。logicUnify 是形式清理（and 桶吸收 logic_and 桶，
合计 223,592→223,519 基本不动）；muxNotAbsorb 受 1-bit 限制只杀 93 个（广
播型 logic_not 多为宽操作数，受 select 1-bit 校验约束不能吸收）；sliceFuse
主要是节点/边数收益。

difftest（coremark 50k，判据 instrCnt=73,580 / cycleCnt=49,996）：
- fanout1（无 commit 保护的首版）：**ABORT pc=0 @ instrCnt=2** —— §4 的 bug。
- fanout3（全部修复 + notUnify 开）：**通过**，73,580/49,996，host 324.9s。
- fanout4（终版，notUnify 关）：**通过**，73,580/49,996，host 315.2s（基线
  324.4/318.2s；本专题不以性能为目标，顺带无回退）。

单测：`tests/grhsim/am/test_optimize.cpp` 新增/更新 5 项（快照保留与旁路、
逻辑统一、mux 吸收含共享与混合消费者、slice 融合、notUnify 显式开启）。

## 6. 剩余 excess 的边界（重要）

图形级 pass 的可攻击面已基本打满。剩余 ~322k excess 的归属：

1. **when→mux 展开（主因，表征性差异）**。同名信号对照坐实：gsim 的
   `OP_WHEN` 把条件更新的守卫扇出走控制边（guard→when，od=1），AM 把守卫
   经 mux select 走数据边（同一 `or` 节点 od=258 vs 1；`and` od=188 vs 1）。
   这与 nextValue 合并形式一体两面：`reg.write(mux(g,v,old))` 若恢复
   cond 形式（mem.write 现有cond/mask），约 8 万个更新 mux 及其守卫的数据
   扇出将从 compute 图消失（转入 commit 侧 cond 边，不计入 compute 口径）。
   **注意：这与早先"reg.write 去除 cond、合并入 nextValue"的指令模型决策
   冲突，是否为此恢复 cond 形式需要专门裁决**（粗测 od0 更新 mux 16,334 个、
   相关守卫 12.5k 个会连带死亡，但精确影响需在全 AM 图上评估，split 导出
   看不到 commit 侧）。
2. **mem.read 标量化**（excess 13%）：AM 121,852 读指令 vs gsim 1,841 整阵列
   读口，需 mem2reg 级别的 lowering 改造，图形 pass 够不着。
3. **not 族**（22.8k vs 829）：`a & ~b` 无吸收目标 op；gsim 一侧 not 总数
   仅 5,038，推定其单用表达式内联进消费者，属节点粒度差异，不可经 pass 收敛。
4. 控制广播（od≥16）两侧相当（11,597 vs 9,491），本来就不是问题。
