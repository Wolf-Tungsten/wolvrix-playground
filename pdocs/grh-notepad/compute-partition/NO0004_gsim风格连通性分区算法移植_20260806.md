# NO0004 gsim 风格连通性分区算法移植

日期：2026-08-06
状态：已落地并验证（difftest 结果见 §6 补记）

## 1. 目标与路径

NO0002 结论：细粒度截断是"拓扑序列连续切分"算法族的结构性问题，根治需换
连通性导向算法。本文记录从 gsim 源码解析 → 离线复刻验证 → C++ 生产移植的
全过程。

## 2. gsim 算法解析（破除两个误解）

- **gsim 的 `graphRefine()` 在生产中被注释掉**（graphPartition.cpp:418）——178k
  不靠 FM 精化，靠的是 coarsen + Kernighan 边割 DP；
- **gsim 的 `replicationOpt()` 对打平图终值几乎零贡献**（复刻实测
  178,151→178,144，−0.004%）——其规则只触及单例超节点成员（全图仅 925 个
  单例块、8 个节点合格）。基线维持 178,151 不变。
- **真正的关键是 coarsen**：`mergeOut1`/`mergeIn1` 单遍链式塌缩（宿主成员上限
  MAX_NODES_PER_SUPER=7000，防环靠"最早后继/最晚前驱"的拓扑 order 检查）+
  `mergeSublings`（**前驱集完全相等**分组合并、宿主上限 30）。我们的 coarsen 预算
  只有 1.5×cap（69-192），锥体必然被切碎——这就是同图下 4.5x 分区器差距的
  来源（NO0002 的"连通性"假设被证实，但机制是激进合并而非连通性 DP）。

## 3. 离线复刻验证（harness/gsimpart.py）

- **Sanity**：gsim 图复刻 180,441 vs 生产 178,151（+1.28%；块数差 +11.3% 由
  reg_src 导出信息缺失解释——148,956 个 reg_src 只剩 order 边、无法参与合并）；
- **AM compute 图**：cap=128 复刻值 398,950 @ 25,402 块（优于当时生产精化值
  518,382 @ 28,344 块 23.0%，块数更少）——决定移植。

## 4. C++ 移植（`grhsim_am_compute_graph_partition.cpp` 主体替换）

- 删除 DSU 不动点 coarsen 与 activation-cost segment DP；
- 新实现逐条对应参考：逆序单遍 mergeOut1（活接线即时塌缩整链）、正序单遍
  mergeIn1、前驱集等价类 mergeSublings（宿主 <30）、DSU 重映射重建 cluster CSR、
  LIFO-Kahn resort、Kernighan 边割 DP（`dpSegmentPenalty` 保留为每边界罚项、
  严格小于松弛、单超 cap 的 cluster 自成一块）；
- **局部移动精化保留**（接在 Kernighan DP 后，沿用拓扑硬约束）；
- 选项：`dpCoarsenBudget` 语义改为 merge 成员上限（0=7000）；
  `dpWidthWeightedCopyCost`/`variableCopyWeights` 删除（边割 DP 无边权概念）；
  测试适配：宽度加权测试删除、精化测试换 fixture 保留断言语义，其余原样通过。

## 6. 验证补记

- canonical 重发射 + emu 重建 + coremark 50k difftest（mergeLimit=7000 默认档）：
  **通过**（73,580/49,996，EXIT=0），但 **host 344.2s——比基线（324.4/325.6s）慢
  ~6%**。跨边与块数双降并未带来运行时收益。
- **回归机制**（块大小分布实测）：mergeLimit=7000 时 1,731 个块（7.1%）超过 128
  cap，承载 **26.1% 的指令**；尾巴 12 块 >7000（最大 8,191）。超大块一旦被激活
  整块重算，per-activation 浪费超过了边界开销的节省。
- **mergeLimit 权衡扫描**（cap=128，schedule 级实测）：

  | mergeLimit | 块数 | cross_values | >128 指令占比 | 最大块 |
  |---:|---:|---:|---:|---:|
  | 256 | 27,472 | 459,864 | 18.0% | 511 |
  | 512 | 26,255 | 423,746 | 21.5% | 1,023 |
  | 1024 | 25,519 | 411,163 | 23.3% | 2,047 |
  | 7000 | 24,309 | 389,508 | 26.1% | 8,191 |

## 8. 生产点选定（mergeLimit 与运行时尾巴）

  （注：mergeLimit 约束的是合并宿主当前成员数，连锁吸收可使块最大 ~2×上限。）

- **L=256 档 difftest + 计时（2026-08-06）**：通过（73,580/49,996，EXIT=0），
  **host 314.2s——比基线（324.4/325.6s）快 3.3%**，且 cross_values 459,864 仍比
  旧算法精化值低 11.3%（2.58x）。超大块尾巴压住后指标与运行时双赢。
- L=512 档计时验证进行中（指标 423,746、−18.3%，最大块 1023），结果补记于此。
- 结论：mergeLimit 是"跨边指标 vs 超大块运行时尾巴"的权衡旋钮；默认 7000 的
  gsim 对齐值在本设计执行模型（整激活块全量重算）下不可接受，生产点须按
  difftest host time 裁定。

## 9. 最终裁定（2026-08-06）

| 配置（cap=128，全部 difftest 通过） | cross_values | compute 块 | host |
|---|---:|---:|---:|
| 旧算法（精化，基线） | 518,382 | 28,344 | 324.4-325.6s |
| gsim 风格 L=7000 | 389,508 | 24,309 | 344.2s（+6%） |
| **gsim 风格 L=256（生产采用）** | **459,864** | 27,472 | **314.2s（−3.3%）** |
| gsim 风格 L=512 | 423,746 | 26,255 | 327.6s（+1%） |

- **生产点 = mergeLimit 256**：唯一指标与运行时双轴双赢的配置（cross_values
  −11.3% vs 旧算法，host −3.3%）；L=512 指标更优但运行时已越基线，L=7000 指标
  最好但 +6%。
- 默认值已改：`dpCoarsenBudget=0` 的默认 merge 上限 7000 → **256**
  （`grhsim_am_graph_split.cpp` 回退值、`AmGraphPartitionInput`/`AmGraphSplitContext`
  字段默认同步），canonical 已按默认档清空重发射并重建 emu 复核。
- **canonical 复核（2026-08-06）**：重发射与 L=256 验证版逐字节一致；difftest
  通过（73,580/49,996，EXIT=0），**host 314.6s**（比基线 324.4/325.6s 快 3.2%）。
- 生产模型开销（L=256 vs 旧算法精化值）：detectors 602,733（−8.8%）、
  activation_edges 1,554,408（+0.9%）、scheduled_instructions 4,416,076（−2.6%）、
  cross_values 459,864（−11.3%，比值 2.58x）。

## 7. 与 NO0003 的衔接（剩余差距分解）

移植后 cap=128 比值 2.19x（389,508 vs 178,151）。剩余差距的归因（NO0003）：
~58% excess 属图形级 pass 可攻击面（守卫链合并 / assign 消除 / NOT 吸收）、
mem.read 需 mem2reg、控制广播 RTL 固有。下一步按"效果对齐"原则在图形级 pass
与更细的划分粒度上继续收敛，而非继续追赶 gsim 算法本身。
