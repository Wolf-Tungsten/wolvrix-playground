## 1. 决定

2026-08-04 用户裁定终止 next-state（commit 吸收）方案并整体回滚，理由：**该方案使纯组合逻辑节点被过度激活——边指标虽然下降，但仿真性能会严重恶化**。

## 2. 方案的两个致命面（记录备查）

1. **eval 不收敛**（首轮 difftest 发现）：copy 以 `Ne(next, target)` 为 event 时，`t <= t+1` 型逻辑在 round 循环中每轮产生新值，永不收敛（`AM eval did not converge`）。曾修复为 `firedAny = OR(fired_i)`（事件自熄门控）。
2. **过度激活（终审死因）**：链逻辑是普通 compute 指令，其所在块会被类型③激活边在 state 变更后反复触发（act.b 回扫）。原设计中写指令在 commit 块里每轮无条件执行但幂等收敛；把 RMW 逻辑搬进 compute 块后，每个 state 写都引入一条"commit 写 → 链块重算 → copy 再写"的往返激活路径，等于把全设计的寄存器更新逻辑纳入 act.b 回扫范围，仿真性能结构性恶化。这是架构层面的问题，不是实现 bug——**gsim 的 $NEXT 模型依赖其超节点执行语义（按依赖调度执行，不是 AM 的轮扫+激活回扫模型），不能平移**。
