# NO0019 E3 块级运行时激活分布对照

日期：2026-08-12
前置：./NO0018_分区校准atom到block映射贴合_20260812.md（E3 校准点，pair-F1 0.9255）

## 1. 目的

NO0018 已经把 atom→block 与 node→supernode 的结构映射校准到 pair-F1 0.9255，
但结构指标是静态的：nesting 63.07% 意味着仍有三成多的 block 边界不嵌套。
本文是 emit-cost 主线入场前的裁决实验：**在 coremark 50k 周期窗上对照两侧
block/supernode 的运行时激活分布**，回答一个问题——

> 残余的 37% 非嵌套边界是否落在热路径上（即运行时激活分布仍有显著差异）？

- 若两侧激活分布接近：分区变量彻底关闭，后续 runtime 差距全部归因 emit/调度，
  图结构对齐线封存。
- 若差异显著：带着 profile 证据回到分区算法定点修复（而非盲推结构指标）。

## 2. 方法

两侧均使用**已有的** runtime profile 设施，不新增插桩代码：

| 侧 | emit 时开关 | 运行时开关 | per-单元输出 | 静态 cost |
| --- | --- | --- | --- | --- |
| gsim | `GSIM_EMIT_RUNTIME_PROFILE=1`（difftest gsim.mk 原生支持，追加 `-DGSIM_RUNTIME_PROFILE`） | `EMU_RUNTIME_PROFILE=1` + `GSIM_SUPERNODE_TSV=<path>` | `supernode_id × f`（fire count，NO0190 设施，`runtimeProfileFireCount`，激活分支内自增） | emit 时写 `SimTop_supernode_static.tsv`（n_comp/n_src/n_sink/n_const/a_succ） |
| grhsim am | `grhsim-am-lower-json ... --emit <dir> --runtime-profile`（E3 参数已为 CLI 默认） | `EMU_RUNTIME_PROFILE=1` + `EMU_AM_BLOCK_EXECS=<path>` | `block_id kind(w/c) execs`（NO0017 B-layer 设施，`profilePerBlockExecs_`，byteFlags 位测试通过后自增） | block→atom 成员 jsonl（复用 NO0018 E3 导出） |

口径对齐说明：

- 两侧计数点都在"激活判断通过、进入执行"处，口径一致（fire = 本周期窗内该
  super/block 实际执行次数）。
- gsim 侧 supernode 激活后全量执行其 node；am 侧 block 激活后全量执行其 instr
  （commit 块同理），故 `fire × 静态大小` 可推出动态计算量分布。
- am 侧 commit 块（kind=c）单列：gsim 无对应物，对照时 compute 与 commit 分开统计，
  compute 部分才与 gsim super 可比。

运行窗：coremark `-b 0 -e 0 -C 50000`（与 NO0009/NO0018 基线同一窗口）。

join 依据：复用 NO0018 E3 的 `am_block_atom_cal.jsonl` 与
`build/logs/no0009/membership_join_v3.json`（block↔super 成员 join）。重 emit 后
重新导出 block/atom 成员并与 NO0018 产物 diff 校验确定性（profile 开关不改变
分区算法与编号）；gsim 侧同理校验 supernode members jsonl 一致性。

## 3. 对照指标（规划）

1. 总量：Σ fire（compute 侧）、Σ fire × 静态大小（动态指令量上界）。
2. 分布形态：fire 直方图、top-N 集中度、分位数（p50/p90/p99）、Gini 系数。
3. per-pair：按 join 簇聚合后，AM block 组 fire 和 vs 对应 gsim super fire 和
   的比值分布（过度激活/欠激活定位）。
4. commit 块附加账：am commit 块 Σ fire 与其占 eval 总开销的比例（gsim 无此概念，
   属 AM 模型的固有附加成本，单独量化）。

## 5. 结论

**裁决：分区变量关闭，图结构对齐线封存。**

1. **激活分布同构**：gini 0.744 vs 0.758、top10% 份额 0.525 vs 0.532、p90/p99
   同量级、直方图同形。NO0018 残余的 37% 非嵌套边界**没有**落在热路径上造成
   系统性畸形——结构差异存在但不转化为运行时激活差异。
2. **am 激活总量不劣于 gsim**：compute 0.62x、含 commit 0.94x、动态工作量
   0.85x；80.4% 的簇 am 激活 ≤ gsim（p50=0.514），仅 2.1% 的簇 overshoot
   >1.1x。"am 块大导致过度激活"的担心被数据否决——块大反而摊薄了激活次数。
3. 由此，NO0017 观测到的引擎级性能差距（同图 571.7s vs 27.6s）**不来自激活
   次数与分区形态**，归因方向锁定 emit 形态与执行模型（单次激活的内部成本、
   changed 检测/act 传播的实现成本），即 emit-cost 主线。

**附带发现（移交 emit-cost / 调度线）**：

- **commit 块激活过滤近乎失效**：commit p50=100,102 ≈ eval 数（每 eval 必
  激活），占 am 总块激活 33.9%，而引擎时间上 commit 只占 13.64%——单次
  commit 激活极便宜但次数巨大，act 传播/轮询成本值得单列审计。
- am 存在每 round 必激活的块（max=150,102 = rounds 数）；gsim 无冷 super
  （最小 fire∈[128,256)）而 am 有 40% 冷块（fire<128）——两侧初始化/常量
  处理的激活语义差异，供 emit-cost 线参考。
