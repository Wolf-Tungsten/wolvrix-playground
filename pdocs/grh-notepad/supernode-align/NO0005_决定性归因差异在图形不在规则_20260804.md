# NO0005 决定性归因：差异在图形结构，不在 coarsen 规则

日期：2026-08-04
前置：[NO0004](NO0004_剩余差距归因与规则实验_20260803.md)（规则实验矩阵平台期）

## 1. gsim 式合并规则的忠实复刻

细读 `reference/gsim/src/mergeNodes.cpp` 后发现 gsim 的 mergeOut1/mergeIn1 与 AM 实现有三个关键差异：

1. **单遍扫掠**：`mergeOut1` 按逆拓扑序扫一遍（`mergeNodes.cpp:273`），合并即时生效，链一趟折叠完毕；AM 用 mergeMark 每轮每簇限一次，需 log 轮且被 tail-stop 截断。
2. **单边容量**：gsim 只限制吸收方 `nextSuper->member.size() ≤ 7000`（`:280`），不限制两侧之和，鲸鱼可吸到 7000+；AM budget 限制 sum ≤ 192。
3. **dep 边处理**：gsim 的 order/dep 边不计入出度，而是作为位置约束（`depNext->order < nextSuper->order` 则禁并，`:282-284`）。

沙盒实现 GOut1/GIn1（降/升 level 序单遍、无 mergeMark、单边容量；无环论证：路径沿 level 严格递增）。

## 2. 决定性对照实验

| 实验 | cross_values |
|---|---:|
| GOut1+GIn1 跑 **AM 图**（budget=7000） | 620,522 |
| GOut1+GIn1 跑 **gsim 图**（同参数，含 state 节点） | **204,972** |
| gsim 自身生产结果（参照） | 185,716 |

复刻在 gsim 图上复现 gsim 结果（偏差 10%，差在未跑 when/sibling 与真实 DP）。**同一套规则在两张图上差 3 倍 → 差异在输入图，不在 coarsen 规则。**

辅助证据：
- gsim cluster（coarsen 段导出）按 AM 容量重打包：cap=192 → 171,344（10,507 块）、cap=15 → 186,741（82,637 块）。cluster 质量是全部差异，鲸鱼尾巴只是表象。
- AM 无 coarsen 纯打包：1,223,816（coarsen 确有 1.7x 价值，但已压到平台期）。
- gsim `mergeWhenNodes` 实际只合并 53,510 个节点（导出日志 `[mergeNodes-when] remove 53510 superNodes`）——不是主因。
- 组合下限：sequential b100k + replication tier2 = 540,888（2.91x）。

## 3. 图形结构差异（根因）

| 指标 | gsim 图 | AM 图 | 比值 |
|---|---:|---:|---:|
| 节点/指令 | 2,708,079 | 3,394,012 | 1.25x |
| def_use 边 | 3,996,156 | 5,734,197 | 1.44x |
| **fanout≥2 的 value** | **270,706** | **659,520** | **2.44x** |
| fanout=1 占比 | 88.7% | 79.3% | — |

coarsen 的收敛形态是"crossings ≈ 未被吸收的 fanout≥2 value"（两侧皆然：gsim 185,716 ≈ 其 fanout≥2 的 69%；AM 也收敛于此）。fanout≥2 是链式合并的天花板，**AM 图多出 38.9 万个 fanout≥2 点，这就是 3 倍差距的来源**。

fanout≥2 value 的生产者 op 对比（过量项）：

| op | AM | gsim 对应 | AM/gsim |
|---|---:|---:|---:|
| logic_and | 97,204 | ≈0（gsim 折叠进树） | — |
| assign | 62,339 | aliasAnalysis 消除 | — |
| slice_static+dynamic | 68,677 | OP_BITS 44,829 | 1.5x |
| mem.read | 45,587 | （read 在节点内） | — |
| concat | 29,670 | OP_CAT 23,792 | 1.2x |
| and+logic_and 合计 | 232,087 | OP_AND 75,671 | 3.1x |

## 4. 路线修正

coarsen 规则空间已穷尽（Out1/In1/Sibling/PrevSibling/MuxCond/GOut1/GIn1/预算/replication 全部实测）。下一阶段按"一组 pass"的框架转向 **AM 图形级 pass**（目标：减少 fanout≥2 value 与边数）：

1. **alias 消除**：assign 产生的跨块 value 77,654 个（全部跨块的 10%）且为纯间接层；消除后指令数、边数、跨块数同降。注意重定向后被别名值 fanout 会上升，需实测净效果。
2. **slice/concat 融合**：静态 slice 并入消费端（GRH 层已有同类惯用法优化，排查为何未覆盖）。
3. **logic_and 过量归因**：先查清 AM 侧 logic_and 为何是 gsim OP_AND 无法对账的 3 倍（CSE 不足？惯用法展开？），再定 pass。
4. commit 侧 182,810 的架构/口径决策仍待用户定夺（见 NO0004 §4）。

即使图形收敛到 gsim 水平，commit 部分仍使总量超 1.10x 线；但 compute→compute 部分是压边数的主战场，继续推进。
