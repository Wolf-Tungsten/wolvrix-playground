## 0. 立项背景

锚点档（cap15 / budget7000 / penalty0 / refine0，gsim 常数全对齐，NO0010 增量(二)）当前读数：**cross_values_compute_network = 396,008 = 2.2229x**（gsim 178,151，mergeWhen state-select 修复后）。mergeWhen 线已收官——覆盖率 3.35% 已超 gsim 1.77%，修复指标中性，**残余 2.2x 差距不在 mergeWhen**。

NO0010 增量(三) 指认的下一方向即本专题：**链粗化形状**——同样 7,000 粗化预算（MAX_NODES_PER_SUPER 对齐）下，AM 的 out1/in1 合并吃得不如 gsim 深。点状证据（出处与口径见 §2）：

- coarsen 整体削减率：gsim 90.6% vs AM 71.1%；
- coarsen 后 cluster 均值：gsim 10.62 node/cluster vs AM 3.46 atom/cluster；
- 可链合并供给：outdeg==1 节点占比 gsim 81.0% vs AM 71.5%；
- oversized(>cap15) 质量覆盖：gsim 76.0% vs AM 55.0%——gsim 把约三成节点藏进 >1025 成员的链式巨块（每节点近零边界代价），AM 做不到。

## 1. 核心问题

为什么 AM 的 out1/in1 在相同预算下吃不深？拆成三个可观测层，诊断要把差距分解到层：

- **(a) 候选供给（图形状）**：outdeg==1 / indeg==1 / sibling 前驱集等价类的占比与规模分布，两侧各是多少？AM 缺的 9.5 个点（81.0%−71.5%）是什么节点/atom 形态贡献的？
- **(b) 合并接受率（规则行为）**：各路合并的候选中，多少被 `mergeLimit`（7000）拒绝、多少根本因形状（度≠1、前驱集不共享）进不了候选？两侧规则语义是否还有未对齐处（合并准入条件、member 计权、扫描/不动点结构）？
- **(c) 链深度**：极大可链路径长度分布。gsim 巨块（>1025 成员）是长链反复吞并的产物；AM 的链在何处提前断掉——度分叉、预算打满，还是 atom 形态本身（mux 根多扇出等）？

### state 边界核查结论（§3 P1 核查项）

1. **gsim 导出口径下 reg_src（REG_UPDATE，148,956 个）是孤立节点**：
   def-use 边进出均为 0（topoProjExport.cpp:172-178 显式跳过），寄存器边界
   双侧切断（读者经 reg_dst 作 external_read 源；更新锥→reg_src 边不导出）。
2. **AM 生产 commit 原子 = 含 state_write 指令的原子，精确一致**
   （147,365 个，split 代码 blockClass 判定即此）。AM compute 图同样切断
   寄存器边界（commit 原子及其边不进 compute 分区）。
3. **两侧边界口径对称，差距无口径成分**。唯一反向 artifact：NO0014 的 AM
   指纹是在含 commit 原子的全图上量的（436,869 条 compute→commit 边虚增
   了 outdeg==1 供给 160,617 个"唯一消费者是 state 写"的原子）——旧 71.5%
   被**高估**，真实缺口比旧数字更大。
4. 附带发现：gsim 导出有 5,719,920 条 order 边（dep-only，含 reg reset 依
   赖），其 coarsen 的 `next`/`prev` 不含它们；lab 把 du+order 合并进 DAG
   使 gsim cluster DAG 度数 1.885→4.435。对 cross 实测影响 <2.3%
   （NO0014 忠实性），但对指纹口径需注意：本文一律用 du 边集对照。

### 三层归因矩阵

**(a) 候选供给——主因，结构性**。AM 生产 compute 图 outdeg==1 仅 26.13%
（剔除 changed 事件网络后数据逻辑原子 817,962 个，outdeg==1 = 24.63%，
fanout≥2 = 55.85%）vs gsim 80.95% / 8.9%。**差距不在分区算法层，在图形态
层**：gsim 节点=命名信号+assignTree（单消费者内联、命名信号留节点），AM
atom=单输出树（NO0008 fold 同规则）——折叠/钉住语义两侧对称，差异来自更
上游的变量使用结构本身。fanout≥2 源头的 op 分解（AM compute）：
and 134,569 / eq 71,015 / slice_static 56,490 / not 50,918 /
mem.read 42,524 / slice_dynamic 32,719 / concat 31,036（gsim 对应：
AND 75,674 / BITS 45,017 / EQ 30,885 / OR 25,509 / CAT 23,885）。
另有 gsim 完全没有的事件网络：changed.* 根原子 **157,336 个全部落在
compute 侧**（commit 侧为 0；NO0002 设计意图是随 event 进 commit block，
当前实现未如此），占 compute 图 16.1%，且因 ChangeDetector effect 不可
折叠。outdeg==1 的 254,857 个 atom 中 183,334 个是"单使用但未折叠"
（消费方多为 changed.neg/changed.pos 事件锥，136,953 个纯逻辑根属此类；
钉住语义与 gsim 对称，不算丢失供给）。

**(b) 规则行为——排除**。gsim `graphCoarsen()` 同为**单遍**
（mergeWhen→resort→mergeOut1→mergeIn1→mergeSublings，graphPartition.cpp:51-58），
无不动点迭代差距；gsim 还多两道 AM 没有的门（superType≠VALID 跳过、
depNext 顺序检查 canMerge）——gsim 规则**更严**却合得更多，规则层无修复
空间。预算拒绝两侧均可忽略（上表）。

**(c) 链深度——(a) 的下游表现**。out1 坍缩深度分布：gsim max=740、
depth≥9 的节点 903,860 个（占 outdeg1 节点 36.7%）；AM max=12、depth≥9
仅 204 个。gsim 的"三成节点藏进巨块"机制（27.34% vs 6.34%）即此长链
坍缩；AM 链短是因为供给稀且散，不是合并中途被拒。

## 增量更新 2026-08-08（二）：勘误与复核（两"计划外发现"的处置）

### 勘误 1：增量(一)中所有 op 名标签错误——"事件网络错位"证伪

增量(一)的 op 级分解用 `replace/split` 解析 `opcode_names`（JSON 数组含空
串占位），空串被 split 吞掉导致索引整体前移，**所有 op 名标签错位**
（度分布/链长/coarsen 计数与 op 名无关，不受影响）。用 `ast.literal_eval`
重解析后的修正事实：

- **changed.* 指令总共 413 条**（413 个原子，compute 侧）——事件信号是
  共享单例（一个 changed.pos(clock) 广播给上万写口），不是"157,336 个原子
  错位"。当前归侧符合实际结构：一个 changed 驱动多个 commit 块，无法"放进
  同一个 commit block"；commit 侧 = 纯 state write 原子（reg.write.c
  84,787 / reg.write 50,495 / mem.write_lanes 4,729 / mem.write.cm 3,384 /
  mem.write.c 3,350 / latch.write.c 402 / mem.fill 217）——**split 实现
  正确，无需修复**。增量(一)中"事件网络归位"的 P2 方向 1 撤销。
- fanout≥2 源头修正表（AM compute）：and 209,045 / eq 42,799 /
  mem.read 42,524 / slice_static 35,863 / or 35,507 / mux 25,441 /
  slice_dynamic 23,092 / not 21,258 / concat 20,512 / add 15,129。
  （增量(一)对应表作废。）
- "单使用未折叠"183,334 个修正：root 构成 mem.read 76,730（StateRead
  effect 屏障，预期行为）+ and 31,941 / or 13,346 / mux 13,287 /
  concat 12,053 / eq 9,785 等纯逻辑（消费方全部在 compute 侧，主要喂
  concat 100,848 / mux 25,054 / and 20,587；屏障嫌疑为变量钉住，与 gsim
  "命名信号留节点"语义对称，不视为丢失供给）。"changed.neg 消费 88,156"
  的说法作废。

## 增量更新 2026-08-08（四）：fanout 吸收生产落地——主指标 1.078x 达标

### 增量(四)追记：host 回退与"修图后降容量"的兑现

**cap48 出货档 + 吸收（预算×1.0）实测**：difftest 功能正确
（73,580/49,996 逐位一致），但 host **810.7s**（对 NO0007 基线 309.7s
**+162%**）。机制：吸收把共享逻辑复制进各消费方，激活粒度（块）变粗变胖
——每次块激活重算全部复制锥；scheduled_instructions 3.9M→6.8M，而块数只
降 11%（22,084→19,672），激活门控省不下重算开销。**结论：修图收益不能
在 cap48 的粗激活粒度上白拿。**

**转机（lab，吸收后 c2b2.0 图上的 cap 曲线）**：

| cap | blocks | cross |
|---|---:|---:|
| 48 | 17,122 | 177,025 |
| 24 | 30,371 | 185,617 |
| 15 | 43,289 | 188,483 |
| 9 | 62,672 | 190,578 |

吸收后的图**对容量几乎免疫**（cap48→9 cross 仅 +7.7%）——正是 NO0014

性，以 cap15+预算×2.0 出货档 difftest 实测为准（进行中）。

### 增量(四)追记 2：cap15 实测——host 回退是复制的内在成本，非容量问题

cap15+预算×2.0 出货档：difftest 正确（73,580/49,996），host **875.2s**
——比 cap48/×1.0（810.7s）更差。细容量方向**不成立**：块更细带来更多
act 求值/调度开销，而复制锥的重算成本不随容量变化。host 涨幅 ≈ 静态指令
涨幅（b1.0：3.03M→5.92M = +95% → host +164%；b2.0：→7.49M = +147% →
host +183%）——激活门控没有摊薄复制计算：块激活时其全部 atom 无条件
重算。

**结论（当前形态下）**：fanout 吸收在指标上达标（1.078x），但 host 成本
与指令复制量近似线性，作为出货默认不可接受。gsim 的低 fanout 是 IR 结构
免费得来的（命名信号 + assignTree + when 骨架，81% 单使用），不是复制买
来的——用复制买同样的图形态，就要付复制的执行钱。

**已识别的可优化点（未做）**：孤本 atom（b1.0 时 106k 个、~1.2M 条指令）
只喂 commit/host，却留在 compute 块里随块激活白算——若把孤本挪到 commit
侧（随事件触发才算），可回收相当一部分 host。这是 commit 分区器接受纯
compute 原子的设计改动，待立项。

## 增量更新 2026-08-08（五）：copy vs absorb 对照——独立复制不如锥吸收

**用户质疑**：方向不应是把单个 atom 搞大，而是复制 fanout≥2 的 atom（独
立小 atom、各自 outdeg=1），靠链合并粘合成更长链。lab 实现 copy 模式
（`--rep-mode copy`，拷贝为独立 atom 参与 out1 链合并；`--rep-freeze`
按原图资格、不级联）与 absorb 同图同参对照（基线 394,306）：

| 模式 | 预算 | 复制指令 | atoms | cross |
|---|---|---:|---:|---:|
| absorb（级联） | ×1.0 | 2.88M | 665,335 | **180,213** |
| absorb（级联） | ×2.0 | 3.83M | 583,944 | **177,248** |
| copy（级联） | ×1.0 | 2.88M | 3,383,832 | 322,706 |
| copy（级联） | ×2.0 | 5.39M | 5,499,011 | 261,912 |
| copy（冻结） | ×1.0 | 2.88M | 3,347,568 | 286,734 |
| copy（冻结） | ×2.0 | 4.36M | 4,573,541 | 252,683 |
| absorb（冻结） | ×1.0 | 2.88M | — | 210,253 |
| absorb（冻结） | ×2.0 | ~5.7M | — | 199,133 |

**结论：独立复制全面不如锥吸收**（同预算 322,706 vs 180,213 @ ×1.0）。
机制：独立拷贝仍要从输入的产地导入全部输入——不私有化锥，输入值的跨
块就顶掉 fanout 值的跨块（−1 换 +K）；absorb 把整条锥私有化、跨块点一
路上移到自由的读口才赢。冻结资格（不级联）对 copy 有小幅改善但仍远不
及 absorb 级联；absorb 冻结也比级联差——**级联 privatize 到读口是收益
本体**。另外 copy 模式的原子数爆炸（975k→3.4M-5.5M），分区/调度开销也
更差。

**对 host 回退问题的含义**：copy 模式在同预算下 host 成本不会更好（复制
指令量相同），且指标更差；该方向放弃。host 治理的正解仍在：孤本归置
（commit 侧）+ 更细的激活粒度机制，另立项评估。

## 增量更新 2026-08-08（六）：runtime profile——回退机理定案与两个优化的裁决

**方法**：新增 `XS_WOLF_GRHSIM_AM_RUNTIME_PROFILE=1` 透传（emit
`--runtime-profile`），`EMU_RUNTIME_PROFILE=1` 运行 50k coremark，对照
吸收开/关两档。（注：第一次"基线"运行 325.2s ≈ 306.6s + profile 开销 ✓。）

**对照（50k 周期）**：

| | 关 | 开（cap2/×1.0） |
|---|---:|---:|
| host | 325.2s | 778.3s（+139%） |
| compute 块激活次数 | 223.06M | 232.92M（+4.4%） |
| commit 块激活 | 15.53M | 15.53M（不变） |
| act 前向传播 | 1.466B | 1.579B（+7.7%） |
| compute 时间占比 | 230.6s（71%） | 675.4s（87%） |
| 单次块激活均耗 | ~1.03µs | ~2.90µs |

**机理定案**：回退**不是**激活变多（块激活 +4.4%、act 传播 +7.7%），而是
**单次激活的重算量 2.9x**——复制锥落在与其输入共激活的热块里，每次块触
发全量重算。跨边减少并没有换来唤醒减少（复制锥直接共享枢纽信号，枢纽一
动全部拷贝块照旧被唤醒）。

**两个候选优化的裁决**：

1. **孤本归置 commit 侧——量级不足，不做**。孤本 atom ≤2 条指令/个
   （cap2），b1.0 合计 ≤21 万条（占 5.9M 的 ~3.6%）；且孤本只在其宿主块
   激活时多算 2 条，边际成本极小。此前"~1.2M 指令白算"的估计有误
   （把孤本 atom 数与复制指令数混淆），特此勘误。
2. **块内 per-atom 门控——理论上限不够，暂不做**。乐观估计跳过 50%
   拷贝重算，host 778→~550s，仍 +70%；实现是 emitter 大改（逐 atom 前
   值比较，含宽值比较成本）。拷贝的输入本就是共享枢纽（变化频繁），
   实际跳过率大概率远低于 50%。

**根本结论**：在这个"块=激活单元、激活即全块重算"的执行模型里，用复制
买图形态的收益与执行成本 1:1 对价，**cross 指标与 host 在此脱钩**
（cross 396k→282k 的同时 host 325→778s）。cross_values_compute_network
作为 host 代理指标在复制语境下失效——它度量分区质量，不度量重算成本。
后续若要兼得，方向是把 fanout 在 IR 上游消解（slice/concat 显式网络、
CSE 策略——AM fanout≥2 密度 51.6% vs gsim 8.9% 的来源治理），让单使用
结构免费获得，而不是事后复制。吸收 pass 保持默认关闭，旋钮留作研究档。

## 增量更新 2026-08-08（七）：fanout 上游归因终审——CSE 无罪，差距=粒度浓缩+真实共享

**任务**（用户指令）：查 AM fanout≥2 密度 51.6% vs gsim 8.9% 的上游原因
（嫌疑：slice/concat 显式切片网络、CSE 策略），让单使用结构免费获得。

**pass 消融**（生产 schedule-only 导出，compute 侧指纹）：

| 变体 | atoms | fanout≥2 占比 | outdeg==1 |
|---|---:|---:|---:|
| 基线（全优化） | 975,298 | 51.55% | 26.13% |
| **关 CSE** | 1,023,431 | 52.91% | 25.54% |
| 关 alias | 1,158,782 | 45.70% | 35.35% |
| 关 unify | 974,722 | 51.52% | 26.15% |

- **CSE 无罪**（关掉反而更密 52.91%）——CSE 不是 fanout 制造者。
- alias 消除（assign 别名穿透）是轻度 fanout 浓缩器（35.35%），但量级
  不足以解释差距。
- unify 无影响。

**粒度分解（关键）**：同边口径（去重、剔 state-write 消费方）下——

| | AM 指令级 | gsim 节点级 |
|---|---:|---:|
| outdeg==1 | 69.22% | 76.06% |
| fanout≥2 | **18.74%（568,332）** | **8.31%（253,029）** |

atom 级的 51.6% vs 8.9%（5.8x）大部分是 **fold 的粒度浓缩幻觉**：fold 把
单使用质量折进树 atom，剩下的多是共享骨架，密度被动抬高。对齐到最细粒
度后真实差距是 **2.25x**（18.7% vs 8.3%）。

**真实差距的成分**（AM 侧 fanout≥2 指令分解）：1-bit `and` 是绝对主力
（fanout≥2 的 and 205k vs gsim AND 75k，+134k），`eq` +12k、
mem.read +42.5k（gsim 无读口在值网络）、slice_static/dynamic +14k。
对 fanout≥8 的 `and` 做消费方画像：消费者是 and(168k)/mux(140k)/
concat(31k)/or(24k)/reg.write.c(16.6k)——**这是设计真实的共享条件网络
（译码/限定符逻辑），不是 pass 制品**。

**终审结论**：
1. 没有 pass 级的"免费"修复——CSE/alias/unify 消融均不成立。
2. 唯一大件可治理项是 **mem.read 读口**（42,524 个 fanout≥2 读口 atom，
   gsim 用 splitArray 把小数组拆成寄存器+mux 树，读口不进值网络）——即
   NO0014 P-A array-split，旧图估计 −59k cross，仍是独立待做项。
3. 条件网络的共享是 RTL 固有结构；要"免费"获得 gsim 式图形态，方向不
   是消 fanout，而是接受粒度事实后改分区/激活经济模型（超出本专题范围）。
