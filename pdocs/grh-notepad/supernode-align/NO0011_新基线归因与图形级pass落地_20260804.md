**commit 项复核（新基线）**：AM commit 消费方跨块 194,972（其中 189,927 仅 commit 消费，5,045 与 compute 共享）；gsim 打平图 commit_blocks=0（15.1 万 state 写是普通超节点成员，97%+ 被吸收进生产者块）。结论维持：这部分是 AM 单态+commit 后缀执行模型的结构性差距（next-state 方案已因性能回滚，NO0009）。生产者 op：slice_static 51,036 / mux 50,061 / logic_or 42,757 / assign 18,831——即写使能与数据选择的末段逻辑。

**达标线可达性**：commit 结构性部分 194,972 已占 gsim 总量 193,181 的 100.9%；1.10x（212,499）要求 compute 侧压到 ≤17,527（-97%）——不可达的判定不变（NO0006 §3 证明在新基线数字下成立）。本专题的现实目标修正为：**在性能不回归前提下把总差距压向 2.0x 量级**（commit 地板 + compute 侧收敛到 gsim 水平）。

## 3. 图形冗余量化（scripts/supernode_align_excess_scan.py，新增）

口径修正：JSONL 导出的 external_read 边携带常量/状态操作数，dup key 必须包含（首版漏算导致 mem.read 假阳性 118k——修正后 mem.read 完全无重复）。修正后实测：

- 精确重复（同 op+结果宽度+操作数多重集）冗余指令 174,702 条（surface 数字，**slice_static 占 123,278 但有口径陷阱，见 §3.1 勘误**）、assign 19,061、and 12,702、eq 7,891。
- alias 可消除 assign（宽度一致单操作数）184,549 条，其中 63,455 个结果当前跨块（此数与生产实测 185,426 吻合，可靠）。
- slice-of-slice 链 = 0（上游已融合）；全常量操作数指令 = 0（已折叠）。

### 3.1 探针口径勘误（2026-08-04，同日下午修正）

两个"发现"被证伪，均为导出格式陷阱：

1. **slice_static 重复数高估**：JSONL 导出不带 slice 的 lsb 属性（它是 C++ 侧的 sliceStaticAttributes，不是操作数）。探针按 (宽度, 操作数) 聚合时，同源不同 lsb 的切片被判为重复（最大假组：同 src 的 2,048 个 1-bit 切片 = 2,048 个不同 bit 位，全非重复）。生产 CSE（精确 key：opcode+完整 resultType+lsb+有序操作数）实测消除 **162,488**，这才是真值。
2. **mem.read "从未写入" 是导出伪影**：导出器的 `isDependencyOperand`（production_activity_schedule.cpp:58-69）把 StateReadWrite 指令的 state-target 操作数排除在 uses 之外，所以写→memory 的 operand 边不出现在 JSONL 里，全部 memory 看似无写。C++ 侧实况：**全部 118,965 条 mem.read 的目标 memory 都有写入者**（MemoryWriteLanes 4,734 + MemoryWrite 6,696 + MemoryFill 191 覆盖），ROM 常量折叠在生产实测 memfold=0（正确跳过，pass 保留在代码中对其他设计有效）。mem.read 35x 差距（118,965 vs gsim 3,394）的根因转为：**AM 把寄存器堆类结构建模为 memory + 逐 cell 常量地址读**，是 lowering 建模差异，不是可折叠冗余。

mem.read 对照：AM 118,965 条 / 跨块 70,951 vs gsim OP_READ_MEM 3,394 条 / 跨块 2,280——最大的单 op 差距项，需从建模层面另行处理（非本批 pass 范围）。

## 5. 生产落地：optimize.cpp 三个改动

根因发现：生产 AM 优化器（`wolvrix/lib/grhsim/am/optimize.cpp`）早有 fixpoint CSE，但日志实测只消掉 **cse=15,405**（3,387,378→3,371,971）。瓶颈是 `aliasable()` 拒绝一切 interface 引用变量——香山 declared_variables 达 **843,988**（25% 变量具名可观测），重复结果大多带 Observable 角色而被跳过。落地三改动（`AmOptimizeOptions` 新增 `assignAlias`/`constMemFold`/`interfaceAlias`，默认开）：

1. **CSE/折叠解锁 Observable**：`aliasable()` 改按角色位拒绝（仅 State/ExternalInput 不可别名）；`compact()` 把 interface（ports/declaredVariables）重指向别名代表，并把 ExternalOutput/Observable 角色位转移到代表变量（角色-接口一致性校验要求集合精确匹配）；DCE 根标记跟随解析后的代表。
2. **assign 别名消除**（assignAliasPass）：单操作数、类型完全一致、操作数非 State（State 操作数的 assign 是 commit read-old 快照，消除会破坏 preCommit 语义，lowering.cpp:1409）。
3. **常量地址 ROM 折叠**（constMemFoldPass）：MemoryRead 的 memory 无任何写/填充、地址为常量 → 折叠为常量（存储零初始化语义：Undef/Zero 读出恒 0，与解释器/发射器逐位一致；越界地址按解释器语义折 0；Actions init $readmemh 不折）。Array 变量不可能带 Constant init（validate 禁止），故只需零值路径。

单测：`grhsim-am-optimize` 全过（两个旧策略测试改写为新语义：observable 可折叠+接口重指向；新增状态快照保留、ROM 折叠两组）。全量 ctest 仅剩 3 个既有失败（transform-comb-lane-pack、transform-repcut、ingest-write-back-slice，NO0009 已记录）。

## 7. opt1 后的剩余差距盘点（下一批方向）

opt1 划分上的最新分解（`supernode_align_gap_attr.py`）：

| 残余项 | 量级 | 性质判定 |
|---|---:|---|
| 出度1 纯链环跨块 | 280,980 | 容量截断（块上限 128/192，p50=126/p90=128 顶满）；只能容量路线，须过性能门控 |
| commit 消费方跨块 | 192,118 | 执行模型结构性（单态+commit 后缀；next-state 已回滚）；alias 只消了 2,854 |
| mem.read 跨块 | 70,186 | lowering 建模差异（逐 cell 常量地址读 vs gsim OP_READ_MEM 3,394）；mem2reg 标量化方向：把常量地址读写的小 memory 炸成逐 cell 状态变量——读变为 er 边（不计跨块）且指令 -11.9 万，但 MemoryWriteLanes 需展开为逐 cell 条件写，commit 相位每轮多扫数万条写指令，性能代价未量化，暂缓 |
| and/logic_and/logic_or/mux 形态差 | 约 29 万跨块 | 惯用法展开的形状差（守卫 fanout-2 模式等），非精确重复，CSE 已尽；需更深重写（守卫重构），收益不明 |

结论：图形级"免费"杠杆（减指令又减跨块）在本批已基本采完。下一步唯一活跃实验是**容量微调**（opt1cap：m256/b384），沙盒预测与空载计时见增量更新；若性能中性则采纳，否则 opt1 即为本专题生产的终点状态。
