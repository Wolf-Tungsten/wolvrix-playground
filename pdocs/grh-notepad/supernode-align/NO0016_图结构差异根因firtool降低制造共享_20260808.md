# NO0016 图结构差异的根因：firtool release 降低制造了共享结构

日期：2026-08-08
前置：[NO0015](NO0015_链粗化形状诊断与修复_20260808.md)（增量(七) 上游归因终审：CSE/alias/unify 无罪、真实差距成分）。

## 0. 问题

gsim 与 grhsim 的源头同为 XiangShan Chisel：gsim 直接分析 FIRRTL，grhsim
走 SV → slang → GRH IR 路线。等价功能为何在 SV 路线上图结构显著不同？
（what 早已确证，本文回答 why。）

## 1. 分叉点与两条处理链

同一棵编译树在 MFC 产出 `SimTop.fir` 后分叉
（`testcase/xiangshan/Makefile`）：

- **gsim 链**：`firParser` 直接读 `SimTop.fir`（MFC 产物）。
- **grhsim 链**：firtool-1.135.0 以 **`-O=release` +
  `lowering-options=explicitBitcast,disallowLocalVariables,disallowPortDeclSharing`**
  把 FIRRTL 降低为 SV，再经 slang → GRH IR。

关键事实：**firtool `-O=release` 是一个完整优化器**（canonicalize/CSE/常
量折叠/内联全跑），不是格式转换器。

## 2. 证据一：输入文本的共享度截然不同

对两侧前端各自的真实输入文本做使用计数（fanout≥2 占比）：

| 输入 | 节点/wire 总数 | fanout≥2 | 占比 |
|---|---:|---:|---:|
| FIRRTL `SimTop.fir`（gsim 的输入） | 2,484,014 node | 209,600 | **8.4%** |
| SV `*.sv`（grhsim 的输入，firtool 产物） | 348,792 命名 wire | 237,138 | **68.0%** |

交叉验证：gsim 最终图 fanout≥2 = 253,029 ≈ FIRRTL 输入的 209,600
（gsim 管线基本保留输入的共享结构）；AM 最终图 568,332（指令级）与 SV
wire 的共享规模同源。**差异在模拟器拿到输入之前就已存在。**

## 3. 证据二：同一模块的两种形态（AMOALU 实例）

FIRRTL 形态（~100 行摘读）：逐 node 展开，且**重复逻辑各自独立**——
`less_signed_mask` 与 `less_signed_mask_1` 是同一个 `xor(0hc,0he)` 的两
份拷贝，`_wmask_T`..`_wmask_T_8` 八个相同 bits+mux 各自单使用。Chisel/
MFC 的 FIRRTL 风格是"按使用点展开、不提升共享"，因此单使用链占绝对主
体。

SV 形态（firtool 输出，全模块仅 43 行）：重复被合并、子表达式被提升为
命名共享 wire（`_logic_xor_T_1 = io_cmd == 5'hA` 同时喂 `logic_and` 与
`logic_xor`），常量折叠+强度削减（`xor(0hc,0he)` 与掩码逻辑折成
`io_cmd[1]`），其余内联成巨型三目嵌套。**firtool 把重复逻辑合并成了具
名的多使用 wire——共享是它制造并固化的**；`disallowLocalVariables` 再
把所有共享临时量逼到模块级，成为 ingest 可见的具名多使用变量。

## 4. 机理总账：图结构差异的来源分解

1. **共享制造（主因）**：firtool release 优化把 FIRRTL 里重复的、单使
   用的逻辑合并/提升成具名多使用 wire。grhsim 的 IR 从 ingest 起就继承
   这个多使用变量结构——这解释了为什么 wolvrix 自己的 CSE 消融无感
   （NO0015 增量(七)：共享在源码到达前已固化）。gsim 读原始 FIRRTL，
   保留单使用链形态。
2. **聚合打包**：FIRRTL 的 bundle/vector 聚合并保留字段结构；firtool 打
   包成扁平位向量，字段访问变位选——AM 的 slice_static/slice_dynamic/
   concat 显式切片网络（~120k fanout 源）由此而来。
3. **when 骨架压平**：FIRRTL 的 `when/else` 条件赋值在 gsim 里以骨架形
   式留在 node 内（87,356 个嵌套 mux 被折叠隐藏，NO0013）；firtool 把
   它们展平成三目/assign 链，AM 侧 468,709 个 mux 全部显式可见。
4. **存储降低**：gsim 的 splitArray 把小数组拆成寄存器+mux 树（读口仅
   3,394 个且不进值网络）；SV 路线的 mem 保持读口形态——AM 有
   121,852 个 mem.read（NO0014 P-A 病灶）。

## 5. 结论与含义

图结构差异的根因不在任何一个模拟器的内部 pass，而在**前端分叉**：
firtool 的 release 降低是设计级重写，它系统性地把单使用、含重复的
FIRRTL 网表改写成共享多使用的 SV 网表；gsim 拿到的则基本保持了
Chisel/FIRRTL 的原始形态。这也是为什么"在 grhsim 内部找某个 pass 消掉
fanout"不可能成功——要拿到 gsim 的图形态，只能在前端对齐（例如研究
firtool 的可选 pass、或在 GRH 层做逆向的"去共享"变换），或者在模拟器
侧接受这一输入差异并把经济模型做对应的鲁棒化。

**后续可选项**（待点题）：
- 考察 firtool 是否有降低共享强度的选项/管线定制空间（如关闭其 CSE），
  从源头降低 SV 的多使用结构；
- NO0014 P-A array-split 仍是独立可做的图形修复（mem.read 读口）。
