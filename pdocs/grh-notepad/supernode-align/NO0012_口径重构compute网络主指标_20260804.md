# NO0012 口径重构：compute 网络主指标与 commit 开销审计

日期：2026-08-04
前置：[NO0011](NO0011_新基线归因与图形级pass落地_20260804.md)（3.65x 落地生产）
用户裁定（2026-08-04）：commit block 不需要被激活——它按 event 聚类判断执行，compute block 不应给 commit block act.f，可减少激活判断；仿真模型相应修改；**本专题指标同步修改**。

## 1. 指标口径修改（主指标 = cross_values_compute_network）

**裁定落实**：cross_values 主指标改为 **compute 网络口径**——两侧同规则剔除 state-write 消费方：一个跨块 value 只有当它至少跨向一个**非 state-write 指令**时才计入。AM 侧 commit 块消费与 gsim 侧 state-write 超节点成员消费按同一规则剔除（value 级：同时跨向 compute 与 state 写的 value 仍计入）。实现：`scripts/supernode_align_metrics.py`（指令级 `state_write` 标记，不再依赖块级 commit_mask；默认 AM 数据集同步切到 opt1）。

旧口径下 AM 的 commit 块消费跨块（192,118，占 gsim 总量 100.9%）是执行模型固有的"结构性地板"（NO0006/NO0011 不可达证明的核心）；新口径下该地板移除，且修正了旧 compute-consumer 口径对 AM 的不公平（旧口径 AM 剔 commit、gsim 不剔 state 写）。

## 3. commit 开销审计（仿真模型侧）

结论：**act.f 入 commit 及相关激活开销为零剩余，无需代码改动**。逐条核实（`production_activity_schedule.cpp` + 发射模型 opt1 实证）：

| 审计项 | 结果 |
|---|---|
| compute→commit 的 act.f 边 | **零**（`:1533` `isCommitBlock(targetBlock)` 直接跳过；注释"Commit Blocks are scanned unconditionally every round"） |
| 外部输入→commit 的激活边 | **零**（`:1501-1503` 同样跳过） |
| commit 消费 value 的 changed 检测器 | **零**（检测器只由激活边物化，无入 commit 边则无检测器） |
| commit→compute 的 act.b（state 变更回扫） | 存在，语义必需（state 读者须重算），非 commit 消费开销 |
| commit 块每轮扫描 | 存在（483 块/轮），已两级短路：块级 event 门（ST00012，发射模型实测 **482/483 块有门**，仅含 LatchWrite/无 event 写的块无门）+ 逐写 guard&&event 短路 + 写点判变融合（ST00011/13） |
| commit 跨块 value 拷贝 | 存在（incoming_copy_cost 的一部分），commit 读取新鲜值的语义必需，除非执行模型改版（next-state，已回滚） |

残留成本（每轮 483 块调度 + 约 15.4 万写 guard 求值 + act.b 尾部检测）是单态+commit 后缀执行模型的**固有成本**，与"激活判断"无关；降低它需执行模型级改动，超出本口径重构范围。

## 4. 新口径下的可达性重估

剩余差距分解（opt1，`supernode_align_gap_attr.py` + 指令级过滤）：

| 分量 | AM opt1 | gsim | 判定 |
|---|---:|---:|---|
| compute_network 总计 | 518,808 | 178,151 | 2.9122x |
| ├ 生产者出度=1 | 110,454 | 25,322 | 容量截断（块上限顶满）；opt1cap 吸收一部分 |
| ├ 生产者出度=2 | 227,584 | 57,712 | 结构差（fanout≥2 规模 2.7x） |
| └ 生产者出度≥3 | 180,770 | 95,117 | 同上 |

出度≥2 部分的生产者 op 集中项：and=141,990、mem.read=69,482、logic_and=56,158、eq=43,388、mux=39,451。

可达性判断：1.10x（195,966）要求从 opt1 再 -62%。路径库存：容量微调（opt1cap 已到 2.59x，+2% 仿真时间）、mem.read 建模（69k，mem2reg 标量化，commit 相位代价未量化）、守卫形态重构（and/logic_and/mux 的 fanout-2 模式）、更深的容量（性能受限）。**不再存在结构性不可能证明，但也无单一杠杆可达 1.10x**；继续按"性能不回归"约束逐批评估。
