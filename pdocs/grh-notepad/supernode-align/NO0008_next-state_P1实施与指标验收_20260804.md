## 3. 收敛性缺陷与修复（增量更新 2026-08-04）

首轮 difftest 暴露致命缺陷：emu 在启动阶段抛异常 `AM eval did not converge`（eval 的 round 循环不收敛）。

**根因**：copy 的 event 取 `det = Ne(next_n, target)`。以 `t <= t+1` 为例：round 1 链算出 next=t_old+1、copy 写 t；类型③激活让链在 round 2 以**新 t** 重算 next=t_old+2、det 恒为 1 → copy 每轮都写、值每轮都变 → 死循环。普通 changed 事件靠 old 快照在 round 2 自熄，Ne 是普通 compute，不自熄。

**修复**：copy 的 event 改为 `firedAny = OR(fired_i)`（原写各自的 fire 条件，内含自熄的 changed 事件）：
- register 写：round 2 事件自熄 → fired_i=0 → copy 不再 fire，链/快照漂移无害（与 preCommitValue 依赖事件门控的既有设计一致）。
- latch 写（无事件，fired=cond）：cond 稳定时 copy 每轮 fire，但写的是同一个 nextValue（或保持值），靠"写同值不触发 act.b"收敛；cond=1 时 nextValue 变化本来就该被 latch 捕获，语义保持。
- 幂等性：fired=1 时 rmw 对已写入的 T 再 RMW 是幂等的（与原设计 round 2 行为一致）。

配套改动：cycle_boundary 指纹从 "Ne(next,target)" 改为 nextValue 变量的 `__am_next` label（`production_activity_schedule.cpp` 的 `isNextStateCommitCopy`）；commit 分桶改为对 copy 直接返回哨兵 key（`commitInstructionBucketKey` 特判），撤销 canonicalCommitEvent 的 Ne 特判；单测 `test_next_commit.cpp` 同步（29 条指令的精确链形态）。

**修复后指标（同一 post-stats/参数）**：cross_values 602,848（与修复前 602,703 持平），比值 3.25x；超节点 35,649 ≤ 84,786 ✓。
