# NO0018 分区校准：atom→block 映射贴合 gsim node→supernode 映射（2026-08-12）

## 1. 目标

emit-cost NO0009 打通了跨侧 id 溯源（gsim node↔AM atom 1:1、supernode/block 成员关系
双向可查）。本记录在**同一打平图**上校准 grhsim am 的 compute 分区算法，使：

- atom→block 的映射关系尽可能贴合 gsim node→supernode 的映射关系。

贴合度指标（`scripts/compare_supernode_block_membership.py`，口径与 NO0009 相同）：

- `supernodes_perfect_nesting`：mapped 成员全部落在**同一个** AM compute block 的
  gsim supernode 数（占比越高越好）；
- `blocks_single_supernode`：成员全部来自**同一个** gsim supernode 的 AM compute
  block 数（占比越高越好）；
- 辅助观察：member 加权嵌套率、逐 super 散度（am_blocks）、逐 block 散度
  （gsim_supers）、dominant share。

非目标：本记录不改 atom 的数量与连接关系（NO0008 冻结约束仍然有效），不动
commit 侧，不追求仿真性能变化本身；性能与跨边指标只做回归观察。

## 2. 同图基础（已核实）

NO0009 v3 数据（`build/logs/no0009/`）：

- AM compute 分区输入 atom 数 3,069,067，其中 node_mapped=3,068,421 且
  distinct_nodes=3,068,421 —— compute atom 与 gsim node **严格 1:1**，无主 atom
  仅 646 个；gsim PreCoarsen super 数 3,146,474（含 ~78k commit 侧映射节点）。
- 即：两侧分区器消费的本质上是同一张 compute DAG，分区结果差异只能来自
  **分区算法本身**——这正是本记录校准的对象。

## 3. 算法差异归因（vs gsim graphPartition/mergeNodes，flatten 图配置）

gsim 侧运行点：`--flatten-nodes --no-replication --supernode-max-size=15`
（NO0009 §5.1 复现命令）；AM 侧运行点：lower-json 默认（emit-cost NO0002 锁定）。

| 环节 | gsim（flatten 图） | AM（当前默认） | 影响 |
|---|---|---|---|
| mergeWhen | flatten 后无 OP_WHEN 根（flattenNodes.cpp 全部转 OP_MUX），实质死亡：remove 仅 1,183（0.04%） | mux 根 atom 按 select 归组：**433,095 merges / 22,989 groups**（含虚拟锚点 97,636） | AM 独有的大 cluster，gsim 不存在对应物 |
| mergeOut1/In1 host 上限 | 7,000 member **nodes** | 32,768 member **instructions**（mean 1.59 instr/atom ≈ 20.6k atoms） | AM host 可约为 gsim 的 3x |
| mergeSiblings 上限 | 30 | 30 | 一致 |
| resort | LIFO Kahn，ORDERED_TOPO_SORT（按 node id） | LIFO Kahn（按 rid 升序） | 近似一致，平局破序不同 |
| DP 块容量 | 15 nodes/segment | **9 atoms**/block | AM 块更小，把 gsim 的 6-15 成员 super 切碎 |
| DP 代价 | 纯割边 Cij | 割边 + segmentPenalty=0 | 已一致 |
| 非 VALID 隔离 | EXTMOD/reset super 强制 singleton（DP 前后强制切） | 无此概念 | 111 EXTMOD + 3 ASYNC_RESET，小影响 |
| graphRefine | 关闭（源码注释） | refinementRounds=0 | 已一致 |

运行日志量级（NO0009 v3）：

- gsim：coarsen 3,146,474 → 354,438 clusters；DP → 113,963 supers。
- AM：coarsen 3,069,067 → **151,988** clusters（out1 2,308,491 / in1 106,700 /
  sibling 68,793 / when 433,095 merges）；DP → **84,872** blocks。

AM 比 gsim 多合并掉 ~20 万 clusters，主因就是 mergeWhen 43 万 merges 与
out1 的 32k 指令预算。

## 4. 基线失配画像（E0 = NO0009 v3 join 结果）

- perfect nesting 41,817/113,963 = **36.69%**；member 加权仅 **48.87%**。
- blocks single-super 35,868/84,873 = **42.26%**。
- 逐 super 散度按尺寸分桶（am_blocks==1 占比 / 平均散度）：
  - 1 成员：86.4% / 0.86；2：69.8% / 1.26；3-5：57.7% / 1.56；
  - **6-15：27.6% / 2.84**（DP cap 9 把 gsim 的 ≤15 super 一切为二以上）；
  - 16-30：46.6% / 3.75；31-100：57.5% / 3.15；101-1k：61.0% / 7.13；
  - **>1k：55.7% / 114.68**（gsim 7k 成员巨 super 被 AM 拆成上百块）。
- 逐 block：**58.7% 的 atom 住在 >100-atom 的块里**（101-1k: 5,993 块 / 1.26M
  atoms；>1k: 347 块 / 1.08M atoms）——gsim 最大 super 仅 7,136 成员，AM 巨块
  是 mergeWhen 群 + 32k 指令预算 out1 host 的产物。

结论：失配是双向的——AM 在 DP 层把 gsim 保持完整的中等 super 切碎（cap 9 < 15），
又在 coarsen 层把 gsim 不打散的内容并成巨块（mergeWhen + 高 instr 预算），
两者都只能靠**对齐 gsim 在同一张图上的实际行为**消除，而非调参玄学。

## 5. 校准实验矩阵

全部用现有 CLI 旋钮控制变量（无需改码），输入复用 NO0009 的
`gsim_flat_export/SimTop.exec.json` 与 `SimTop_supernode_members.jsonl`：

- **E1** = E0 + `--max-atoms-per-block 15`（DP 容量对齐 gsim 15 nodes）
- **E2** = E1 + `--dp-coarsen-instr-budget 0 --dp-coarsen-atom-budget 7000`
  （merge host 上限对齐 gsim 7,000 nodes，atom==node 1:1）
- **E3** = E2 + `--merge-when-min-group 1`（关停 mergeWhen：gsim 在 flatten 图
  上该 sweep 已死，对齐就是不开火）
- **E4**（待定，需改码）：ext/dpi atom 不参与合并且强制 singleton block，
  对齐 gsim 非 VALID super 隔离；mergeWhen 关停后 emitter 块内同 select 融合
  改由 partition 尾部按块重算 fusionAnchor（不动分区几何），保住 emit 融合特性。

每一步跑 `grhsim-am-lower-json --schedule`（不 emit，约 90s/次）导出
block/atom membership 后重跑 join，记录指标变化。验收：nesting 与
single-source 双双大幅上升；同时记录 block 数、cluster 数是否回落至 gsim 的
354k/114k 邻域。

## 6. 实验记录

数据基础：全部复用 NO0009 同一次 gsim run 的产物（exec.json /
supernode members / topo proj 三件套，node id 同进程空间）；AM 侧只跑
`grhsim-am-lower-json --schedule`（约 90s/次），产物在
`build/logs/no0018/`。

### 6.1 统一度量：pair-F1（主）+ 嵌套双指标（辅）

仅有方向性指标（nesting / single-source）会在"块更碎还是更整"之间摇摆，
无法判定总体贴合度。本节起用**逐节点对的聚类一致性**作为校准主指标：

- 对每对 compute-mapped gsim 节点，判定"同 supernode"与"同 AM block"
  是否一致；pair-F1 = 2TP/(2TP+FP+FN)，辅以 Fowlkes-Mallows。
- 口径：dup 边界节点（REG_UPDATE 等，compute+commit 双映射，73,459 个）
  计入 commit（见 §6.4）；join 脚本已加 `refined_dup_as_commit` 节。

### 6.2 E0-E3：参数校准（纯 CLI 旋钮）

| 实验 | 配置变化 | clusters | blocks | nesting | single-source | pair-F1 |
|---|---|---|---|---|---|---|
| E0 | 现状默认（cap9 / 32k instr 预算 / mergeWhen 5） | 151,988 | 84,872 | 36.69% | 42.26% | 0.4260 |
| E1 | +cap 15 | 151,988 | 68,874 | 37.54% | 34.28% | 0.4260 |
| E2 | E1 + atom 预算 7000（替 32k instr） | 156,674 | 70,940 | 34.87% | 37.16% | — |
| E3 | E2 + mergeWhen 关停 | 175,261 | 83,209 | 63.07%* | 51.65%* | **0.9255** |

（*为精炼口径；nesting/single-source 的 E0/E1 值为旧口径，F1 为精炼口径。
E1 与 E0 F1 相同：块数变化在同 cap 族内重新分配边界，pair 一致性未变。）

结论：mergeWhen 关停是最大单项（F1 0.43→0.93 的主要贡献者）——gsim 的
mergeWhenNodes 在 flatten 图上实质死亡（remove 仅 1,183），AM 侧按 mux
select 归组的 43 万 merges 是该图上不存在的结构。

### 6.3 残余差距归因：gsim 分区跑在 value 图上，AM 跑在 compute 诱导子图上

E3 后仍有差距（F1 0.93）。逐 cluster 对照（新增
`WOLVRIX_GRHSIM_AM_CLUSTER_ASSIGN_JSONL` 导出 + gsim topo proj 的
coarsen assignment，脚本 `scripts/compare_coarsen_clusters.py`）：

- gsim compute-bearing clusters 296,274 vs AM 175,261；95.36% 的 gsim
  cluster 完整嵌在 1 个 AM cluster 内（AM 合并更多），反向只有 68.17%。
- gsim 内部 value 图探针（graphCoarsen 处插入直方图，本提交含
  `[coarsen-probe]` 与 per-sweep 计数打印）：**gsim 的 merge 扫描跑在含
  寄存器节点的 value 图上**（state 读 = reg→reader 边，state 写锥 =
  cone→reg 边），总边 5.48M vs AM compute 诱导子图 4.57M（+91.2 万边）。
- per-sweep 计数对比（gsim vs AM E3）：out1 2,658,874 vs 2,702,081；
  in1 89,732 vs 131,152；sibling 42,247 vs 60,573；dep-guard 仅拦截
  23,359（非主因）。
- 极端例证：某 robIdxMatchSeq 352 个 EQ（0 compute 前驱 + 读 1 个状态
  变量）在 gsim 内经 in1 并入 reg 超节点成 1 个 cluster；AM 内 352 个
  孤岛 cluster 散到 352 个块。

### 6.4 dup 边界节点的口径修正

join 细化：73,459 个节点同时映射到 compute atom 与 commit atom
（REG_UPDATE 72,756 + OP_READ_MEM 480 + OP_WRITE_MEM 223）——gsim 把
寄存器节点作为惰性成员留在 compute super，AM 把 nextValue 锥根
（compute atom）与状态写（commit atom）拆开、二者共用同一 node id。
精炼口径把 dup 计入 commit 侧（join 脚本 `refined_dup_as_commit` 节）：
E3 的 single-source 由 38.25% 修正为 51.65%（旧口径低估了块纯度）。

### 6.5 E4/E5：state-anchor 扫描实验（按 F1 裁决）

给 AM 的 merge 扫描补建虚拟锚点边（读锚点：atom 读到的无生产者变量按
变量归组；写锚点：结果被 commit atom 使用的关系按 commit atom 归组），
CLI `--dp-state-anchor-mode`：0=关，1=仅读锚点归组，2=全量（含
out1/in1 有效度数守卫与 sibling 锚点键）。

| 实验 | clusters | blocks | nesting* | single-source* | pair-F1 |
|---|---|---|---|---|---|
| E4 = E3 + mode 2 | 241,239 | 99,844 | 56.34% | 56.59% | 0.8268 |
| E5 = E3 + mode 1 | 156,405 | 79,999 | 63.96% | 51.39% | 0.8935 |

E4 判定：**模式 2 使 F1 从 0.9255 降至 0.8268**——in1 守卫拦截 8.8 万
merges 带来的簇碎裂对内容一致性的伤害大于锚点归组的收益；写锚点合并
仅 166 次（每个寄存器锥恰有 1 个尾巴，归组退化为指定 host 无合并），
out1 守卫仅拦 3,050 次。模式 2 否决。

E5 判定：读锚点归组（+16,479 merges）把 nesting 微升到 63.96%、
member-weighted 到 80.11%，但 pair-F1 降至 0.8935——锚点组把分属不同
gsim super 的同变量读者拉进同一 oversized 块，产生的 FP 对超过归组
收益。模式 1 同样否决。**E3（mode 0）为最终校准点**；锚点扫描代码以
`--dp-state-anchor-mode` 默认关的形式保留为实验装置。

## 7. 结论与后续

### 7.1 最终校准配置（已锁定为 lower-json CLI 默认）

`--max-atoms-per-block 15 --dp-coarsen-atom-budget 7000
--dp-coarsen-instr-budget 0 --merge-when-min-group 1
--dp-segment-penalty 0 --dp-refinement-rounds 0 --dp-state-anchor-mode 0`
（lower_json_smoke.cpp 默认值，无需显式传参）。

相对 gsim 的逐项对齐依据：DP cap 15 = SuperNodeMaxSize（atom↔node 1:1）；
coarsen 预算 7000 atoms = MAX_NODES_PER_SUPER；mergeWhen 关停 = flatten
图上 gsim mergeWhenNodes 实质死亡（remove 1,183）的事实对齐；
penalty/refine 本就一致。

### 7.2 校准成果（vs NO0009 v3 基线）

- pair-F1（主指标，精炼口径）：**0.4260 → 0.9255**。
- nesting：36.69% → 63.07%（精炼口径 63.07% vs 旧口径 62.53%）；
  member-weighted 48.87% → 78.93%。
- single-source：42.26% → 51.65%（精炼口径）。
- >1k 成员巨 super 的平均散落：114.68 块 → 2.12 块（E3 join 分桶）。
- 残余差距结构性归因：gsim 在含寄存器节点的 value 图上做 merge
  （5.48M 边），AM 在 compute 诱导子图上做（4.57M 边）；寄存器读/写
  锚点边的缺失造成 per-sweep 差（out1 +4.3 万 / in1 +4.1 万 /
  sibling +1.8 万）与 reg-anchor 簇型差异。按 state-anchor 补齐的两种
  模式均被 F1 否决（§6.5），残余差距判定为**图对象差异的固有成本**：
  AM 的 compute/commit 分图执行模型不允许寄存器节点做 merge 宿主，
  这是与 gsim 语义模型差异的边界，不是分区算法缺陷。

### 7.3 配套变更

- `fusionAnchor` 改为 DP 后按块局部同 select 计算
  （grhsim_am_compute_graph_partition.cpp），与 mergeWhen 解耦——
  mergeWhen 关停后 emitter 块内同 select 融合特性保留；两个钉旧语义的
  测试更新为新语义（test_production_activity_schedule.cpp 的
  minGroup/wavefront 锚点断言、test_cpp_emitter.cpp 的
  testSelectChangeRegroupsMuxRun）。
- 新增 `WOLVRIX_GRHSIM_AM_CLUSTER_ASSIGN_JSONL` 导出（atom→coarsen
  cluster）与 `scripts/compare_coarsen_clusters.py`（cluster 级对照）。
- join 脚本新增 `refined_dup_as_commit` 节（dup 边界节点计入 commit）。
- gsim 侧新增 coarsen 诊断打印（mergeNodes.cpp per-sweep 计数 +
  graphPartition.cpp `[coarsen-probe]` 度数直方图），不改变其行为。
