# NO0004 剩余差距归因与规则实验（PrevSibling / 无预算）

日期：2026-08-03
前置：[NO0003](NO0003_归因轮询扼杀Out1链式合并_20260803.md)（相位式落地，4.01x）

## 1. 剩余差距的两侧分解（sequential 划分）

按跨块 value 的消费方类型拆分：

| 口径 | gsim | AM sequential | 比值 |
|---|---:|---:|---:|
| 全部跨块 value | 185,716 | 744,513 | 4.01x |
| 消费方 = state write（commit） | 27,796 | 182,810 | 6.58x |
| 消费方 = 非 state（compute→compute） | 171,021 | 566,792 | 3.31x |

- **commit 部分（182,810）是 AM 架构性差距**：AM 的 state 写指令必须进 commit 块（周期末统一提交），不能像 gsim 那样把 reg_dst 合并进生产者超节点（否则周期内扫描语义被破坏）。gsim 侧 reg_dst 是普通超节点成员，97% 被内聚。这部分靠 coarsen 规则压不下去，需要架构级方案（如 next-state 缓冲/提交吸收）或接受口径差异。
- **compute→compute 部分（566,792）是主战场**，目标 ~171k。

## 2. 规则实验：PrevSibling（gsim mergeSublings 等价物）

动机：gsim `mergeSublings` 合并前驱集合完全相同的兄弟超节点（DAG 中直接前驱集相同 ⇒ 互相不可达 ⇒ 合并安全），是收拢扇出的主要规则。沙盒实现（`harness/amcoarsen.py` 的 `prev_sibling_pass`）并 A/B（sequential、budget=192、max=128）：

| pass 组合 | cross_values | dag_edges | compute blocks |
|---|---:|---:|---:|
| Out1+In1+Sibling（=生产） | 724,131* | 338,858 | 27,835 |
| Out1+In1+PrevSibling | 750,043 | 299,131 | 28,355 |
| Out1+PrevSibling+In1 | 751,479 | 300,788 | 28,462 |

*256 轮上限截断值，In1 未充分收敛。
结论：**PrevSibling 无效**（255k~412k 次合并，cross_values 反而 +3%）。扇出兄弟合并在 AM 图上不内聚跨块 value——与 Sibling 实验（437k 合并、cross_values 变差至 795,265）一致：sibling 类合并只是挪动打包边界。

## 3. 规则实验：放开 coarsenBudget

sequential Out1+In1、budget=100000（≈无上限）、max=128：

| 配置 | cross_values | compute blocks | Out1 merges |
|---|---:|---:|---:|
| budget=192 | 724,131 | 27,835 | 2,385,656 |
| budget=100000 | 626,897 | 23,646 | 2,495,512 |

仅 -13%。**预算不是约束**：剩余跨块 value 是出度≥2 且入度≥2 的真 DAG 扇出/扇入结构，Out1/In1 在任何预算下都吸不动（In1 在无预算时甚至 0 次合并——所有可吸收的都已被 Out1 拿走）。1024 轮上限仍未让 Out1 完全收敛（扇入星型簇限速），但边际量不影响结论。

## 4. 结论与下一步

Out1/In1/sibling/budget 四个维度都已压到平台期（~62-74 万）。与 gsim 的 171k compute→compute 差距只能来自 AM 侧尚不具备的机制：

1. **replication（gsim replicationOpt 等价物）**：把小型扇出生产者复制进各消费块，值的本地副本不再跨块。量化估算（sequential 划分上）：全操作数在消费块可得的 1-level 可复制 value = **116,075 / 566,792**（20%），多级递归覆盖更多但 op 数膨胀。注意 gsim 自己的 replicationOpt 其实很窄：只处理 singleton 超节点（member==1 且 op×fanout<3），作用是消除孤块、降低超节点数，不是通用跨边削减器；AM 若做需自行加宽（`reference/gsim/src/replication.cpp:83`）。
2. **mergeWhenNodes 等价物 → MuxCond 实验（已完成，无效）**：gsim 把同 when 条件的 when-body 合并（`mergeNodes.cpp:78` active 版）。AM 无 when 节点，等价形态是"共享 select 条件的 mux"（kMux 条件必为 1-bit，`lowering.cpp:1854`）。香山上该结构巨大：477,723 个 mux，采样中 59% 处于 ≥8 同条件组（最大组 2,048）。沙盒实现 MuxCond（同条件 + 同 level 的 mux 簇合并，select 用"唯一 1-bit 操作数"启发式，覆盖 327,513/468,701 mux）：29,256 次合并，cross_values 725,915 ≈ 持平。**同条件合并同样不内聚跨块 value**——这些 mux 的数据输入来自远方，合并 mux 本身并不能把数据源拉近。
3. **排序质量**：两侧 DP 都依赖拓扑序质量；AM 当前是 minInstruction Kahn 序，可实验深度优先锥形序等变形（沙盒可测）。
4. **commit 侧的结构性差距（182,810 vs 27,796）**：AM 单态 + commit 后缀 vs gsim 双态（$NEXT 缓冲）。吸收这部分需要 AM 引入 next-state 缓冲架构，超出 coarsen 规则范畴。

**量级判断**：即使 compute→compute 做到与 gsim 等质量（按边数归一 171k×1.44≈246k），加上 commit 结构性部分后总量仍显著超 1.10x 目标线（204,288）。**达标很可能需要 commit 架构改动或指标口径调整（把 commit 侧跨块视为执行模型固有、不计入超节点构造质量）——这属于范围决策，提交用户定夺。**
