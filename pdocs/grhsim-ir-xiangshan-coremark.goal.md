# Goal: 优化 GrhSIM-IR 单线程 XiangShan CoreMark 100k（微观差距驱动）

## 目标与范围

逼近 **gsim 单线程仿真性能**。整个 goal 关闭须同时满足：100k 行为等价、最终性能相对 gsim 归档测量的差距进入噪声底以内（或由用户判定关闭）、完整 SV→C++ 生成和 C++ 编译各 `<1800 s`、完整归档已提交。

允许修改 GrhSIM-IR 语义、op、emit、分区、调度及等价子图/状态访问优化。禁止修改冻结的 GRH IR、GRH 上已有 pass、XiangShan 和测试源码；禁止多线程仿真及模块名称匹配优化。方案必须由语义、依赖、位宽、读写属性等通用特征触发。不以任何理由放宽正确性和时间门槛。

## 方法论重启说明（2026-09-23）

本 goal 自 2026-09-23 起重启为**微观差距驱动**方法论。旧 pdocs（NO00001–NO00059 报告及旧 goal/index）已删除；其中的结论、人工判定、验收门调整、已排除方向清单与移交候选**一律不继承**。仅两条实测锚点（gsim 归档测量、当前最佳构建时间）保留为选题参考，且须在首个节点复核。节点编号自 NO00060 起延续，不复用历史编号；战役编号自 C01 起。

重启动机（旧方法论的四个失效模式，本结构逐条设防）：短平快选题耗尽低垂果实后够不到高处果实；不敢做"先付代价后收割"的大动作；在已证伪的机制家族上反复钻牛角尖；存在退出通道时过早宣告失败。

## 核心原则：微观差距驱动

一切优化工作从差距账本出发、回到差距账本。**不允许无账本锚点的优化节点。**

1. [ledger](grhsim-ir-xiangshan-coremark.ledger.md) 是唯一选题来源，记两张表：**差距条目表**（GAP-x：定量描述、份额/理论上限、证据、状态、对应战役）与**类级关闭表**（机制类、机制层面证据、重开条件）。
2. 每条差距条目必须来自**本分支的实测定量**（profile/插桩/perf），写明测量方法、数据、占总运行时间份额与理论上限算术。猜测、直觉、历史印象不得入表。
3. **类级关闭**：一个机制类被证伪到机制层面（结构性证据，或同类多次独立复证）即类级关闭，其所有实例默认关闭；仅当出现机制级新证据（编译器版本、框架语义等变化）才可重开，举证责任在重开方。
4. **噪声底门槛**：理论上限低于噪声底的候选禁止立项。噪声底以最近一次 6 次交替窗口实测离散度登记于账本。
5. 候选疑似落入历史死区时，允许先用低成本微实验复核再决定立项——复核数据入账本；不凭记忆判死刑，也不凭记忆放行。

## 层级结构

```
Goal ⊃ 战役（Campaign）⊃ 节点（Node）
```

- **战役 C01、C02……**：锚定账本一条差距的攻坚战，跨多次 `/goal` 存在。任何时刻只有一个进行中的战役；战役由用户启动（其首节点即立项，立项时预注册机制清单）。
- **节点 NOxxxxx**：每次 `/goal` 完成一个节点，攻击战役机制清单上的一族机制。编号全局单调延续、不复用。例外：用户指示的诊断/画像节点与本 goal 规定的账本建立节点不属战役，索引中标"战役：—"。节点内的中途尝试只是过程记录，不构成结构层级。

## 判定

节点 BASELINE 阶段须预注册本节点的验证标准与证伪标准。节点内单次尝试被证据否定时记 `REJECTED`（过程记录，含理由），随后在同一节点内修正或改换实现继续实验；`REJECTED` 不是节点终态。

### 节点终态（三选一，AI 按预注册标准记录）
- `ACCEPTED`：取得 6 次交替门确认的真实收益，正确性与生成/编译门槛通过。
- `STAGED`：战役内**预注册**的准备步骤。门槛：机制建成、正确性门全过、回退不越预注册包络、收割预测收益 ≥ 回退的若干倍（算术展示）、回滚方案预注册。只能事前声明，不得事后把未达 ACCEPTED 的节点改判 STAGED；每战役连续 STAGED ≤ 2，收割节点必须紧随其后。
- `FALSIFIED`：该节点攻击的机制族被证伪（BASELINE 预注册的证伪标准触发），证据归档；战役清单划掉该族，下一节点自动打清单上的下一族。**FALSIFIED 是族证伪记录，不是放弃——战役仍开着，差距仍挂着。**
- 诊断/画像节点终态记 `PROFILE`，交付测量数据与账本条目。

### 战役终态（三选一）
- `ACHIEVED`：差距缩小到立项目标。须在战役收尾以**战役起点基线**做 6 次交替复测确认净收益（节点收益不自动累加为战役收益，防漂移累积）。AI 可依数据记录。
- `QUANTIFIED-AWAY`：重定量表明差距小于此前估计或结构性不可提取；测量本身是交付物。**只能由用户盖章关闭。**
- `EXHAUSTED`：预注册机制清单全部 FALSIFIED，或剩余族上限之和已低于立项目标。**只能由用户人工判定。** AI 请求判定时必须出示完整清单状态（每族上限算术与证伪证据）；单族证伪只是清单推进，不构成结束理由，AI 不得自行宣告战役失败或停止推进。

## 选题规则

1. 每个节点 IDEA 阶段首段固定写 **altitude check**：当前最佳、账本状态、本节点攻击的 GAP ID 及理论上限算术、为何这是剩余上限最高的选择；不选最高者须显式论证（如"为某大动作解锁"）。
2. 每 3 个节点中至少 1 个攻击账本 top-3 差距（按理论上限排序）。
3. 上一节点的移交候选必须重新对照账本验证（上限 ≥ 噪声底、未被类级关闭）才可晋升为新节点。
4. 节点收益不设固定下限；上限排序取代幅度下限成为选题约束。局部调整必须服务于战役锚定的差距，禁止围绕边角 helper 或同一参数的无锚点微调。

## 执行与验证

所有构建、安装、生成、测试和仿真均通过 Makefile 目标；缺少目标时先补充，禁止手拼底层命令。常用目标为 `xs_wolf_grhsim_ir`、`xs_wolf_grhsim_ir_build_emu`、`run_xs_wolf_grhsim_ir_emu`，以当前 Makefile 为准。

每个节点有唯一 ID，每次实验有唯一 `RUN_ID`。日志和临时产物放 `ptmp/`，不写 `/tmp`。仿真固定 CPU 并显式设置 `XS_EMU_THREADS=1`；编译按机器实际核数并行——默认 `VM_BUILD_JOBS=$(XS_VM_BUILD_JOBS)`（`nproc`），不得沿用固定小并行度；节点文档须记录实际 job 数。聚焦回归可用 `make run_hdlbits_test DUT=001`。

| 区间 | 计时边界与门槛 |
|---|---|
| SV→C++ 生成 | Make 启动至完整目标 C++ 和 Makefile 生成完成，墙钟 `<1800 s`；恢复已有 IR 的时间不能替代完整 SV 路线 |
| C++ 编译 | 编译目标启动至 emu 可执行文件完成，墙钟 `<1800 s` |
| 仿真 | 仅 emu 执行区间；记录 Host/墙钟时间、cycle 上限、退出状态及等价性 |

截止机制：生成或编译达 1800 s 立即终止该步骤及子进程，记 `TIMEOUT_KILLED` 并隔离未完成产物；仿真达预选可比较基线的 1.5 倍立即终止进程树，记 `REGRESSION_KILLED`。基线有多次测量时须在运行前选定比较值。触发后否定当前尝试并记录，修正后在同一节点内重新验证。退出非零、崩溃、断言失败、difftest mismatch 或输入不一致均记 `INVALID`；失败或部分结果只能用于原因分析，不能作为性能收益证据。

比较口径：机器、输入、CPU 绑定、cycle 范围和 waveform/trace 设置一致；**每次运行前以 posix_fadvise 驱逐 page cache**（页帧固定偏差实测可达 ±6–9%，不驱逐则交替协议无效）。配置未变时复用已归档 gsim 测量，不重复运行；配置变化时重建相应基线。采样/插桩时间不得混入未插桩性能基线。

收益判定统一为 **6 次新旧交替复测**：同一时间窗口内交替执行新、旧构建（3 新 + 3 旧），运行前预注册执行顺序与比较口径，记录全部 6 次的 Host/墙钟时间、退出状态与等价性；任一构建出现 `INVALID` 运行时该次作废补跑，两组各保持 3 次有效。报告两组均值、离散度与效应量；秩次判据：全部 3 次新运行均优于全部 3 次旧运行（n=3+3 等价 Mann-Whitney U 单侧 p≤0.05）方可判定提升真实；交错后仍无法与噪声区分时须加跑或改进机制，不得按 `ACCEPTED` 收尾。约 90 分钟尺度的机器漂移可达 ~4%，禁止用跨窗口或非交错历史数据充当对照。

## 文档与 Git 归档

报告须自包含，临时产物中的证据须整理入正文，不能用"详见日志"、路径或哈希代替分析。正式引用只能指向已跟踪或随节点一起提交的文件。不得提交生成代码、日志、profile、波形和二进制，不得强制添加生成目录。

仅节点完成时集中暂存、检查并提交代码、测试、报告、账本与索引，每个有改动的仓库原则上一次提交。涉及子模块时先提交子模块，再提交根仓库指针与档案。中间版本用基线及差异记录，不为取得 commit 而提前提交。

用户启动 `/goal` 已授权正常暂存和节点最终提交，复用已有 Git 授权，不按阶段、文件或仓库反复询问；环境确需额外权限时，完成全部准备后在节点收尾集中处理，不绕过权限限制。

## 当前性能锚点（继承实测，首节点复核）

自 2026-09-14 起统一 **100,000 cycles**。配置：`testcase/xiangshan/ready-to-run/coremark-2-iteration.bin`，`XS_NUM_CORES=1`，`XS_EMU_THREADS=1`，`XS_EMU_CPU=2`，waveform/commit/RAM trace 关闭，cycle 上限 `100000`。

- **gsim 归档测量**（emu 编译于 2026-09-10 01:50:26）：Host time **46.965 s**；`instrCnt=238550`、`cycleCnt=99998`、IPC **2.385548**、末端 PC `0x80000b40`、guest cycles 100001，退出码 0，DIFFTEST 无 mismatch。
- **GrhSIM-IR 当前最佳**（2026-09-22 三次正式 new 均值）：**71.309667 s**；`instrCnt=240349`、`cycleCnt=99996`、IPC **2.403586**、末端 PC `0x80000c0c`，退出码 0，DIFFTEST 无 mismatch。对 gsim ≈ **1.518×**，即剩余差距 ~24.3 s。
- 两条锚点继承自旧分支归档测量，代码状态未变故物理有效；首个节点须以 6 次交替复测复核当前最佳并实测噪声底，账本据此定标。

上述 gsim 归档和 IR 实测分别使用 Makefile 目标 `run_xs_gsim_emu` 和 `run_xs_wolf_grhsim_ir_emu`，均设置 `XS_SIM_MAX_CYCLE=100000`、`XS_NUM_CORES=1`、`XS_EMU_THREADS=1`、`XS_EMU_CPU=2`、`XS_WAVEFORM=0`、`XS_COMMIT_TRACE=0`、`XS_RAM_TRACE=0`。

## 启动自举
