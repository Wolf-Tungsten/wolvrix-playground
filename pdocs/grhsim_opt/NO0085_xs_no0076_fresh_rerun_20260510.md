静态数据说明：

1. 当前 DP 对数量合并很强，但它不是 activation cost 的主要优化器。coarsen 后 `1066173` 个 cluster 被最终 packing 成约 `8万` 个 compute supernode，数量压缩明显；但 fresh baseline 的 `boundary_activation_edges` 仍达 `2545743`。
2. 直接把 activation cost 塞进 DP 切段只降了 `2.34%`，同时 supernode 增加 `3.74%`，收益不足，复杂度不值得保留。
3. 合法 topo ordering 对静态 activation 影响更大。只改变 coarsen 后、DP 前 ready cluster 的 tie-break，就把 activation 降低 `12.82%`，代价是 compute supernode 增加 `2.51%`。
4. ordering-only 不是单纯减少 final DAG edge；它反而让 `dag_edges` 增加 `14.10%`，但 `boundary_values` 和 duplicate activation 明显下降。因此有效机制是把有边界输入亲和性的 cluster 靠近，让后续 greedy packing 更容易减少跨 supernode 的 value multiplicity。
5. ordering+cost-DP 的 activation 降幅更大，但 supernode 增加 `10.66%`，当前不作为默认路径。

因此，`activation-affinity ordering` 虽然让静态 `boundary_activation_edges` 下降 `12.82%`，但在 CoreMark 50k 上没有转化为速度收益，反而导致：

- `compute_supernodes` 从 `79801` 增加到 `81802`；
- generated sched batch 从 `1474` 个左右增加到 `1477` 个左右；
- host instructions / branches / cache misses 明显增加；
- wall time 变慢 `18.49%`。

本轮结论修正为：静态 activation edge 不能单独作为默认优化目标。这个 ordering 方向只适合继续作为分析实验，不应保留为默认实现。

## 结论

`NO0076` 的 `grhsim` 数据确实已经过期，但 fresh rerun 后没有看到改善：

1. `grhsim boundary_activation_edges` 从 `2346640` 增加到 `2545743`。
2. 相对 `gsim` 的 activation edge 差距从 `+70.21%` 扩大到 `+84.65%`。
3. `supernodes` 现在从略少于 `gsim` 变成略多于 `gsim`，但差距只有 `+1.38%`，不是主要矛盾。
4. `other_compute` duplicate activation 仍占 `71.81%`，说明 activation multiplicity 仍是最直接的问题。
5. 后续不应把问题简化为“DP 本体没有合并作用”。DP 的数量 packing 有效，但 activation cost 主要受 DP 输入顺序与 boundary value multiplicity 影响。

2026-05-11 的追加实验修正了两个判断：topo 顺序确实会通过 greedy packing 显著影响静态 activation cost；但静态 activation 降低并不保证 runtime 变快。本轮 `activation-affinity ordering` 已实测回退，不应作为默认实现。

后续若继续优化，应优先围绕：

- computeNode 构建阶段减少 shared/common boundary value 泄出；
- coarsen 阶段更强地吞掉局部 boundary；
- DP 输入 ordering 需要同时约束 generated code footprint、batch 数、host instruction/branch/cache 成本，不能只看静态 activation；
- final segment cost model 只作为可选实验，不作为当前默认方向。
