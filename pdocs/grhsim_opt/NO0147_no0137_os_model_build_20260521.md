# NO0147: NO0137 同源 `-Os` model build

> 从 `NO0093_essent_mffc_activity_schedule_plan_20260518.md` 拆出的独立实验记录，避免继续把多轮实验追加成单个长文档。


背景：

- NO0145 显示 NO0137 的主要瓶颈偏 frontend / iTLB / branch 压力。
- NO0146 的 `-O2` 没有明显缩小 `.text`，本轮继续复制 NO0137 同源 emit 产物，仅把 grhsim model 编译参数改为 `-Os`，验证 size-oriented 编译能否把结构收益转换为 CoreMark 50k runtime 收益。

命令摘要：

```bash
cp -a tmp/no0137_xs_gated_mux_and tmp/no0147_no0137_os_model
/usr/bin/time -p make -B -C tmp/no0147_no0137_os_model/grhsim_emit -j32 CXX=clang++ CXXFLAGS='-std=c++20 -Os'
/usr/bin/time -p make -C testcase/xiangshan/difftest grhsim-build-emu GSIM=1 \
  DESIGN_DIR=/home/gaoruihao/wksp/wolvrix-playground/tmp/no0147_no0137_os_model \
  BUILD_DIR=/home/gaoruihao/wksp/wolvrix-playground/tmp/no0147_no0137_os_model/build \
  GEN_CSRC_DIR=/home/gaoruihao/wksp/wolvrix-playground/testcase/xiangshan/build/generated-src \
  SIM_TOP=SimTop \
  GRHSIM_MODEL_DIR=/home/gaoruihao/wksp/wolvrix-playground/tmp/no0147_no0137_os_model/grhsim_emit \
  NOOP_HOME=/home/gaoruihao/wksp/wolvrix-playground/testcase/xiangshan \
  WITH_CHISELDB=0 WITH_CONSTANTIN=0 WITH_DRAMSIM3=1 \
  DRAMSIM3_HOME=/home/gaoruihao/wksp/gsim-playground/DRAMsim3 \
  EMU_TRACE=fst EMU_THREADS=1 NUM_CORES=1 WOLVRIX_GRHSIM_WAVEFORM=0 -j32
```

结果：

- model archive 强制重编：
  - `real 258.17s`
  - `user 5750.34s`
  - `sys 62.38s`
- difftest emu relink：
  - `real 1.24s`
- 产物 size：
  - `libgrhsim_SimTop.a`: `119M`
  - `emu`: `110M`
  - `.text`: `113042583`
- `.text` 对比：
  - NO0137 `-O3`: `114291599`
  - NO0146 `-O2`: `114102996`
  - NO0147 `-Os`: `113042583`
  - 相比 NO0137 只下降约 `1.09%`。
- CoreMark 50k：
  - 10k: `host_ms=24798`
  - 20k: `host_ms=100034`
  - 30k: `host_ms=178309`
  - 40k: `host_ms=258487`
  - 50k: `host_ms=349978`
  - `Host time spent=349991ms`
  - 约 `142.86 cycles/s`
  - 退出码 `0`，未出现 difftest mismatch。

对比：

- NO0137 `-O3` 50k: `346589ms`，约 `144.3 cycles/s`
- NO0146 `-O2` 50k: `350976ms`，约 `142.46 cycles/s`
- NO0147 `-Os` 50k: `349991ms`，约 `142.86 cycles/s`

判断：

- `-Os` 正确性通过，但 `.text` 只下降约 `1.09%`，runtime 未超过 NO0137。
- 50k 比 NO0137 慢约 `3402ms`，约 `0.98%` 负向；不应把 `-Os` 作为默认模型编译策略。
- NO0145 的 frontend 压力判断仍成立，但编译选项无法直接解决；下一步应回到 emit 结构，减少 generated code footprint / branch 数量本身。
