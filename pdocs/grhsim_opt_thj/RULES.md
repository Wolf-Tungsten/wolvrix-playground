# grhsim_opt_thj 文档管理规则

本文是 `pdocs/grhsim_opt_thj` 的独立规则说明文档，用于约束本目录后续的增量记录方式。

## 1. 适用范围

- 本目录中的“记录类文档”统一采用增量归档方式管理。
- 本目录中的“管理类文档”仅包含 `README.md` 与 `RULES.md`，不占用记录类文档的 `TNOxxxx` 编号。

## 2. 编号与命名规则

- 记录类文档文件名统一采用 `TNOxxxx_主题_YYYYMMDD.md`。
- `TNOxxxx` 为四位数字，按记录形成时间单调递增，编号一经分配不得复用。
- 同一天内新增多篇文档时，仍按形成先后继续递增，不按主题分段编号。
- 新文档默认从当前目录已分配的最大 `TNOxxxx` 的下一个编号继续；不要把“当前下一个可用编号”写死在本规则中。

## 3. 增量记录规则

- 本目录采用“只追加、不覆盖”的记录方式。
- 已有文档允许扩展，但只能追加新的章节、补充说明、勘误说明或增量更新记录。
- 不允许删除历史结论、整体替换旧内容、复用旧文件承载新的独立主题。
- 如果新增内容已经构成独立议题，优先新建一篇新的 `TNOxxxx` 文档，而不是覆盖旧文档。
- 阶段计划、实现记录、结构 gate、runtime gate、性能实验、诊断快照、A/B 复测、root-cause 更新均视为独立议题，应逐篇新建 `TNOxxxx_*.md`，不要继续把多轮实验写成一坨长文档。
- runbook 修正、工具/verifier 更新、fresh/no-fresh 配置确认、build 结果、20k gate、50k gate 也按阶段拆分；除小范围勘误外，不把后续执行结果继续塞回旧 runbook。
- 如果必须修正文档中的错误，应保留原结论上下文，并以“勘误”或“增量更新 YYYY-MM-DD”形式追加说明。

## 4. 链接规则

- 目录内文档互相引用时，统一使用相对路径，例如 `./TNO0008_xxx_20260713.md`。
- 跨目录引用时，统一使用相对路径，例如 `../grhsim_opt/NO0221_xxx_20260707.md`。
- 不再使用仓库绝对路径或机器本地绝对路径作为 Markdown 链接目标。
- 普通代码块、命令示例、实验产物路径可以保留原始绝对路径文本，但它们不应写成 Markdown 绝对链接。

## 5. 当前历史文档整理规则

- 本目录初始 `TNO0001..TNO0020` 由 `pdocs/grhsim_opt` 中 `NO0221..NO0526` 的 306 篇细粒度记录按连续技术议题整理形成。
- 原始 `NOxxxx` 文档保持原位且不修改；TNO 文档记录来源范围、阶段结论和保留/停止状态，细节仍可回查原始记录。
- 整理后的稳定标识以文件名中的 `TNOxxxx` 为准，文档标题与 `README.md` 索引必须保持一致。
- 后续新增文档直接使用 `TNOxxxx_主题_YYYYMMDD.md` 命名。

## 6. 时间顺序判定规则

- 优先按文档明确记录的日期排序。
- 如果多篇文档日期相同且没有更细粒度时间戳，则按“依赖关系优先、阅读顺序优先”的原则排序：
  - 基线文档排在对齐/汇总文档之前。
  - 单边机制记录排在双边对照快照之前。
  - 被引用文档排在引用它的文档之前。
- 如果仍然无法区分，则保持当前目录索引中既有顺序，不反复改号。

## 7. 目录维护要求

- 每次新增记录类文档后，必须同步更新 `README.md` 中的时间顺序索引。
- 每次新增目录内交叉引用后，必须检查链接是否仍为相对路径。
- 若旧文档追加了重要增量更新，可在 `README.md` 的备注列中补充“已追加更新”的说明，但不改变其原始编号。
