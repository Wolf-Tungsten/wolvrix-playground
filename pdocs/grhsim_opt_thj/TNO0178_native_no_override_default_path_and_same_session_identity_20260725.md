# TNO0178 native no-override default path and same-session identity

## 1. 状态与结论

本记录关闭 [TNO0176](./TNO0176_gen24_four_arm_function_formal_walltime_and_default_decision_20260725.md)
第 9 节遗留的 native no-policy identity：`commit_exact_event_policy` 的默认值确实来自通用
Wolvrix C++ emitter，而不是 SimTop/XS wrapper 的专用覆盖；`active_mask_gap_pack_policy` 仍保持
C++ default-off。

最终采用同一个 Wolvrix `Session`、同一个已经完成 activity-schedule 的 production SimTop design
连续双 emit：第一份显式传入 `targeted-cold-layout`，第二份完全省略 exact-event 与 gap-pack option。
两份输出的 `134` 个 C++/header 文件逐路径、逐字节相同，evaluator 同算法 fingerprint 均为
`3bffd9dfdd0fda943f6ffbc23a08df6b71e7fdae3f6bb19ba8d0df12da72351b`。

这不是新的 50k 性能裁决，也不替代
[TNO0177](./TNO0177_simpletes_grhsim_bench_contract_v2_migration_and_continuation_readiness_20260725.md)
要求的提交后 direct-evaluator native-control canary。TNO0176 的 exact-event `18.040208%` 默认开启
结论与 targeted-direct gap-pack `0.155120%`、保持关闭的结论均不变。

## 3. 为什么独立 fresh 产物不能直接作 identity

第一次 no-resume、no-stats、no-policy fresh emit 正常 exit `0`，绝对生成时间为
`1,561,176 ms`，并得到正确诊断：

```text
[GRHSIM_COMMIT_EXACT_EVENT] policy=targeted-cold-layout selected=1 fallback=none cold_runs=16 cold_guards=44976 lockstep_groups=2089 lockstep_writes=11799
```

但它与 TNO0176 arm C 并非同一 RTL 输入，不能据此声称 literal identity：

| 项目 | arm C | independent native fresh |
| --- | ---: | ---: |
| logical filelist entries | `2,100` | `2,100` |
| logical input bytes | `244,291,174` | `244,291,174` |
| logical input SHA-256 | `913ab0f8cd3e2c4580a532959db16db720417667e780f4a9151f19aafe42be03` | `ed6d240bab8e837f771d182e46bee9d8ad4551657fda56cee4ff6aed89eaff01` |
| generated files | `134` | `134` |
| generated bytes | `1,341,619,230` | `1,342,388,670` |
| generated fingerprint | `9f1200284dc887eecf8adc47147cab0e80c319944fded414b32439d1c5c896ca` | `f063a8f018ad8f1d17665b5a71e50cd989c20f8e8bcbb0898f47c2649019e093` |
| raw-different generated files | — | `66` |

两个 filelist 的 logical label 顺序 SHA 均为
`6eaf46e7dc565fd187cdac2764556055980d2be4ec64172c2d97ade0e9ad63a1`，但 arm C 的 `2,097`
个 RTL 条目指向 7 月 7 日的 `build/xs/rtl/rtl`，native fresh 指向 7 月 25 日的新 build root。
只有三个 logical RTL 内容不同：

| RTL | bytes | arm C SHA-256 | native fresh SHA-256 |
| --- | ---: | --- | --- |
| `Ifu.sv` | `554,154` | `495c6d83ce63d3e3d5c5f83d7b6d73859507c1cc98d7e61ace8a7d16a52e8054` | `d2dc92caca8dd1cf818d0c172b4e844c65f4763b65e83a31dcb74e768c9fbac3` |
| `LogPerfEndpoint.sv` | `18,706,293` | `9301b078b65cefd44285b3629659d71e0da1e1119f16467192c830c6e738e0f3` | `859b33b6acdd1c62f82ea988e5d850734ca677c716d03e65c8ae0fe7c2eb00b7` |

差异不只限于 `_op_` 注释；删除独立注释行后仍有 `64` 个 generated 文件不同。因此本记录明确
废弃“独立 fresh 与 arm C 字节相同”的原假设，不用不同输入的 fingerprint 反推 policy 身份。

第二次仅共享 pre-reg JSON 的跨进程重放也不与原 arm C byte-identical：JSON roundtrip 后重新执行
reg-to-mem/activity-schedule，得到 `134` files、`1,340,129,434 B`、fingerprint
`3bffd9dfdd0fda943f6ffbc23a08df6b71e7fdae3f6bb19ba8d0df12da72351b`。它证明 native 路径能正常
完成，但仍不是单变量 identity；最终 gate 因此进一步收紧为同 Session 双 emit。

## 4. 同 Session 双 emit 最终 gate

dual harness 从同一 pre-reg checkpoint 读取一次 design，只执行一次 reg-to-mem 和一次
activity-schedule，然后按以下顺序连续调用 emitter：

1. explicit：仅加入 `commit_exact_event_policy=targeted-cold-layout`；gap option 省略；
2. native：exact-event 与 gap-pack option 均省略，低层环境变量也均不存在。

绝对阶段耗时如下；这些是生成 gate 耗时，不是 SimTop walltime 性能口径：

| 阶段 | 绝对耗时 |
| --- | ---: |
| read pre-reg JSON | `174,376 ms` |
| reg-to-mem | `142,057 ms` |
| activity-schedule | `262,059 ms` |
| 两次 emit 合计 | `143,920 ms` |
| harness 总计 | `722,414 ms` |

最终 identity 结果：

| 字段 | explicit | native default |
| --- | --- | --- |
| exact policy source | harness explicit attribute | C++ default，无 attribute/env |
| gap policy source | C++ default | C++ default |
| selected/fallback | `1/none` | `1/none` |
| cold runs/guards | `16/44,976` | `16/44,976` |
| lockstep groups/writes | `2,089/11,799` | `2,089/11,799` |
| generated files | `134` | `134` |
| generated bytes | `1,340,129,434` | `1,340,129,434` |
| evaluator fingerprint | `3bffd9dfdd0fda943f6ffbc23a08df6b71e7fdae3f6bb19ba8d0df12da72351b` | `3bffd9dfdd0fda943f6ffbc23a08df6b71e7fdae3f6bb19ba8d0df12da72351b` |
| path set | identical | identical |
| per-file bytes | identical | identical |
| gap-pack active diagnostic | absent | absent |

最终 gate 为 `PASS`。这直接证明“显式选中 C 臂 exact-event policy”和“通用 Wolvrix C++ 默认”在
相同 production SimTop design 上生成完全相同的程序，同时没有借用 `targeted-direct`。

## 5. 功能、性能和 continuation 边界

本 identity 阶段只 emit，不另行链接 emu，也不把 TNO0176 的 arm C 运行伪写成一次新的 native
运行。功能与性能采用 TNO0176 已完成的独立四臂证据：A/B/C/D 的 100/10k 功能均 PASS；A/C
accepted 双 order pooled wall 为 `74,773.25 -> 61,284.00 ms`，绝对减少 `13,489.25 ms`，改善
`18.040208%`。C/D pooled wall 为 `60,759.50 -> 60,665.25 ms`，仅减少 `94.25 ms`，改善
`0.155120%`，所以 gap-pack 继续 default-off。

提交并更新 SimpleTES pins 后，仍需 direct evaluator 用 schema-v2 `control` seed fresh 构建 native
`options={}`，通过 focused、fixed-ASLR 100/10k、quiet whole-CCD 50k ABBA、artifact marker 与
immutable attempt gate。该 canary 将另立 TNO 记录绝对 walltime 与 SHA；本阶段没有启动 auto
research、launcher/main、API 或模型调用。
