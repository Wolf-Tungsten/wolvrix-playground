# TNO0027　香山逐站点 PGO、调度边界和值计算归因

## 构建与选点

`make xs_wolf_grhsim_emu` 支持 `XS_GRHSIM_SITE_PGO=off|sparse|commit|both`。使用 `PGO_WORKLOAD` 指定训练固件，`XS_GRHSIM_SPARSE_PERMILLE=5` 表示 0.5%，`50` 表示 5%。生成器在合格的 C++ 位置声明图中的值 ID 或写口操作 ID。在私有训练目录内，工具按翻译单元给每个 ID 分配计数槽。训练一次记录访问和实际变化次数。后两次编译与训练使用已经选定的分支形态，最终 ELF 没有站点计数器。可以用 `XS_GRHSIM_SITE_PROFILE` 重放已发布的 `grhsim-sites.tsv.gz`。重放会校验完整模型源码、头文件、生成的 Makefile、各文件的站点清单及计数范围。[PGO 驱动](../../scripts/xs_grhsim_pgo.py) · [逐站点计数与选择](../../scripts/grhsim_change_sites.py)

计算侧只在新旧值不同时写回并通知。事件值需要在相等时清除旧边沿，生成器在这条路径上继续执行原来的事件分类。提交侧在原有时钟、写使能和块比较内部计算 `state_changed`，写入标量寄存器，用变化掩码更新已有的读者激活位。只选择普通、至多三个激活写入的标量寄存器。存储器与宽寄存器沿用原模板。现有生成器已经有按扇出开启 eager 的模板，历史实验用 32 分区普通编译测试过。该全局选项会影响块比较，本实验只选择单独写口。[生成器](../../wolvrix/lib/emit/grhsim_cpp.cpp) · [历史 eager 实验 §7.25](../../../wolvrix-playground-select-first/pdocs/grhsim_opt_thj/TNO0333_repcut_grhsim_backend_20260925.md)

旧汇总把 9,724 个生成代码位置统称为独立寄存器比较，其中 567 个是内存写口。对其余 9,157 个，9,156 个直接比较标量状态与下一值槽，1 个从 `reset` 取值。按这个旧分类，CoreMark 每拍约 6,840 次直接槽比较、315 次内存比较、1 次输入比较。邻接检查在同一翻译单元按逐项比较出现的顺序查看前后一个位置，再用模型头文件还原状态字段的物理声明顺序。4,898 个直接槽位置没有同类型标量快照邻居，1,782 个有同类型邻居但下一值槽不连续，1,707 个的下一值槽连续而状态字段不连续。另有 769 个满足邻接布局，仍要检查同组使能、块长度上限与写口次序。此前“约 2,800 次预测失败≈每次真实写入都猜错”的说法把 IBS 外推量和覆盖计数作了逐事件对应。两个总量无法确定某一次写入的预测结果。[比较位置、动态计数及实例](../../build/armor-xs-site-pgo-v1/standalone-coremark.json)

## 调度追踪

八路 `uopCanEnqSeq_{0..7}_67` 在初始计算节点中都是独立的单操作生产者，每路有两个消费者操作。声明拆分及解环后仍各自独立。在迭代 1 的兄弟合并之前，第 1 至 7 路生产簇各有 3 个计算节点，两个消费者已经同簇。该次兄弟合并把七路分别装入两个 96 **节点**的生产簇；最终第 1 至 3 路在组 19212，第 4 至 7 路在组 14110。第 0 路在迭代 2 合入消费者簇，最终生产者和两个消费者都在组 37139。这些是按操作和依赖追踪得出的成员关系，单独比较不同快照的组号会得到错误结论。[八路的全部阶段与消费者](../../build/armor-xs-site-pgo-v1/rob.json)

| 固定现有组、按值考虑一次移动或复制 | CoreMark 可去比较/拍 | MicroBench 可去比较/拍 |
|---|---:|---:|
| 单计算读者，顺序允许、没有留在原组的外部使用，容量 160 | 5,151 | 4,670 |
| 同一条件，给目标组局部容量 176 | 8,795 | 8,011 |

单读者容量 176 行只有 968 次 CoreMark 比较/拍同时满足无需新增输入边。多读者的 15,658 次中，12,659 次已经是 5% 简单原型会命中的稀疏比较。这些是冻结拓扑上的毛上限。每个值单独评估，没有扣除多个候选争用容量、复制操作自身成本、执行次数变化以及事件区域重分配。[场景计算与新增输入边](../../build/armor-xs-site-pgo-v1/scenarios.json) · [审计工具](../../scripts/armor_single_reader_audit.cpp)

## 值计算

对 TNO0026 已采集的两个工作负载分别按原有语句口径分账。逐一核对计时 ELF 地址、诊断 ELF 函数长度与指令字节，再查最外层 DWARF 行。GrhSIM 用局部变量中的 ValueId 或该次物化结果对应的 ValueId 联到 GRH 定义操作的 RTL 文件。GSIM 将赋值目的或条件中一致的限定名沿原始 FIRRTL 实例树解析到模块类型。一个内联表达式可能跨过原模块边界，归属表示生成语句的结果。各后端分配到模块及“所有者未知”的样本之和等于 TNO0026 的值计算桶。缺行号、机器字节不一致的样本另留在原来的桶中。[逐模块样本、指令类型与地址](../../build/armor-xs-site-pgo-v1/modules) · [映射程序](../../scripts/armor_xs_gap_diagnostics/value_modules.py)

| 模块类型 | CoreMark 指令/拍，GSIM → GrhSIM | MicroBench 指令/拍，GSIM → GrhSIM | CoreMark 周期/拍，GSIM → GrhSIM |
|---|---:|---:|---:|
| Rob | 96,200 → 283,586 | 83,120 → 220,371 | 66,192 → 166,372 |
| Ftq | 1,360 → 133,422 | 1,520 → 114,904 | 2,528 → 82,415 |
| VectorDecodeChannel | 329,439 → 294,507 | 307,601 → 279,008 | 219,152 → 160,954 |
| 值计算有行号、模块归属未知 | 145,559 → 305,107 | 138,481 → 280,574 | 见原始表 |

结果支持优先检查 ROB 与 FTQ。向量译码在两侧都热，但在这套可归属的指令和周期口径下，GrhSIM 已较低。GSIM 另有较多缺少有效语句行的指令，不能把模块表中的差额直接相加当作可兑现的加速。

2026-11-22 更正。此处的 GSIM 归属遗漏了 FIRRTL 聚合字段，尤其影响 FTQ。CoreMark 的 FTQ 赋值数修正为 19,409 次/拍。下表保留当时的结果，更新后的跨引擎比较和相同寄存器路径的核对见 [TNO0028](./TNO0028_xiangshan_value_paths.md)。

|---|---:|---:|---:|---:|

## 复现与功能验证

在项目已有 XiangShan 构建环境运行以下命令。

```sh
make xs_wolf_grhsim_emu \
  PGO_WORKLOAD=testcase/xiangshan/ready-to-run/coremark-2-iteration.bin \
  XS_GRHSIM_SITE_PGO=both XS_GRHSIM_SPARSE_PERMILLE=5
```

切换到 `sparse` 或 `commit` 可单独使用计算或提交策略。设置 `XS_GRHSIM_SITE_PROFILE=/绝对路径/grhsim-sites.tsv.gz` 可跳过站点计数的编译和执行。改过调度或生成模型后要重新收集站点计数。各策略都使用自己的 Clang profile。当前策略由调用者显式选择，额外的站点训练需要一次编译和一次负载执行。

前 100,001 拍将五个正式策略分别与同一默认 GrhSIM 的 DiffTest 轨迹比较，同时核对 CoreMark 的期末性能计数。再让 0.5% 稀疏版及其与提交组合的版本执行完整 MicroBench。程序通过全部子项，在 PC `0x80003a4e` 正常退出，退休 326,377 条 guest 指令，报告 225,601 个 guest cycles。225,599 条 DiffTest 记录中有效字段逐项相同，最后架构周期为 225,595。CTest 的 commit blocks、scalar eager、same readers 和 execution plan 四项通过，40 项 XiangShan 选项测试以及站点计数重放测试通过。[短窗口轨迹](../../build/armor-xs-site-pgo-v1/verify) · [完整 MicroBench](../../build/armor-xs-site-pgo-v1/long) · [CTest](../../build/armor-xs-site-pgo-v1/ctest.log)
