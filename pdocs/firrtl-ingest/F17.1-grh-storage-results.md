# F17.1：单一 GRH 存储的实现与验证

日期：2026-11-03；状态更新：2026-11-04。本文先保留首轮 `native/candidate` 和
v2 `soa-hash` 的历史证据。首轮完成了当时的正确性验收与 S4 测量，但六类热点的 1/4
预算未达成。当前 F17.1/2/3 集成候选另见文末：r4 回归、oracle 与独立分配基准通过，
整机 r1 曾因 bulk SrcLoc 继承遗漏导致 flat JSON 身份失败；r5 已修复并重验。最终 r2 的
两个终点、完整诊断和配置身份均已通过；性能预算按实测仍未全部达到，详见文末。
下文各版本的二进制和结果不得混用。

F17.1 将 Graph 的构图、读取、修改和 compact 统一到一份 GraphStore。
实体固定字段按列保存，列表和属性值放入图级池，删除保留 tombstone，compact 回收并重编号。
旧 GraphBuilder / GraphView 及 freeze/thaw 布局转换已删除。
实际字段、ID、池切片与正反向边的说明见
[GRH 数据结构](../../wolvrix/docs/grh/grh-storage.md)。

## 首轮实现范围（历史）

- ValueColumns / OperationColumns 保存固定字段；PoolVector 指向图级 topology 数组。
- operand、result、use-list、backlink、属性 ID 共用各自的连续池；删除 use 以末项交换并修正 backlink。
- 属性使用 key/tag/payload 三列及按类型分开的值池。读取、clone、flatten 使用借用视图；需要拥有值时显式复制。
- 符号和 payload 共用字符串字节；StringId 与 SymbolId 独立，属性文本不会预留实体名字。
- SrcLoc 和 shape 按内容去重。compact 先准备完整新池，再提交；保留 symbol reservation 与旧 canonical 顺序。
- 增删实体期间 ID 稳定；compact / freeze 重编号。frozen 记录 compact 后是否修改，写入无需 thaw。

这份首轮快照未包含 F17.2 的列块拼接。工作区当时的 F17.3 第 1 步等前端修改保留在候选中，
因此相对 F16 的整机时间差包含这些已有修改，不能全部归因于本次存储替换。

## v2：单次文本查找与独立分配测量（历史）

`soa-hash/alloc-bench` 测量的是 v2 历史候选，不能代替上面的首轮整机证据，也不能转用到当前集成候选。
该版将符号的第二张文本哈希表改为 StringId → SymbolId 数组，StringPool 只计算一次
文本 hash，并用整数键和完整文本碰撞链处理查找；addValue 不再为了归一化字段复制 shape。
flatten 直接导入 SrcLoc record，减少拥有型中间副本。

新增 `make build_grh_allocation_bench` / `make benchmark_grh_allocations`，独立测量公开
Graph 构图、mutable 来源 clone、compact 来源 clone 和跨 Design import。
目标创建、全部 reserve 和目标池导入均在计数窗口内；来源准备、验证、输出与析构在窗口外。
默认不预留容量，分别测 4,096、65,536、1,048,576 个 operation，每个 operation
创建一个结果并连接前一个结果。三种负载为纯拓扑、八类共享属性与完整来源、再加唯一长名字；
后两种均包含非空 shape `[2,2]`。

| 1,048,576 个 operation | 构图 events/op | mutable clone | compact clone | 跨 Design import |
| --- | ---: | ---: | ---: | ---: |
| 纯拓扑 | 0.001068 | 0.000496 | 0.000496 | 0.000506 |
| 八类属性、来源、shape | 0.001252 | 0.000681 | 0.000681 | 0.000691 |
| 再加唯一长名字 | 0.002582 | 0.002011 | 0.002011 | 0.002022 |

空统计窗口为 0 次、显式 operator new 为 1 次；36 组均通过连接、属性、来源、shape 和名字
验证，所有计数窗口的 allocator worker 数均为 0。规模增长时 events/op 明显下降，
支持这些公开构图/clone 路径的摊还分配接近零；它不证明任意属性长度或整个前端/pass 流程零分配。
原计划没有数值化“近零”，报告额外显示 0.01/op 观察线，不将它追认为原始验收定义。
初次数据保存在 `soa-hash/alloc-bench/`。来源 view、SmallVector 临时参数、canonical 属性
直接写池，以及节点统计 flat hash 改动完成后，`soa-hash/alloc-bench-final/` 曾复测 36 组。
最终 bulk result SrcLoc 继承修复后的 r2 证据位于
`soa-hash/alloc-bench-final-r2/analysis.md` 和 `results.json`；它重新登记了全部 36 组，
其中共享属性和唯一长名字的计数随最终库身份变化，本文使用 r2 数字。两个历史目录仍保留
各自执行的 native 与未跟踪核心头文件归档。

该 v2 历史快照通过正常版本 81/81 CTest、9 项 Python ingest、72 项 FIRRTL workflow、
5 项 GrhSIM flow 及生成模型执行、FIRRTL comb 模型执行。新用例覆盖 borrowed SrcLoc 输入
销毁后的所有权、op/value 共享 record、非法 paired setter 不修改另一实体、payload-first
符号登记及 compact/clone 后独立写入；八类属性在三个 JSON 模式下 load→store 完整字节一致。
该字节夹具按已有 loader 的规则使用 canonical metadata key 顺序；不扩展任意 metadata
插入顺序的 byte-roundtrip 契约。

独立 oracle 使用同一份 driver，分别以旧头文件链接 F16 归档库、以新头文件链接候选库，
两个进程记录每次 mutation 后的完整公开字段。`soa-hash/oracle-r4/result.txt` 确认 trace
及 **207 份**三个打印模式的完整 JSON 逐字节相同；覆盖非尾追加、operand/result mutation、
use-list、全属性、来源、shape、三类端口、symbol、declared/generate、tombstone、两次 freeze、
freeze 后修改、clone/import、源销毁及拒绝路径。此比较发现并修正了新 getter 的两类
已删除实体异常文本漂移，未通过忽略诊断或排序输出来隐藏差异。

v2 没有在本文补齐独立整机正式计时、perf、两端身份和 roundtrip；首轮数据不能填入这些空项。

## 修复前 r1 候选：历史证据（2026-11-04）

本节保留修复前 r1 的失败证据，便于追溯；最终结论以文末“最终 r2 候选”为准。

修复前 r1 的源码在单一 GraphStore 上加入 F17.2/F17.3：256 行固定类型共享页、分段 payload 与字符页
所有权、全局 DFS 多 run 计划、定向端口合并与最终 operand 重定位，以及单次来源的拓扑接管。
共享列只限 value 的 width/isSigned/type/domain 与 op kind；不足页或非连续范围复制。
symbol、shape、来源/属性 record 和实体 ID 仍按目标域建立，不能描述为整张 GraphStore 直接转移。

XMR、multidriven 和 blackbox barrier，仅局部链按图流水。retention 发布后，只提前 compact

## §8 symbol/payload 回归（r3）

统一 Make r3 的 81/81 CTest 包含 GRH 的 symbol/payload 状态回归；这些是语义和所有权
门禁，不能替代单次 hash/lookup 的性能测量。`test_grh` 覆盖以下状态转换：

- payload 先出现再提升为 symbol：动态属性 key、字符串/list、SrcLoc 和长文本先写入
  StringPool，确认 payload-only 文本不占用 SymbolId；随后 `internSymbol()` 得到独立的
  SymbolId，共享同一份字节且不改变 payload。内部 `_op_N`/`_val_N` fresh-name 路径也验证
  payload-only 文本不会错误地预留或跳过名字。
- compact 后的共享 entry：回收 payload-only 垃圾并重建 StringId 映射，保留已绑定和未绑定
  symbol reservation；compact 后再次查询、插入和提升 payload 文本时，reservation、编号
  错位、无洞/不重用规则及 JSON 语义保持不变。
- clone/import 的独立写入：来源销毁后，目标仍可独立修改 payload、提升同名文本为 symbol、
  再 compact；目标的 StringPool、SymbolTable、属性/list 和 SrcLoc 不借用来源存储。
- 空字符串边界：StringPool 的 StringId 0 仍表示空/无 payload，SymbolTable 仍允许空文本
  作为独立有效 SymbolId；copy/move 和后续非空插入不混淆两套编号空间。
- 并行池隔离和回收：独立 Graph 的 payload arena、属性列表、shape/SrcLoc 记录及 compact
  垃圾回收互不影响，覆盖共享字节但独立可变 record 的路径。

对应实现入口为 `sharedSymbolPayloadStrings`、`symbolPayloadStateTransitions`、
`isolatedPayloadArenasAndReclamation` 及 `collidingStringPool`；r3 的统一 CTest 结果确认
这些用例随 `test_grh` 通过。历史 `soa-hash/oracle-r3` 仍是独立 207-checkpoint oracle 的
归档（其旧 trace 只保留删除实体错误文本差异），最终可引用的公开字段差分和完整身份以
`soa-hash/oracle-r4`、`complete-r2` 为准。回归通过只证明 symbol/payload 语义；StringPool
和 SymbolTable 的热点 self CPU、构图/clone events per op 仍按文末 r2 正式证据登记，不能
由这些功能用例推导性能预算达成。
