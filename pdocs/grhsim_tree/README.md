# grhsim AM 性能优化树搜索 — 策略与规则

本目录是 grhsim AM 性能优化的**树搜索管理层**。它以树结构组织优化探索：
每次优化尝试是树的一条边，代码状态是节点，测量数据驱动扩展与剪枝。

本目录是 grhsim AM 性能优化的**树搜索管理体系**，独立成体系：不依赖、不引用其他文档目录
（包括 `pdocs/grhsim_opt/` 历史归档）。所有结论、依据、数据都记录在本目录内。

**持久化原则**：`build/`、`ptmp/` 等构建/临时目录不跨机器持久化，且路径提及会误导其他机器的读者。因此：

- 任何**必要结论**（指标数值、测量环境、功能 gate 结果、关键 profile 计数、判定依据）必须以文字/小表格形式写进节点或 analysis 文档，缺一不可；
- 文档中**禁止出现** `build/`、`ptmp/` 等不持久化路径（链接和纯文本提及都不行）；源码树内的路径（`wolvrix/`、`scripts/` 等 git 跟踪内容）允许引用；
- **禁止**把大规模原始数据搬进文档（全量日志、完整 top-N 列表、perf 原始输出等），只保留提炼后的结论性数字，防止 git 膨胀。

## 1. 目标与基准

- **基准测试**：XiangShan CoreMark 50k，固定用例与运行口径，所有节点同一协议。
- **目标**：grhsim AM 运行时间贴近 gsim，主指标为 `ratio = grhsim_time / gsim_time`，越接近 1.00 越好。
- 正确性门槛先于性能测量：结果不一致的节点直接 `pruned-correctness`。

## 2. 树模型

- **节点（STxxxxx）**：一份可编译、可正确运行的代码状态。`ST00000` 为 baseline 根节点。
- **边**：一次具体优化修改，只有一个父节点，保证收益可归因。
- **编号**：五位数字单调递增（`ST00001` 起），一经分配不复用；编号不代表父子关系，父子关系记录在节点文档和 `TREE.md` 中。
- **主干（trunk）**：已确认有效并互相兼容的优化累积线。任何时刻 `TREE.md` 必须能回答"当前主干头节点是哪个"。

## 3. 节点状态机

`open`（候选） → `in-progress`（实现/测量中） → 终态之一：

- `trunk`：有效，并入主干；
- `branch-alive`：有效但与主干互斥或未合并，保留在分支；
- `pruned-no-gain` / `pruned-regression` / `pruned-correctness` / `pruned-complexity`：剪枝，负结果保留原因，防止重复踩坑；
- `parked`：暂缓（等前置条件、等工具、优先级低），可被重新激活。

## 4. 测量协议

- 用例：XiangShan CoreMark 50k；性能数字取不少于 3 次运行的中位数。
- 记录环境：机器、CPU 绑定/ASLR 配置（标准口径：`setarch -R` 固定 ASLR + `taskset` 绑定空闲核）、代码 commit、emit 配置。
- 判定：收益需超出噪声带（默认 ≥2%）才算有效；噪声带存疑时加跑次数。
- 每次测量同时在 gsim 上取对照值，更新 ratio；gsim 数字变化时回填 `TREE.md` 基准行。

## 5. 扩展策略（选下一个动作）

候选动作池维护在 `TREE.md`。每轮迭代：

1. **先处理 `INBOX.md`**：用户提示优先于一切自动策略，逐条转为候选动作或标记暂缓；
2. 从候选池按 `expected_gain / cost` 贪心选择，expected_gain 必须有 profile 依据；
3. 每约 5 个节点强制安排一次高上限高风险的探索性动作（epsilon-greedy），防止陷入局部最优；
4. 分支上连续 2-3 条边无净收益时回退分支点，换下一个候选；
5. 每 10 个节点做一次回顾：修剪候选池、确认主干合并、重估 expected_gain。

## 6. 文档规则

- 每个节点一份 `nodes/STxxxxx_主题.md`，模板见 `ST00000`；节点文档自包含，大段调查/分析数据放入 `analysis/ANxxxxx_主题.md`（五位编号，独立于节点编号）并在节点内链接。
- `TREE.md` 是唯一入口：节点表（ID / 父节点 / 动作 / 状态 / 50k 时间 / vs gsim / 证据链接）+ 候选池 + 当前主干头。每次状态变更先更新它。
- `INBOX.md` 是用户提示收件箱，条目只追加不删除，处理后在条目上标注去向。
- 目录内引用一律用相对路径；不引用本目录以外的文档（历史归档如 `pdocs/grhsim_opt/` 仅允许纯文本提及，不作链接、不作依据）。
- `TREE.md` 节点表的"证据"列只引用本体系内的文档（节点/analysis）；数值结论必须内联在节点文档中（见持久化原则）。
- 节点文档遵循"只追加"原则：结论变更以追加"更新 YYYY-MM-DD"章节方式记录。
