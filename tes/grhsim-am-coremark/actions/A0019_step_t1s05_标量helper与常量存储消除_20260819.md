# A0019 - step r001/t1/s05：标量 helper 与常量存储消除

日期：2026-08-19。action 类型：step（trajectory t1, step 5, K=2）。
proposal：`tes/grhsim-am-coremark/proposals/r001-t1-s05.md`。

本 action 只使用 t1 轨迹的 Φ 节点 `e00024` 与 `e00006`。共同父节点为 t1/s04
winner `e00024`（Host 中位 241348 ms），继承参数：
`--block-chunk-instructions 3000 --resize-elision --inline-scalar-helpers
--inline-scalar-constants`。两个候选机制分别作用于 helper 调用边界和状态存储，
不是同一想法的参数微调。

## 候选设计与可证伪假设

### c1 `--inline-scalar-divmod-helpers`

- 分支 `tes/r001/t1/s05-c1`，commit `d4624a3`，eval `e00029`。
- `GrhSimAmCppEmitter` 新增 `inlineScalarDivModHelpers` attribute 和 CLI 开关；
  窄标量 `divide_value` / `modulo_value` 在生成 header 中定义，runtime TU 保留
  关闭开关时的外联实现。除零、signed min/-1、结果掩码和宽值路径保持原语义。
- 假设：除法 helper 的固定 width/signedness/常量参数可在各 Block TU 中专门化，
  消除剩余跨 TU 调用边界后 Host 至少下降 1%；若无收益，除法调用边界不是 t1
  当前的一阶成本。

### c2 `--inline-scalar-constant-storage-elision`

- 分支 `tes/r001/t1/s05-c2`，commit `d7b9f01`，eval `e00030`。
- 在 `inlineScalarConstants` 已发射字面量的前提下，新增 escape/pin 分析结果：
  仅对 `InitKind::Constant`、BitVector 不超过 64 bit、没有全局/提前读取和地址
  需求的变量删除 `v<K>` 成员及 `init()` 常量 store；端口、状态写、host/DPI、
  memory/array helper 等路径自动保留 backing storage。新增单元测试检查生成物
  缺失成员/store 且模型可编译。
- 假设：常量 backing storage 的布局和初始化写入是独立成本；安全删除后应在不改
  语义的前提下减少模型对象和初始化工作，Host 至少下降 2%。

## 机制分析与裁决

e00029 固定 exec-GRH 中有 1,267 个静态 divide 站点、0 个 modulo 站点，因而
1.64% 的稳定改善主要归因于 divide helper 的 header 内联；它低于 3% 一阶门，
但没有编译膨胀或功能代价，作为正向旋钮保留。

e00030 的 generated header `v<K>` 成员从 1,263,224 减至 1,253,782，常量
`init()` store 从 158,069 减至 148,627，runtime 源文件从 107,319,040 bytes
减至 106,652,747 bytes，减少 666,293 bytes。4.52% 的收益超过 c1 且 CV 1.12%，
说明常量存储/初始化是 t1 当前可独立收取的成本；escape/pin 防线和生成模型编译
通过了回归门。

winner = **e00030**（score `-230447`）。`tesctl.py finish-step` 已将其合入
`tes/r001/t1/main`，t1 best 从 e00024 更新为 e00030；下一 action 由状态机给出
为 `r001/t2/s05`，本 action 到此停止。
