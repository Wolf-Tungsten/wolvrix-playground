## 候选预注册

### c1 / e00063：base-first 稀疏覆盖

- 来源节点：`e00059`，并回接其父节点 `e00056` 的 branchless fused helper。
- 反馈/病灶：`e00059` 已证明从高优先级做 `ctz` scatter 没有正收益；recon 进一步显示
  selector 极稀疏，但该实现仍用 `ctz` 枚举 7009 万个 unresolved base lane，稀疏性收益
  被 base 落值路径吞没。
- 局部改动：新增默认关的显式 emit 开关 `--wide-mux-chain-sparse-overlay`。多级链先用
  连续循环复制宽 base 或填充标量 base，再按低到高优先级扫描 selector word，只对置位
  lane 做 `ctz` 覆盖；后级自然覆盖前级，保持 mux 优先级语义。单级链与开关 off 路径不变。
- 可证伪预期：17/17 ctest、3 rep difftest 和 2400s 编译门全过；Host 相对 `e00059`
  至少下降 2%，低于 0.75% 或回退则证伪。

### c2 / e00064：零 selector tile 旁路

- 来源节点：`e00056` 的 branchless fused helper，并针对 `e00059` 暴露的稀疏 selector
  病灶采用不同控制策略。
- 反馈/病灶：23-level 原 helper 对每个 lane 重放全部 level；recon 显示 selector
  机会密度仅 0.0188%，绝大多数 64-lane tile 应无需执行 23 层 blend。`e00059` 的全局
  sparse scatter 又证明不能牺牲连续 base 流。
- 局部改动：新增默认关的显式 emit 开关 `--wide-mux-chain-zero-tile-bypass`。每个 tile
  先 OR 全部 level 的 selector mask；全零时连续复制/填充 base，非零时保留原有按 lane
  branchless level replay。它以 tile 门控减少工作，不枚举 base lane，也不改活跃 tile
  的数据流。
- 可证伪预期：全部功能/回归/编译门通过；Host 相对 `e00059` 至少下降 1.5%，低于
  0.5% 或回退则证伪。

## 机制分析

### c1：消除了 base 位枚举，但高负载 noisy 窗没有正收益证据

- helper 语义与覆盖均成立：先连续初始化 base，再按低到高优先级覆盖，重叠 selector
  由后级自然取胜；生成器 oracle、17 项回归与生产 difftest 全过，5 条多级链全部命中。
- e00063 起跑 loadavg 为 49.50，rep1 574.430s 与 rep2/3 495.496/495.495s 分裂，
  CV 8.73% 超过 5% 噪声线。冻结协议规定 noisy 仍只取 3 rep 中位，不扩增、不重测。
- 名义相对 e00059 回退 92.62%，远不能视为纯机制幅度；结论只到“本窗口没有正收益
  证据”。原 e00059 对 unresolved base 的 ctz 枚举病灶已在代码形态上消除，但动态
  收益被宿主慢窗/进程态混杂，不能据此关闭所有 base-first sparse overlay 实现。

### c2：同高负载窗口机械胜出，tile 门控保留

- c2 起跑 loadavg 50.18，与 c1 的 49.50 接近；三 rep 409.731/409.730/409.741s
  完全同态，较 noisy c1 中位低 17.31%。两版 ELF text 只差 816 bytes，且两者同样
  扫描 selector word，因此 raw 排名与“零 tile 保留连续 base 流、活跃 tile 才做
  dense replay”的机制方向一致。
- 但 c1 本身 noisy，且两候选仍是先后独立构建/进程，17.31% 不能升级为精确因果量级；
  c2 相对历史 e00059 仍名义回退 59.28%，该跨窗口比较也不可裁。故 c2 作为状态机
  winner 保留，机制结论为“比本窗 sparse-overlay 更有证据”，不是刷新 t1 真值。
- c2 compile_s 2229.3s 已逼近预算（余 7.1%），即使运行方向保留，后续也不得通过
  扩大生成代码或复制 helper 来精修；应保持公共 helper/固定代码体量。
