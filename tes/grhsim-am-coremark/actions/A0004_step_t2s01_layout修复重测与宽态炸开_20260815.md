### c2 `--wide-state-explode`（宽状态标量炸开）— 状态表示轴（emit 规则面）

  预期 <0.5G cycles，净正预期，计时门裁决）。
- **假设**：炸开后计数器网络族的「词提取 + 栈数组往返 + 全宽掩码写循环」成本
  消亡（NO0017 锚点：匹配对内 56.7G Δ + 同模式未匹配 ~110G AM cycles 量级），
  Host 中位降 ≥3%；若 <1.5% → 炸开覆盖不足（274/~33.5K 候选）或该族已非

- 功能冒烟（实施期、非计时）：emu 构建正常（最慢单 TU ~9min，无膨胀），

### 机制互异性说明

c1 置换池内 offset（局部性假设：gather 成本来自工作集散布，靠聚簇回收）；
c2 改变状态表示本身（打包假设：成本来自词池打包的提取机械，只有换表示才能
消除）。两者同指状态面但根因假设与变换手段正交；若双赢可组合（c2 炸开后
c1 在剩余池上聚簇）。

## 机制分析与裁决

### c1（e00007，compile_timeout）——init 排序修复不充分，炸弹是 store 流本身

init 宽池 store 升序化（bee2e28，emit 文本核验 violations=0）**未能**恢复
affinity 编译：runtime.o 单独 ≥27min（id 布局 ~10min），预算触顶。评估后
对 e00001（id）vs e00007（affinity）两版 runtime.cpp 做纯文本取证：

1. 两版 init() 的宽池 store **多重集完全相同**（排序后 diff=0），非标量行
   仅差 4 行（memset 锚 v0→v1797916）；全部差异 = 宽池 store 顺序 +
   头文件成员声明顺序（2.5M 行重排）。
2. 零值-run 结构统计等价（62,482 vs 60,182 run，top run 354k vs 325k，
   ≥1000 run 覆盖 23.7% vs 22.6%）——局部排序修正确实把亲和布局的
    memset-idiom 可识别性拉回了基线水平，**但编译时间没有回来**。
3. 剩余结构差：id 布局宽池 store 是**一次全局升序扫描**；affinity 修复版被
   158k 条标量 store（VariableId 序，与亲和声明序错位）切成 **1,237 个
   升序 run**。若 clang 的 store 合并/DSE 类 pass 依赖全局单调性，
   碎片化即超线性惩罚——与观测吻合，但不做编译器实验无法坐实。
4. **更本质的发现**：init() 182 万行中，宽池 store 98.2%（1,633,254/1,663,331）、
   标量 store 93.5%（147,822/158,069）是字面量 **0**——而 init() 开头已有
   `memset(&成员区)` + `wideValues_.fill(0)` 全覆盖，这些 store **按构造就是
   死 store**（emitter 自己知道，无需编译器证明）。init() 的体量本身就是
   编译预算的结构性风险（id 布局也已在 ~10min 高位运行），任何布局类玩法
   都会被它卡住 40min 门。

**含义**：亲和布局假设**连续两次死于编译预算，运行时证据仍为零**。继续修
顺序是缘木求鱼——正解是发射期消除死 store（见建议 1），把 init() 从
1.82M 行压到 ~4 万行后，布局假设才有被计时门裁决的资格。

### c2（e00008，ok 272.7s，-0.13%）——炸开命中目标族但持平，轴关闭

emit 文本实证 ABTB 族确实被变换（b38653 侧 4,875 处词提取 → `wv1729_[k]`
元素直读；b83569 侧 3,072 处 32-word 掩码循环 → 单元素条件 RMW；b83570
全宽写 → 32×32 解包循环），但 Host 中位与基线持平（-0.13%，低于 CV 1%
与历史 rep 摆幅）。结论：**NO0018 的切片内联已吸收该族的主要成本**，
NO0017 §5 锚点（56.7G 匹配 Δ + ~110G 同模式账）是 NO0018 之前的账；
残余的提取机械在关键路径之外。炸开覆盖窄（274/~33.5K 候选）不是主因——
目标族本身命中了也没动。宽态炸开轴**关闭**；b83570 全宽写退化的理论风险
（10-30×/站点）实证净影响可忽略。

### 裁决

winner = **c2**（唯一 ok 候选，机械规则），已合入 `tes/r001/t2/main`
（commit `0919aec`），t2 best = -272743。**注意这是噪声级 adoption**
（+0.13% < CV），不代表机制收益；t2 主线携带 explode 特性（默认 off，
对后续候选无行为影响）。best_overall 不变（-270502，t1/s01）。

**本 step 归因小结**：状态面两连击——布局轴两次败于编译预算（修复方向从
「排序」升级为「死 store 消除」），表示轴证伪。至此 x0 三大残余轴
（跨 chunk 往返、状态 gather、适配胶）+ 表示轴全部关闭或降级，11x 差距的
重心彻底移向**尚未触探的运行时结构成本**（调度器/事件/commit 机械本身）
与**组合既有弱正**。

## 对 Φ 下一步的建议

1. **`--init-zero-elision`（新旋钮，最高优先）**：init() 发射期消除字面量 0
   死 store（memset/fill(0) 已覆盖；保守规则：变量唯一 init action 且为
   字面量 0 才消；random/seeded/多 action 不动）。预期 init() 1.82M→~4 万行，
   runtime.o 编译 ~10min→~1min 量级——既直接改善全部候选的编译预算余量，
   又是布局假设（affinity）取得运行时证据的前置条件。可作为下一步候选
   （单独评估其编译收益 + 运行时中性验证），随后布局候选叠加复测。
2. **弱正组合**：`--branchy-mux --resize-elision`（t0/t1 各 -0.74%/-0.95%，
   机制正交）组合验证可加性，期望 ~-1.5%。
3. **运行时结构成本探针**：调度器/事件/commit 机械是唯一未被单变量触探的
   大轴。可设计候选如活动字扫描批量化、commit 路径检测合并等（需先形成
   可证伪假设；EMU_AM_BLOCK_EXECS 计数数据可离线复用 pdocs 既有 profile）。
4. **测量环境**：连续两个 action 的 rep 期 loadavg 1.0-1.6，亚 1% 效应已
   低于协议分辨极限；后续评估尽量空载时段，winner 裁决对 <0.5% 读数应保持
   存疑（本 step 的 c2 adoption 即为例证）。
