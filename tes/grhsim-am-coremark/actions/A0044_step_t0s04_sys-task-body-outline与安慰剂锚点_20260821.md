## 机制分析

- 本机制是 A0041（t0 自有证据链）关闭守卫门控轴后预言的「atom 代码瘦身」在 t0
  整块守卫池上的确认：b90656/90657 每 eval 触发、门控无空闲重估可跳（e00011
  证伪），但 60% 块体是从不/极少执行的 task 冷体，把冷体移出热函数后每 eval 的
  ~7000 次 fire 求值流过的代码足迹减半（TU text -50%），前端/i-cache 压力下降。
- 与 t1/s03 的 task-body-outline 属同族机制的独立实现（t0 依据全部来自
  recon-t0s02/s03 与 A0041；t0 命名该路径在先）。差异：t0 版对全部非 final
  fwrite 站（含带参站）统一 outline 为 per-site noinline 成员函数；未做共享冷体
  坍缩与 DPI String 免拷贝。残余空间：带参站的 append 参数物化已做，但 7,235 个
  per-site 函数体彼此高度相似（同格式串族），共享坍缩是 t0 侧未试的下一层。
- 收益 -5.91% 相对守卫池 9.3% 的占比说明：outline 收掉了守卫块约六成成本
  （前端流式部分），残余为 fire 求值本身与真实触发的 task 体。
- e00007 overturn 后的真值口径更新：t0 tip 真值（常态窗）363.4s → **339.7s**；
  ledger best_overall 仍为 e00007 的 261.543s（快态抽签读数，不作比较基准）。
