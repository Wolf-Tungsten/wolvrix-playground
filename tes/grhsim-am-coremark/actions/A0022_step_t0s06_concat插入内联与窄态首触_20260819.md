## 候选设计与可证伪假设

### c1 `--concat-insert-inline`

- 分支 `tes/r001/t0/s06-c1`，commit `424c569`，eval `e00033`。
- 宽 `Concat` / `Replicate` / window-chain（chain head / chain step / F2）中
  bit 区间落在单个目标 word 内的窄操作数改为一条内联语句：单字非满字 →
  `|= (v & mask) << shift`（insert 系）或 RMW（replace 系）；64-bit 对齐满字
  → 直接 word store（拼接区间独占该 word，insert/replace 语义等价于 store）；
  全部操作数都是满字 store 时 `zero_words` 前导为死代码并消除。跨 word 与宽
  操作数保持 outlined 调用。新增 emitter 单测（文本形态 + 常量语义 harness）。
- 假设：单字退化拼接的 outlined 调用边界是一阶适配成本，内联后 Host 中位较
  e00027 降 >=2%；<1% 则该边界非一阶。

### c2 `--narrow-storage-first-touch`

- 分支 `tes/r001/t0/s06-c2`，commit `3a6b7f5`，eval `e00034`。
- 持久窄标量 `v<K>` 成员（本模型 1,263,224 个、约 10.1MB）的声明顺序从
  VariableId 升序改为按 scheduled Block 首触排序（先 operand 后 result，未
  被 Block 引用的成员按 id 追加）；只改成员偏移，访问点仍按名字引用，init()
  成员区 memset 仍精确覆盖连续声明区。新增单测覆盖声明顺序、memset 区域与
  语义 harness。
- 假设：窄态成员区 gather 是一阶成本，压实热点成员后 Host 中位较 e00027 降
  >=2%；<1% 则窄态 gather 非一阶，布局轴在窄态类关闭。

## 机制分析与裁决

**c1 确认（winner）**：单字退化拼接的 outlined 调用边界是一阶适配成本。
内联消除 9.59 亿次动态 `insert_words` 调用（每次含边界检查、word_count 计算、
单迭代循环与一次冗余 top-word RMW）后 Host 中位 216.481s，较 e00027 **-2.78%**
（CV 0.35%，干净窗口），达到 >=2% 假设门。与 t0 既往的 guard/布局收益不同源：
本候选不减少 AM schedule 工作量，收益来自生成 C++ 的调用边界与 store 形态。
残余空间：56,759 个跨 word insert 站点（动态 6.8 亿次）保持 outlined，是下一层
同类细化候选，但须先离线量化其动态权重再决定。

**c2 证伪并反转**：窄态首触压实（span -27.8%、pages -14.9%）换来 +3.23% 回退
（三个 rep 全部差于 e00027 全部 rep，超出 CV 1.2% 与历史 run-to-run 噪声带），
且 emu_build 从 ~282s 恶化到 964.5s。解释：窄态 VariableId 序本身已与
创建/数据流顺序对齐（热块成员在 id 空间本来就稠密，b83400 的 7,001 个 guard
值即为例证），首触重排反而把共访问成员拆散；touched 集合高达 72% 也意味着
「热点子集」假设在窄态不成立。**窄态布局轴关闭**，不再以任何排序变体重试。

winner = **e00033**（score `-216481`），已合入 `tes/r001/t0/main`。
t0 best 从 222.654s 更新为 216.481s：较 AM y0 273.103s 累计 **-20.73%**，
仍为 gsim 24.688s 的 **8.77x**，AM/gsim 绝对差距关闭 **22.76%**。
t0 完成 6/8，run 使用 34/48 eval。

对 Φ 下一步的建议：t0 余 2 步。扫描剪枝 x 布局的组合已在 e00027 收敛，
本步新增「宽拼接调用边界」一阶池并已收掉单字退化层；候选方向优先级：
(1) 跨 word insert 的半字/unroll 特化（先离线核动态权重）；(2) commit 相
26.2% 中的非门控残余（b83400 类 guard 块的每 eval 全量重估，须锥级证据）；
(3) 不建议再回到窄态布局或 word 局部 snapshot（均已证伪）。
