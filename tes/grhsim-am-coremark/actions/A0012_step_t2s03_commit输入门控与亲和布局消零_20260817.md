proposal：`tes/grhsim-am-coremark/proposals/r001-t2-s03.md`（Phi 仅从 t2 选中

## 候选设计与可证伪假设

### c1 `--commit-input-gating` - commit next 锥输入脏传播门控

- 分支 `tes/r001/t2/s03-c1`，commit `06986dc`，eval e00019。
- emit-args：`--block-chunk-instructions 3000 --guard-event-gating
  --commit-input-gating`。
- 机制：从 commit 块状态写的 next 输入反向追踪块内纯计算锥与块外叶子。
  compute 生产块执行或 ST00013 状态写真实变化时，通过块级 dirty byte
  传播到依赖的 commit 块；剩余少量窄叶在门处做精确 snapshot 比较。
  `event && (!valid || dirty || snapshot_changed)` 为假时，整个幂等写后缀
  跳过；首次执行强制开放，dirty 在执行写后缀前清零，不丢同轮新变化。
- **假设**：commit 块 next 锥的外部叶子在绝大多数时钟事件不脏；若覆盖
  至少 90% 写站，Host 中位较 t2 主线下降至少 3%；若低于 1.5%，则 dirty
  传播开销或动态命中率不足。
- 开关默认 off；文档、CLI、规划统计、初始化和生成模型 oracle 随 commit
  提交。保守拒绝 Host effect、不固定写布局、宽/非 BitVector 不安全叶、
  snapshot 超 64 或保护工作不足的块。

### c2 `--state-layout affinity --init-zero-elision` - 亲和状态布局重测

- 分支 `tes/r001/t2/s03-c2`，commit `da4c199`，eval e00020。
- emit-args：`--block-chunk-instructions 3000 --guard-event-gating
  --state-layout affinity --init-zero-elision`。
- 机制：状态按静态 Block 引用亲和性聚簇，热 primary Block 组优先；标量
  成员声明与 `wideValues_` pool offset 同步置换。`init-zero-elision` 消除
  已被 init prologue 的 memset/fill(0) 覆盖的字面量 0 store，使此前因
  百万行 init 函数超编译预算的 affinity 路线首次可进入运行时评估。
  literal-only 宽初始化按最终 offset 发射，含随机初始化的变量保持
  VariableId 相对顺序。
- **假设**：消除 98%+ 冗余 init store 后 affinity 可在 40min 门内取得
  运行时证据；按 Block 热度聚簇 194MB 状态改善 gather 局部性，使 Host
  中位较 t2 主线下降至少 2%；若持平或恶化，则静态亲和布局轴证伪。
- 两个开关均默认 off。成员区连续、宽池从 0 连续、总尺寸、
  `changedResults_` 密集下标与随机初始化映射保持不变；CLI、文档、诊断
  计数与确定性/运行时 oracle 随 commit 提交。

### 机制互异性

c1 不改变任何状态地址，只用运行时变化传播跳过稳定的 commit 写后缀；c2
不跳过运行时计算，只改变持久状态物理地址布局，并用编译期可证死 store 消除
恢复编译门。两者分别作用于控制流工作量与 cache/TLB 局部性，动态成本和
失败方式不同。

## 机制分析

### c1：覆盖目标成立，收益部分确认但传播成本不可忽略

- 91.9% 写站覆盖（162,422/176,682）超过假设的 90% 前提，且 0.74% CV
  给出干净读数；相对 t2 tip 的 1.95% 改善越过 1.5% 证伪线，说明稳定
  commit next 锥确实存在可跳过工作。
- 结果未达到 3% 目标。240,198 条静态 dirty 边会在生产 compute 块触发时
  产生运行时 store，55,320 个生产块的扇出传播与门检查抵消了部分
  440,821 条受保护指令收益；仅有静态覆盖不能推出高动态关闭率。
- 下一次细化前应增加不计时的动态统计：每块 gate open/skip 次数、dirty
  来源和传播 store 数，按净跳过工作排序后只保留高收益块。没有至少 3%
  的离线净收益模型，不再直接扩大全覆盖。

### c2：编译障碍解除，静态亲和布局得到首个弱正运行时证据

- `init-zero-elision` 将 affinity 全流水线编译压到 1036.1s，较 2400s 门
  留出 1363.9s；此前“布局候选无法评估”的结构性障碍已解除。正式 emit
  与预发射的消除计数完全一致。
- 265.243s 相对 t2 tip 改善 1.66%，没有达到 2% 假设阈值，但也不是持平或
  恶化；因此结论是**弱正、未充分确认**，不能把静态亲和布局轴判死。
  单次跨构建布局读数仍可能受 ASLR/机器状态影响，且 1.66% 与当前协议
  分辨边界接近。
- c2 没有进入 t2 main。若未来重开，必须先用 cache/page 或按 Block 的地址
  跨度证据定位具体受益状态族，再设计更有针对性的布局；不再原样重测全局
  affinity。
