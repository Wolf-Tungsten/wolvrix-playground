## 候选设计与可证伪假设

### c1 `--commit-input-gate-whitelist`（动态证据 gate 筛选，eval e00043）

t2 commit 轴唯一认可的重开条件（A0021/A0024：须先有逐 gate 动态 open/skip 与
净收益证据）。先加 recon 插桩旋钮 `--commit-input-gate-stats`（per-gate opens/skips
计数 + emit 目录 `commit_gate_map.json` 静态成本映射），离线 recon（非计时，
`build/tes/grhsim-am-coremark/evals/recon-t2s07c1/`）实测 50k 周期全程，再按规则
`keep(gate) ⇔ skips×protectedInstructions ≥ (opens+skips)×dirtyEdges`
（1 跳过指令 ≈ 1 传播 store 的近似）筛选，白名单文件随候选分支提交
（`tes-evidence/commit_gate_whitelist_r001_t2_s07.txt`）。

- 假设：2,922 个静态 gate 中大量 gate 的动态跳过工作不抵其 dirty 传播 store；仅保留
  净正 gate 后 Host 中位较 e00037 降 ≥2%；<1% 或回退则动态筛选亦无净收益，
  commit gating 细化轴彻底关闭。
- recon 筛选结果：**保留 151/2,922 gate**（丢弃 94.8%）；dirty 传播边
  240,198→**130,433**（-46%）；保护指令 440,821→293,202；保留 **66.8%** 动态跳过
  工作（16.28G/24.38G 指令·次）。Top 丢弃族 = b83415 等 MemoryWrite 提交块
  （4,096 写站，opens≈skips≈50k，每轮 ~50% 开门，传播边 6,473 条）。
- 计数口径说明：skips 计于合并门（事件门 && 输入门），含事件门未开的情形，
  规则偏保守（倾向保留），不会误删真省工 gate（见 wolvrix `docs/grhsim/
  grhsim-am-pipeline.md` §3.2.14）。

## 机制分析

- **c1 为什么无效（信息量最大）**：三种解读并存——(a) 在 t2 现 tip 上，传播边 store
  与门控跳过收益同为二阶，净差低于协议分辨率；(b) 「传播边抵消 e00019 收益」的
  理论建立在 e00019 的 -1.95% 上，而该读数本身是跨日值（A0024 安慰剂：同代码
  8-17→8-19 漂移 -2.58%），抵消模型可能一直在拟合漂移；(c) 被丢弃的 MemoryWrite
  提交块族 skip 收益 ≈ 传播成本（净零），与成本模型自洽。三者共同结论：
  **commit 写站 compare/门控机械在当前 AM 结构上无一阶可收成本**，t2 的
  commit 轴（门控、稀疏化、位图、producer/读侧快照、动态白名单，共 7 个变体）
  全部以证据关闭。
- **c2 为什么接近持平**：热度分布平坦（单块最高 0.02%、top 6.65% 才覆盖 50%）
  意味着「热工作集」≈ 全模型，重排无法压缩工作集；affinity 簇已按访问关系聚簇，
  动态权重在全热情形下只是另一个全序，局部性增量天然微小。t2 布局轴
  （affinity 弱正 → 热度加权持平）收敛：布局类收益上限 ~1-2%，非一阶。
- **编译侧**：两候选 compile_s 473/565s，预算裕量充裕（affinity+init 消零的
  编译杠杆保持）；c2 的 emu_build 398.3s 比 c1 303.6s 略高（布局重排改变
  生成代码顺序），无预算风险。
