## 跨轨迹对比

- **收敛：稀疏性只有在连续数据流外形上才显示希望。** t1 的 zero-tile bypass
  （e00064）保留全零 tile 的连续 base copy，active-tile sparse（e00067）在此基础
  上只对置位 lane 做局部 scatter；这条“局部门控 + 连续 base 流”路线是本轮唯一越过
  预注册收益门的方向。相反，t0 的 ctz/switch、direct-tree 和 nibble 都是在活动
  byte 内进一步减少控制测试，仍未超过 r003 best e00057 的 branch-hinted 线性扫描。
  可复用判据是先保护顺序访存和可预测 fall-through，再尝试稀疏控制；间接派发或大幅
  增加控制节点没有独立收益证据。
- **发散：两条轨迹的证据强度不同。** t0 两候选相对 e00061 均落同一慢窗，不能从
  62.81%/63.99% 名义回退估计 direct-tree 或 nibble 的净成本；t1 e00068 与 e00064
  的 loadavg（51.07/50.18）接近且回退 4.23%，足以关闭固定层专化；e00067 的低负载
  读数则仍需同态锚点或非计时动态计数确认。round-summary 只做跨轨迹人读分析，不把
  这些观察回流到当前 run 的 proposal。
- **代码体量与编译预算形成共同约束。** e00068 将动态 helper 展成 L4/L23 两份大
  helper，最终 `.text` 比 e00064 增 11,624 B，循环控制省项没有抵过前端/I-cache
  压力；e00067 的 `compile_s=2136.2s` 只剩约 264s 余量。后续任何 wide-mux 变体
  都应先给出动态覆盖和生成体量证据，避免继续扩大 helper。
- **测量限制仍是主要混杂项。** 本轮再次出现 loadavg≈50 的慢态，且 e00066 在固定
  3 rep 内直接出现离群 rep；CV=0 只说明一批内部一致，不能证明跨批同态。继续遵守
  固定 3 rep、串行评估和不补测纪律，所有跨窗百分比仅作方向筛选。
