## 裁决与机制分析

c1 用 64-bit words 将 commit scratch 清零流量和 footprint 压缩约 8 倍，但每个
flag 的生成代码从直接 byte load/store 变成 bit-mask read-modify-write；b93159/
b93141 的数千个写站和尾部 fanout 都逐 flag 访问。正式 Host 回退 5.29%，说明热路径
逐站位操作成本明显超过一次性清零与 cache footprint 收益。commit scratch 位压缩轴
关闭；未来若做批量表示，必须连同消费者一起 word-at-a-time 消费，不能只换容器。

c2 确实消除了 6,349 对重复 fire predicate，但整体回退 0.95%。这证明
`bool condition && changedResults_[0]` 的重复求值不是 4.795% system-task 池的一阶成本；
主成本仍在大块扫描、冷 call 边界或同块其他 compute。纯 fwrite run 在其他轨迹的弱正
不能外推为异构 run 收益，该共享谓词细化关闭。

`finish-step` 按两个候选的 raw score 选择 e00118，并以 ±3% 规则判
outcome=`neutral` 后移动 `tes/r004/t3/main`。t3 的统计 best 仍是 e00106
**166.947s**，全局 best 仍是 t1/e00113 **166.014s**；预算为 **34/48**，冻结
