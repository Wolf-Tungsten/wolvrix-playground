## 裁决

- **winner = c2（e00012，363.444s）**，finish-step 已机械合入 `tes/r002/t0/main`
  （48916f2 为空 commit，t0/main 内容与 ecb4c3f 逐字节一致，无代码变化）。
- **e00007 归因 overturn**：安慰剂 363.444s = 261.543×1.389 精确落带，三重证据
  （recon tick 持平 / 插桩 Host 持平 / 同窗安慰剂回读 ~363s）一致支持——
  `wide-detect-fast-path` 机制**亚分辨中性**，e00007 的 -27.9% 是双态快态抽签。
  **t0 tip 真值 ≈ 363s（常态窗）**；ledger best 261.543s 此后只作历史读数，
  不作比较基准。旋钮仍默认 off 携带无妨（off 逐字节等价），但不得再以
  「e00007 机制收益」为前提设计候选。
- **c1 假设证伪**：+1.94%（同态），未过 <2% 证伪线且方向为负。机制解读：
  守卫块每 eval 激活 ~1 次（100,791/88,260 execs），激活很可能本就集中在门开
  的 round（posedge 驱动链），**没有空闲重估可跳**；+2% 为门测试开销 + 布局
  位移，在 ±4% 构建噪声带内。守卫池的成本是**必要激活轮内的 i-cache 流式**
  （7000 atom 函数体），门控路线（整块/run 级）对守卫池**关闭**；残余可探方向
  只剩 atom 代码瘦身（缩小分支体体积）。
- 观察（不影响裁决）：e00011 emu_build 341.9s vs e00012 1512.7s，近同体量代码
  构建时间 4.4x 差——构建墙钟也存在大幅非频率因素波动（A0039 的 ~340s 与
  A0038 的 ~1513s 同样分裂）；compile_s 余量评估须取保守侧。

## 机制分析

- **数据侧 stall 主导 commit 巨块**：宽站 fast path 改了指令数没改时间
  （recon tick 实证），说明 b93159 族的瓶颈是散布访存 miss 而非计算/前端。
  窄站 SIMD 化、批量比较等「省指令」类机制预期同样被 miss 主导淹没——
  **commit 相省指令轴在 t0 关闭**；若重访须先证明目标池是计算/前端绑定。
- **门控类机制的适用前提再确认**：门有收益需「门关闭的激活真实存在」（r001
  e00014 的 negedge 半数）。新图守卫块激活与门开 round 重合时门控恒开，
  静态池占比不构成收益证据；后续门控候选必须先离线量出门关闭率。
- **双态 ×1.39 是 r002 最大测量危害，且能完美伪装成大机制收益**：e00007 教训
  ——任何 >15% 的名义单步收益必须有同窗安慰剂/锚点 corroborate，否则默认存疑；
  逻辑控制论证对「整运行时乘子」型混杂无效（它只能排除与池大小相关的混杂）。
- 评估时延正面观察：e00011 compile_s 690.4s（emu_build 341.9s）显示本机快构建
  路径存在（对比 e00012 1858.8s）；若可复现（未归因），评估吞吐可翻倍。
