# A0006 — step r001/t0/s02：init 死 store 消除（元杠杆）与弱正组合

日期：2026-08-15。action 类型：step（trajectory t0, step 2, K=2）。
proposal：`tes/grhsim-am-coremark/proposals/r001-t0-s02.md`（Φ 选中 e00004，t0 当前
best = branchy-mux 271.1s）。两候选均承载 t0 轨迹状态（`--branchy-mux` 随 emit-args
延续），设计来源：A0005 第 1 轮小结的方向优先级（元杠杆 + 弱正组合）。

## 候选设计与可证伪假设

### c1 `--init-zero-elision` — 编译预算元杠杆（emit 规则面）

- 分支 `tes/r001/t0/s02-c1`（commit `8087d74`），worktree
  `build/tes/grhsim-am-coremark/src/e00009-t0-s02c1`，eval e00009。
- emit-args：`--block-chunk-instructions 3000 --branchy-mux --init-zero-elision`。
- 机制：init() 的逐变量 init store 中，字面量 0 的死 store（宽池 98.2%、标量
  93.5%，A0004 取证）被 prologue 的 `memset(成员区)` / `wideValues_.fill(0)` 按
  构造覆盖；发射期逐 word/逐 store 消除（Literal 且 payload==0 才消；
  random/seeded/Fill/String 不动；多 action 变量保守保留——合法模型下被校验器
  先行拒绝，守卫实际不可达）。窄值消除要求成员资格与声明处同源
  （`hasMemberStorage` helper，声明循环重构复用同一判定）。
- 大模型实测（实施期）：消除 wide 1,633,254 + narrow 147,822 条 store，
  init() 1,823,166 → **42,090 行（-97.7%）**；非零 store 集合与基线逐三元组
  比对 missing=0/extra=0；runtime.cpp 单 TU 编译 **572.4s → 14.7s
  （-97.4%，38.9x）**；默认 off 逐字节一致；ctest 17/17。
- **假设**：全程 compile_s 下降 ≥30%（runtime.o 编译瓶颈移除），Host 中位
  变化 <±0.5%（运行时中性——死 store 只影响 init 一次执行与编译）；若运行时
  退化超噪声 → 死 store 参与了某种有利 idiom（意外，需回撤分析）。
- 动机（A0004/A0005）：init() 体量是编译预算门的结构性风险（id 布局 runtime.o
  ~10min；布局类候选两次 compile_timeout 皆因它），本旋钮是全部后续候选的
  预算改善 + 布局轴取得运行时证据的前置。

### c2 `--branchy-mux --resize-elision` — 弱正可加性验证（旋钮组合面）

- 分支 `tes/r001/t0/s02-c2`（commit `95aa68d`），worktree
  `build/tes/grhsim-am-coremark/src/e00010-t0-s02c2`，eval e00010。
- emit-args：`--block-chunk-instructions 3000 --branchy-mux --resize-elision`。
- 代码来源：resize-elision 自 b798b9d（t1/s01-c2）零冲突 cherry-pick 平移，
  叠加 t0/main 已有的 branchy-mux；两特性在 emitter/CLI/tests/docs 四面共存
  核实。组合 emit 的 `resize_value(` 残余 350,984 == e00006 单开计数
  （branchy-mux 不影响胶消除率）；branchy-mux 在组合中生效（三元表达式行
  2,116→0）。默认 off 逐字节一致；ctest 17/17。
- **假设**：两规则机制正交（分支形态 vs 胶消除），组合收益近似可加——
  期望 Host 中位 ≈ y0 × (1-0.0074) × (1-0.0095) ≈ 268.6s（-1.3%~-1.7%）；
  若显著劣于可加预期（如 >-0.5%）→ 两规则存在交互（分支形态改变胶的
  CSE/调度），需分解归因。

### 机制互异性说明

c1 改生成代码体量（编译期成本，运行时中性预期），c2 改热路径动态指令
（运行时收益预期）；前者是基础设施型候选，后者是收益型候选。机制、
目标度量、假设门均不同。

## c1 机制分析（e00009）

- **编译假设：机制目标超额达成、口径目标未达**。runtime.o/init 瓶颈被移除
  （单 TU -97%，emu_build -56%），但全程 compile_s 仅 -11%（1223→1090）——
  ctest（含 emit-grhsim-cpp 的模型编译）+ emit + wolvrix 构建的固定 ~740s
  稀释了分母。假设中「≥30% 全程」的措辞未达标，但候选的真实目的——
  **消除 40min 预算门的结构性风险点**——完全达成：runtime.o 从 ~10min 降到
  15s 后，任何布局/表示类大 emit 变更都有了预算余量（亲和布局两次
  compile_timeout 的直接根因被移除）。
- **运行时中性成立**：274.4s vs 271.1s（+1.2%）在同代码三次评估的噪声带
  （±1.5%）内；机制上 init 是一次性代码、不参与稳态循环，方向安全。
  二进制布局彩票（NO0338+）解释了 ±1% 量级的漂移。
- 语义等价证据：非零 store 集合逐三元组比对 missing=0/extra=0 + 三次评估
  difftest 全过 + ctest 17/17。

## c2 机制分析（e00010）——可加性证伪，~1% 级微调组合路线到头

- 单因子：branchy-mux -0.74%（e00004）、resize-elision -0.95%（e00006）；
  可加预期 ≈ -1.7%（268.6s）。实测组合 **273.3s（+0.06%）**——叠加后收益
  不仅不可加，反而全部消失。相对 branchy-mux 单因子（271.1s）为 +0.8%。
- 两种读法二选一（现有数据无法区分，也无需区分）：(a) 两个单因子读数本身
  就是布局彩票/run-to-run 噪声（±1.5% 带已实测）中的幸运抽取；(b) 两规则
  存在负交互（if/else 形态改变胶的 CSE/分支布局）。任一解读下结论相同：
  **~1% 级 emit 微调及其组合路线到头**，后续候选不应再在这个量级上消耗
  评估预算。
- 附带数据点：组合 emit 的 resize 残余计数与 resize-elision 单开完全一致
  （350,984），branchy-mux 不影响胶消除率——交互发生在运行时而非发射期。

## 裁决

winner = **e00010**（机械规则取 max score；两候选分数同为噪声级），已合入
`tes/r001/t0/main`（commit `95aa68d`，resize-elision 代码入主线，默认 off
不影响后续候选基线行为）。t0 best 保持 -271095（e00004）。best_overall
不变（-270502，t1/s01）。

**c1（init-zero-elision）未入主线但战略价值已立**：分支
`tes/r001/t0/s02-c1`（`8087d74`）常备，是后续布局/表示类候选的编译预算
前置（亲和布局两次 compile_timeout 的直接根因已除）。注意：它改动面大
（init() 文本 -97.7%），与任何改 init/布局的分支合并时优先以它为底座。

**本 step 归因小结**：编译预算元杠杆落地（emu_build -56%）+ 弱正组合路线
关闭。至此第 2 轮开局明确了唯一剩下一阶潜力的方向：**运行时结构成本**
（调度器/活动字扫描/事件/commit 机械）。
