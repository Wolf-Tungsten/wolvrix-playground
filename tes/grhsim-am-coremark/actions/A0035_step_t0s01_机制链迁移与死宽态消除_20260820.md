## 测量事故一：emit-args 整体替换语义导致首轮调度点错配（已纠正）

evaluator 的 `--emit-args` 是**整体替换**语义（`override if not None else
config`）。两候选首轮只传了旋钮 → 实际跑在 CLI 默认的 **gsim-aligned 调度点**
（maxAtomsPerBlock=15、dpCoarsenAtomBudget=7000、dpCoarsenInstrBudget=0、
mergeWhenMinGroup=1；supernode-align NO0018 锁定），而 r002 基线 e00001 跑在
manifest 冻结的 **config 调度点**（max-atoms-per-block 9、
dp-coarsen-instr-budget 32768、merge-when-min-group 5 等）。首轮读数对基线
无效，两候选以 config 基组 + 各自旋钮重测（同 eval-id 覆盖 result.json）。
e00003 的首轮 ledger 记录无法重登记（record-eval 无 replace 路径），保留并
在此勘误：其 insight 中「机制链迁移确认 -41.38%」的归因错误（混入了调度点
差异），正确分解见下表。

r001 无此问题的原因：r001 manifest emit_args 仅 `--block-chunk-instructions
3000`（= CLI 默认值），旋钮-only 覆盖不改变调度点。**操作教训固化：r002 起
候选 emit-args 必须显式携带目标调度点全参数，或明确以默认调度点为候选意图。**

## 机制分析

- **机制链迁移确认（带因子分解）**：9 旋钮链在 config 调度上收 -14.1%
  （452.8→388.9），在 gsim-aligned 调度上只收 -4.1%（378.4→362.9）——
  gsim-aligned 调度（15 atoms/block + 7000 coarsen + mergeWhen off）本身已
  消除大部分适配胶，与旋钮链机制高度重叠（扫描面/调用边界随块组织收缩）。
  r001 的「适配层胶」画像在新输入图上依然成立，但其规模是调度点的函数。
- **调度点是一阶变量（本 step 最大发现）**：gsim-aligned 默认调度比 r002
  config 调度快 16.4%（同窗口、旋钮~0 对照）。旧 gsim 导出图上 NO0002
  「分区形状中性」的结论不适用于 wolvrix 自解析新输入——分区/调度轴在
  r002 重新打开，且是当下最大单变量。
- **死态瘦身轴在新输入图上证伪**：wolvrix 自解析流程产生的图死宽池仅
  0.46%（r001 旧图 66%），死态已在 ingest/normalize 侧被消化，
  dead-wide/dead-narrow/常量存储族在 r002 无对象，勿再投入。
- **c2 的 -26.85% 名义读数是测量窗口漂移的量化证据**（0.46% 机制改动
  不可能产生 27%），不作为机制收益。
