## 候选假设（可证伪一句话）

- **c1**：commit 写站的 wrNext 输入在其生产者 compute 块未触发时必然等于
  已提交状态（compare 幂等失败）；按生产者块触发朝代（tick）对写站分组
  门控可跳过空转 compare——commit 相占 Host 23.75%，若空转率 >80% 且
  静态覆盖足够，Host 中位降 ≥4%；若 <1.5% 则空转率或覆盖不成立。
- **c2**：b83400 型纯守卫块（fatal/fwrite/finish 全部以 changedResults_
  时钟沿槽为事件条件、块写值无块外消费者）每 eval（含 negedge 半数）
  全量重估守卫条件；整块按事件槽门控后 negedge 半数触发跳过，
  b83400（~61.9G cycles ≈ 8% Host、100,102 次触发）成本近半，
  Host 中位降 ≥2%；若 <1% 则块成本已迁移或命中失败。

## 机制分析

- **c1 朝代门控：机制成立、覆盖不足、测量环境恶劣，三重结论**。
  1. 空转本体属实：离线插桩实测 idle=97.35%（7.32G compares / 194M hits），
     假设的物理前提成立；
  2. 朝代门控路线关闭：静态覆盖仅 6% 写站（10,524/176,682）——绝大多数
     写站的 next 锥在 commit 块内部（生产者非 compute 块）被保守排除，
     收益上限 ~1%，而 tick 记账（601M 次块触发各一次 store）与组检查的
     固定开销已同量级；协议中位 +13.5% 判证伪；
  3. 但 +13.5% 不能读作机制回退：rep5（274.8s，loadavg 1.66）与基线
     272.7s 仅差 +0.8%，rep1/2/4 的 loadavg_before 达 3.0-4.6、rep3
     （652.4s）为明显离群——当日共享机（7 用户）同居负载主导了读数；
     机制量级估算（tick ~0.4s 开销 vs 6% 写站跳过省 ~1-4s）也指向
     ≈中性。诚实记录：**真值最可能是 ±1% 中性，无论如何不达采纳线**。
- **c2 守卫门控：机制确认，收益 -1.10%（3.0s）落袋**。假设立bar ≥2% 未达、
  证伪线 <1% 未触——低于预期的原因：假设锚定的 b83400「61.9G ≈ 8% Host」
  是 NO0017（NO0018 切片内联修复**之前**）的旧账，当前该块实际成本已被
  后续修复摊薄（-1.10% ≈ 9G cycles 反推其 negedge 半数触发成本 ~9G、
  全账 ~18G）。机制本身被干净读数（CV 0.88%、rep 间全距 1.6%）确认：
  negedge 半数触发的整块守卫重估被事件门消除。b26518（1,327 atoms）
  附带同族收益。emit 覆盖与离线冒烟一致（gated=2）。
- c1b-fix 的教训：门控的 seen 槽必须按「原子执行单元」（run）而非
  「逻辑组」分配——跨 chunk 同组写站的首次 eval 丢写 bug 由 c1 agent
  自查捕获（difftest 兜底前），emit 侧单元测试覆盖此类语义 corner 的
  价值再次体现。

## 对 Φ 下一步的建议

- commit 写站空转轴：idle 97.35% 已实测坐实，剩余 94% 写站的 next 锥在
  commit 块内部——正确机制是「commit 内锥状态输入快照检测」（按块内锥的
  状态读集合做 changed 检测，复用 ST00010 检测器分组设施），而非生产者
  朝代。静态估计收益上限 = commit 相 23.75% 的大部。这是块间机械轴上
  目前唯一有实测锚点的大额方向，建议下 step 优先（可先离线评估快照
  检测的覆盖与开销平衡，再上正式候选）。
- 守卫门控族（b83400+b26518）收益落袋，同族无更多巨块，**该轴关闭**。
- 测量纪律：e00013 的 CV 41.7% 噪声日（共享机同居负载 loadavg 3-7）与
  e00014 的 CV 0.88% 干净窗口对比——>2% 级效应可在干净窗口裁决，
  <1% 级效应在本环境已超出协议分辨极限，勿再为其消耗评估预算。
