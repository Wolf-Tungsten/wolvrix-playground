# grhsim-ir-st-opt 研究需求

## 研究目标

尽可能优化单线程 grhsim-ir 路线仿真 XiangShan CoreMark 50k 负载的性能，缩小与 gsim 的显著差距。用户提供的 gsim 参考耗时约为 40 秒；该数值是研究目标的参考，需在同机、同负载、同测量口径下重新核实，不作为已复现结果。

本任务从第 1 周开始。50k 的执行口径暂定为现有 Makefile 的 `XS_SIM_MAX_CYCLE=50000`；实验必须记录实际周期数、指令提交数、退出状态和计时区间，确保各路线完成相同工作量。

## 允许的研究范围

- 扩展 GrhSIM IR 的定义、操作及 CPU 后端映射，并补齐语义说明、验证和序列化支持。
- 优化 GrhSIM IR 层的分区、活动度传播与单线程调度算法。
- 增加或改进 GrhSIM IR 层的模式替换 pass。
- 优化生成 C++ 的 emit 模式、数据布局和 runtime helper。
- 优先将优化显式表达为 GrhSIM IR pass、操作或可持久化的后端映射决策，能够独立开关、复现和归因。

## 不可变约束

- 不修改 XiangShan，包括 RTL、工作负载和会改变被测行为的配置。
- 不修改前序 GRH IR 的定义、语义、变换或产物来取得收益；从相同的 GRH 输入进入 GrhSIM IR 路线。
- 研究对象为单线程仿真，不以多线程、减少仿真工作量、关闭正确性检查或改变时序语义换取速度。
- 保持初始化、复位、多时钟与派生边沿、状态读旧写新、掩码与多写口优先级、DPI/system task 副作用及收敛语义。
- 宽值 helper 以 legacy 路线为性能参考，优先采用指针和调用者提供的输出缓冲，避免热路径中的大块返回值和临时复制。

## 执行与验收

第 1 周安排恰好四个相互独立的探索方向，分别从同一基线实现和验证，以正确性通过后的单线程 50k 实测性能进行赛马。每个方向须给出优化假设、IR 层动作、独立候选、正确性证据、性能与资源成本、适用边界；负结果也应保留证据。

构建、测试、安装和脚本工作流一律经过项目 Makefile 目标；缺少入口时先补目标再执行。命令日志和临时工作流产物放在仓库 `ptmp/` 下，测试产物遵守仓库目录规则。不得手工调用编译器、CMake、CTest、pip 或 Python 完成构建测试工作。

本次周一规划只创建或更新需求和本周规划，并在当前 `grh/grhsim-ir` 分支恰好提交一次。`job.json` 和 `week_1/progress.json` 由调度器管理，禁止修改或提交；不切换或创建分支，不执行破坏性 Git 操作或推送。
