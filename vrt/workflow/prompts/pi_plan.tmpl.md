# 你必须完成的工作

1. 综合任务需求与前序经验，构想本周研究方案，分解为 {{R}} 个相互独立的探索方向（赛马关系）。每方向固定使用 {{W}} 次工程调用，不设提前终止；工时和虚拟周均与物理时间无关，不得换算为小时或分钟预算。用户明确要求的性能指标和外部超时独立处理；
2. 将任务需求写入 `{{JOB_DIR}}/requirements.md`：已存在时保持原文、把补充需求追加为新段落并标注"第 {{WEEK}} 周补充"；不存在时创建并写入完整需求；
3. 将本周规划写入 `{{WEEK_DIR}}/pi_plan.md`，内容包括每个方向的：方向标题、目标、理由、待验证假设、证明/证伪判据、完整目标测试与预期产出。尽早安排目标测试与必要的验证设施，预留调用修复失败和独立复核；不得把“未测”或工程实现失败当作假设被证伪。方向用"方向 1"、"方向 2"……编号，共 {{R}} 个；
   在规划中建立带固定编号的最终验收表：原始需求、完整目标命令/操作、输入与参数、通过/证伪判据及所需证据。各 RA 只能分解实施，不能缩减或改写最终验收。要求每方向首轮实际尝试完整目标流程；遇阻时后续调用围绕最早实际阻塞推进。辅助任务必须说明解除哪个阻塞、结果如何改变下一步以及何时接回目标测试；
4. 提交改动。

首个方向实施前完成 `baseline.md` 的多仓库版本清单、原始输入和测试口径，并在规划中固定排名规则。按项目经理安排建立 `race.md`，记录所有方向使用同一基线的隔离位置；后执行的方向不能从先执行方向的成果建立分支。基线清单和实验可比性按 `race_contract.md` 核查。
