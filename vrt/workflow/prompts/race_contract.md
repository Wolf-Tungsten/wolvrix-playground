# 每周同基线赛马契约

本契约适用于项目经理、PI、全部 RA 和工程师。它是 Agent 必须核对的流程约束，不由 Python 执行器执行 Git 操作或裁定技术优胜者。

## 表达要求

- 所有报告、指令、任务安排和派发理由必须简明扼要。内容较复杂时优先采用总分结构：先给结论或总述，再列必要依据、动作和缺口。
- 使用准确、直白的语言，避免互联网黑话、口号、套话、重复复述和无关背景；技术术语仅在准确表达所必需时使用。
- 精简不得省略流程规定的字段、证据、命令、路径、退出码和验收缺口。项目经理必须把本要求写入每次技术角色派发。

## 共同基线与证据

- 每周 R 个方向必须从同一份代码基线独立探索。项目经理在派发首个方向实施之前，安排 PI 核查并归档 `week_<N>/baseline.md`，在 `pi_plan.md` 引用其版本/指纹。不能让后执行的 RA 从前一个 RA 的成果起步。
- 基线是仓库版本清单，不是一个根分支名称。逐项记录涉及的仓库身份、实际路径、父子关系、完整基线 commit、必要的父仓库 gitlink、相关源码/输入文件指纹，以及本周成果拟合入的目标引用和当时提交。独立嵌套仓库也必须记录；递归子模块按实际依赖确定范围，不要求统一分支名称或遍历切换无关仓库。
- 未提交代码不能默认为所有方向的基线。存在用户改动时先保留并明确纳入或排除方式；纳入的内容须有可复现快照/补丁指纹，不能依赖易变工作区。构建脚本、依赖、测试输入、参数和工具版本均需足以复现比较。
- 清单核定后本周不可由 RA/工程师改写，基线引用不得指向持续变化的分支。方向内后续步骤从本方向上一步成果继续，不必每步退回原基线。报告记录“共同起点、本方向修改、测量候选”的完整关系。
- 中途发现遗漏仓库时，由项目经理安排 PI 追加有版本的补充清单，确认该仓库在原共同起点的版本，并让全部受影响方向核查一致性。不能只给一个方向升级依赖或基准。若必须改变共同起点或测试口径，PI 必须要求全部受影响候选重新取得同口径证据；无法补齐的方向不参与本周选优。

## 独立隔离与可比实验

- 项目经理安排 `week_<N>/race.md` 记录各 RA 对应仓库、基线条目、隔离分支/worktree/检出目录、当前候选提交及核查记录。不同目录或分支名称可以不同，对应基线源码必须相同；共同档案目录中的报告提交不算方向代码差异。
- RA 派发与工程师开工都必须核查本方向起点和续接提交。禁止从其他方向 merge/cherry-pick/copy 尚在赛马中的实现，禁止将其他方向生成物冒充本方向基线或候选。需要公共修复时提交 PI 评估，按共同基线变更处理，不能暗中串联方向。
- 构建输出、实验日志和可变缓存按方向及版本隔离；共享只读输入须核对指纹。顺序复用同一物理工作区时，Agent 必须核对实际源码、嵌套仓库状态和生成物来源，不只检查顶层分支名。
- PI 在规划中固定完整目标、正确性门槛、性能计时范围、输入/参数、资源限制、测量与排名规则。同一原始基线的 A/B、相同工作负载与可比环境是选优依据；局部微基准、旧日志或不同规模实验不能直接用于全目标排名。
- 发现污染、基点不符或测量不可比，应保留证据并由项目经理安排核查、修复隔离或重测；缺口未补齐不得宣布该方向通过验收。不能删除其他方向或用户现场来制造干净起点。

## 周末单一优胜者

- 每个 RA 用满 W 次工程调用，分别提交方向周报：基线指纹、各仓库候选提交、独立性核查、完整目标证据和未完成项。done/no_value 不提前停止，未测不能作为证伪。
- PI 对所有方向逐项核查共同基线、独立性、正确性和可比性，按周初排名规则选择**至多一个**最优方向；并列时说明选择依据。没有合格方向时明确“无优胜方向”，保持集成代码不变，归档报告。
- PI 必须写明选择的 RA 编号与精确候选提交。项目经理据此安排 Agent 将该方向的多仓库成果集成到周初记录的目标位置，处理必要的父子引用；不能擅自拼接多个方向成为未参加比较的混合方案。
- 集成前复核目标是否发生漂移，集成后验证真实集成版本。若冲突修复或目标变化使结果不同于被测候选，保留前后提交与差异并由 PI 要求重新验收；不能把原候选测量直接报作集成后成绩。多仓库部分完成不能宣布全部集成成功。
- 最终报告记录排名表、排除原因、获胜提交、各仓库集成前后状态、集成验证及所有落选成果位置。保留各方向档案，不删除落选分支。下一周以已完成验证的集成结果重新建立统一基线；集成失败时明确哪些状态不能作为下一周起点。

## 各角色必须交接的信息

| 角色 | 本动作必须提供或核查 |
| --- | --- |
| 项目经理 | 派发附基线清单与 race.md 的实际可读位置、方向隔离位置、已核查流程状态；将本契约纳入每次相关派发 |
| PI_PLAN | 创建并核定 baseline.md，定义共同验收/排名规则，在 pi_plan.md 中引用基线；按项目经理安排记录 race.md |
| RA_PLAN_STEP | 任务书引用基线与本方向续接提交，说明实验隔离、目标口径及禁止混入其他候选 |
| ENGINEER | 开工/完工记录相关仓库提交、工作区差异、生成物来源；按共同口径提供实测与日志 |
| RA_REVIEW | 独立核查基线、候选差异和测量来源，不能只相信工程师自述；不合格时明确返工项 |
| RA_SUMMARY | 交付可比较的独立候选，列明完整目标成绩、版本和证据范围 |
| PI_FINAL | 按共同证据选择一个或零个优胜方向，精确指定集成对象并验收集成结果 |

以上文件统一存放在当前项目档案目录；技术 worktree 可以位于其他位置。执行器不自动渲染这些文档，项目经理必须读取并把具体路径、版本与相关条款写进实际派发 prompt。
