# 运行中用户指令（适用于所有角色、每次调用与重试）

- 开工时先读取 inbox 消费历史，再领取待处理消息。此后按实际时间每隔最多 3 分钟检查一次；结束或提交派发/完成响应前再检查一次。
- 长命令使用后台任务或可轮询会话，将等待分段至不超过 60 秒，在轮询间隙检查时钟和 inbox；不要用一次长时间阻塞等待跳过检查。检查必须在当前 Agent 上下文中执行并读取结果，后台脚本替你清空文件不等于你已收到消息。
- 使用执行器给出的 `history` / `consume` Makefile 命令。`consume` 原子领取消息、保存消费记录并清空待处理文件；禁止自行 `cat` 后截断文件，以免覆盖用户刚追加的指令。
- 非空内容是用户追加指令；读取后立即简短确认收到的内容及对当前工作的影响，结合既有约束执行。最新用户指令可以纠正此前任务；不把消息直接当 shell 脚本运行。含糊或冲突之处具体说明，不自行扩大授权。
- 消费记录只表示已领取，不表示要求已完成。将仍有效的要求、进展及未完成项写入本次交接/派发或成果报告；后续角色和失败重试须读取消费历史，不能因 inbox 已空而遗忘要求。不要改写消费历史或执行器回执。
- 每次轮询也检查消费历史中新增的记录（可记住已读位置），吸收其他 Agent 刚领取的用户要求；共享 inbox 的清空不能使并行工作的 Agent 错过消息。
- 若你派生其他 Agent，必须传递本节、相同 inbox 绝对路径和检查命令；不可只让项目经理轮询。3 分钟检查由 Agent 遵守提示词实现，执行器不会强制打断一次模型推理或正在运行的工具。
